# 研究迭代

用于实现新的研究想法、修改现有方法或设计对照实验。这个流程不预设当前模型的模块划分、输入模态、动作表示或训练算法。

## 流程

1. **明确假设**：用一句话说明要验证什么，以及预期为什么会改变结果。
2. **确定变量**：指出本次真正改变的研究变量，并列出需要保持不变的主要控制变量。
3. **读取当前事实**：从当前配置、入口和源码找到真实执行路径，不根据命名或历史文档猜测实现。
4. **定位改动面**：确认实现该想法所需的最小代码 / 配置范围，以及可能受到影响的训练、评测、推理或恢复路径。
5. **完成最小实现**：实现到可运行、可比较；研究特有逻辑尽量局部，不顺带重构无关代码。
6. **最低成本验证**：先做最便宜且足够证明改动正确的检查；只有必要时才扩大到更昂贵的运行。
7. **给出下一步实验**：提供一条可直接执行的命令或清楚的下一步实验方案。

## 输出

最终保持简洁，说明：

- 研究假设与主要变量；
- 实际修改范围；
- 哪些行为刻意保持不变；
- 已执行的验证及结果；
- 尚未验证的风险；
- 下一步实验。

## 原则

- 不假设存在 encoder、backbone、decoder 或其他固定模型分层。
- 不绑定某一种视觉表示、动作空间、生成算法或 Policy family。
- 不把当前 config 字段、checkpoint 结构或超参数写成 skill 的永久前提。
- 优先得到清楚、可运行、可比较的实现，而不是建立可复用框架。
- 除非用户明确要求，不启动长时间训练或大规模评测。
- 非关键实现细节未指定时，采用最简单合理方案并继续推进。
