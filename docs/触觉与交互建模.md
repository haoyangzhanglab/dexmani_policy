# 触觉与交互建模

## Interaction Representation

`dexmani_policy.agents.obs_encoder.interaction` 提供以手部为中心的单帧交互表征，以及 CordViP 和 AdapTac 的交互模块。InterFlow 使用 `HandObjectInteractionEncoder` 将 RGB 和点云编码为场景记忆，将末端位姿和指尖位置编码为手部 token，再融合五指触觉并查询场景记忆。 [InterFlow 训练与评测](../README.md#interflow)

### Hand Kinematic Representation

`HandKinematicEncoder` 的腕部 MLP 接收除以 `0.25 m` 的 Base Frame 腕部位置和 `eef_pose` 中按旋转矩阵前两列排列的 6D 旋转。编码器通过 Gram–Schmidt 正交化恢复从 Wrist Frame 到 Base Frame 的旋转矩阵，再将腕到指尖的 Base Frame 位移以行向量右乘该矩阵，得到 Wrist Frame 下的三维局部位置。旋转恢复和坐标变换均使用 FP32。五指共享的 Finger MLP 接收除以 `0.10 m` 的局部位置。每个 token 加上对应的解剖 slot embedding 后做 LayerNorm。`hand_landmarks_base` 保留米制的 Base Frame 腕部和五指位置。 [数据集坐标](仿真数据集格式.md#几何坐标)

### Finger-wise Tactile Representation

`FingerTactileEncoder` 用共享的无偏置 MLP 编码五指汇总力，沿用数据源的坐标、单位和尺度。每指获得一个 64 维局部触觉特征，五指取均值得到 64 维全局触觉特征。

`TactileFusion` 的逐指局部门控接收触觉特征和对应手指 token，共享接触门控接收全局触觉特征和融合前六个手部 token 的均值。局部残差乘以逐指局部门控和共享接触门控后加到对应手指 token。全局残差乘以同一接触门控后加到全部六个 token。无偏置编码和残差投影保证零力时融合精确等于输入手部 token。

### Hand-Object Geometric Relation Modeling

`GeoAwareRelationAttention` 以六个手部地标和场景 patch 中心描述 Hand-Object Geometric Relations。六个手部 token 先做一次四头 Self-Attention，再通过 Geometry-biased Cross-Attention 查询场景记忆。对每个手部地标与场景 patch，计算 Base Frame 下由地标指向 patch 中心的 XYZ 位移和欧氏距离，四个分量均除以 `0.10 m`。几何 MLP 将这四个分量映射成四个注意力头的加性偏置，末层权重和偏置初始化为零。

使用 FP32 参数和 AMP 时，位移、距离与几何 MLP 均以 FP32 计算。几何偏置在传入 SDPA 前转为 query 的 dtype。Cross-Attention 后应用残差 FFN 和最终 LayerNorm。

### Hand-Centric Spatial Interaction

`HandObjectInteractionEncoder` 默认从最多 1024 个点中取 128 个 patch，每组 32 点。相机外参将 Base Frame 坐标变换到 OpenCV 相机坐标，供 RGB 投影使用。默认 `center` 在 patch 中心采样 RGB 特征，`group_mean` 对投影有效的邻域点取平均。模型拼接 192 维几何特征与 192 维 RGB 特征，以原始 Base Frame patch 中心做 3D RoPE，经两层、八头空间 Transformer 后投影到 192 维，形成场景记忆。

手部 token 经 Tactile Fusion 后，与 Base Frame 地标一起参与几何关系建模。编码器输出 `[B, 6, 192]` 的交互 token，依次对应腕部、拇指、食指、中指、无名指、小指。

`effective_config["geometry_scales"]` 按坐标系记录固定归一化尺度。`wrist_position_base` 为 `0.25 m`，`finger_position_wrist` 和 `hand_scene_relative_position_base` 均为 `0.10 m`。使用该配置重建编码器时会校对记录值，前向计算始终使用内部常量。

### Baseline Interaction Modules

#### CordViP — Contact Coordination

`ContactCoordinationEncoder` 接收手部点云、物体点云和关节状态。手部点云与物体点云互相提供注意力上下文，手部关节与手臂状态也以同样的方式交互。编码器返回两组视觉表征和两组状态表征，供 CordViP 预训练和策略使用。 [观测预训练](观测预训练.md#cordvip)

#### AdapTac — Future Tactile / Visuotactile Fusion

`VisuoTactileAttention` 在场景点云 token 与五指触觉 token 之间执行双向交叉注意力。AdapTac 策略用编码后的视觉和触觉特征预测未来绝对接触力，再用 `ForceGuidedFusion` 根据当前和预测力融合视觉与触觉。融合表征结合关节状态生成动作。

`bash scripts/training/train.sh adaptac` 默认使用五指汇总力 `finger_tactile_force`，与 `dexmani_sim` 的评测观测一致。数据含密集触觉 `taxel_tactile_force` 时，训练可用 `tactile=taxel` 选择对应编码器。两种配置均沿用数据源的触觉坐标、单位和尺度。 [示教数据格式](仿真数据集格式.md)

训练时将无效标签置零，再对真实未来力加噪，用一步去噪结果引导动作。显式力损失按每次更新的有效元素取均值。设 `agent.force_loss_weight=0` 后，力预测器仍参与动作生成并接收动作损失的梯度。部署时从噪声采样未来力，条件来自当前观测。 [AdapTac 官方实现](https://github.com/kingchou007/adaptac-dex/blob/60e2ef1b7b0a29f5d29f5d755e8fe6d048f69fa5/src/adaptac/policy/FFG_policy.py)

### Input and Output Specification

`HandObjectInteractionEncoder` 的单帧输入 `obs` 包含以下字段。

- `point_cloud` 为 `[B, N, 3]` 或 `[B, N, 6]`，XYZ 采用米制 Base Frame 坐标。默认 `pc_dim=3` 时使用 XYZ，设置 `pc_dim=6` 时使用输入的 XYZRGB。采样后的点数 `min(N, num_points)` 至少为 `max(num_patches, group_size)`，默认下限为 128。仿真用全零 XYZ 表示空场景，批次中任意一帧为空时编码器抛出 `ValueError`。
- `rgb` 为 `[B, 3, H, W]`，接受 `uint8` 或取值在 `[0, 1]` 的 `float32`。示教数据和部署观测中的 `camera_intrinsic` 和 `camera_extrinsic` 按帧展平，组成 `[B, 9]` 和 `[B, 12]`。直接调用编码器也可传入 `[B, 3, 3]` 和 `[B, 3, 4]` 的矩阵。
- `eef_pose` 为 `[B, 9]`，包含 Base Frame 腕部位置与 6D 旋转。`fingertip_xyz` 和 `finger_tactile_force` 均为 `[B, 5, 3]`，按拇指、食指、中指、无名指、小指排列。指尖位置采用米制 Base Frame 坐标，触觉沿用数据源的坐标和单位。

InterFlow 对关节状态和动作使用 `limits`，对点云、RGB、相机标定、末端位姿、指尖位置和触觉使用 `identity`。图像尺寸由 `ImageProcessor` 调整，投影同步使用对应的像素变换。

`encoder(obs)` 返回交互 token。`encoder.forward_with_aux(obs)` 使用同一计算路径，返回以下张量。形状按默认场景配置列出。

| 键 | 形状 | 含义 |
| --- | --- | --- |
| `tokens` | `[B, 6, 192]` | 六个交互 token |
| `scene_tokens` | `[B, 128, 192]` | 场景记忆 |
| `scene_points_base` | `[B, 128, 3]` | 米制基座系 patch 中心 |
| `hand_landmarks_base` | `[B, 6, 3]` | 米制基座系腕部和五指地标 |
| `local_tokens` | `[B, 5, 64]` | 逐指触觉特征 |
| `global_token` | `[B, 64]` | 五指平均触觉特征 |
| `rgb_projection_valid` | `[B, 128, 1]` 或 `[B, 128, 32]` | `center` 或 `group_mean` 对应的布尔投影有效性 |

### 独立组件的 RGB 初始化

独立使用时，先按所选 Backbone 的架构构建 Encoder，再显式加载 RGB 预训练权重。

```python
from dexmani_policy.agents.obs_encoder.interaction import HandObjectInteractionEncoder

encoder = HandObjectInteractionEncoder(rgb_backbone_name="dinov3")
encoder.rgb_encoder.initialize_weights("path/to/pretrained/rgb")
```

DINOv3 的本地权重目录需要包含与配置架构匹配的 `model.safetensors`。独立构建 DINO 或 SigLIP 时，需在 `rgb_backbone_config` 中提供 `architecture`，预训练来源需包含该架构所需的参数。SigLIP 默认将图像缩放到 `architecture.image_size`，可通过 `rgb_backbone_config.image_size` 显式设置。

### RGB 策略的初始化与恢复

从头训练 InterFlow 等 RGB 策略时，在配置中指定预训练来源。

```yaml
initialization:
  rgb: path/to/pretrained/rgb
```

训练框架通过 `agent.rgb_backbone_name` 识别 Backbone 类型。DINO 或 SigLIP 未显式配置 `agent.rgb_backbone_config.architecture` 时，框架先从 `initialization.rgb` 读取架构。Fresh Training 在创建 EMA 模型前直接调用 RGB Backbone 的权重加载接口。

Warm Start 从源 Checkpoint 恢复模型参数，当前配置未指定 RGB 架构时也从中继承架构。Full Resume 从本次训练的 Checkpoint 恢复模型及训练状态。两种 Checkpoint 路径均跳过 `initialization.rgb` 的权重加载。
