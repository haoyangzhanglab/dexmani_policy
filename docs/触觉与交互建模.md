# 触觉与交互建模

触觉描述正在发生的接触。未来力预测既可以参与动作生成，也可以只用于训练交互表征；AdapTac 与 InterAct-Dex 分别采用这两种方式。

## 触觉表征

| 表征 | 编码内容 |
| --- | --- |
| force | 每根手指的汇总力 |
| taxel | 密集触觉单元的通道信息 |
| patch | 从密集触觉中提取区域描述，再汇聚为手指特征 |

这些表征对应不同的输入组织方式。当前仿真提供五指汇总接触力，不提供密集触觉；真实传感器通道的尺度和坐标也不能直接视为与仿真一致。

XHand Real 的 Aggregate `(5,3)` 与 Dense `(5,120,3)` 共用固定 divisor `255.0`，公式为 `F_scaled = F_SDK / 255.0`。唯一缩放入口是 `dexmani_real` 的 `XHandFeedback.consume()`；SDK State 保持 Native，Feedback Cache、Raw HDF5、Online Observation 和 Canonical Zarr 均为 `float32` 的 SDK / 255，不改变手指或 XYZ 顺序，也不裁剪。Raw 与 Online 直接读取缓存，Canonical 直接复制 Raw，不再缩放。

XHand Real 触觉数组应已按上述约定完成 SDK / 255 缩放，单位正确性由研究者负责。生产端仍记录 Raw 的 `hand_tactile_scale_divisor=255.0` 和 Canonical Zarr 的 `tactile_scale_divisor=255.0`；EpisodeStore 保留 attrs，但不再核验缩放声明。旧 Raw、Zarr 和 Checkpoint 不提供兼容或迁移，实验使用新规范数据重新训练。

仿真数据的 `tactile_config_json` 仅作为说明性元信息，策略不读取或解析该字段。force、taxel、patch 均要求 `identity`，不创建触觉 affine，不使用 Dataset Min-Max 或 Z-score。当前输入和未来标签直接使用数据集值，XHand Real 即 SDK / 255。恢复仅创建 limits 字段并严格加载保存参数。

Patch 的 `activity_scale=1/255`（`0.00392156862745098`），与输入使用相同单位。对 `a(f;s)=‖f‖/(‖f‖+s)`，有 `a(f/255;s/255)=a(f;s)`，因此 Activity Fraction 的数学含义保持不变。Mean Force、Peak Force 和 Strength 自然缩小 255 倍，由重新训练的 MLP 学习，不乘回 255。仿真触觉的单位由数据源决定，不能默认套用 XHand 的 `/255`；其他数据源应按自身单位配置 activity scale 和 loss beta。

## AdapTac：未来力引导动作生成

AdapTac 先编码场景点云与触觉，再通过双向注意力融合视觉和接触信息。未来力扩散模型根据观测历史预测未来绝对力，预测结果进一步引导特征融合，作为动作扩散的条件。

其主要链路为：**视觉与触觉交互 → 未来力预测 → 力引导融合 → 动作生成**。

未来力分支同时参与训练和在线推理。训练时使用未来力监督，推理时从噪声采样未来力，再生成动作。

对于 XHand Real，Current Force Observation、Future Force Target、Force Predictor 输出与 ForceGuidedFusion 的当前/预测力均为 SDK / 255。ForceDiffusion 在这一归一化力空间中保持标准 Gaussian Noise、DDIM Scheduler、MSE 和 `prediction_type="sample"`；`force_loss_weight=1.0` 不变，不在内部乘回 255 或补偿 65025，也不增加其他归一化。这是新数值空间中的重新训练，不要求复现旧 SDK Native 数据的噪声比例。保留 `loss_force` 和 `loss_force_weighted` 日志，供检查辅助任务贡献。

## InterAct-Dex：Geometry-Grounded Contact-Aware Policy

HandGeometryEncoder 用 Base-frame 腕部 XYZ+Rot6D 和 Wrist-relative 五指 XYZ 生成六个独立身份查询。四头 Relative3DCrossAttention 读取128个 Point Transformer patches；位置偏置与 Value 分支均使用 Base-frame 三维相对位移及固定 `0.10 m` 尺度。Value 分支只有一个零初始化的无偏置线性投影（576个参数），以 Wrist 为共同数值原点，在 SDPA 前加入 Scene Geometry、输出投影前减去 Anchor Geometry，无需构造完整 pairwise value tensor。它不直接改变 Attention Weights，不保证产生不同的手指关注模式或提升任务表现。

TactileGatedFusion 将五指零参考力编码为64维局部特征，用对应手指几何条件化的加性注意力生成全局触觉。六个共享参数的标量 gate 调制残差：Wrist 接收全局触觉，五指各自接收局部触觉。所有 Value 投影无 bias，残差后不做 LayerNorm，因此物理零力严格恢复几何输入。

每帧按 `[wrist, thumb, index, middle, ring, pinky, joint_state, global_scene]` 排列。Joint 使用原 StateEncoder，Scene 使用轻量注意力池化，三帧共24个192维 Token。现有 DiTX + Rectified Flow 预测16个动作位置，裁掉两个历史位置后返回14个未来关节目标，执行前8个；RTC 保持原协议。

当前触觉在策略边界通过 Identity 透传。训练辅助头仅读取三帧六个 Interaction Token，以可学习时间权重池化，预测 `q+8` 的五指 Aggregate 绝对力 `[B,5,3]`；标签来自 `finger_tactile_force`。XHand Real 的预测和标签均为 SDK / 255，按 episode-valid mask 在此空间计算 Smooth L1，不乘回 255。构造函数的 `future_force_loss_beta` 默认 `1.0` 并要求有限正数；本次 XHand 配方显式设为 `1/255`，即一个 SDK 数值单位对应的归一化阈值，`future_force_loss_weight=0.1` 保持不变。

对误差 `e`，`L_{β/255}(e/255)=L_β(e)/255`，且相对于归一化预测值的梯度等于原损失相对于 SDK Native 预测值的梯度，因此无需把 Loss Weight 乘以 255。日志 `future_force_mae_scaled` 为当前输入尺度下的 MAE，`future_force_mae_sdk = future_force_mae_scaled * 255.0` 仅在 XHand Real 契约下表示 SDK Native 数值；两者均不参与反向传播。其他数据源可独立配置 beta，其指标单位应按数据源解释。

辅助梯度进入几何、Point Transformer、Cross-Attention 和触觉融合，不直接进入 DiTX、Joint Encoder 或 Scene Pool。推理不调用辅助头；`future_force_loss_weight=0` 不创建头，Dataset 类型保持不变，仅跳过未来标签读取；当前触觉观测仍正常读取。

此任务是 observation-conditioned future absolute contact force forecasting，不是动作条件动力学；场景输入没有目标实例真值，应称 hand–scene interaction。

## 坐标与传感器契约

策略接口要求 Base-frame 米制点云、EEF 和指尖坐标。已检查的本地仿真数据使用 World 坐标，机器人根位姿为 `[0,0,0,1,0,0,0]`，因此这些数据中 World 与 Base 重合。非单位安装的 World 数据必须由生产端完成共同的 World→Base 转换。

Rot6D 连续存储旋转矩阵前两列，`(tip_base-wrist_base) @ R_base_from_wrist` 得到 Wrist-local 坐标。触觉输入及未来标签保持数据生产端定义的同一语义，策略不将其旋转到 Wrist。

当前相邻 dexmani_sim 的 XHandTactileSensor 在每个物理子步将接触力转到各指传感器轴，再在控制周期内平均；输出三分量为传感器 X、Y 投影及 `max(0,-sensor_z)`，除以 `[50,50,100] N` 后裁剪到量程，法向分量非负。该实现使用 SAPIEN 报告的法向接触冲量，不包含摩擦冲量，不能把 X/Y 分量直接解释为完整摩擦剪切力。已有 World 轴原始力数据不会因使用 identity 自动转换为这一表征。

真机几何生产端通过 Base-frame FK 和相机外参提供几何。真机触觉读取 SDK `calc_force.fx/fy/fz`，其轴、单位及零偏与仿真的一致性尚需硬件标定，不能仅凭字段名互换。normalizer offset 不是传感器零偏标定。

## 验证入口

`smoke_test` 统一负责两种验证：不传配置名时，使用临时合成数据检查 DP3/CordViP 的数据、归一化、训练恢复与部署；传入配置名（如 `smoke_test interact_dex`）时，运行该配方的真实数据短程训练恢复。投影诊断图使用 `visualize_patch_projection`。checkpoint 必须包含当前模型要求的全部字段，包括 `relative_value.weight`。

可运行的短程检查示例：

```bash
python -m dexmani_policy.test_tools.smoke_test --device cpu
OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 python -m dexmani_policy.test_tools.smoke_test interact_dex --device cuda:0 --max-updates 1 --resume-updates 1 --override dataloader.batch_size=2 --override dataloader.num_workers=0 --override dataset.max_train_episodes=1 --override training.loop.total_train_steps=2 --override training.lr_warmup_steps=0 --override training.use_bfloat16=true
```

最后一条命令可追加 `--override agent.future_force_loss_weight=0` 检查关闭辅助监督的路径。未指定输出目录时，测试产物使用临时目录并自动清理。

上述检查验证接口、数值计算及训练恢复链路，不代表策略收敛、任务成功率或不同触觉数据源已经完成标定；闭环任务表现与真机标定需要单独验证。

InterAct-Dex 的 future_force_horizon 可以超过动作预测窗口。未来标签从同一 episode 读取，越过回合末尾的填充值仍由 mask 标为无效；较大 horizon 可减少有效监督。RectifiedFlow 的 time_shift_alpha 接受所有有限正数，包括 0.5、1、3，公式不变。
