# 触觉与交互建模

触觉描述正在发生的接触。AdapTac 将场景与触觉融合，并通过未来力预测引导动作生成。

## 触觉表征

| 表征 | 编码内容 |
| --- | --- |
| force | 每根手指的汇总力 |
| taxel | 密集触觉单元的通道信息 |
| patch | 从密集触觉中提取区域描述，再汇聚为手指特征 |

这些表征对应不同的输入组织方式。当前仿真提供五指汇总接触力，不提供密集触觉；真实传感器通道的尺度和坐标也不能直接视为与仿真一致。

force、taxel、patch 均要求 `identity`，不创建触觉 affine；当前输入和未来标签直接使用数据集值。EpisodeStore 保留数据源 attrs，策略不依据单位声明换算数值。仿真传感器的坐标与尺度见下文“坐标与传感器契约”。

XHand Real 的 Aggregate `(5,3)` 与 Dense `(5,120,3)` 在 `XHandFeedback.consume()` 中统一除以 `255.0`；Raw、在线观测和导出 Zarr 均使用该尺度，不重复缩放、不改变指序与轴序。这一约定不适用于仿真数据。

Patch 的 `activity_scale=1/255`（`0.00392156862745098`），与输入使用相同单位。对 `a(f;s)=‖f‖/(‖f‖+s)`，有 `a(f/255;s/255)=a(f;s)`，因此 Activity Fraction 的数学含义保持不变。仿真触觉的单位由数据源决定，不能默认套用 XHand 的 `/255`；其他数据源应按自身单位配置 activity scale。

## AdapTac：未来力引导动作生成

AdapTac 先编码场景点云与触觉，再通过双向注意力融合视觉和接触信息。未来力扩散模型根据观测历史预测未来绝对力，预测结果进一步引导特征融合，作为动作扩散的条件。

其主要链路为：**视觉与触觉交互 → 未来力预测 → 力引导融合 → 动作生成**。

当前实现适配了五指力 token、Point Transformer 场景编码、池化前双向交互、按时间拼接的历史融合和 joint state 动作条件。默认 H16／观测2／执行8，以最新观测 q 为起点预测 q+1…q+15 的五指绝对力 `[B,15,5,3]`，不是力增量或动作条件动力学；越过回合末尾的标签由 valid mask 排除。

`AdapTacDataset` 只保留 q+1 仍在本回合内的样本，保证每个样本至少有一帧有效未来力。它连续读取 `horizon - n_obs_steps + 1` 帧目标，越过回合末尾时重复最后一帧真实力并将对应 mask 标为无效。`tactile=force` 的标签为 `[B,F,5,3]`，`tactile=taxel` 和 `tactile=patch` 的标签均为 `[B,F,5,120,3]`，有效 mask 统一为 `[B,F]`；F 为上述未来步数。

未来力分支同时参与训练和在线推理。训练 guide 来自 noisy-GT 的单次去噪预测，推理则从噪声多步采样未来力；动作 loss 仍通过 guide 训练力预测器。`force_loss_weight=0` 只取消显式力监督，预测、guide 及在线采样仍运行。

观测、未来目标和预测使用同一数据坐标及尺度。ForceDiffusion 使用标准 Gaussian Noise、DDIM、MSE 和 `prediction_type="sample"`。默认 `force_loss_weight=1.0`、力扩散 `clip_sample=false`、动作 `clip_sample=true`；`loss_force` 与 `loss_force_weighted` 分别记录原始和加权辅助损失。

## 手部几何与触觉融合模块

以下模块作为独立组件保留，当前没有策略将三者组合接入动作生成链路。

HandGeometryEncoder 用 Base-frame 腕部 XYZ+Rot6D 和 Wrist-relative 五指 XYZ 生成六个独立身份查询。四头 Relative3DCrossAttention 从场景 Token 读取特征；位置偏置与 Value 分支均使用 Base-frame 三维相对位移及固定 `0.10 m` 尺度。Value 分支只有一个零初始化的无偏置线性投影（576个参数），以 Wrist 为共同数值原点，在 SDPA 前加入 Scene Geometry、输出投影前减去 Anchor Geometry，无需构造完整 pairwise value tensor。它不直接改变 Attention Weights，不保证产生不同的手指关注模式或提升任务表现。

TactileGatedFusion 将五指零参考力编码为64维局部特征，用对应手指几何条件化的加性注意力生成全局触觉。六个共享参数的标量 gate 调制残差：Wrist 接收全局触觉，五指各自接收局部触觉。所有 Value 投影无 bias，残差后不做 LayerNorm，因此物理零力严格恢复几何输入。

## 坐标与传感器契约

上述几何模块要求 Base-frame 米制点云、EEF 和指尖坐标。已检查的本地仿真数据使用 World 坐标，机器人根位姿为 `[0,0,0,1,0,0,0]`，因此这些数据中 World 与 Base 重合。非单位安装的 World 数据必须由生产端完成共同的 World→Base 转换。

Rot6D 连续存储旋转矩阵前两列，`(tip_base-wrist_base) @ R_base_from_wrist` 得到 Wrist-local 坐标。触觉输入及未来标签保持数据生产端定义的同一语义，策略不将其旋转到 Wrist。

当前相邻 dexmani_sim 的 XHandTactileSensor 在每个物理子步将接触力转到各指传感器轴，再在控制周期内平均；输出三分量为传感器 X、Y 投影及 `max(0,-sensor_z)`，除以 `[50,50,100] N` 后裁剪到量程，得到无量纲值，法向分量非负。该实现使用 SAPIEN 报告的法向接触冲量，不包含摩擦冲量，不能把 X/Y 分量直接解释为完整摩擦剪切力。已有 World 轴原始力数据不会因使用 identity 自动转换为这一表征。

真机几何生产端通过 Base-frame FK 和相机外参提供几何。真机触觉读取 SDK `calc_force.fx/fy/fz`，其轴、单位及零偏与仿真的一致性尚需硬件标定，不能仅凭字段名互换。normalizer offset 不是传感器零偏标定。

## 验证入口

`smoke_test` 统一负责两种验证：不传配置名时，使用临时合成数据检查 DP3/CordViP 的数据、归一化、训练恢复与部署；传入配置名时，运行该配方的真实数据短程训练恢复。投影诊断工具 `visualize_patch_projection` 为每个数据集生成一张原始 RGB 与采样中心的叠图，点的颜色来自采样点自身的 RGB。

可运行的短程检查示例：

```bash
python -m dexmani_policy.test_tools.smoke_test --device cpu
```

未指定输出目录时，测试产物使用临时目录并自动清理。

上述检查验证接口、数值计算及训练恢复链路，不代表策略收敛、任务成功率或不同触觉数据源已经完成标定；闭环任务表现与真机标定需要单独验证。
