# 触觉与交互建模

触觉描述正在发生的接触。AdapTac 将场景与触觉融合，并通过未来力预测引导动作生成；手部几何与触觉融合组件则提供独立的交互建模能力。

## 触觉表征

| 表征 | 编码内容 |
| --- | --- |
| force | 每根手指的汇总力 |
| taxel | 密集触觉单元的通道信息 |

`tactile=force` 使用 `finger_tactile_force [5,3]`，`tactile=taxel` 使用 `taxel_tactile_force [5,120,3]`；两种编码器都输出五个 64 维手指 token。

当前仿真提供五指汇总接触力，不提供密集触觉。触觉输入与未来目标沿用数据源定义的坐标和尺度，不同来源的触觉不能仅凭字段相似互换。

## AdapTac：未来力引导动作生成

**视觉与触觉交互 → 未来力预测 → 力引导融合 → 动作生成**

场景点云与当前触觉先通过双向注意力交换信息，未来力扩散模型再根据观测历史预测未来绝对力。预测结果引导视觉与触觉融合，并结合关节状态，作为动作扩散的条件。

训练联合优化动作生成与未来力预测，力损失仅统计同一回合内的有效未来帧。未来力分支也参与在线推理，为动作生成提供预测的接触信息。

日志中，`train/loss` 为动作损失与加权力损失之和；`train/loss_action`、`train/loss_force` 和 `train/loss_force_weighted` 分别记录动作损失、原始力损失和加权力损失。

[AdapTac](../dexmani_policy/agents/policies/adaptac.py) 组合未来力预测与动作生成。[ForceTransformer](../dexmani_policy/agents/action_decoders/backbones/force_transformer.py) 负责力预测网络，[ForceDiffusion](../dexmani_policy/agents/action_decoders/diffusion.py) 与动作扩散共用加噪和训练预测流程；观测交互与力引导融合位于 [future_tactile.py](../dexmani_policy/agents/obs_encoder/interaction/future_tactile.py)。

## 多模态交互编码器

[MultimodalInteractionEncoder](../dexmani_policy/agents/obs_encoder/multimodal_interaction.py) 将场景、手部几何与触觉组合为两组独立 token，当前未接入策略。调用方式为 `encoder(obs)`；输入已展平为 BT，几何量统一使用 Base-aligned 坐标，单位为米。

| 输入 | 形状 | 坐标与尺度 |
| --- | --- | --- |
| `point_cloud` | `[BT,N,C]` | XYZ 为 Base-aligned 米制坐标；`C≥pc_dim`，`pc_dim` 为 3 或 6 |
| `rgb` | `[BT,3,H,W]` | uint8 或 `[0,1]` float32 |
| `camera_intrinsic` | `[BT,9]` | 展平的 3×3 内参 |
| `camera_extrinsic` | `[BT,12]` | 展平的 Base-aligned→Camera 3×4 外参 |
| `eef_pose` | `[BT,9]` | Base 系位置（米）与 6D 旋转 |
| `fingertip_xyz` | `[BT,5,3]` | Base 米制坐标 |
| `finger_tactile_force` | `[BT,5,3]` | 原始数据源的坐标、单位与尺度 |

局部编码只使用所需的 XYZ 或 XYZRGB；XYZ 和 RGB 数值保持不变，多余属性不参与编码，原始输入不被修改。

当前仿真使用单位 Root Pose，World 与 Base 重合；真实机器人点云和 FK 几何直接使用 xArm Base。两种来源的点云、EEF 位置与 6D 旋转、指尖均可直接输入，无需额外转换。数据生产依据见[数据集坐标约定](仿真数据集格式.md#几何坐标)。

场景分支为：点云预处理 → `LocalPatchEncoder(192)` → `RGBPatchFusion(384)` → `SpatialContextEncoder(384)` → `Linear(384,192)`。点云只预处理一次，结果直接传入局部编码器。

RGB 投影直接使用统一坐标：`center` 使用 Patch XYZ，`group_mean` 根据 `neighbor_idx` 从预处理点云读取 XYZ。`project_to_image()` 接收 `points`、`intrinsics` 和 `extrinsics`；外参必须将点云所在坐标系变换到 OpenCV Camera 坐标系，此处为 Base-aligned→Camera。图像变换使用半像素中心约定，特征采样使用 `align_corners=False`。

手部分支为：`HandGeometryEncoder` → `Relative3DCrossAttention` 单向读取场景（Scene→Hand）→ `TactileGatedFusion` 融合原始力。Patch XYZ 与 Hand Anchors 直接传入相对注意力；零力时最终手部特征等于相对注意力输出。

输出为 `scene_tokens [BT,P,192]`、`scene_xyz_base [BT,P,3]`、`hand_tokens [BT,6,192]` 和 `hand_anchors_base [BT,6,3]`。`P` 默认为 128，可通过 `patch_config.num_patches` 调整；Scene 与 Hand 不拼接、不做全局 Pooling。

`patch_config` 与 `spatial_config` 分别配置局部编码和空间 Transformer，不接受固定宽度 `channels`。恢复时用保存的 `effective_config` 调用 `MultimodalInteractionEncoder(**config)`，再通过 `load_state_dict` 加载完整权重，无需重新加载外部预训练权重。

RGB Backbone 支持 `dino`、`dinov3` 和 `siglip`；`dino` 与 `siglip` 需要在 `rgb_backbone_config.architecture` 中显式提供结构。预处理后的图像宽高必须能被 `patch_size` 整除，使 Patch 网格完整覆盖图像。

构造模型不会自动加载或下载预训练权重。默认 `tune_mode="freeze"`，DINOv3 以 `pretrained=False` 创建，因此未加载权重的 Backbone 是随机且冻结的。

方式 A：显式加载预训练视觉 Backbone。

```python
encoder = MultimodalInteractionEncoder(rgb_backbone_name="dinov3")
encoder.rgb_encoder.initialize_weights(pretrained_source)
```

`pretrained_source` 遵循 [ViTEncoder.initialize_weights()](../dexmani_policy/agents/obs_encoder/rgb/vit.py) 的现有接口：DINOv3 使用包含 `model.safetensors` 的本地目录，或提供该文件的 Hugging Face 模型来源；权重须与配置结构匹配。

方式 B：从头训练视觉 Backbone。

```python
encoder = MultimodalInteractionEncoder(
    rgb_backbone_name="dinov3",
    rgb_backbone_config={"tune_mode": "full"},
)
```

`full` 开启 Backbone 梯度，不会自动加载预训练权重。

## 手部几何与触觉融合组件

| 组件 | 职责 |
| --- | --- |
| `HandGeometryEncoder` | 将腕部位姿与五指位置编码为六个带身份信息的查询 |
| `Relative3DCrossAttention` | 结合手部与场景的三维相对位置，从场景特征中读取几何信息 |
| `TactileGatedFusion` | 从五指触觉读取特征，以全局触觉门控残差更新六个几何 token |

这些组件由多模态交互编码器组合使用，也可单独调用。

组件分别位于 [proprio.py](../dexmani_policy/agents/obs_encoder/proprio.py) 和 [interaction/](../dexmani_policy/agents/obs_encoder/interaction/)，整体模块关系见[项目架构](项目架构.md)。

### 几何坐标与尺度

`HandGeometryEncoder` 接收 `eef_pose [...,9]` 和 `fingertip_xyz [...,5,3]`，前导维度必须完全匹配；输出 `tokens [...,6,192]` 和 `anchors_base [...,6,3]`。支持单样本、Batch 和时序输入。wrist 对应生产端的 `custom_eef_link`。

位姿的后六维依次为旋转矩阵的第一列、第二列，表示 EEF 轴在 Base 系中的方向。解码沿用 FP32 Gram–Schmidt，输入应为有效、非退化的旋转表示；局部指尖为 `(fingertip_xyz - wrist_position) @ rotation`。几何计算在 autocast 外完成。

| 构造参数 | 默认值（米） | 作用 |
| --- | ---: | --- |
| `HandGeometryEncoder.wrist_scale` | 0.25 | Base 系腕部位置的网络输入尺度 |
| `HandGeometryEncoder.finger_scale` | 0.10 | Wrist 局部指尖位置的网络输入尺度 |
| `Relative3DCrossAttention.geometry_scale` | 0.10 | position bias 的相对位置尺度 |

三个尺度独立且必须有限、严格大于零，不是可学习参数。`anchors_base` 始终保留原始米制坐标。尺度不写入 state dict，恢复模型时需传入相同构造参数。

手部 anchors 和 Point Transformer 的 Patch XYZ 均保留输入坐标。单独组合这些组件时，调用方须提供同一 Base 系下的米制几何。

`EpisodeStore` 保留几何量的原始尺度。通用策略预处理会对配置为 `limits` 的字段执行归一化，因此上述组件要求原始坐标或 `identity` 处理后的输入，不能接收已经归一化的位姿或场景坐标。

### 相对几何注意力

`Relative3DCrossAttention` 接收 `body_tokens [B,L,192]`、`scene_tokens [B,N,192]` 及对应的 `anchors_base [B,L,3]`、`scene_xyz_base [B,N,3]`，输出 `[B,L,192]`。支持动态 Batch、Query 和 Scene Token 数量；与手部编码器组合时 `L=6`。时序输入需将 Batch 和时间轴一同展平，单样本需补 Batch 轴。

单层 Pre-LN Cross-Attention 使用 4 个 48 维 head：手部 token 生成 Q，场景 token 通过一次 Linear 联合生成 K/V。广播计算 `scene_xyz_base[:, None] - anchors_base[:, :, None]` 得到 `[B,L,N,3]` 的相对坐标，除以 `geometry_scale` 后，经 `Linear(3,32) → SiLU → Linear(32,4)` 生成 `[B,4,L,N]` 的加性 Bias，直接加入 SDPA 的 Attention Logits。合并 head 后执行 `LayerNorm(body_tokens + OutputProjection(context))`。MLP 末层 weight 和 bias 零初始化，使初始行为等价于普通 Content-based Cross-Attention。

相对坐标与 Geometry MLP 在 autocast 外使用 FP32。Bias 在进入原生 SDPA 前转换为 Q 的 dtype 并整理为连续的 `[B,4,L,N]` 布局；连续布局便于后端处理，具体后端由 PyTorch 根据输入选择。使用 AMP 时，模块参数和输入坐标保持 FP32，其余投影、残差和 LayerNorm 遵循原生 autocast 规则。

### 触觉门控融合

`TactileGatedFusion` 接收 `geometry [B,6,192]` 和 `force [B,5,3]`，输出 `[B,6,192]`。geometry 按 Wrist、Thumb、Index、Middle、Ring、Little 排列，force 对应相同顺序的五指。组合时直接传入 `Relative3DCrossAttention` 的六个输出 token；力输入保留数据源的坐标、单位和尺度。

融合模块直接编码原始力，不能传入 `XHandForceEncoder` 的 64 维输出；后者用于 AdapTac，是独立的三层带 Bias MLP。时序输入需将 geometry 和 force 的 Batch、时间轴一起展平，融合后再恢复前导维度。

共享无 Bias MLP `3 → 64 → 64` 使用 SiLU 激活，生成五个触觉 token。共享的 `Linear(64,64,bias=False)` 经 Sigmoid 后逐特征调制触觉，再对五指取均值得到全局触觉。Finger Embedding 仅加入 Key，Value 保持为调制后的触觉；Embedding 在相加前匹配触觉 dtype。

Geometry 经 LayerNorm 后作为 Query，通过单层 Cross-Attention 读取触觉：`embed_dim=192`、`num_heads=4`、`kdim=vdim=64`、`bias=False`、`dropout=0.0`，调用使用 `need_weights=False`。全局触觉经过 `LayerNorm(64) → Linear(64,64) → SiLU → Linear(64,1) → Sigmoid` 生成每个样本的标量 Gate，扩展为 `[B,1,1]` 后广播到六个 token，输出 `geometry + gate * tactile_context`。

Channel Gate 使用 Xavier Uniform 初始化，Finger Embedding 使用 `trunc_normal_(std=0.02)`，全局 Gate 末层 Linear 的 bias 初始化为 `-1.5`。零力经 Force Encoder 和 Channel Gate 后仍为零；Value 不含身份偏置，Attention 投影也无 Bias，因此参数训练更新后仍保持零力恒等。其余运算遵循原生 AMP 规则。

机制来源与本模块适配：

- [DeCAL Cross-Attention 与全局 Gate](https://github.com/AureleoPKU/DeCAL/blob/09de1855cfc933a2d2680d6011744476647ed7d1/src/lerobot/policies/DeCAL/modeling_decal.py)：以 Geometry 为 Query，通过触觉门控残差融合；采用其[全局均值汇总](https://github.com/AureleoPKU/DeCAL/blob/09de1855cfc933a2d2680d6011744476647ed7d1/src/lerobot/policies/DeCAL/tactile_utils.py)，不引入触觉 Transformer。
- [DexTacWAM Finger Embedding](https://github.com/dextacwam/DexTacWAM/blob/4f7c5a80dda2ca06667a9a583075d8c92108eb56/models/tactile_models/visual_vae_adapter.py)：沿用可学习参数和截断正态初始化；原实现加入 K/V，本模块仅加入 Key 以保持零力恒等。
- [DECO 逐特征门控](https://github.com/BAAI-Humanoid/DECO/blob/fdd159e2a149ff0b91f001569ae7e9d60220697c/models/deco/deco.py)：沿用无 Bias Linear、Sigmoid 乘法门控和 Xavier Uniform 初始化，将原 68 维操作适配到每指 64 维，五指共享权重。
