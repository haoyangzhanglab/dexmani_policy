# 触觉与交互建模

## AdapTac

AdapTac 用场景点云与触觉预测未来绝对接触力，再用力预测引导视觉与触觉融合，结合关节状态生成动作。

`bash scripts/training/train.sh adaptac` 默认使用五指汇总力 `finger_tactile_force`，与 `dexmani_sim` 的评测观测一致。数据含密集触觉 `taxel_tactile_force` 时，训练可用 `tactile=taxel` 选择对应编码器。两种配置均沿用数据源的触觉坐标、单位和尺度。 [示教数据格式](仿真数据集格式.md)

训练时将无效标签置零，再对真实未来力加噪，用一步去噪结果引导动作。显式力损失按每次更新的有效元素取均值。设 `agent.force_loss_weight=0` 后，力预测器仍参与动作生成并接收动作损失的梯度。部署时从噪声采样未来力，条件来自当前观测。 [AdapTac 官方实现](https://github.com/kingchou007/adaptac-dex/blob/60e2ef1b7b0a29f5d29f5d755e8fe6d048f69fa5/src/adaptac/policy/FFG_policy.py)

## 多模态交互编码器

`HandSceneEncoder` 对单帧观测输出 `[B, 6, 192]` 的交互 token，顺序为腕部、拇指、食指、中指、无名指、小指。`fingertip_xyz` 与 `finger_tactile_force` 均按上述五指顺序排列。场景 token 作为交互模块的内部记忆。

- **手部几何**使用米制机器人基座坐标。腕部 MLP 接收除以 `0.25 m` 的腕部位置，以及 `eef_pose` 中按旋转矩阵前两列排列的 6D 旋转。共享的手指 MLP 接收指尖绝对位置和腕到指尖位移，分别除以 `0.25 m` 和 `0.10 m`。绝对位置和相对位移均沿基座轴表示。每个 token 加上对应的解剖 slot embedding 后做 LayerNorm。 [数据集坐标](仿真数据集格式.md#几何坐标)
- **场景记忆**默认从最多 1024 个点中取 128 个 patch，每组 32 点。相机外参将基座坐标变换到 OpenCV 相机坐标，供 RGB 投影使用。默认 `center` 在 patch 中心采样 RGB 特征，`group_mean` 对投影有效的邻域点取平均。拼接 192 维几何特征与 192 维 RGB 特征，用原始基座 patch 中心做 3D RoPE，经两层、八头空间 Transformer 后投影到 192 维。
- **触觉融合**对保留源坐标、单位与尺度的五指汇总力使用共享的无偏置 MLP。每指获得 64 维局部特征，五指取均值得到 64 维全局特征。独立的标量门控将局部残差加到对应手指，将全局残差加到全部六个 token。无偏置编码和残差投影保证零力时融合精确等于输入手部 token。
- **手部与场景交互**在触觉融合后执行。六个 token 先做一次四头手部自注意力，再查询场景记忆。对每个手部地标与场景 patch，计算基座系中从地标指向 patch 中心的位移，除以 `0.10 m` 后用 MLP 生成四个注意力头的加性偏置。偏置 MLP 的末层初始化为零。一次交叉注意力之后应用残差 FFN 和最终 LayerNorm。使用 FP32 参数和 AMP 时，相对位移和偏置 MLP 保持 FP32，偏置在传入 SDPA 前转为 query 的 dtype。

### 输入与输出

单帧输入 `obs` 包含以下字段。

- `point_cloud` 为 `[B, N, 3]` 或 `[B, N, 6]`。默认 `pc_dim=3` 时使用 XYZ，设置 `pc_dim=6` 时使用输入的 XYZRGB。采样后的点数 `min(N, num_points)` 至少为 `max(num_patches, group_size)`，默认下限为 128。
- `rgb` 为 `[B, 3, H, W]`，接受 `uint8` 或取值在 `[0, 1]` 的 `float32`。`camera_intrinsic` 和 `camera_extrinsic` 分别为 `[B, 3, 3]` 和 `[B, 3, 4]`，也可使用仓库数据中的展平形式 `[B, 9]` 和 `[B, 12]`。
- `eef_pose` 为 `[B, 9]`，`fingertip_xyz` 和 `finger_tactile_force` 均为 `[B, 5, 3]`。

`encoder(obs)` 返回交互 token。`encoder.forward_with_aux(obs)` 使用同一计算路径，返回以下张量。形状按默认场景配置列出。

| 键 | 形状 | 含义 |
| --- | --- | --- |
| `tokens` | `[B, 6, 192]` | 六个交互 token |
| `scene_tokens` | `[B, 128, 192]` | 场景记忆 |
| `scene_points_base` | `[B, 128, 3]` | 米制基座系 patch 中心 |
| `hand_landmarks_base` | `[B, 6, 3]` | 米制基座系腕部和五指地标 |
| `local_tokens` | `[B, 5, 64]` | 逐指触觉特征 |
| `global_token` | `[B, 64]` | 五指平均触觉特征 |
| `rgb_projection_valid` | `[B, 128, 1]` 或 `[B, 128, 32]` | `center` 或 `group_mean` 对应的布尔投影有效性 |

### 独立组件的 RGB 初始化

独立使用时，先按所选 Backbone 的架构构建 Encoder，再显式加载 RGB 预训练权重。

```python
from dexmani_policy.agents.obs_encoder.hand_scene_encoder import HandSceneEncoder

encoder = HandSceneEncoder(rgb_backbone_name="dinov3")
encoder.initialize_weights("path/to/pretrained/rgb")
```

DINOv3 的本地权重目录需要包含与配置架构匹配的 `model.safetensors`。独立构建 DINO 或 SigLIP 时，需在 `rgb_backbone_config` 中提供 `architecture`。传入 `None` 时保留当前参数。

### 现有 RGB Policy 的训练初始化

通过项目训练框架从头训练现有 RGB Policy 时，在配置中指定对应的预训练来源。

```yaml
initialization:
  rgb: path/to/pretrained/rgb
```

训练框架通过 `agent.rgb_backbone_name` 识别 Backbone 类型。DINO 或 SigLIP 未显式配置 `agent.rgb_backbone_config.architecture` 时，框架先从 `initialization.rgb` 读取架构。Fresh Training 在创建 EMA 模型前加载权重。

Warm Start 从源 Checkpoint 恢复模型参数，当前配置未指定 RGB 架构时也从中继承架构。Full Resume 从本次训练的 Checkpoint 恢复模型及训练状态。两种 Checkpoint 路径均跳过 `initialization.rgb` 的权重加载。
