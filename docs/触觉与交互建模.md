# 触觉与交互建模

触觉描述正在发生的接触。AdapTac 将场景与触觉融合，并通过未来力预测引导动作生成；手部几何与触觉融合组件则提供独立的交互建模能力。

## 触觉表征

| 表征 | 编码内容 |
| --- | --- |
| force | 每根手指的汇总力 |
| taxel | 密集触觉单元的通道信息 |

`tactile=force` 使用 `finger_tactile_force [5,3]`，`tactile=taxel` 使用 `taxel_tactile_force [5,120,3]`；两种编码器都输出五个 64 维手指 token。

当前仿真提供五指汇总接触力，不提供密集触觉。触觉输入与未来目标沿用数据源定义的坐标和尺度，不同来源的触觉不能仅凭字段相似互换。

## AdapTac：未来力引导动作生成

**视觉与触觉交互 → 未来力预测 → 力引导融合 → 动作生成**

场景点云与当前触觉先通过双向注意力交换信息，未来力扩散模型再根据观测历史预测未来绝对力。预测结果引导视觉与触觉融合，并结合关节状态，作为动作扩散的条件。

训练联合优化动作生成与未来力预测，未来力监督来自同一回合的后继观测。未来力分支也参与在线推理，为动作生成提供预测的接触信息。

日志中，`train/loss` 为动作损失与加权力损失之和；`train/loss_action`、`train/loss_force` 和 `train/loss_force_weighted` 分别记录动作损失、原始力损失和加权力损失。通用动作 decoder 不重复记录 `loss_action`，该指标由 AdapTac 在策略层记录。

核心实现位于 [AdapTac 策略](../dexmani_policy/agents/policies/adaptac.py)。

## 手部几何与触觉融合组件

| 组件 | 职责 |
| --- | --- |
| `HandGeometryEncoder` | 将腕部位姿与五指位置编码为六个带身份信息的查询 |
| `Relative3DCrossAttention` | 结合手部与场景的三维相对位置，从场景特征中读取几何信息 |
| `TactileGatedFusion` | 用局部与全局触觉门控腕部及五指特征，零力时保持几何输入 |

这些组件独立保留，当前策略未实例化 `HandGeometryEncoder` 或 `Relative3DCrossAttention`。几何输入要求统一的 Base-frame 米制坐标，触觉保持数据源自身的语义。

组件分别位于 [proprio.py](../dexmani_policy/agents/obs_encoder/proprio.py) 和 [interaction/](../dexmani_policy/agents/obs_encoder/interaction/)，整体模块关系见[项目架构](项目架构.md)。

### 几何坐标与尺度

`HandGeometryEncoder` 接收 `eef_pose [...,9]` 和 `fingertip_xyz [...,5,3]`，前导维度必须完全匹配；输出 `tokens [...,6,192]` 和 `anchors_base [...,6,3]`。支持单样本、Batch 和时序输入。wrist 对应生产端的 `custom_eef_link`。

`Relative3DCrossAttention` 接收 `body_tokens [B,L,192]`、`scene_tokens [B,N,192]` 及对应的 `anchors_base [B,L,3]`、`scene_xyz_base [B,N,3]`，输出 `[B,L,192]`，第一个 anchor 为腕部。与手部编码器组合时 `L=6`；时序输入需将 Batch 和时间轴一同展平，单样本需补 Batch 轴。

位姿的后六维依次为旋转矩阵的第一列、第二列，表示 EEF 轴在 Base 系中的方向。解码沿用 FP32 Gram–Schmidt，输入应为有效、非退化的旋转表示；局部指尖为 `(fingertip_xyz - wrist_position) @ rotation`。几何计算在 autocast 外完成。

| 构造参数 | 默认值（米） | 作用 |
| --- | ---: | --- |
| `HandGeometryEncoder.wrist_scale` | 0.25 | Base 系腕部位置的网络输入尺度 |
| `HandGeometryEncoder.finger_scale` | 0.10 | Wrist 局部指尖位置的网络输入尺度 |
| `Relative3DCrossAttention.geometry_scale` | 0.10 | position bias 与 relative value 的相对位置尺度 |

三个尺度独立且必须有限、严格大于零，不是可学习参数。`anchors_base` 始终保留原始米制坐标。默认构造及原有 state-dict 名称、形状保持兼容；尺度不写入 state dict，使用自定义尺度恢复模型时需传入相同构造参数。

本机 `dexmani_sim` 的位姿、指尖和场景点云均由 world 系产生，当前固定机器人 Base 与 world 重合；本地四个任务数据集的 `robot_setup_json` 和 `observation_geometry_json` 也记录了这一关系及米制单位。`dexmani_real` 的对应生产端直接使用 xArm Base 系。两者都连续序列化旋转矩阵前两列。其他数据源必须自行确认或预先转换坐标，不能将 world 与 Base 在任意场景下视为等价。

`EpisodeStore` 保留几何量的原始尺度。通用策略预处理会对配置为 `limits` 的字段执行归一化，因此上述组件要求原始坐标或 `identity` 处理后的输入，不能接收已经归一化的位姿或场景坐标。

### 有界尺度诊断

使用已确认处于统一 Base 系、单位为米的数据：

```bash
python -m dexmani_policy.test_tools.diagnose_proprio_geometry robot_data/pick_apple_messy.zarr --max-frames 128 --reference 0 0 0
```

工具默认均匀抽取最多 128 帧，通过 `EpisodeStore` 逐帧读取原始位姿、指尖及场景 XYZ，输出米制 P50/P90/P95/P99，不应用模型尺度、归一化或增强。参考点默认为 Base 原点，工具不推断或转换坐标系。

点云要求 `[T,N>0,C>=3]`，仅统计前三个 XYZ 通道。输入检查和非有限值报告复用数据读取机制，点云形状由诊断入口检查。

| 输出 | 距离定义 |
| --- | --- |
| `wrist_reference` | 腕部到固定参考点 |
| `finger_local` | Wrist 局部指尖到局部原点 |
| `hand_scene` | 六个 anchor 与全部场景点的所有点对距离 |

这些分位数用于描述输入范围，不代表最优超参数或任务性能；默认保留 `0.25 / 0.10 / 0.10`。

几何组件及诊断统计的独立测试不加载策略或训练数据：

```bash
python -m pytest -q -rs dexmani_policy/test_tools/test_proprio_geometry.py
```
