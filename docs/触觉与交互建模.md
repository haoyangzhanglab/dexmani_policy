# 触觉与交互建模

触觉描述正在发生的接触。AdapTac 将场景与触觉融合，并通过未来力预测引导动作生成；手部几何与触觉融合组件则提供独立的交互建模能力。

## 触觉表征

| 表征 | 编码内容 |
| --- | --- |
| force | 每根手指的汇总力 |
| taxel | 密集触觉单元的通道信息 |
| patch | 从密集触觉中提取区域描述，再汇聚为手指特征 |

当前仿真提供五指汇总接触力，不提供密集触觉。触觉输入与未来目标沿用数据源定义的坐标和尺度，不同来源的触觉不能仅凭字段相似互换。

## AdapTac：未来力引导动作生成

**视觉与触觉交互 → 未来力预测 → 力引导融合 → 动作生成**

场景点云与当前触觉先通过双向注意力交换信息，未来力扩散模型再根据观测历史预测未来绝对力。预测结果引导视觉与触觉融合，并结合关节状态，作为动作扩散的条件。

训练联合优化动作生成与未来力预测，未来力监督来自同一回合的后继观测。未来力分支也参与在线推理，为动作生成提供预测的接触信息。

核心实现位于 [AdapTac 策略](../dexmani_policy/agents/policies/adaptac.py)。

## 手部几何与触觉融合组件

| 组件 | 职责 |
| --- | --- |
| `HandGeometryEncoder` | 将腕部位姿与五指位置编码为六个带身份信息的查询 |
| `Relative3DCrossAttention` | 结合手部与场景的三维相对位置，从场景特征中读取几何信息 |
| `TactileGatedFusion` | 用局部与全局触觉门控腕部及五指特征，零力时保持几何输入 |

这些组件独立保留，当前没有策略将三者组合接入动作生成链路。几何输入要求统一的 Base-frame 米制坐标，触觉保持数据源自身的语义。

组件分别位于 [proprio.py](../dexmani_policy/agents/obs_encoder/proprio.py) 和 [interaction/](../dexmani_policy/agents/obs_encoder/interaction/)，整体模块关系见[项目架构](项目架构.md)。
