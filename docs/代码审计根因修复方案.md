# DexMani Policy 代码审计根因修复方案

> 状态：Design Proposal（尚未实施）  
> 日期：2026-09-12  
> 目标：以**代码整体简洁、高效、可验证**为第一原则，针对当前审计中确认的问题做根因修复；不以兼容所有历史行为为目标，不把研究性算法改动混入工程 bugfix。

---

## 1. 总体结论

本轮问题可以归并为 5 类根因，而不是 10 余个互不相关的小 bug：

1. **Resume 状态不完整且 single-GPU / DDP 恢复逻辑重复**：checkpoint 只保存 `epoch/global_step`，没有保存当前 epoch 的数据游标；DDP 又独立实现了一套恢复逻辑，因此 contract、RNG、EMA 容易漂移。
2. **接口能力是隐式的**：SAT 使用统一 point-cloud registry，却默认所有 encoder 都返回 `(patch, center, global)`；`pointnet_dense` 实际只返回 dense tensor。
3. **同一职责存在多个 owner**：RGB spatial augmentation 同时由 Dataset 和 `DPObsEncoder` 执行，形成 double crop。
4. **可变输入被隐式修改、日志只反映局部状态**：`SequenceSampler` 修改 caller mask；gradient accumulation / DDP logging 没有对 effective update batch 做正确聚合。
5. **若干 helper/config 缺少 fail-fast contract**：CUDA deployment helper、manual normalizer、`assert` validation、`num_workers=0`、`gpu_ids`。

因此修复不应逐个堆条件分支，而应围绕以下 5 条原则：

- **Single source of truth**：训练恢复 contract、DataLoader 构建、checkpoint restore 各只有一处实现。
- **Explicit capability**：策略在构造阶段声明并检查 encoder 能力，不等到 forward 才靠 tensor shape 偶然失败。
- **Single ownership**：随机数据增强只属于 Dataset；模型 encoder 只负责模型所需的 deterministic preprocessing / feature extraction。
- **Boundary-safe state**：checkpoint 只落在 optimizer/gradient-accumulation 边界；保存的游标必须指向“下一条尚未消费的数据”。
- **Fail closed**：不支持的配置尽早 `ValueError`，不 silent fallback，不通过兼容分支改变算法语义。

# 3. P1：重做 Resume 的“状态边界”，而不是继续补字段

## 3.1 当前问题

当前 checkpoint schema `simple.v2` 保存：

```text
(epoch, global_step)
model / ema / optimizer / scheduler
train_params
ema updater state
single-process rng_state
```

训练循环在 epoch 内按 `micro_step` 运行，但 `micro_step` 没有持久化。恢复时直接从：

```text
checkpoint.epoch + DataLoader beginning
```

重新开始，因此已经消费的数据会被再次训练。

更关键的是，signal 可以在 gradient accumulation 的中间 micro-batch 到达。当前循环会在该 micro-batch 后退出，但 checkpoint 不保存 `.grad`，因此如果未来简单增加 sampler cursor 并从下一 micro-batch 继续，会产生：

```text
已经消费前半个 accumulation group
+
未保存前半个 group 的 gradient
+
resume 后跳过这些样本
```

这是比“epoch replay”更隐蔽的 correctness 问题。

## 3.2 设计决策：checkpoint 永远表示一个 optimizer boundary

定义唯一不变量：

> **可恢复 checkpoint 必须在 `optimizer.step() + scheduler.step() + EMA.step()` 完成、且 gradients 已 `zero_grad()` 后生成。**

因此：

- milestone 本来就在 accumulation boundary 检查，保持不变；
- signal 在 non-boundary micro-batch 到达时，只设置 stop flag；
- trainer 继续完成当前 accumulation group；
- 到 boundary 后再退出并保存 interrupt checkpoint。

这样 checkpoint 不需要序列化 partial gradient，也不需要引入额外 gradient-state schema。

这是最小且正确的设计。

---

## 3.3 新 checkpoint schema：`simple.v3`

建议 bump format，不继续向严格 `simple.v2` schema 塞 optional key。

`TrainCheckpoint` 新增两个核心字段：

```python
next_micro_step: int
rng_states: list[dict[str, Any]]
```

并将 `train_params` 升级为明确的 `resume_contract`（仍使用普通 dict，避免额外序列化类型）：

```python
resume_contract = {
    "policy": {...},
    "data": {...},
    "loop": {...},
    "optimizer": {...},
    "scheduler": {...},
}
```

其中最少 hard contract 为：

### policy

```text
n_obs_steps
n_action_steps
action_dim
horizon
action_key
tcp_dim
hand_dim
control_action_dim
use_aux_ee
```

### data

```text
dataset._target_
zarr_path\ Sensor modalities
pad_before
pad_after
```

`zarr_path` 用 resolved string 保存即可；本项目训练数据路径本身就是实验语义的一部分，不需要为“数据迁移目录”牺牲 resume 安全性。

### loop

```text
total_train_steps
batch_size
gradient_accumulation_steps
world_size
drop_last
training.seed
use_bfloat16
use_ema
use_ema_teacher_for_consistency
max_grad_norm
```

这些字段变化都会改变 optimizer trajectory、sample cursor 或随机流，resume 应 hard fail。

### optimizer / scheduler

保存 resolved optimizer dict，以及：

```text
lr_scheduler
lr_warmup_steps
lr_min_ratio
num_training_steps
```

不要保存 `device`、`num_workers`、W&B、output path、logging interval、video 等 runtime-only 参数。

---

## 3.4 只保留一个 validation 入口

删除当前只检查 training steps 的窄逻辑：

```python
validate_training_steps(...)
```

改成：

```python
validate_resume_contract(saved: dict, current: dict) -> None
```

行为：

1. key set 必须一致；
2. 递归比较值；
3. 错误信息打印所有 mismatch，而不是只报第一个。

示例：

```text
Resume contract mismatch:
  policy.n_action_steps: saved=8 current=12
  loop.batch_size: saved=128 current=64
```

`strict=True` 的 state dict load 继续保留，但它只负责 tensor schema，不承担训练语义校验。

# 4. P1：统一使用 ResumableDistributedSampler

## 4.1 不再依赖 DataLoader `shuffle=True`

新增一个很小的 sampler：

```text
dexmani_policy/datasets/sampler.py
    ResumableDistributedSampler
```

直接继承 PyTorch `DistributedSampler`，只增加一个能力：

```python
start_index: int
```

其 `__iter__()`：

1. 调用父类得到当前 `seed + epoch` 下 deterministic local-rank index sequence；
2. 返回 `indices[start_index:]`。

单卡也使用同一个 sampler：

```text
num_replicas=1
rank=0
```

从此 single-GPU / DDP 的 sample ordering 走同一套代码。

### 为什么不保存整个 permutation

不需要。

`DistributedSampler` 的 order 已经是：

```text
pure function(seed, epoch, dataset length, world_size, rank)
```

checkpoint 只需保存：

```text
epoch
next_micro_step
```

并要求 resume contract 中：

```text
batch_size/world_size/drop_last/seed
```

不变即可。

local sample offset：

```python
start_index = next_micro_step * batch_size
```

---

## 4.2 cursor 定义必须是“next”，不能是“current”

checkpoint 保存：

```text
next_micro_step = 当前已成功消费并完成 optimizer boundary 后，下一个尚未消费的 micro-batch index
```

不要保存模糊的 `micro_step`。

如果 checkpoint 在 epoch 最后一批之后生成，应 canonicalize：

```text
epoch = epoch + 1
next_micro_step = 0
```

避免 resume 后先进入一个空 epoch。

---

## 4.3 Trainer resume 流程

恢复第一轮 epoch 时：

```text
sampler.set_epoch(saved_epoch)
sampler.set_start_index(saved_next_micro_step * batch_size)
```

之后 epoch：

```text
sampler.set_epoch(epoch)
sampler.set_start_index(0)
```

由于 checkpoint 只允许在 accumulation boundary 保存，resume 后剩余 micro-batch 可以从新的 group position 0 开始，不需要恢复 partial accumulation state。

---

## 4.4 Resume 的准确性边界

修复后保证：

- model / optimizer / scheduler / EMA 连续；
- sample order 不重放、不跳过；
- process-side RNG（包括每个 DDP rank）连续；
- milestone/global step 连续。

**不承诺** `num_workers>0 + stochastic Dataset augmentation` 下 bitwise-identical augmentation stream。

原因是 persistent DataLoader worker 拥有独立 Python/NumPy/Torch RNG state；要做到完全 bitwise resume，需要把所有 augmentation 改成 stateless `(seed, epoch, sample_index)` RNG，这是一次大范围 API 改造，与当前 correctness 问题不成比例。

因此文档与代码注释中不要再使用“full training state machine / exact bitwise continuation”这种过强表述。正确表述应是：

> sample-continuous and optimizer-state-consistent resume；多 worker stochastic augmentation 不保证 bitwise replay。

# 5. P2：DDP RNG 状态按 rank 保存

当前 DDP 在 model 初始化后执行：

```python
set_seed(base_seed + rank)
```

因此每个 rank 明确拥有独立 RNG stream。既然如此，resume 只恢复 rank0 RNG 就与本项目自身设计不一致。

## 5.1 最小方案

checkpoint 触发时所有 rank 都调用：

```python
local_rng = get_rng_state()
```

DDP 下：

```python
dist.gather_object(local_rng, rng_states, dst=0)
```

单卡：

```python
rng_states = [local_rng]
```

只有 rank0 执行文件写入。

resume：

```python
set_rng_state(checkpoint.rng_states[rank])
```

`world_size` 已是 resume hard contract，因此无需处理 rank 数变化。

## 5.2 Checkpoint call-site 必须所有 rank 对称

当前 `_check_milestone()` 在 non-main rank 提前 return，这会阻止 RNG gather。

修改原则：

```text
所有 rank：决定是否 checkpoint + 参加 collective
rank0：序列化/写磁盘/latest symlink
```

checkpoint 一共只有 5 个 milestones + 少量 interrupt，因此 gather 开销可忽略。

## 5.3 DDP stop flag

在 accumulation boundary 上同步一个 0/1 stop flag：

```python
dist.all_reduce(stop_flag, op=MAX)
```

只要任意 rank 收到 SIGINT/SIGTERM，所有 rank 在同一 optimizer boundary 停止并进入 checkpoint collective，避免某 rank 保存、其他 rank 继续而造成 deadlock。

该 scalar collective 相比 DDP backward 已有通信成本很小，而且只在 optimizer boundary 执行。

# 6. P1/P3：single-GPU / DDP 共用 DataLoader builder

当前：

- `train.py`：`DataLoader(dataset, **cfg.dataloader)`；
- `train_ddp.py`：手工重新拼一次参数。

这既导致 sampler 行为分叉，也导致 `num_workers=0` 时 `prefetch_factor/persistent_workers` 容易出错。

新增：

```python
build_train_dataloader(cfg, dataset, *, rank=0, world_size=1)
    -> (loader, sampler)
```

职责只做三件事：

1. 创建上述统一 resumable sampler；
2. 将原 `cfg.dataloader.shuffle` 转换成 sampler 的 `shuffle`，DataLoader 自身固定 `shuffle=False`；
3. worker 参数规范化：

```python
if num_workers == 0:
    prefetch_factor = None
    persistent_workers = False
```

`train.py` 和 `train_ddp.py` 都调用它，不再各自创建 DataLoader。

这一个改动同时解决：

- R2 sampler resume；
- H5 worker override；
- single/DDP data-order 代码漂移。

# 7. P2：SAT encoder contract — fail-fast，不伪兼容

## 7.1 官方事实

SAT 官方仓库 `XiaohanLei/SAT` 的默认 observation tokenizer 不是通用 registry。

默认 `use_pc_color=false` 时走：

```text
FPSPointNetEncoderXYZ
  → explicit global token
  + local grouped tokens
  → TransformerEncoder
  → [B*T, G+1, D]
```

之后 policy 固定：

```text
[B*T, N, D] → [B, N, T*D]
```

进行 temporal feature fusion。

官方 `pointnet_type` 只支持 `"pointnet"`，其他类型直接 `NotImplementedError`。

因此 dexmani 将 `pointnet_dense` 暴露给 SAT 是本地泛化，不是官方能力。

## 7.2 修复原则

`PointNetDense` 是 ManiFlow-style dense point token encoder：

```text
[B*T, N, D]
no global token
```

不能通过：

```python
global = dense.mean(dim=1)
```

伪装成 SAT，因为这会改变：

- official global token definition；
- token count；
- obs/action token ratio；
- attention FLOPs；
- temporal fusion semantics。

这属于新 architecture，不是 bugfix。

## 7.3 最小正确修复

在 `SATObsEncoder.__init__` 构造 `pc_encoder` 后立即：

```python
if not getattr(self.pc_encoder, "supports_global_token", False):
    raise ValueError(
        "SAT requires a point-cloud tokenizer with explicit global-token support; "
        f"got encoder_type={encoder_type!r}."
    )
```

forward 中不要通过 tensor indexing 模拟 tuple unpack：

```python
outputs = self.pc_encoder(pc, return_global_token=True)
if not isinstance(outputs, tuple) or len(outputs) != 3:
    raise RuntimeError("SAT point-cloud tokenizer violated its output contract")
patch_token, _, global_token = outputs
```

当前阶段**不新增复杂 `PointCloudTokenOutput` dataclass / Protocol**；registry 只有少量 encoder，一个 capability flag + runtime contract check 已足够清晰。

若未来第三种策略需要更多 capabilities，再统一升级成结构化 metadata：

```text
token_type / has_global_token / has_centers / fixed_token_count
```

# 8. P2：RGB spatial augmentation 只允许一个 owner

## 8.1 当前问题

Dataset 已执行：

```text
raw RGB
→ resize
→ one random crop shared across T frames of one sample
→ optional color augmentation
```

而 `DPObsEncoder` 又支持：

```python
crop_ratio
→ RandomCrop(B*T tensor)
```

默认配置组合时产生第二次 spatial crop。

问题不在于 torchvision batched crop 是否共享参数；真正的根因是**同一训练随机增强同时存在于 Dataset 和 Model**。

## 8.2 设计决策

**Dataset 拥有所有 stochastic augmentation。**

`DPObsEncoder` 只做：

```text
model-required deterministic processor
→ backbone
→ state fusion
```

删除 `DPObsEncoder`：

```text
crop_ratio
v2.RandomCrop
```

同步删除 DP / MultiTask 相关 config 的 `rgb_backbone_config.crop_ratio`。

为了避免旧配置 silent 继续工作，构造 encoder 时若发现 legacy key：

```python
if "crop_ratio" in cfg:
    raise ValueError(
        "rgb_backbone_config.crop_ratio is no longer supported; "
        "configure dataset.rgb_random_crop_size instead"
    )
```

这样 spatial augmentation 的时间一致性天然由 Dataset 当前 `(T,C,H,W)` 单次 crop 保证：

```text
一个 sample 的 T 帧共享 crop
不同 sample 在各自 __getitem__ 中独立采样
```

# 9. P2：SequenceSampler 不得修改 caller-owned split mask

当前 short-episode filter：

```python
episode_mask[i] = False
```

会直接改变 `BaseDataset.train_mask/val_mask`。

修复只需在 sampler boundary 做 defensive copy：

```python
if episode_mask is None:
    episode_mask = np.ones(..., dtype=bool)
else:
    episode_mask = np.asarray(episode_mask, dtype=bool).copy()
```

不要为了这个问题引入 immutable mask class，也不需要让 BaseDataset 额外 copy 两次。

调用者传入对象永远不被修改，是 sampler 最合理的 API contract。

# 10. P2：Metrics 对齐 effective optimizer update

## 10.1 当前语义错误

当 `gradient_accumulation_steps > 1`：

```text
microbatch 0 → backward
microbatch 1 → backward + optimizer.step
```

当前日志只保留最后一个 `log_dict`。

DDP 又只由 rank0 写日志，因此记录值只代表：

```text
rank0 × last microbatch
```

而不是实际 optimizer update 对应的数据。

## 10.2 不引入复杂 logging framework

Trainer 内维护两个小变量：

```python
group_metric_sums: dict[str, float]
group_metric_count: int
```

每个 micro-batch：

```python
scalars = to_log_scalars(log_dict)
accumulate(scalars)
```

到 accumulation boundary：

```python
step_metrics = sums / count
reset group accumulator
```

仅在真正需要 log 的 step 上做 DDP reduction，避免每步额外通信：

1. 将 scalar values 按稳定 key 顺序 pack 成一个 tensor；
2. `dist.all_reduce(..., AVG)`；
3. rank0 写 workspace。

这样一次 collective 就能得到 global mean。

不必引入通用 `MetricsTracker` 类；当前 Trainer 的需求很小，局部 dict accumulator 更直接。

# 11. P3：Deployment helper device 以 agent 为唯一真值

不要在 `RestoredDeployment` 再存一份 `device`，否则 agent/device 可能再次漂移。

`prediction_snapshot()` 直接：

```python
agent_device = next(restored.agent.parameters()).device
```

若 observation 为 None：

```python
deterministic_observation(restored.spec, device=agent_device)
```

若用户传入 observation：

1. `prepare_deployment_observation()` 完成 contract validation / RGB preprocessing；
2. 最后统一 `.to(agent_device)`。

原则：**helper 接受 host/device observation，但 model input 最终永远跟随 agent device。**

# 12. P3：Normalizer manual params 创建即 freeze

`fit_params()` 已经明确 freeze；`create_manual()` 应保持同一语义。

最小修复：

```python
params_dict.requires_grad_(False)
```

然后再构造 object。

不需要重构 ParameterDict 为 buffer：当前 state-dict / device transfer 体系已依赖 ParameterDict，单行 freeze 风险最低。

# 13. P3：Config validation 全部 fail-fast exception

将：

```python
assert cfg.optimizer.obs_lr >= 0
assert pc_dim >= 6
```

改成显式 `ValueError`。

原因不是代码风格，而是 `python -O` 会删除 `assert`。

### DDP GPU IDs

增加：

```text
all ids are int
id >= 0
len(set(gpu_ids)) == len(gpu_ids)
id < torch.cuda.device_count()
```

这类配置错误应在 NCCL 初始化前失败。

# 14. P3：Smoke test 修正 static-graph 判断

当前 smoke test 文案：

```text
trainable params received no gradient (DDP will fail)
```

不准确。

`DDP(static_graph=True)` 允许稳定的 unused parameter set；真正有风险的是：

```text
某参数在不同 iteration 中 used/unused 状态变化
```

因此最小修改是：

- 保留 `grad is None` 列表，作为 dead/unreached parameter warning；
- 删除“DDP will fail”的断言式描述；
- 文案改为：

```text
trainable params received no gradient in this smoke batch; verify they are intentionally unused and usage is static across iterations
```

当前阶段不为了检测所有动态 graph path 而把每个 smoke test 强制跑两遍 backward；该测试成本高且仍不能证明所有 conditional path。

如果未来出现真实 static-graph DDP error，再针对具体策略增加两-batch regression test。

# 15. ManiFlow：不修官方算法，只保护 baseline

## 15.1 官方事实

原作者 `geyan21/ManiFlow_Policy` 与当前 `allenai/maniflow` 的 consistency 核心逻辑一致：

```python
delta_t1 = sample_dt(...)
t_next = clamp(t + delta_t1, max=1.0)

# relative mode
target_t_next = delta_t1
target_t_ct = delta_t1
```

官方默认 config 同样使用：

```yaml
sample_target_t_mode: relative
```

因此 dexmani 当前 behavior 是 official inherited behavior，不是移植 bug。

## 15.2 Bugfix 分支应该做什么

**不修改算法。**

增加一个 regression test 固化该语义：

```text
t=0.8
dt=0.5
→ t_next=1.0
→ target_t_ct=0.5
```

测试命名建议：

```text
test_maniflow_relative_target_t_matches_official_behavior
```

这样未来不会有人再次把它当 typo 修改。

## 15.3 Research 分支再做 ablation

研究问题保留三组：

```text
A. Official:
   dt ~ U(0,1), target_t = sampled dt, t_next=clip(t+dt)

B. Effective-dt:
   target_t = t_next - t

C. Boundary-aware:
   dt = U(0,1) * (1-t), target_t=dt
```

这属于 algorithm experiment，禁止和本轮 engineering bugfix 同一个 PR。

# 21. 最终推荐实施顺序

按风险/收益比：

```text
1. ResumeContract + resumable sampler + boundary-safe checkpoint
2. shared DataLoader builder + per-rank RNG
3. SAT fail-fast + SequenceSampler copy
4. remove DP encoder random crop
5. accumulation/DDP metric reduction
6. deployment/normalizer/config/smoke robustness cleanup
7. ManiFlow 只增加 official-behavior regression test
```

其中 1–2 应作为一个完整 resume PR：不要只增加 `next_micro_step` 而不处理 accumulation boundary 和 sampler determinism，否则会把“重复数据”修成“跳过已计算但未保存 gradient 的数据”。

SAT 与 RGB 可以作为第二个独立 PR；其余 P3 cleanup 可以最后合并成一个小 PR。

该拆分使每个 PR 都有单一可验证假设，方便回归与定位，不会把训练状态机、模型结构和算法实验混在一起。
