## 1. Scope

本记录覆盖 observation parameter freeze、resume 随机性边界、step throughput telemetry、LoRA optimizer dtype，以及当前 zero-LR checkpoint 的恢复闭环。项目保持个人研究代码库定位。

未改变模型结构、Observation / Action Representation、Diffusion / Flow Matching objective、scheduler/EMA clock、gradient accumulation、DDP `no_sync`、checkpoint schema 或 precision policy；未新增 config 字段、框架依赖、optimizer migration 或永久测试框架。

## 2. Baseline findings

修复前真实 DP 实验确认：`obs_lr=0` 仅阻止 observation 参数更新，LoRA 和其它 trainable observation 参数仍有 gradient、进入 AdamW state，并参与全模型 gradient clipping。旧 zero-LR optimizer 有 4 个 parameter groups。

原 RNG docstring 对恢复范围表述过强：checkpoint 保存训练进程 RNG 和 sampler cursor，没有保存 worker augmentation RNG / prefetch state。原训练日志也缺少单次 update 的吞吐指标。LoRA optimizer moments dtype 当时尚需真实一步验证。

## 3. Implemented changes

- `BaseAgent.configure_optimizer()` 在解析 observation LR 后、构造 parameter groups 前，对零 LR 调用 `obs_encoder.requires_grad_(False)`。原分组过滤排除这些参数；不隐式改变 module mode，也不自动解冻已有冻结参数。`obs_lr=None` 仍继承主 LR。
- RNG helper docstring 明确训练进程 RNG、sample ordering 与 worker augmentation 的边界，实现和 checkpoint schema 保持不变。
- Trainer 增加 `train/step_time`、`train/samples_per_step`、`train/samples_per_sec`：按实际 accumulation group 样本计数，覆盖 data wait 和训练 update，排除 logging/checkpoint。DDP 在日志 boundary 使用 SUM(samples)/MAX(time)，未增加 CUDA synchronize。
- Closeout 将 `print_param_count(model)` 从 model builder 移至 optimizer 配置后；DDP 入口也在 optimizer 配置后仅 rank 0 打印。Validation 文案明确为 `0 freezes obs_encoder parameters`。
- 稳定 optimizer / resume contract 已写入 [项目架构](./项目架构.md)，旧 checkpoint compatibility 边界见第 5 节。

## 4. Validation results

证据来源：4.1–4.4 及 full smoke 为上一轮已执行记录，本轮未重复运行；4.5 和下列增量检查在 closeout 工作树上实际执行。

环境：`policy` Conda，Python 3.10.20、PyTorch 2.4.1+cu124、CUDA runtime 12.4。真实数据为本地 `pick_apple_messy.zarr`（下称 `<LOCAL_ZARR>`），125 episodes / 21,527 frames；DP train dataset 为 13,127 samples。DINO 使用已有离线 cache。

### 4.1 obs_lr freeze A/B — PASS（已有证据）

真实 DP dataset / normalizer / DINO-LoRA / AdamW，batch=2、workers=2、bf16 autocast、gradient clip=1，compile/EMA 关闭。

| 检查 | zero-LR | positive-LR |
|---|---|---|
| observation trainable | 0 | 原 LoRA/obs trainable 集合保留 |
| optimizer observation parameters | 0，无 obs optimizer state | trainable obs 参数进入 optimizer |
| observation gradients | 全部 None | 存在有限梯度 |
| observation 参数状态 | 全部不变 | 存在实际更新 |
| action decoder | 有限梯度、正常更新 | 有限梯度、正常更新 |
| loss | 0.5065913796，finite | 0.5248326659，finite |

`obs_lr=None` 继承 `lr=1e-4`，各 group LR 一致，observation trainable 集合保留。三种模式下 optimizer 配置均未改变各 module 的 training flag。

### 4.2 Resume ordering boundary — PASS（已有证据）

真实 dataset，batch=2、workers=2、shuffle/persistent workers/prefetch 开启，保留 joint noise 与 RGB crop/color augmentation。消费 3 batches 后保存训练进程 RNG/cursor，重建 dataset/loader，与连续路径随后 3 batches 比较：

- sample indices equal；action equal。
- joint_state / RGB augmented observation 均非 bit-exact。
- 代表性首批 max absolute diff：joint_state `0.0006928444`，RGB `0.7939319611`。

该结果支持 sample ordering 可恢复，同时不承诺 worker augmentation bit-exact parity；不构成 sampler 错误。

### 4.3 Throughput telemetry — PASS（已有证据）

真实 GPU DP Trainer，batch=2、EMA 开启、compile 关闭，分别执行 accum=1 和 accum=2 各 3 updates。accum=2 使用 9 个真实样本，包含 partial tail；实际 samples/update 为 `4、4、1`。两组 global_step、scheduler.last_epoch、EMA optimization_step 均为 3。

所有日志时间/吞吐有限且为正，逐条通过 `samples_per_sec × step_time == samples_per_step`（rel_tol=1e-12）。CPU 双 rank Gloo 验证 DDP SUM(samples)/MAX(time)：`(3, 0.1s)` 与 `(7, 0.4s)` 汇总为 `10 / 0.4 = 25 samples/s`。

额外 Gloo Trainer 范围检查覆盖跨 epoch、partial accumulation、日志间隔，以及 logging/checkpoint 耗时排除；注入时钟结果只验证计时范围，不是性能实测。CUDA telemetry 为异步 wall-clock 近似值。NCCL multi-GPU real throughput：**NOT VERIFIED**。

### 4.4 LoRA optimizer dtype — PASS（已有一步证据）

与 positive-LR 真实一步共用 forward/backward/clip/AdamW：

| Tensor | LoRA | action decoder 对照 |
|---|---|---|
| parameter | bf16 | FP32 |
| gradient | bf16 | FP32 |
| exp_avg | bf16 | FP32 |
| exp_avg_sq | bf16 | FP32 |

参数、梯度和两个 moments 均 finite。该结果不证明长期 FP32/bf16 optimizer precision 等价，也不证明长期稳定或收敛质量；本轮无证据修改 precision policy。

### 4.5 Current zero-LR resume — PASS（本轮新增）

真实 `dp` config，仅覆盖 `<LOCAL_ZARR>`、obs_lr=0、compile=false、EMA=true、batch=2、workers=2；gradient accumulation=1。保留真实 dataset/normalizer、DINO/LoRA construction、DP objective、AdamW、原 scheduler/warmup、EMA、resume contract 与 checkpoint schema。

Run A 以 seed=42 新建全部组件，调用 `Trainer.train_one_step()` 执行 2 个 optimizer updates；loss 分别为 `0.5067209005`、`0.3578619659`。使用 `TrainCheckpoint` / `CheckpointStore` 将完整 current-format checkpoint 保存至自动清理的临时目录，然后销毁 run A。

Run B 以不同初始化 seed=123 重新构建 dataset、loader、model、EMA、optimizer、scheduler 和 resume contract，再调用 `restore_training_state()`。实际断言通过：

- returned `(global_step, epoch, next_micro_step) = (2, 0, 2)`。
- main model / EMA 完整 state dict、AdamW state（含 moments）、scheduler state 与 checkpoint 逐项一致。
- EMA optimization_step=2、decay 恢复一致；Python/NumPy/Torch CPU/CUDA RNG state 全部恢复一致。
- fresh 与 saved optimizer 均为 2 groups，组内 parameter names/order 一致，optimizer state 加载成功。
- observation 参数全部 `requires_grad=False`，grad 全 None，且不在 optimizer 中。

按 restored sampler `set_epoch(0, 2)` 获取下一批并执行真实一步：loss=`0.4449001253` finite；optimizer boundary 的 action-decoder gradients 全部 finite；optimizer/scheduler/EMA 正常推进至第 3 步，cursor=3。全部 observation 参数逐项不变、grad 全 None；所检查 decoder weight 实际更新，main model 参数全部 finite。

**PASS — current zero-LR checkpoint is self-resumable。** 此实验验证训练状态恢复及继续一步，不要求 stochastic augmentation bit-exact，也不宣称与 uninterrupted run 数值完全相同。

## 5. Compatibility boundary

Pre-fix zero-LR checkpoint is not optimizer-state compatible with post-fix zero-LR optimizer grouping。已实测旧 DP zero-LR groups=4、新 groups=2，直接 `load_state_dict()` 报 `ValueError: loaded state dict has a different number of parameter groups`。

兼容性还涉及训练语义：旧实现 observation parameters `requires_grad=True`，其 gradient 参与 global gradient clipping，LR=0 仅阻止参数更新；新实现不产生 observation parameter gradient，因此不参与 clipping。即使强行删除旧 observation optimizer groups，也不能称为严格 resume。

严格继续旧实现创建的 `obs_lr=0` 实验，应使用产生 checkpoint 的旧 commit / environment。采用新 parameter-freeze semantics 应视为新的 experiment / warm-start，而非透明的 same-run exact resume 或 optimizer migration。本轮不实现自动迁移、不修改 checkpoint schema、不偷偷 drop optimizer groups，也未新增 warm-start CLI。

- NCCL multi-GPU、compile 路径、DP3/SAT full smoke、长期训练与 LoRA bf16 长期稳定性：**NOT VERIFIED**。DDP rank-0 参数日志 gating 本轮通过源码 diff review，未运行多 GPU 验证。
- Worker stochastic augmentation RNG / prefetch state 不属于 resume contract，不承诺 augmentation bit-exact parity。
- 旧 zero-LR 严格续训需原版本；本记录不将 optimizer-group migration 列为严格 resume 的修复方案。
