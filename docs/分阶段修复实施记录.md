# 分阶段修复实施记录

日期：2026-09-12。按 Phase 1 → Phase 2 → Phase 3 实施；每阶段先语法检查，再完成最小 CPU 回归后推进。

## 阶段变更

- **Phase 1 — Resume correctness**：训练 checkpoint 升级为严格 `simple.v3`，以递归比较的 `resume_contract` 替换 `train_params`；保存 `next_micro_step` 和 rank-ordered `rng_states`。单卡/DDP 共用 loader、契约与状态恢复，权重在 compile/DDP 包装前加载。sampler 按 seed/epoch/rank 重建顺序并从消费游标继续，完整 epoch 与剩余长度分离，epoch 末归一游标。仅在更新完成、清梯度后保存；signal 请求在边界同步，全部 rank 参与 RNG gather，仅 rank 0 写入。零 worker 参数归一，loader generator 不消耗模型 RNG；GPU IDs 在 NCCL 前验证。评测/export/qualification/smoke 消费者同步使用 v3，deployment artifact 公共格式保持不变。
- **Phase 2 — Architecture/data contracts**：SAT 依据 capability flag 拒绝不支持 global token 的 tokenizer，forward 验证三元 tuple 和形状，保留 token 顺序及 temporal feature fusion。删除 DP model-side random crop 和 DP/MultiTask 的 crop_ratio；旧键显式指向 Dataset rgb_random_crop_size。SequenceSampler 先复制 caller mask，再过滤短 episode。
- **Phase 3 — Observability/robustness**：指标按完整 micro-batch group 取 mean，仅 log step 按排序键打包跨 rank 求 mean，rank 0 记录。deployment synthetic/input observation 最终跟随 agent 当前 device；manual normalizer 创建即 freeze；相关配置 assert 改为 ValueError；修正 smoke unused-gradient 文案。增加 ManiFlow `t=.8, dt=.5 → t_next=1, relative target_t=.5` regression，ManiFlow/ActionFlow 算法实现未改动。

## 必要方案调整与验证边界

1. 生产 DDP flags 的回归暴露 PyTorch 2.4 `static_graph=True` 首次 backward 处于 `no_sync()` 时的 reducer 断言。现在新 DDP 实例的第一次 backward 正常同步以初始化 reducer，之后仍在非累积边界使用 no_sync。保留 static_graph。两 rank、累积 2/3 步及尾组、无 clipping 的 SGD 与等效全局 batch 比较均通过；仅 log step 发生 metrics collective。
2. ManiFlow 默认 batch 的 FP32 smoke 在本机显存不足（额外申请 1.50 GiB 时失败）；补测只在临时脚本中覆盖 batch_size=4 和 num_workers=0，没有修改训练配置或算法。**默认 batch smoke 未通过**。
3. 本机仅一张 GPU，因此没有多 GPU NCCL 实测；分布式训练状态机以真实两进程 Gloo 验证。没有验证生产规模长训练。
4. 恢复保证采样连续与优化器状态一致；多 worker stochastic augmentation 不保证 bitwise continuation。旧训练 schema 严格拒绝，无历史兼容层。

实现无待办项；上述资源/验证边界保留。测试日志位于 `/tmp/dexmani_regression.log`、`/tmp/dexmani_pc_smoke.log`、`/tmp/dexmani_sat_rgb_smoke.log`、`/tmp/dexmani_maniflow_small_smoke.log`，未加入仓库。
