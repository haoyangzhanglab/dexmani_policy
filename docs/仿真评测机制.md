# 仿真评测

评测直接读取 checkpoint 内的当前配置与 affine，不迁移预处理配方，也不依赖实验目录的 config.yaml、训练数据或原初始权重。需要可用的 dexmani_sim 环境与对应任务的评测 seed 池。来源检查由 `SimRunner.run()` 根据实际 agent 的消费字段与 `tactile_source` 执行；模型恢复后、创建环境前拒绝 real-source 触觉策略，原异常直接传播。

`evaluate_policy` 与部署路径入口 `restore_policy()` 共用内部模型恢复函数：normalizer 形状从实际选中的 raw/EMA state 推导，严格加载后一次性迁移设备并转为 FP32，再进入 eval，按原有方式合并 RGB LoRA。构造模型前解除完整 checkpoint 的引用，释放未选权重及 optimizer、scheduler、RNG 状态；构造期间保留进程 RNG 的保存与恢复。`SimRunner.predict_action_chunk()` 显式关闭 autocast；结果记录中的参数 dtype 是恢复后的实际推理精度。训练的 BF16 配方和训练状态恢复不受影响。

## 单 checkpoint

```bash
python -m dexmani_policy.evaluate \
  --checkpoint <run>/checkpoints/latest.pt --weights ema \
  --inference-steps 10 --episodes 100 --seed 1024 --device cuda:0
```

`--weights raw|ema`、`--inference-steps` 默认取 checkpoint 配方；请求不存在的 EMA 明确失败。`--action-steps` 默认取恢复后模型的 `agent.n_action_steps`，不能超过 `agent.future_steps`。`--seeds` 可显式给出 episode seeds，顺序和数量不受 `--episodes` 影响；否则从 `dexmani_sim.DATA_DIR / "eval_seeds" / f"{task_name}.txt"` 按 `--seed` 和 `--episodes` 确定测试集合，不提供配置覆盖 seed 池的入口。CLI 仅转发参数；每次 `evaluate_policy` 只调用一次 `load_checkpoint`，从同一次加载取得配置、所选权重与 global_step，并直接将 global_step 写入结果。`--no-video` 关闭视频，`--output-dir` 指定新的空输出目录；未指定时自动创建独立目录。

Runner 的历史长度来自 `agent.n_obs_steps`，观测字段来自 `list(agent.consumed_observation_fields)`，未消费字段不进入历史缓冲或设备传输。点云在 CPU 上按 `agent.normalization_dims` 裁剪并转为连续数组后传输，减少不必要的数据传输；需要颜色的模型保留对应通道，Policy 内部的通道处理仍供训练和其他推理入口复用。RGB 继续使用已有预处理配方。每个控制步更新历史；完整 `future_actions` 的有限性检查通过后才截取执行前缀，每个动作后检查环境终止。

评测成功完成后原子保存一次 result_details.json，记录实际 checkpoint、global_step、推理/执行步数、权重、seed 列表、`runner_options`、逐 episode 成绩和统计，以及 Torch/CUDA 版本和模型参数 dtype。`runner_options` 中模型相关参数采用实际使用值；其中 `env_kwargs` 仅表示传入环境的覆盖参数，不是展开全部默认值后的环境状态。首个真实环境创建成功后读取一次 `environment`：`control_dt_s` 来自实际 `env.dt`，另记录 `frame_skip`、`action_cnt_limit`、`success_hold_steps` 及实际 `randomization`、`stability` 设置。每次 run 重新采集，不保留环境引用或逐 episode 重复记录；只记录控制周期，不调整频率或重采样。

统计中的 `n_episodes` 表示实际完成的 episode 数；保留 `success_rate`、`n_success`、成功 episode 的 `avg_steps`、全部 episode 的 `avg_steps_all` 和 `wilson_95`。`steps` 仍记录首次满足原始成功条件的步数，`total_steps` 是结束时的动作数，最终成功仍由环境的 `success` 判定。stdout 仅供阅读，不用于解析成绩。不预写空结果或维护失败状态；失败直接传播异常并关闭环境，可以留下视频和本次目录，但不产生完整结果 JSON。

## 执行长度

实际执行长度 C 必须满足 `1 <= C <= agent.future_steps`，其中 `future_steps = horizon - (n_obs_steps - 1)`。普通评测在模型恢复后取默认执行长度并检查上限；选模入口仍从首个 checkpoint 的 `agent.n_action_steps` 确定统一执行长度，各次 rollout 再按实际模型检查上限。覆盖 C 只改变每次查询后消费的动作数，不改写保存的训练配置、采样窗口或 padding。InterAct-Dex 的预测边界 K 独立来自 `interaction_horizon`，模型构造时要求 K 不超过可用未来动作数。默认窗口有13个未来动作；C=1、K=4 合法。`policy_metadata` 保留给尚未构造模型的 `inspect_policy()` 使用。

`inspect_policy(experiment, checkpoint="best")` 将选优记录 `inference.action_steps` 恢复为 `PolicyInfo.n_action_steps`；latest、百分比和显式文件 selector 使用 checkpoint 的 `agent.n_action_steps`。best 的权重与推理步数同样取选优记录，其余 selector 取 checkpoint 的 `eval`，已有 `weights`、`inference_steps` 参数可显式覆盖。`PolicyRuntime.predict()` 始终返回完整未来动作窗口，由调用方按 `info.n_action_steps` 消费；加载模型不会用 C 覆盖 K。

## 显式候选选模与独立测试

```bash
python -m dexmani_policy.eval_pipeline \
  --checkpoints <run>/checkpoints/<a.pt> <run>/checkpoints/<b.pt> \
  --weights ema --inference-steps 10 \
  --selection-episodes 25 --test-episodes 100 --seed 1024 \
  --output-dir <run>/eval_ckpt_selector/<new-comparison>
```

候选是研究者明确选定的同任务、同评测协议文件，允许位于不同目录，不要求凑齐所有 milestone。20/40/60/80/100% 仍是论文完整预算的默认候选方案；子集比较必须按实际列表报告，不称为完整预算比较。外部布局可加 `--run-dir <publication-dir>` 指定 best 发布目录和默认结果目录锚点；未指定时使用首候选解析后父目录的父目录。

从同一任务 seed 池确定性划分：测试 seeds 先固定，再取不相交的 selection seeds。seed 必须是 `[0, 2**32)` 内的整数且无重复；显式 seeds 非空，任务池必须满足所需容量。所有候选使用完全相同的 selection seeds、预算、推理和执行参数。排序依次为 success_rate 较高、avg_steps 较低、global_step 较大；缺失 avg_steps 排最后。选模不读取 test 成绩，胜者直接进入独立 test 调用。

pipeline 仍单独读取首个候选，以确定统一推理设置和 seed 池；胜者的独立 test 也重新加载 checkpoint。不在阶段间缓存 checkpoint 或模型。

独立 test 完成后才原子保存 selection_result.json，集中记录候选路径/step/分数、胜者、两组 seeds、实际推理参数和 test 结果位置。其内路径均相对 selection 结果目录，外部位置用 `..` 表达。候选输出和 test 位于本次独立目录；`--output-dir` 可在任意位置，重用非空目录明确失败。

## 发布与部署接口

固定顺序为候选评测、选优、独立测试、保存完整 selection 结果、原子更新 best_ckpt.json。best 只保存 `ckpt_relpath` 和 `inference`，checkpoint 路径相对发布 run，可含 `..`。test 分数低仍发布原 selection 胜者；test 或完整结果保存失败时旧 best 完全不变，不写看似完整的 selection 结果，已完成候选结果可保留。

`inspect_policy` 保留 best/latest/百分比 selector；显式绝对文件路径直接使用，相对文件路径以 experiment/checkpoints 解析，允许指向外部文件的 symlink。文件搬迁后由用户更新路径，不自动搜索修复。Real 与其他部署调用方使用 inspect_policy、load_policy 和 PolicyRuntime.predict，默认选择 best；predict 返回完整物理 future window 的 NumPy 数组。

不协调同一 run 的并发发布；一次 pipeline 发布一个 run。若并发使用同一发布目录，最后一个成功写入者覆盖 best。远程同步先传权重和记录，再更新 best 指针。

CLI 提供单点评测 evaluate 与选模加独立测试 eval_pipeline；选模直接由 run_pipeline 顺序执行。普通评测和候选选模共用 `evaluation/seeds.py` 中的 seed 池读取、校验与划分；显式 seeds 在评测入口校验后直接使用。

闭环成功率须通过实际仿真运行验证。CPU 合成检查不代替 CUDA、仿真后端或硬件部署验证。
