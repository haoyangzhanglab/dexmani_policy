# 仿真评测机制

仿真评测衡量策略在环境交互中完成任务的能力。评测模块恢复完整策略，由仿真运行器提供观测、执行动作并记录回合结果。

## 闭环执行

每个回合从指定场景开始，重复以下过程，直到环境结束回合：

1. 读取最近的观测历史。
2. 生成未来动作窗口。
3. 执行配置的动作步数，并在每个控制步更新观测。
4. 根据新观测重新预测。

Diffusion/Flow 的预测窗口决定可规划的范围，采样步数决定模型的迭代预算，执行前缀长度决定重新规划的频率。

ODE 正常执行完整的 `n_action_steps=H`，运行器拒绝其他执行长度；`inference_steps` 是每个控制周期的积分子步数，不改变 H 或控制周期。每次执行后从环境返回的 `info["executed_joint_action"]` 读取经过硬关节限位裁剪的实际目标，传给下个 chunk 的 `prev_action`；回合开始为 None。绝对目标保留角度分支，环境不会将越界请求整圈折返。终止或截断发生在 chunk 中途时立即结束，不补执行剩余动作。

承接需求由策略的 `requires_prev_action` 声明；其他策略不读取该环境字段，也不额外传递预测参数。

无裁剪时，下一 chunk 直接承接上一段积分终点；裁剪生效时，使用实际目标是本项目的执行约束适配，执行轨迹不再严格等于无约束 ODE 的积分曲线。

## 任务结果

最终成功由环境判定，成功率表示完成任务的回合比例。执行步数用于补充描述完成效率，逐回合记录帮助理解失败和行为差异。

训练损失衡量模型对学习目标的拟合，闭环成功率衡量实际任务表现。不同动作表示或监督目标的训练损失不能直接横向排名。

## 候选选择与独立测试

| 阶段 | 作用 |
| --- | --- |
| 候选选择 | 在共同的 selection 回合上比较候选策略，确定胜者 |
| 独立测试 | 在不重叠的 test 回合上评估胜者，报告最终成绩 |

两组回合在比较前固定。独立测试结果用于评价已经选定的策略，不反过来调整候选选择。

每个候选默认使用自己 checkpoint 配方中的 `eval.use_ema`、`eval.inference_steps` 和 `n_action_steps`。仅显式传入 `--weights`、`--inference-steps`、`--action-steps` 时，才统一相应设置。候选顺序不会决定其他候选的推理配方；胜者的独立测试沿用 selection 阶段实际使用的三个值。

`selection_result.json` 的 `overrides` 记录命令行覆盖（未指定项为 `null`），`candidates` 逐项保存实际权重、推理步数、执行长度和成绩，并链接每次评测的 `result_details.json`。排名依次比较成功率、较少的平均执行步数、较大的训练步数。

## 比较条件

候选入口仅要求同一任务；同任务内不同环境参数由研究者负责确认可比性。

跨方法比较应保持任务、环境条件和回合预算一致，并明确观测模态、先验来源及推理预算。评测结果对应实际使用的任务池与环境条件。

仿真只能评估环境实际提供的观测路径；当前支持五指汇总力，不提供密集触觉。真实执行仍需由独立执行端完成传感器适配与控制调度。

模块关系见[项目架构](项目架构.md)，远程运行步骤见[SSH 服务器训练部署](SSH服务器训练部署.md)。

Selection 在确定 winner 后立即原子保存 `selection_result.json`；独立 test 成功后才补入 `test_result`。没有该字段表示尚无成功完成的 test 结果，test 失败不会丢失已完成的选模汇总。
