# DexMani_Policy 仿真评测机制

本文说明 checkpoint selection、held-out eval 和 demo 的实际协议。训练与模型接口见 [项目架构](项目架构.md)，常用入口见 [README](../README.md#仿真评测)。评测依据保存的实验配置和 checkpoint，不重新组合当前 Policy YAML。

## 入口与流程

```text
训练 milestone → 所有候选使用相同初始 seeds → 最高成功率精确并列时加测一批
                                                        ↓
                                      selection_result.json + best_ckpt.json
                                                        ↓
                                 排除实际 selection seeds → held-out eval
```

以下命令从仓库根目录运行，`<...>` 替换为实际值：

```bash
bash scripts/eval/eval_pipeline.sh <policy_name> <task_name> <run>
```

流水线只接收这三个位置参数，依次运行 selection 和不录视频的最终评测。它通过本次选择的固定记录交接，避免随后更新的 `best_ckpt.json` 改变已选 checkpoint；同一实验的流水线由文件锁避免并发执行。

需要调整参数时使用分步入口：

```bash
bash scripts/eval/select_checkpoint.sh <policy_name> <task_name> <run> \
  --initial-episodes 25 --batch-size 5 --max-episodes 100
bash scripts/eval/evaluate.sh <policy_name> <task_name> <run> \
  --episodes 100 --no-videos
bash scripts/eval/record_demo.sh <policy_name> <task_name> <run> \
  --seeds 5 12 33
```

三个分步 Shell 入口转发参数，`--help` 直接显示对应 Python 入口的参数说明。帮助不要求实验目录或 DISPLAY；实际 demo 录像需要 X11 或 XWayland。实验配置在 Python 加载边界检查，Shell 不重复检查路径。

selection 默认关闭录像，可用 `--videos` 开启；独立 final eval 沿用保存的 `eval.video.enabled`，未设置时开启，可用 `--no-videos` 关闭。demo 用于查看轨迹或补录指定 episode，不作为 held-out 性能证据。

## Checkpoint selection

### 候选与预算

selector 只发现具体 milestone checkpoint，不将不断变化的 `latest.pt` 作为选点候选。每个候选使用相同的环境配置、raw/EMA 选择、NFE 和按任务生成的 seed 计划。

预算由 `eval.select_best.*` 或 CLI 决定。缺省 `initial_episodes=25`、`batch_size=5`、`max_episodes=100`，实际预算还受最小任务 seed 池限制：

1. 所有候选运行同一批初始 seeds，以 micro success rate 排名。
2. 只有最高成功率精确并列，且还有额外预算时，才对这些并列候选加测一批新 seeds。
3. 在加测候选中按合并后的成功率选出最高者；仍并列时，优先较低 `avg_steps`，再优先较高 `global_step`。

加测最多一次；`max_episodes` 是上限，不表示会循环测试到该数量。`--batch-size 0` 关闭加测。多任务各任务预算相等，不会因某任务 seed 池较大而增加其权重。

### 全零与失败

所有 episode 正常完成但全部失败，仍是有效选点结果，全零可直接从 episode 记录计算。这里 `status=success` 表示选择流程完成，不代表策略任务成功率非零。成功步数不可用时，最终可按较高训练 step 打破并列。

OOM、环境异常、缺失或重复 episode、错误任务、非法结果类型等属于技术失败。selector 中止并写失败记录，保留此前成功发布的 best，不把异常记为普通的 `success=False`。

### 选择产物

每次调用创建独立 `eval_ckpt_selector/<run-id>/`，只维护一份 `selection_result.json`。它包含运行状态、本次配置快照、候选路径、推理设置、各阶段的 seed 计划及实际 episode；运行中原子更新，成功后固定。失败时记录错误，保留上一份 best。

实验根目录的 `best_ckpt.json` 只包含成功记录的相对路径 `selection_result`。成功率、阶段索引和选点 seed 并集从 episode 与阶段记录推导，不再复制成多份结果并交叉比较。

自动化流程可指定实验内的空目录，并直接固定使用本次结果：

```bash
EXP_DIR="experiments/<policy_name>/<task_name>/<run>"
mkdir -p "$EXP_DIR/eval_ckpt_selector"
SELECTION_DIR="$(mktemp -d "$EXP_DIR/eval_ckpt_selector/manual_XXXXXXXX")"
bash scripts/eval/select_checkpoint.sh <policy_name> <task_name> <run> \
  --output-dir "$SELECTION_DIR"
bash scripts/eval/evaluate.sh <policy_name> <task_name> <run> \
  --selection-record "$SELECTION_DIR/selection_result.json" --no-videos
```

`--output-dir` 必须位于该实验的 `eval_ckpt_selector/` 内，且目录为空。`--selection-record` 直接读取成功的选择结果，锁定具体 checkpoint、EMA/raw 和 NFE，并拒绝冲突请求；不创建额外交接文件。

## Seed 与 held-out

### Seed 池

每任务 seed 池按以下顺序解析：

1. 单任务的 `env_runner.eval_seeds`，或多任务各 `task_configs` 中的 `eval_seeds`。
2. `dexmani_sim.DATA_DIR/eval_seeds/<task>.txt`。
3. 默认 `range(100)`。

池先去重，再以 eval seed 确定性打乱。selection 的 `--seed` 可覆盖 eval seed，否则使用 `training.seed + 1024`；final eval 没有 `--seed` 参数，可通过允许的 `training.seed` dotlist 调整打乱基准。

多任务传递实际映射 `{task: [seeds]}`，不通过首任务的序号间接映射。公共计划按各任务可用数量的最小值截断，保证各任务预算一致。

执行时通过单任务 `run(seeds=...)` 或多任务 `run(task_seeds=...)` 传入计划，保留 runner 的原始 seed 池和默认预算，供后续调用复用。

### 最终评测

`--ckpt-tag best` 在开始时固定具体 checkpoint 和选择记录，验证选择证据，排除每任务实际参加过 selection 的 seeds，再对剩余池打乱取样。请求预算大于可用数量时按剩余池截断；没有 held-out seed 时失败。

`latest`、百分比 tag 或显式 checkpoint 路径不自动具有 held-out 语义；只有同时绑定有效选择记录的调用，才能声明相对该次 selection 的 held-out。选择记录中的 checkpoint、`use_ema`、正整数 `inference_steps` 和 `policy_seed_mode=episode_seed` 必须有效，不能靠 CLI 覆盖修复损坏记录。

best 统一解析到选择记录。部署与 demo 读取 checkpoint 和推理设置；final best eval 还核对阶段完整性，从所有实际参与选点的阶段推导排除 seeds，包括落选候选和已执行的加测阶段。

### 随机性边界

环境通过 `reset(seed)` 接收物理 seed；每个 episode 开始时重新设置 Torch CPU/CUDA RNG，将生成式策略的采样起点绑定到 episode seed。

这保证 seed 计划和 RNG 初始化可重建。不同模型、NFE、dtype 或随机数消费顺序可能产生不同噪声，GPU/driver/kernel 也可能影响数值；不承诺轨迹逐位一致。

Demo 的 `--seeds 5 12 33` 表示每个任务使用同一组物理 seed 数字，覆盖 `--episodes`；需要每任务不同列表时使用 `MultiTaskSimRunner.run(task_seeds=...)`。demo 不排除 selection seeds，结果标记 `heldout_from_selection=false`。

Demo 在加载模型、创建输出目录前检查显式 seed 的唯一性和池内可用性；日志与快照记录实际执行的 episode 数量。

## 推理参数与恢复

### 参数优先级

普通 final eval 的 EMA/raw 与 NFE 按以下优先级解析：

```text
显式 CLI > 显式 eval dotlist > 选择记录 > 保存的实验配置
```

切换 EMA/raw 只改变同一 checkpoint 中加载的状态，不重新进行 checkpoint selection。显式 `--selection-record` 要求 checkpoint、EMA/raw 和 NFE 均与记录一致；冲突时拒绝运行。

单个 NFE 使用 `--inference-steps N`，多个 NFE 使用 final eval 的 dotlist：

```bash
bash scripts/eval/evaluate.sh <policy_name> <task_name> <run> \
  --inference-steps 10 --no-videos
bash scripts/eval/evaluate.sh <policy_name> <task_name> <run> \
  --no-videos 'eval.inference_steps_list=[2,4,8]'
```

Final eval 和 demo 的 NFE 列表必须为非空、互不重复的正整数，避免不同轮次复用同一输出目录。

sweep 固定 checkpoint、EMA/raw、环境和 seed 计划，只改变采样步数；各结果分别保存。该实验评估固定权重的采样预算，不代表为每个 NFE 单独选过 best。

selection 和 final eval 接受 `key=value` 形式的受限 dotlist：`eval.*`、允许的 `env_runner.*`、`training.seed/device`，不使用 Hydra 的 `+`、`~` 前缀。模型输入、观测长度、模态、RGB 配方以及 `agent.*`、`dataset.*`、normalization 不能在评测时替换。demo CLI 不接收 dotlist，使用其显式参数与保存配置。

### 模型恢复

三个 CLI 入口共享 `env_runner/evaluation.py` 的配置解析与评测流程，`selection.py` 负责选点；`common/seeds.py` 处理 seed 采样与计划校验，`common/metrics.py` 负责 episode 检查与统计。评测流程从 runner 获取 seed 池，再以普通字典交给采样函数；runner 直接使用公共辅助模块。checkpoint 路径解析和 `simple.v4` 恢复位于 `training/common/checkpoint.py`，部署无需导入仿真评测模块。

单次评测与 sweep 使用同一执行流程，每次调用只加载一次模型。环境输入来自保存配置，模型按 checkpoint 的 `effective_config` 构建；仅比较影响推理的配置，完整训练配方比较留在续训入口。

每次 CLI 调用只读取一次 `config.yaml`，先解析保存的插值，再应用评测覆盖；runner 构建、候选模型恢复和结果快照复用这份配置。修改评测 seed 或 device 不会通过原配置的插值间接改变模型输入。

多任务按任务名称恢复保存的子数据集输入配方和 `dataset.task_texts`；未指定文本时沿用 Dataset 的任务名称默认值。`env_runner` 中的文本不能重新定义训练时的语言条件，实际使用的文本记录在 `eval_config.yaml.runner_inputs`。

`SimRunner` 通过 `dexmani_sim.resolve_env_class` 获取任务类。`task_configs` 直接使用单任务 runner 的构造参数，任务参数覆盖多任务公共默认值；模型输入仍按保存的数据配方恢复。渲染模式、viewer 分辨率和帧率等任务设置不会被忽略。

raw/EMA 严格加载，normalizer 直接恢复。缺少请求的 EMA 或必要参数会失败；包装器前缀清理不提供架构兼容。完整 checkpoint 中的视觉初始化权重、码本和先验不会再次从外部加载。具体恢复边界见 [Checkpoint 与续训](项目架构.md#checkpoint-与续训)。

## 执行与指标

### 观测和动作

EnvRunner 使用长度为 `n_obs_steps` 的时序 buffer，episode 开始以首帧补齐，按时间顺序提供观测。RGB 使用保存配方的确定性验证预处理，模态、点云通道和状态语义必须与训练一致。

Policy 预测 H 帧，以 `n_obs_steps - 1` 对齐 query，输出物理 `control_action`；执行端消费配置的动作片段。内部码本、latent 和辅助监督维度在 Policy 内转换，不能直接作为机器人控制量。LAMP 的历史更新使用实际执行命令。

### 成功与步数

| 指标 | 定义 |
| --- | --- |
| `success_rate` | 最终成功 episode 数 / 有效完成 episode 数 |
| `task_done_step` | 首次满足 `success_condition` 时的 `env.action_cnt`，缺少该信息时为 `None` |
| `avg_steps` | 成功 episode 中有效 `task_done_step` 的平均值 |
| `avg_steps_all` | 有效 episode 明细中 `total_steps` 的平均值 |

`success_condition` 表示首次达到物理目标，最终 `success` 可额外包含 hold/grace 条件。成功率使用后者；普通任务失败计入成功率分母，但不计入 success-only `avg_steps`。

多任务同时保留每任务结果、macro 和 micro：macro 是各任务成功率平均，micro 是总成功数除以总 episode 数。`result.txt` 写 micro；`result_details.json` 的 `statistics` 保存 micro、macro、每任务统计及 Wilson 区间，`episode_details` 保存实际 episode。

单任务 runner 的步数均值取整；多任务 runner 的 `avg_steps` 对有效的每任务取整均值再平均取整。final eval 的 `avg_steps` 直接对所有成功 episode 的有效步数求浮点均值，保留这两种既有口径。

Wilson 95% 区间描述当前 episode 样本下的成功率不确定性，不是跨训练 seed 的方差，也不是多任务 macro 区间。比较实验需同时记录 checkpoint selection 预算、最终评测 seed 和训练 seed。

### 结果校验与异常

runner 生成明细时写入 `task_name`，校验器直接核对明细列表与 seed 计划。episode 成功标记必须为布尔值，seed 必须为实际计划中的整数，steps 为非负整数或 `None`。缺失、重复、额外 episode、错误任务或异常记录均使结果失败，不能发布部分任务的聚合成功率。runner 的 episode 数直接取 `episode_details` 长度。

环境构建、reset、推理或执行异常统一通过 `EvaluationError` 携带任务、可用的 seed 和原始异常类型上报，保留异常链并立即中止当前评测。多任务仅聚合全部完成的子结果，不返回失败任务占位字段；正常 `success=False` 仍计入分母。单任务 runner 在返回前核对实际 episode 并统一布尔值，多任务与选点直接复用这些明细；磁盘 selection 证据独立核验。

录像由 `env_runner/common/video.py` 尽力导出：编码或写入失败会警告，不注册失败的视频，也不抹去已完成的有效指标。未指定录像目录时不提取视频帧；编码失败仍回收 ffmpeg 子进程。

selection、final eval 和 demo 统一读取 `eval.video.fps`；demo 的 `--fps` 优先。未指定时使用 runner 的 `env_video_fps`，再回退到当前环境的 `video_fps`（缺省为 15）。自动帧率随环境重建重新读取，不写回 runner 配置。

## 结果文件

所有入口按调用创建独立目录，避免覆盖旧结果：

```text
experiments/<policy>/<task>/<run>/
├── best_ckpt.json
├── eval_ckpt_selector/<selection-id>/
│   └── selection_result.json
├── eval_dexsim/<eval-id>/
│   ├── eval_config.yaml
│   ├── result.txt
│   └── result_details.json
└── demo_videos/<demo-id>/
    ├── eval_config.yaml
    ├── result_details.json
    ├── result.txt
    └── 录像文件
```

final eval 与 demo 的 sweep 父目录保存 `eval_config.yaml` 和 `eval_summary.json`，各 NFE 的结果放在 `inference_steps<N>/`。demo 的显式 `--output-dir` 更换父目录，每次仍创建独立 run；保存配置中的多个 NFE 也会按子目录输出。

结果包含具体 checkpoint、global step、EMA/raw、NFE、环境配置、实际 seed 计划及 episode 明细。版本信息可辅助追踪，但 dirty 标记不是源码归档。分析历史结果应读取这些产物，不用当前默认值补写缺失事实。
