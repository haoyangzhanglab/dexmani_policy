# DexMani_Policy 仿真评测机制

评测读取实验保存配置和 checkpoint，不重新组合当前 Policy YAML。一个请求只包含一个 checkpoint、一个标量 NFE 和一份明确的任务/seed 清单；请求解析后，rollout 不再决定参数优先级或选点规则。历史实验使用对应旧源码，不能用当前协议重新解释旧结果。

## 入口与流程

```bash
bash scripts/eval/eval_pipeline.sh <policy_name> <task_name> <run> eval.seed=1024 eval.episodes=70
bash scripts/eval/select_checkpoint.sh <policy_name> <task_name> <run> eval.selection_episodes=25
bash scripts/eval/evaluate.sh <policy_name> <task_name> <run> --checkpoint latest eval.episodes=5 eval.video.enabled=false
```

`eval_pipeline.sh` 固定 test/selection 计划，按相同预算评估所有 milestone，再执行该记录的冻结测试；Shell 继续用 `.pipeline.lock` / `flock` 防止同一流水线并发。selection 默认不录视频，可在创建协议时显式设置 `eval.video.enabled=true`，测试沿用该设置。普通 evaluate 沿用保存配置的录像设置。

| 入口 | 输入与用途 |
| --- | --- |
| `select_checkpoint.sh` | 完整 milestone 集合、固定预算；可指定空的 `--output-dir`，必须位于实验的 `eval_ckpt_selector/` 内 |
| `evaluate.sh --checkpoint ...` | 普通评测，checkpoint 为 best/latest/百分比 tag/文件路径；可覆盖研究参数，始终不是正式 held-out 证据 |
| `evaluate.sh --selection-record ...` | 冻结正式测试，读取完整选点证据；只能改变 `training.device` 和 `--output-dir` |
| `eval_pipeline.sh` | 选点后执行冻结测试；输出目录自动创建 |

各 Shell 的 `--help` 不要求实验目录或 DISPLAY。`record_demo` 已并入普通 evaluate；录像及 viewer 示例：

```bash
bash scripts/eval/evaluate.sh <policy_name> <task_name> <run> --checkpoint best \
  'eval.task_seeds={<task>:[5,12,33]}' eval.video.enabled=true env_runner.render_mode=human
```

将 `<task>` 替换为实际任务名。viewer 需要 X11/XWayland，录像需要 ffmpeg；加载模型前检查这些前提。录像始终使用同一 rollout，不能充当独立测试证据。

## 请求解析

参数采用一组平面的 `eval.*` dotlist，不再提供同义 CLI 参数或 offline/select_best/demo 分区。普通 best 的推理默认值先取选择记录，显式 dotlist 再覆盖；其他 checkpoint 取保存配置。缺失必需字段直接失败，不从当前 YAML 补默认值。

| 字段 | 含义 |
| --- | --- |
| `eval.seed` | seed 池局部 shuffle 和模型初始化种子，与 training.seed 无关 |
| `eval.episodes` | 每任务 test/普通评测数量 |
| `eval.selection_episodes` | 每候选、每任务固定选点数量 |
| `eval.task_seeds` | 普通评测的显式任务→有序 seeds；各任务预算相等，不需要预留选点容量 |
| `eval.inference_steps` | 单个正整数 NFE；sweep 由外层多次普通调用表达 |
| `eval.action_steps` | 执行长度 C；null 时读取保存的 agent.n_action_steps |
| `eval.use_ema` | boolean，选择 EMA 或 raw |
| `eval.video.enabled`、`eval.video.fps` | 录像设置 |

另允许 `training.device` 和符合 SimRunner 接口的 `env_runner.*`。模型输入、观测长度、模态、RGB 预处理、语言条件、agent、dataset 和 normalization 不能通过评测覆盖。多任务使用保存的 child Dataset 配方，外层依次执行单个 SimRunner，没有第二套多任务 runner 或统计实现。

每个已解析请求保存具体 checkpoint、保存配置和覆盖结果、任务环境参数、NFE、C、EMA/raw、seeds 及数值执行设置。当前仿真保持 checkpoint 参数精度、无 autocast、无 compile、`no_grad`，不因重构切换数值路径。

## Checkpoint selection

所有候选必须是实际 milestone 文件，不能是变化中的 latest 或符号链接。加载首个模型前写入完整候选集合、每任务 test/selection seeds 和共同研究条件。当前配置为每候选每任务 **25** 个 selection episodes、每任务 **70** 个 test episodes；这是固定预算协议，删除原来仅对最高成功率平局者追加一批的规则。

每个候选直接调用普通 rollout。排序函数只读取完成的 episode 事实，校验完整候选覆盖、相同推理/任务/数值条件、相同 seeds 和一致的 runtime 记录后，依次比较：

1. 较高 micro success rate。
2. 较低成功 episode 的有效首次成功步数均值。
3. 较高 global_step；仍完全相等则保留候选声明顺序。

全部 episode 正常完成但任务全失败，仍是有效候选，平均成功步数为 null。环境、模型、OOM、非法/缺失/重复 episode 等技术失败中止选点；不替换 seed、不跳过候选、不更新旧 best。每个候选结果独立保存，选择记录只引用它们，避免重复存储 episode。

`best_ckpt.json` 只保存 `selection_result` 相对路径。解析 best 或正式测试时重新核对所有候选结果、统计与排名，拒绝失败、残缺或自相矛盾的证据；不自动修复旧记录。

## Seed 与 held-out

每任务 seed 池来自显式 `env_runner.eval_seeds`（多任务按 task_configs）或 `dexmani_sim.DATA_DIR/eval_seeds/<task>.txt`。缺少来源直接失败，不再 fallback 到 range(100)。池内 seeds 必须为 `[0, 2**32)` 的整数且互不重复，排序后由局部 `random.Random(eval.seed)` 打乱：

```text
test = shuffled_pool[:eval.episodes]
selection = shuffled_pool[eval.episodes:eval.episodes + eval.selection_episodes]
```

选择预算改变不影响 test 前缀。选点需 N+K 容量；普通评测只需自身 N 或显式 seeds，不受 selection 预算影响。显式 seeds 有声明池时还检查池内成员。环境 reset 使用物理 seed，每个 episode 重置 Torch RNG；不同模型、NFE、数值路径及 GPU kernel 仍可能产生不同轨迹。

正式测试只能通过 `--selection-record` 或 pipeline 创建。它冻结 checkpoint、EMA/raw、NFE、C、任务、环境、seeds、录像与数值模式，禁止研究覆盖；普通 `--checkpoint best` 允许消融但标记 `heldout_from_selection=false`，即使恰好使用同一配置也不自动升级为正式测试。

```bash
bash scripts/eval/evaluate.sh <policy_name> <task_name> <run> \
  --selection-record experiments/<policy_name>/<task_name>/<run>/eval_ckpt_selector/<id>/selection_result.json \
  training.device=cuda:0
```

不要基于正式 test 结果重新选 checkpoint、C 或 NFE。开发对照可显式复用记录的 `selection_task_seeds`，并建立独立普通评测；锁定研究条件后重新创建对应选择协议，再执行冻结测试。实验整体复制后，通过相对引用寻找本地候选证据与 checkpoint，记录中原始请求路径保留为来源事实。

## 执行长度

Policy 唯一返回完整物理 `future_actions[B,P,D_control]`。它先完成完整窗口的反归一化与方法解码，再剔除历史前缀和辅助维度。Runner 只执行 `future_actions[0, :C]`，不解释 action_start_index，也不裁剪控制维度。

C 必须为 `1..P` 的整数；LatentFlow 的 P=H，其余当前策略 P=H−N+1。`eval.action_steps` 只影响消费，不改变训练 horizon、观测窗口、normalizer、padding 或 Real 的 execution.action_steps。训练 padding 已显式固定：普通配置为 7、DQ-RISE 为 15、LAMP/LatentFlow 为 0；方法构造及默认执行长度仍保留 n_action_steps。

### LatentFlow 执行时长对照

先核对保存数据的 dt 与实际环境控制周期。dt≈0.0625s 时，H=32 对应约 2s 的预测控制周期预算，C=25 为 1.5625s，C=13 为 0.8125s；首末采样跨度为 `(帧数−1)×dt`，同步推理耗时也影响实际查询周期。默认 H=32/C=25 不变，不重采样；始终完整生成并双向解码 H 后再截取 C。若比较 C，使用开发 seeds 和普通评测，不能覆盖已冻结测试，也不能据此宣称实际闭环已验证。

## 平面记录与统计

每个 episode 一条记录：`task_name、seed、success、steps、total_steps、video`。`steps` 为首次 raw success_condition 的步数，`success` 为环境最终 hold/grace 判定；失败 episode 即使曾满足 raw condition，也不计入成功步数均值。

统计只由 `env_runner/common/metrics.py` 计算：micro 为所有 episode 成功数/总数；macro 为任务成功率等权均值；avg_steps 为所有成功且有有效 steps 的 episode 直接求均值，保留浮点数。它不再对任务均值等权平均或截断为整数，因此与旧统计可能不同。另保存 per_task、总步数均值及二项 Wilson 95% 区间；该区间不是训练 seed 方差或 macro 不确定性。

`result_details.json` 是单次评测唯一结构化事实记录。首个模型加载前写入 request，运行时每完成一个 episode 原子更新前缀；成功标记 completed，失败标记 failed、保留 traceback 和已完成前缀、statistics=null。环境与模型按失败路径收尾；录像继续按原有 best-effort 方式导出，导出错误告警，不把缺失视频冒充有效视频。

```text
experiment/
├── eval_ckpt_selector/<id>/selection_result.json
├── eval_ckpt_selector/<id>/candidates/<id>/result_details.json
├── eval_dexsim/<id>/result_details.json
└── best_ckpt.json
```

视频位于各结果目录的 videos/。不再额外写 eval_config.yaml、文本摘要或 NFE sweep 汇总；需要汇总时读取上述 JSON。记录包含 policy/simulator commit 与 dirty、Python/Torch/CUDA、设备和参数 dtype；dirty 标记不是源码归档，不使用哈希。远端同步先更新候选事实，再同步选择记录与 best 指针。

通用检查见 [验证指南](验证指南.md)，本次迁移验证状态见 [实施状态](infra_simplification_status.md)。离线检查不证明闭环成功率、速度或真机安全。
