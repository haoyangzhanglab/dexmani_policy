# DexMani Policy · 仿真评测机制

评测只使用实验保存的配置与 Checkpoint，不重新组合当前 Policy YAML。每次请求固定 Checkpoint、EMA/raw、单个 NFE、执行长度、任务和 seeds；旧实验须配合对应源码，不自动迁移格式。

## 入口与流程

| 入口 | 用途 |
| --- | --- |
| `eval_pipeline.sh` | 固定选点和测试计划，依次完成 selection 与冻结的 held-out test；同一实验以 `flock` 防并发 |
| `select_checkpoint.sh` | 按统一预算比较全部 milestone Checkpoint |
| `evaluate.sh --checkpoint ...` | best/latest/百分比 tag/指定文件的普通研究评测，**不是**正式测试证据 |
| `evaluate.sh --selection-record ...` | 使用已完成的选点记录进行正式测试，仅可更改 `training.device` 和输出目录 |

命令从仓库根目录执行：

```bash
bash scripts/eval/eval_pipeline.sh <policy_name> <task_name> <run>
bash scripts/eval/select_checkpoint.sh <policy_name> <task_name> <run> eval.selection_episodes=25
bash scripts/eval/evaluate.sh <policy_name> <task_name> <run> --checkpoint latest eval.episodes=5
```

选点与其冻结测试默认均不录像；创建选点协议时可用 `eval.video.enabled=true` 同时启用两者录像。普通评测使用保存配置并接受研究覆盖。录像需 ffmpeg，交互 viewer 需 X11/XWayland；视频来自同一次 rollout，不构成额外测试证据。各入口的 `--help` 不依赖实验目录或 DISPLAY。

## 请求解析

普通评测支持平面 dotlist 覆盖，不能改模型、观测模态/长度、RGB 处理、文本条件、Dataset 或归一化；`best` 的推理默认值来自 best 指针，其他 Checkpoint 来自保存配置，显式覆盖优先。关键字段：

| 字段 | 含义 |
| --- | --- |
| `eval.seed` | seed 池局部打乱及模型初始化，与训练 seed 独立 |
| `eval.episodes` / `eval.selection_episodes` | 每任务测试数 / 每候选每任务选点数 |
| `eval.task_seeds` | 普通评测指定任务→有序 seeds，任务预算相等 |
| `eval.inference_steps` / `eval.use_ema` | 单个正整数 NFE / EMA 或 raw |
| `eval.action_steps` | 执行长度 C；`null` 使用保存的 `agent.n_action_steps` |
| `eval.video.enabled` / `eval.video.fps` | 录像与帧率 |
| `training.device` / `env_runner.*` | 设备与符合 SimRunner 接口的环境设置 |

多任务逐个使用保存的 child 配方运行 SimRunner；`task_texts` 省略时使用任务名，环境参数合并后验证 `action_key/control_mode`。请求保存解析后的 Checkpoint、配置覆盖、任务/seeds、NFE、C、权重与数值设置。推理沿用 Checkpoint 精度，使用 `no_grad`，不启用 autocast/compile。

## Checkpoint selection

候选必须是实际 milestone 文件（不是 latest 或符号链接）。从保存的 `training.loop.total_train_steps` 和训练共用的 `milestone_steps` 推导完整集合，通常为 20/40/60/80/100%；极小预算中相同步数的百分比沿用训练保存规则。selection 在仿真前检查缺失 step、重复 step 与文件名中的 step/百分比，缺失时列出所需 step。离线 verifier 同样拒绝部分候选记录。恢复训练允许历史候选缺失，不代表该 run 已具备正式选点条件。

开始加载模型前冻结候选及评测计划；默认每候选每任务 selection=25、test=70，所有候选使用相同任务、seeds、推理和环境条件，不因平局追加预算。

按以下顺序选点：**最高 micro success rate → 最低成功 episode 的有效首次成功步数均值 → 最大 global_step → 声明顺序**。全部任务失败但评测正常完成仍是有效候选（avg_steps 为 null）；模型、环境、OOM、episode 缺失/重复等技术失败则中止，不换 seed、不跳过候选、不更新原 best。

`best_ckpt.json` 记录 Checkpoint 相对路径、global_step、EMA/NFE/C 和 selection 记录。普通 `best` 直接使用这些设置，加载后核对 checkpoint step，无需重跑 selection 排名。

selection 的 `candidates` 保存路径与 step，`candidate_results` 指向各候选的完整 rollout 结果。评测、选点和发布均不计算权重内容哈希；同路径、同 step 的权重替换不会被检测，选点后的 milestone 文件应保持不变。

发布 best、独立正式测试与独立 verifier 共用 `artifacts.verify_selection_record`，复核完整候选的 episode 事实、统计、排名和推理配方。完成选点后，未选中权重可删除，完整候选结果仍须保留。`publish_best`、`select_best_checkpoint` 返回 `(verified_record, checkpoint_path)`；同步 pipeline 直接构造 frozen request，独立 Frozen Test 则重新复核证据。可离线复核并发布指针：

```bash
python -m dexmani_policy.evaluation.selection \
  --experiment-dir <run目录> --selection-record <selection_result.json路径>
python -m dexmani_policy.evaluation.selection \
  --experiment-dir <run目录> --selection-record <selection_result.json路径> --publish-best
```

证据缺失直接失败；先原子保存 selection record，再发布 best，失败保留旧指针。实验搬迁后按相对引用核对候选和 Checkpoint。

正式测试在创建仿真 runner 前核对选点时的 Torch/CUDA、参数 dtype 与数值设置，允许更换设备编号和输出位置。不扫描源码或自动验证代码一致性；复现实验须自行保留对应源码。普通评测仍可直接指定单个 checkpoint。

## Seed 与 held-out

每任务 seed 池来自 `env_runner.eval_seeds`（多任务取 task 配置）或 `dexmani_sim.DATA_DIR/eval_seeds/<task>.txt`；缺失报错。池内 seed 为不重复的 `[0,2**32)` 整数，排序后以 `random.Random(eval.seed)` 局部打乱：

```text
test      = shuffled_pool[:eval.episodes]
selection = shuffled_pool[eval.episodes:eval.episodes + eval.selection_episodes]
```

选点必须有 N+K 个 seeds；更改 selection 预算不会改变 test 前缀。普通评测只要求本次预算，显式 seeds 若有声明池则必须属于该池。每个 episode 按物理 seed 重置环境，并创建设备匹配的 Policy 采样 Generator；环境 RNG 仍归执行器管理。不同模型/数值内核仍可能产生不同轨迹。

新训练在 `data_recipe[].source_evidence` 中保存 Zarr 已有 task_name/episode_seeds，沿用 split manifest 的 source/episode/trial 身份；评测记录同任务训练 seed 与 selection/test 的交集。`source_evidence` 是附加采集信息，不参与训练恢复配方比较；数据划分、窗口、normalization 和训练参数仍严格核对。当前评测端没有可对照的采集生成/source/trial 身份，`training_test_independence=unverified`；相同整数 seed 不足以判定泄漏，不同 seed 也不能证明场景独立。`heldout_from_selection` 只证明 selection/test 隔离，数据配方不是内容 hash。

正式测试须运行 pipeline 或使用已完成的 selection record：

```bash
bash scripts/eval/evaluate.sh <policy_name> <task_name> <run> \
  --selection-record experiments/<policy_name>/<task_name>/<run>/eval_ckpt_selector/<id>/selection_result.json \
  training.device=cuda:0
```

该记录冻结 Checkpoint、EMA/NFE/C、任务、环境、seeds、录像与数值模式。普通 `--checkpoint` 始终为 `heldout_from_selection=false`；开发对照应使用 selection seeds 或独立普通评测，**不得根据正式 test 结果再次调整 Checkpoint、C 或 NFE**。

## 执行长度

Policy 先完成完整窗口解码与反归一化，输出 query 起的物理动作 `future_actions[B,P,D_control]`，Runner 仅执行 `future_actions[0,:C]`。要求 `1<=C<=P`；LatentFlow 的 `P=H`，其他策略 `P=H−N+1`。`eval.action_steps` 不改训练窗口、padding、normalizer 或 Real 的执行长度；普通配置 `pad_after=7`、DQ-RISE 为 15、LAMP/LatentFlow 为 0。

### LatentFlow 执行时长对照

先核对数据 `dt` 与环境控制周期。若 `dt≈0.0625s`，H=32 为约 2s 的控制周期预算，C=25/13 分别为 1.5625s/0.8125s；首末采样跨度实际为 `(帧数−1)*dt`，同步推理还会影响查询周期。必须完整生成、双向解码 H 后再截取 C；执行长度对照仅用开发 seeds，不覆盖冻结测试，也不意味着真机闭环已验证。

## 平面记录与统计

每个 episode 记录 `task_name、seed、success、steps、total_steps、video`；`steps` 为首次 raw success_condition 步数，`success` 为最终 hold/grace 判定，失败 episode 不纳入成功步数均值。

`env_runner/common/metrics.py` 统计 micro（总成功/总次数）、macro（各任务成功率等权平均）、成功 episode 的有效首次成功步数均值，并记录 per_task、总步数均值和 Wilson 95% 二项区间；该区间不是训练 seed 方差或 macro 的置信区间。

`result_details.json` 是评测事实记录：模型加载前写 request，每个 episode 后原子更新，完成收尾才标记 `completed`。失败则保留 traceback 和已完成前缀，`status=failed`、`statistics=null`；部分前缀不能作为完成结果。录像须先成功导出才登记该 episode，录像失败也令评测失败。

```text
experiment/
├── eval_ckpt_selector/<id>/selection_result.json
├── eval_ckpt_selector/<id>/candidates/<id>/result_details.json
├── eval_dexsim/<id>/result_details.json
└── best_ckpt.json
```

视频在各评测目录的 `videos/`。结果记录 Python/Torch/CUDA、设备、dtype 和数值设置。同步时须先候选结果、再选择记录、最后 best 指针。离线复核检查已记录的实验事实，不验证源码一致性、未选中权重的当前内容或真机安全。
