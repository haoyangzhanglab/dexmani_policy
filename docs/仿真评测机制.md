# DexMani_Policy 仿真评测机制

评测使用保存的实验配置和 checkpoint，不重新组合当前 Policy YAML。模型与输入接口见 [项目架构](项目架构.md)，命令从仓库根目录执行。

## 入口与流程

```bash
bash scripts/eval/eval_pipeline.sh <policy_name> <task_name> <run> --seed 1024 --episodes 70
bash scripts/eval/record_demo.sh <policy_name> <task_name> <run> --seeds 5 12 33
```

流水线固定并原子保存 test/selection 计划，运行 milestone selection，再复用本次记录做不录视频的 held-out eval。Shell 使用 `.pipeline.lock` / `flock` 防并发；`--episodes N` 同时设置测试预留量和最终数量。

| 入口（`scripts/eval/`） | 用途与专用参数 |
| --- | --- |
| `eval_pipeline.sh` | 选点后评测；支持 seed、测试数量、EMA/raw、单个 NFE 和受限 dotlist |
| `select_checkpoint.sh` | 独立选点；额外支持 `--initial-episodes`、`--batch-size`、`--max-episodes`、录像及输出目录 |
| `evaluate.sh` | 评测 tag/路径或选择记录，可做 NFE sweep |
| `record_demo.sh` | 指定物理 seeds、viewer 和帧率，支持受限 dotlist |

流水线通过 `eval.select_best.*` dotlist 调整选优预算。分步调用示例：

```bash
bash scripts/eval/select_checkpoint.sh <policy_name> <task_name> <run> \
  --initial-episodes 25 --batch-size 5 --max-episodes 100 eval.offline.episodes=70
bash scripts/eval/evaluate.sh <policy_name> <task_name> <run> --episodes 70 --no-videos
```

各 Shell 的 `--help` 不要求实验目录或 DISPLAY；实际 demo 录像需要 X11/XWayland。selection 默认不录像，`--videos` 可开启；独立 final eval 的 CLI 和 Python 接口都沿用保存的 `eval.video.enabled`，缺失时须显式设置，`--no-videos` 可关闭。demo 不作为 held-out 性能证据。

## Checkpoint selection

### 候选与预算

只选择具体 milestone，不使用变化中的 `latest.pt`。候选共享环境、raw/EMA、NFE 和 seed 计划；当前配置写入 `initial_episodes=25`、`batch_size=5`、`max_episodes=100`，执行时读取保存配置或显式覆盖：

1. 全部候选运行相同初始 seeds，按 micro success rate 排名。
2. 仅对最高成功率精确并列者在预算内加测一批，最多一次；`batch_size=0` 关闭加测。
3. 按合并成功率选优，仍并列则依次比较较低 `avg_steps`、较高 `global_step`。

`max_episodes` 是上限，不表示循环加测到该数量。多任务各任务预算相等。候选按批累计 episode 数、成功数和有效成功步数；排名使用累计值，完整 episode 保存在阶段记录中。

### 全零与失败

episode 正常完成但全部失败仍是有效结果，`status=success` 表示选点流程完成。OOM、环境异常、非法或不完整 episode 属于技术失败：中止、记录错误并保留旧 best，不记成普通 `success=False`。

### 选择产物

每次创建 `eval_ckpt_selector/<id>/selection_result.json`，保存配置快照、候选、推理设置、计划及实际 episode。完整计划在首个候选恢复/rollout 前原子写入，运行中更新；成功后 `best_ckpt.json` 仅通过相对路径 `selection_result` 引用该记录。

记录的 `evaluation.request` 包含 `shuffle_seed`、`test_task_seeds`、`initial_task_seeds`、`possible_tie_task_seeds`；测试预算取快照的 `effective_config.eval.offline.episodes`。

复用时核对实际计划的任务、数量、唯一性、池内成员与 test/完整 selection 预留互斥；所有实际阶段（包括落选候选）须完成且 episode 匹配，使用 seeds 不得超出预留。缺少实际 test 计划时需重新 selection，不补齐或迁移记录。

需要锁定单次选择结果时：

```bash
EXP_DIR="experiments/<policy_name>/<task_name>/<run>"
mkdir -p "$EXP_DIR/eval_ckpt_selector"
SELECTION_DIR="$(mktemp -d "$EXP_DIR/eval_ckpt_selector/manual_XXXXXXXX")"
bash scripts/eval/select_checkpoint.sh <policy_name> <task_name> <run> \
  --output-dir "$SELECTION_DIR"
bash scripts/eval/evaluate.sh <policy_name> <task_name> <run> \
  --selection-record "$SELECTION_DIR/selection_result.json" --no-videos
```

`--output-dir` 须位于该实验的 `eval_ckpt_selector/` 内且为空。显式 `--selection-record` 锁定 checkpoint、EMA/raw、NFE 和 `action_steps`，冲突请求失败。

## Seed 与 held-out

### Seed 池

每任务池依次取 `env_runner.eval_seeds`（多任务取各 `task_configs`）、`dexmani_sim.DATA_DIR/eval_seeds/<task>.txt`、`range(100)`。校验非负整数、排序去重后，用局部 `random.Random(eval_seed)` 打乱，不消费全局 RNG。

```text
N = eval.offline.episodes
K = min(initial_episodes + batch_size, max_episodes)
test = shuffled_pool[:N]
selection = shuffled_pool[N:N+K]
```

每任务至少需 N+K 个不同有效 seeds，容量不足在模型恢复前失败，不缩减或重复抽样。当前配置默认 N=70、K=30，实际预算以实验保存配置和显式覆盖为准。未执行的平局加测 seeds 仍预留，不计入实际阶段或成功率。

相同池集合、eval seed 和 N 得到相同有序 test，训练 seed、方法、NFE、选优预算和是否加测不影响它。物理实例比较还需相同 task、环境配置和模拟器版本。

selection、无记录 final eval 和 demo 的 seed 优先级为 `--seed` > `eval.seed` dotlist > 保存的 `eval.seed`；缺失时直接报错，不补固定 seed。它与 training seed 无关，不接受 `training.seed` override，冲突的重复 seed 参数报错。

单任务和多任务统一调用 `run(agent, task_seeds={task: [...]})`，并通过 `task_runners` 访问各任务 runner。执行必须完整覆盖显式清单，预算统一由评测入口解析；容量不足在环境创建前失败。

### 最终评测

`best` 或显式选择记录直接复用有序 `test_task_seeds`。省略 seed/数量时以记录为准；显式 CLI/dotlist 与记录冲突则在模型加载前失败。记录中的 checkpoint、EMA/raw、正整数 NFE 和 `policy_seed_mode=episode_seed` 必须有效，CLI 不能修复损坏记录。

直接评测无记录 checkpoint 也生成同一 test 前缀并检查 N+K 容量，但标记 `heldout_from_selection=false`。`latest`、百分比或路径本身不代表 held-out，需绑定有效选择证据。最终快照与明细记录实际清单。

### 随机性边界

环境 `reset(seed)`，每个 episode 重置 Torch CPU/CUDA RNG。seed 计划和初始化可重建，模型、NFE、dtype、随机数消费及 GPU kernel 差异仍可能改变轨迹，不保证逐位一致。

demo 的 `--seeds` 是每任务共用的物理 seed 数字，覆盖 `--episodes`；与 dotlist 同用时用 `--` 分隔，例如 `--seeds 5 12 -- eval.demo.action_steps=4`。加载模型前检查唯一性和池内可用性。它不排除 selection seeds，始终标记 `heldout_from_selection=false`。

## 推理参数与恢复

### 参数优先级

EMA/raw、NFE 和 `action_steps`：显式 CLI > 显式分区 dotlist > 显式共享 dotlist > 选择记录 > 保存配置。显式 `--selection-record` 仍要求与记录一致；普通 best 评测可覆盖 EMA/raw、NFE 或 `action_steps`，但不重新选点。seed/数量遵守上节记录约束。

EMA/raw、NFE、seed、测试数量、选点预算及 demo 数量必须由上述来源提供；缺失时直接报错，不补入固定值。除 seed 外，`null` 表示未指定，继续按来源优先级解析。`action_steps` 未指定时使用保存模型的 `agent.n_action_steps`。

NFE 先按来源优先级选择，再解析单值或列表；因此分区 `inference_steps` 会覆盖共享 `inference_steps_list`。同一来源同时提供非 `null` 的单值和列表时，列表优先，空列表仍报错；`null` 表示未指定。保存配置也先取分区再取共享值。

单个 NFE 使用 `--inference-steps N`，sweep 示例：

```bash
bash scripts/eval/evaluate.sh <policy_name> <task_name> <run> \
  --no-videos 'eval.inference_steps_list=[2,4,8]'
```

NFE 列表须为非空、互不重复的正整数。sweep 固定权重、环境和 seeds，只改变采样步数，每次调用只加载一次模型；不代表每个 NFE 各自选过 best。

pipeline、selection、final eval、demo 接受受限 `key=value` dotlist，不使用 Hydra `+`、`~` 前缀：

| `eval` 分区 | 字段 |
| --- | --- |
| `select_best` | `initial_episodes`、`batch_size`、`max_episodes`、`inference_steps`、`action_steps`、`use_ema` |
| `offline` | `episodes`、`inference_steps`、`inference_steps_list`、`action_steps`、`use_ema` |
| `demo` | 同 offline，加 `viewer_resolution` |
| `video` | `enabled`、`fps` |

另支持 `eval.seed`、上述共享 `eval.<字段>`、`training.device` 和符合 runner 接口且不改变模型输入的 `env_runner.*`。未知 eval 键报错。显式共享值覆盖保存的分区值，显式分区值再覆盖共享值；`episodes`、`use_ema`、NFE 和 `action_steps` 的 `null` 与未指定一致，各入口只消费相关分区。`agent.*`、`dataset.*`、normalization、观测长度/模态、RGB 和语言条件不能在评测时替换。

### 执行长度

`eval.action_steps`（或 `eval.select_best.action_steps`、`eval.offline.action_steps`、`eval.demo.action_steps`）只控制每次消费多少条已解码的物理动作。公共 CLI 为 `--action-steps N`。缺省采用保存模型的 `agent.n_action_steps`；有效范围为整数 `1..(agent.horizon-agent.n_obs_steps+1)`，拒绝 bool、浮点数和越界值。

```bash
bash scripts/eval/eval_pipeline.sh <policy_name> <task_name> <run> eval.action_steps=4
bash scripts/eval/evaluate.sh <policy_name> <task_name> <run> --no-videos --action-steps 4
```

执行段为 `pred_action[0, N-1:N-1+action_steps, :control_action_dim]`。它不改变训练 `n_action_steps`、horizon、观测窗口、Dataset padding 或默认 `control_action`，也不改变真机 `execution.action_steps`。

最终测试默认继承 selection 的执行长度，优先级遵守上节。选择记录必须显式保存 `inference.action_steps`，不从模型窗口推测缺失值。pipeline 显式指定的 offline 长度若与本次 selection 冲突会失败。新记录的 `inference`、评测快照、`eval_config.yaml`、结果明细及 NFE sweep 汇总保存实际长度；普通 best 消融同时记录原 `selection_inference` 和 `matches_selection_inference`，区分是否沿用选点协议。

### 模型恢复

先解析保存配置的插值，再应用评测覆盖；模型按 checkpoint 的 `effective_config` 构建，只比较推理相关设置。多任务输入与文本按任务名取保存的 child 配方和 `dataset.task_texts`，缺省文本为任务名，实际值写入 `runner_inputs`。

`SimRunner` 通过 `dexmani_sim.resolve_env_class` 获取任务；观测历史只缓存数值传感器帧，`task_text` 在组装 batch 时单独注入，每个样本一条文本。多任务默认文本为任务名，`task_configs` 覆盖公共 runner 设置。快照直接记录这些任务 runner 的实际输入和展开后的环境参数。严格加载、内嵌权重和 normalizer 的规则见 [Checkpoint 与续训](项目架构.md#checkpoint-与续训)。

## 执行与指标

EnvRunner 用长度 N 的历史 buffer，首帧补齐。输入 dtype、RGB 预处理和物理动作布局沿用 [策略与部署接口](项目架构.md#部署边界)；LAMP 只记录实际执行命令。

| 指标 | 定义 |
| --- | --- |
| `success_rate` | 最终成功数 / 完成 episode 数 |
| `task_done_step` | 首次满足 `success_condition` 时的 `env.action_cnt`，从未达标时为 `None` |
| `avg_steps` | 成功 episode 的有效 `task_done_step` 均值 |
| `avg_steps_all` | episode 的有效 `total_steps` 均值 |

最终 `success` 可含 hold/grace，区别于首次达标。普通失败计入成功率分母。单任务 runner 步数均值取整，多任务 runner 对每任务的取整均值再平均取整；final eval 直接计算成功 episode 的浮点均值。

macro 为每任务成功率平均，micro 为总成功数 / 总 episode 数；`result.txt` 写 micro，明细保存两者及 Wilson 95% 区间。该区间不表示跨训练 seed 方差或 macro 不确定性。

缺失、重复、额外 episode、错误任务或非法类型使整次结果失败。环境构建/reset/推理/执行异常直接传播，不发布部分任务的聚合结果；episode 执行失败时输出任务与 seed，并尝试保存崩溃录像，退出时关闭环境。

模拟器必须提供 `info.success`、`info.success_condition` 和 `env.action_cnt`；LAMP 还读取 `info.executed_joint_action`。缺失这些字段按接口错误中止，不计为普通失败 episode。

录像统一使用 `imageio-ffmpeg` 定位的 ffmpeg，以 H.264／yuv420p 编码，不自动缩放帧。编码失败会警告，保留已完成指标，不注册失败视频。帧率依次取 demo `--fps`、`eval.video.fps`、runner `env_video_fps`、环境 `video_fps`（缺省 15）。

## 结果文件

每次调用创建独立目录：

```text
experiments/<policy>/<task>/<run>/
├── best_ckpt.json
├── eval_ckpt_selector/<id>/selection_result.json
├── eval_dexsim/<id>/{eval_config.yaml,result.txt,result_details.json}
└── demo_videos/<id>/                 # 同上并含视频
```

sweep 父目录保存 `eval_config.yaml`、`eval_summary.json`，各 NFE 结果位于 `inference_steps<N>/`。demo `--output-dir` 更换父目录，仍创建独立 run。快照记录 checkpoint、step、推理设置、环境和 seeds；dirty 标记不等于源码归档。

## 验证与源码

通用验证入口及边界见 [验证指南](验证指南.md)，闭环性能需实际 rollout。评测代码位于 `evaluation/`：`config.py` 解析请求与参数优先级，`rollout.py` 构建 runner 并执行评测，`artifacts.py` 保存快照与核对选择证据，`selection.py` 选点，`pipeline.py` 串联选点与测试；runner 与评测共用的 seed 和指标工具位于 `env_runner/common/seeds.py` 和 `env_runner/common/metrics.py`。CLI 为根目录的 `eval_pipeline.py`、`select_checkpoint.py`、`evaluate.py`、`record_demo.py`，均相对于 `dexmani_policy/`。
