# 仿真评测

评测直接读取 checkpoint 内的当前配置与 affine，不依赖实验目录的 config.yaml、训练数据或原初始权重。需要可用的 dexmani_sim 环境与对应任务的评测 seed 池。输入能力检查由 `SimRunner.run()` 根据 Runner 的 `sensor_modalities` 执行；模型恢复后、创建环境前明确拒绝仿真不提供的 dense taxel/patch 观测，原异常直接传播。aggregate 触觉直接使用仿真世界系原始力和 checkpoint 保存的 affine，不在线更新统计。

`evaluate_policy` 与部署路径入口 `restore_policy()` 共用内部模型恢复函数：normalizer 形状从实际选中的 raw/EMA state 推导，严格加载后一次性迁移设备并转为 FP32，再进入 eval，按原有方式合并 RGB LoRA。构造模型前解除完整 checkpoint 的引用，释放未选权重及 optimizer、scheduler、RNG 状态；构造期间保留进程 RNG 的保存与恢复。`SimRunner.predict_action_chunk()` 显式关闭 autocast；结果记录中的参数 dtype 是恢复后的实际推理精度。训练的 BF16 配方和训练状态恢复不受影响。

## 单 checkpoint

```bash
python -m dexmani_policy.evaluate \
  --checkpoint <run>/checkpoints/latest.pt --weights ema \
  --inference-steps 10 --episodes 100 --seed 1024 --device cuda:0
```

`--weights raw|ema`、`--inference-steps` 默认取 checkpoint 配方；请求不存在的 EMA 明确失败。`--action-steps` 默认取恢复后模型的 `agent.n_action_steps`，不能超过 `agent.future_steps`。`--seeds` 可显式给出 episode seeds，顺序和数量不受 `--episodes` 影响；否则从 `dexmani_sim.DATA_DIR / "eval_seeds" / f"{task_name}.txt"` 按 `--seed` 和 `--episodes` 确定测试集合，不提供配置覆盖 seed 池的入口。CLI 仅转发参数；每次 `evaluate_policy` 只调用一次 `load_checkpoint`，从同一次加载取得配置、所选权重与 global_step，并直接将 global_step 写入结果。`--no-video` 关闭视频，`--output-dir` 指定新的空输出目录；未指定时在实际 checkpoint 所属 run 的 `eval/` 下自动创建独立目录。

环境参数来自 checkpoint 的 `env_runner.env_kwargs`，包括显式的 `max_stability_retries=0`；缺省值沿用 dexmani_sim。`StabilityConfig` 和新运行的 `GenerationConfig` 共用重试默认值 0，即仅初次尝试；显式 3 表示初次尝试加最多 3 次重试。生成默认从 3 改为 0 是生成配方变化，可能影响接受率，不改写已有 checkpoint。稳定性阈值沿用同一配置类；模型和桌面随机化仍取各自配方：生成 API 默认模型随机化关闭、桌高随机化开启，主策略的新运行（包括 AFRO/CordViP）继承公共配置，两项均开启。已有 checkpoint 继续使用保存的 `effective_config`，不以当前 YAML 回填。生成脚本或调用方可显式覆盖；`pick_apple_messy` 的默认杂物由同一任务环境提供。

任务池由专家执行、终止行为及配置启用的轨迹质量门限筛选，不是未经筛选的随机场景集合。seed txt 不记录生成配置；缺少可靠生成记录时，历史生成条件未知，不能从当前默认值反推。重试会继续消费随机流并重新采样；当前设置下 reset 成功只证明可初始化，不证明复现了历史接受场景或专家仍能成功。核验使用明确的 seeds 和环境参数，初始化异常直接传播，不换 seed、不加重试、不跳过并重算分母。若需新池，沿用 dexmani_sim 的 `EpisodeDataGenerator`，以新的 `output_root` 运行 `GenerateMode.EVAL_SEEDS`，保留现有 txt。

Runner 的历史长度来自 `agent.n_obs_steps`，观测字段来自 checkpoint 保存的 `normalization_dims` 去掉 `action`。fresh 配方的唯一输入列表是 `dataset.sensor_modalities`，不自动过滤自定义配方的额外输入。点云在 CPU 上按 `agent.normalization_dims` 裁剪并转为连续数组后传输；需要颜色的模型保留对应通道，Policy 内部的通道处理仍供训练和其他推理入口复用。RGB 继续使用已有预处理配方。每个控制步更新历史；完整 `future_actions` 的有限性检查通过后才截取执行前缀，每个动作后检查环境终止。

评测成功完成后原子保存一次 result_details.json，记录实际 checkpoint、global_step、推理/执行步数、权重、seed 列表、`runner_options`、逐 episode 成绩和统计，以及 Torch/CUDA 版本和模型参数 dtype。`runner_options` 中模型相关参数采用实际使用值；其中 `env_kwargs` 仅表示传入环境的覆盖参数，不是展开全部默认值后的环境状态。首个真实环境创建成功后读取一次 `environment`：`control_dt_s` 来自实际 `env.dt`，另记录 `frame_skip`、`action_cnt_limit`、`success_hold_steps` 及实际 `randomization`、`stability` 设置。每次 run 重新采集，不保留环境引用或逐 episode 重复记录；只记录控制周期，不调整频率或重采样。

`result_details.json` 的 `checkpoint` 使用 `os.path.relpath()`，相对于结果文件所在目录；读取时按 `result_path.parent / record["checkpoint"]` 解析。完整 run 搬迁后，内部 checkpoint 引用仍有效。外部 checkpoint 仍是外部依赖，须保持相对位置；不复制文件或自动重写路径。模型加载仍使用解析后的真实 checkpoint 路径。

`inference_steps` 表示动作扩散的采样步数；具有 `force_predictor` 的恢复模型另记录其实际 `force_inference_steps`。AdapTac 默认动作与未来力扩散均为 20 步，覆盖 `--inference-steps 10` 只改变动作扩散，力扩散仍采用 checkpoint 的 `agent.force_num_inference_steps`。`action_steps` 表示每次查询后执行的动作数。这些字段同样保存在选模候选与独立测试各自的 result_details.json 中。

统计中的 `n_episodes` 表示实际完成的 episode 数；保留 `success_rate`、`n_success`、成功 episode 的 `avg_steps`、全部 episode 的 `avg_steps_all` 和 `wilson_95`。`steps` 仍记录首次满足原始成功条件的步数，`total_steps` 是结束时的动作数，最终成功仍由环境的 `success` 判定。stdout 仅供阅读，不用于解析成绩。不预写空结果或维护失败状态；失败直接传播异常并关闭环境，可以留下视频和本次目录，但不产生完整结果 JSON。构造失败或中断时，`make_env()` 显式关闭半构造实例；若关闭也失败，报告清理异常并保留原构造异常。构造成功后仍由 `run()` 的既有生命周期关闭。

## 执行长度

实际执行长度 C 必须满足 `1 <= C <= agent.future_steps`，其中 `future_steps = horizon - (n_obs_steps - 1)`。普通评测在模型恢复后取默认执行长度并检查上限；选模入口仍从首个 checkpoint 的 `agent.n_action_steps` 确定统一执行长度，各次 rollout 再按实际模型检查上限。覆盖 C 只改变每次查询后消费的动作数，不改写保存的训练配置、采样窗口或 padding。InterAct-Dex 的预测边界 K 独立来自 `max(future_force_horizons)`，模型构造时要求 K 不超过可用未来动作数。默认窗口有13个未来动作；C=1、K=4 合法。`policy_metadata` 保留给尚未构造模型的 `inspect_policy()` 使用。

`inspect_policy(experiment, checkpoint="latest")` 默认使用最新 checkpoint；也可传入明确文件路径。`PolicyInfo.n_action_steps` 来自保存的 `agent.n_action_steps`，权重与推理步数默认来自 `eval`，可用 `weights`、`inference_steps` 显式覆盖。`PolicyRuntime.predict()` 始终返回完整未来动作窗口，由调用方消费所需前缀；加载模型不会用 C 覆盖 K。

## 显式候选选模与独立测试

```bash
python -m dexmani_policy.eval_pipeline \
  --checkpoints <run>/checkpoints/<a.pt> <run>/checkpoints/<b.pt> \
  --weights ema --inference-steps 10 \
  --selection-episodes 25 --test-episodes 100 --seed 1024 \
  --output-dir <run>/eval/<new-comparison>
```

候选是研究者明确选定的同任务、同评测协议文件，允许位于不同目录，不要求凑齐所有 milestone。20/40/60/80/100% 仍是论文完整预算的默认候选方案；子集比较必须按实际列表报告，不称为完整预算比较。默认在首候选实际所属 run 的 `eval/` 下创建独立目录；跨 run 比较显式指定 `--output-dir experiments/eval/<comparison>/`。

从同一任务 seed 池确定性划分：测试 seeds 先固定，再取不相交的 selection seeds。seed 必须是 `[0, 2**32)` 内的整数且无重复；显式 seeds 非空，任务池必须满足所需容量。所有候选使用完全相同的 selection seeds、预算、推理和执行参数。排序依次为 success_rate 较高、avg_steps 较低、global_step 较大；缺失 avg_steps 排最后。选模不读取 test 成绩，胜者直接进入独立 test 调用。

pipeline 在加载 seed 池、创建输出目录和 rollout 前逐个读取候选的 `effective_config`，比较任务、完整 `env_kwargs` 和 `env_rebuild_interval`；不一致时报告两份 checkpoint、差异字段与取值并失败。比较忽略字典键顺序，按 Runner 语义统一缺省/null/空 `env_kwargs`，补齐本仓库的 `render_mode=rgb_array`、`env_rebuild_interval=25` 默认值；其余参数未指定与显式指定不视为等价，不推断 dexmani_sim 默认值。模型、训练和观测配置允许不同。每次读取后释放 checkpoint 权重及训练状态引用，统一推理设置仍来自首个候选；候选 rollout 和胜者的独立 test 重新加载 checkpoint，不在阶段间缓存 checkpoint 或模型。

独立 test 完成后才原子保存 selection_result.json，集中记录候选路径/step/分数、胜者、两组 seeds、实际推理参数和 test 结果位置。其内路径均相对 selection 结果目录，外部位置用 `..` 表达；同一 run 内的候选和结果随完整 run 搬迁后仍可解析，外部候选需保持相对位置。候选输出和 test 位于本次独立目录；`--output-dir` 可在任意位置，重用非空目录明确失败。

## 选模结果与部署接口

候选评测、选优和独立测试完成后保存 `selection_result.json`，不自动发布 checkpoint 指针。独立 test 分数不改变 selection 胜者。复现胜者必须同时使用记录的 checkpoint、weights/use_ema、inference_steps 和 action_steps，只替换 checkpoint 而回到默认推理设置不是同一实验。

`inspect_policy` 的 experiment 使用相对仓库根目录或绝对路径指定完整 run；checkpoint 接受 `latest` 和明确文件路径。显式绝对 checkpoint 路径直接使用，相对文件路径以 experiment/checkpoints 解析，允许指向外部文件的 symlink。Real 与其他部署调用方继续使用 inspect_policy、load_policy 和 PolicyRuntime.predict，默认选择 latest；predict 返回完整物理 future window 的 NumPy 数组。

例如对选中的文件执行 `inspect_policy("<run>", checkpoint="<winner.pt>", weights="ema", inference_steps=10)`，再调用 `load_policy(info)`。执行长度通过部署调用方的运行配置设置；Real 也从其运行配置指定 action_steps，不从 selection 结果自动恢复。

每个 run 使用单写者。checkpoint 与结果通过同目录临时文件加 `os.replace` 保存；远程同步已停止或完成的 run，传输全部成功后再使用，不提供同步期间的完整快照。

CLI 提供单点评测 evaluate 与选模加独立测试 eval_pipeline；选模直接由 run_pipeline 顺序执行。普通评测和候选选模共用 `evaluation/seeds.py` 中的 seed 池读取、校验与划分；显式 seeds 在评测入口校验后直接使用。

闭环成功率须通过实际仿真运行验证。CPU 合成检查不代替 CUDA、仿真后端或硬件部署验证。
