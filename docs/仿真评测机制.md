# 仿真评测

评测直接读取 checkpoint 内的实际配置与 affine，不依赖实验目录的 config.yaml、训练数据或原初始权重。需要可用的 dexmani_sim 环境与对应任务的评测 seed 池；real-source 触觉策略不能交给仿真 rollout。

## 单 checkpoint

```bash
python -m dexmani_policy.evaluate \
  --checkpoint <run>/checkpoints/latest.pt --weights ema \
  --inference-steps 10 --episodes 100 --seed 1024 --device cuda:0
```

`--weights raw|ema`、`--inference-steps` 默认取 checkpoint 配方；请求不存在的 EMA 明确失败。`--action-steps` 默认取模型执行窗口，不能超过完整 future window。`--seeds` 可显式给出 episode seeds，顺序和数量不受 `--episodes` 影响；否则从任务 seed 池按 `--seed` 和 `--episodes` 确定测试集合。CLI 仅转发参数，`evaluate_policy` 复用已加载的 effective_config 生成默认 seeds；默认评测共加载 checkpoint 两次，分别读取配置和恢复策略。`--no-video` 关闭视频，`--output-dir` 指定新的空输出目录；未指定时自动创建独立目录。

每次评测保存一份 result_details.json，记录实际 checkpoint、step、推理/执行步数、权重、seed 列表、runner 参数、逐 episode 成绩和统计，以及 Torch/CUDA 版本和模型参数 dtype。JSON 由共享 I/O 函数原子写入。异常传播，同时尽力保存失败详情；详情写入再次失败时报告次要错误并保留原异常，失败不会被当作成功率零。

## 显式候选选模与独立测试

```bash
python -m dexmani_policy.eval_pipeline \
  --checkpoints <run>/checkpoints/<a.pt> <run>/checkpoints/<b.pt> \
  --weights ema --inference-steps 10 \
  --selection-episodes 25 --test-episodes 100 --seed 1024 \
  --output-dir <run>/eval_ckpt_selector/<new-comparison>
```

候选为同一 run 中显式列出的文件，不要求凑齐所有 milestone。20/40/60/80/100% 仍是论文完整预算的默认候选方案；子集比较必须按实际列表报告，不称为完整预算比较。

测试 seeds 先固定，再取不相交的 selection seeds。所有候选使用完全相同的 selection seeds、预算、推理和执行参数。排序依次为 success_rate 较高、avg_steps 较低、global_step 较大；缺失 avg_steps 排最后。选模不读取 test 成绩，胜者直接进入独立 test 调用。

selection_result.json 集中保存候选路径/step/分数、胜者、两组 seeds、实际推理参数和结果位置；候选 step 在其实际评测完成后从返回结果写入。候选输出和 test 位于本次独立目录；重用非空目录明确失败。

## 发布与部署接口

selection 输出须在原 run 内，best_ckpt.json 指向本次 selection 记录和真实 checkpoint。选模、best 发布和独立测试在同一 .pipeline.lock 内依次执行。远程同步先传权重和记录，再更新 best 指针。Real 与其他部署调用方使用 inspect_policy、load_policy 和 PolicyRuntime.predict，默认选择 best；predict 返回完整物理 future window 的 NumPy 数组。

CLI 提供单点评测 evaluate 与选模加独立测试 eval_pipeline；select_checkpoint 是内部函数。普通评测和候选选模共用 `evaluation/seeds.py` 中的 seed 池读取、校验与划分；显式 seeds 在评测入口校验后直接使用。

独立测试失败会传播异常并将本次 selection_result 标记为 failed，保留候选成绩和错误详情；已完成选模发布的 best 仍指向该次实际胜者，不能将其解释为独立测试已经完成。

编排单测只验证预算、seed 隔离、排序、记录和输出冲突；只有实际仿真运行才验证闭环成功率。CPU 合成检查不代替 CUDA、仿真后端或硬件部署验证。
