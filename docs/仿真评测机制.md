# DexMani Policy · 仿真评测机制

评测只使用实验保存的配置与 Checkpoint，不重新组合当前 Policy YAML。每次请求固定 Checkpoint、EMA/raw、单个 NFE、执行长度、任务和 seeds；旧实验须配合对应源码，不自动迁移格式。

## 入口与流程

| 入口 | 用途 |
| --- | --- |
| `eval_pipeline.sh` | 固定选点和测试计划，依次完成 selection 与冻结的 held-out test；同一实验以 `flock` 防并发 |
| `select_checkpoint.sh` | 按统一预算比较全部 milestone Checkpoint |
| `evaluate.sh --checkpoint ...` | best/latest/百分比 tag/指定文件的普通研究评测，**不是**正式测试证据 |
| `evaluate.sh --selection-record ...` | 使用已完成的选点记录进行正式测试，仅可更改 `training.device` 和输出目录 |

命令从仓库根目录执行：

```bash
bash scripts/eval/eval_pipeline.sh <policy_name> <task_name> <run>
bash scripts/eval/select_checkpoint.sh <policy_name> <task_name> <run> eval.selection_episodes=25
bash scripts/eval/evaluate.sh <policy_name> <task_name> <run> --checkpoint latest eval.episodes=5
```

选点与其冻结测试默认均不录像；创建选点协议时可用 `eval.video.enabled=true` 同时启用两者录像。普通评测使用保存配置并接受研究覆盖。录像需 ffmpeg，交互 viewer 需 X11/XWayland；视频来自同一次 rollout，不构成额外测试证据。各入口的 `--help` 不依赖实验目录或 DISPLAY。

## 请求解析

普通评测支持平面 dotlist 覆盖，不能改模型、观测模态/长度、RGB 处理、Dataset 或归一化；`best` 的推理默认值来自 best 指针，其他 Checkpoint 来自保存配置，显式覆盖优先。关键字段：

| 字段 | 含义 |
| --- | --- |
| `eval.seed` | seed 池局部打乱及模型初始化，与训练 seed 独立 |
| `eval.episodes` / `eval.selection_episodes` | 每任务测试数 / 每候选每任务选点数 |
| `eval.task_seeds` | 普通评测指定任务→有序 seeds，任务预算相等 |
| `eval.inference_steps` / `eval.use_ema` | 单个正整数 NFE / EMA 或 raw |
| `eval.action_steps` | 执行长度 C；`null` 使用保存的 `agent.n_action_steps` |
| `eval.video.enabled` | 录像开关；帧率使用环境的 `video_fps` |
| `training.device` / `env_runner.*` | 设备与符合 SimRunner 接口的环境设置 |

每次请求使用保存的单个 Dataset 配方运行 SimRunner；环境参数合并后验证 `action_key/control_mode`。请求保存解析后的配置、Checkpoint、任务/seeds、NFE、C 和 EMA/raw 选择。推理沿用 Checkpoint 精度，使用 `no_grad`，不启用 autocast/compile。

Runner 直接接收保存的 RGB 预处理配方，只缓存所需的 NumPy 观测。环境原生参数通过 `env_runner.env_kwargs` 传入，例如 `render_mode=human`、`randomize_model_id=true`、`randomize_table_height=true`；默认 `render_mode=rgb_array`。背景纹理、天空盒、物体纹理、光照和相机随机化分别使用环境的 `use_texture_randomization`、`per_episode_skybox`、`randomize_object_texture`、`randomize_light`、`randomize_camera_pose` 字段。

`env_runner.env_rebuild_interval` 控制环境重建间隔，默认 25 个 episode，非正值表示一直复用；LAMP 和 LatentFlow 配置为 1，以保持每个 episode 独立的仿真状态。录像目录由评测入口根据 `eval.video.enabled` 传入，同时决定环境是否采集视频；不要在 `env_kwargs` 中重复设置 `record_video`。编码使用 H.264、yuv420p 和 CRF 23，失败直接上抛。

## Checkpoint selection

候选必须是实际 milestone 文件（不是 latest 或符号链接）。从保存的 `training.loop.total_train_steps` 和训练共用的 `milestone_steps` 推导完整集合，通常为 20/40/60/80/100%；极小预算中相同步数的百分比沿用训练保存规则。selection 在仿真前一次性检查缺失 step、重复 step 与文件名中的 step/百分比，缺失时列出所需 step。恢复训练允许历史候选缺失，不代表该 run 已具备正式选点条件。

开始加载模型前冻结候选及评测计划；默认每候选每任务 selection=25、test=70，所有候选使用相同任务、seeds、推理和环境条件，不因平局追加预算。

按以下顺序选点：**最高 micro success rate → 最低成功 episode 的有效首次成功步数均值 → 最大 global_step → 声明顺序**。全部任务失败但评测正常完成仍是有效候选（avg_steps 为 null）；模型、环境、OOM、episode 缺失/重复等技术失败则中止，不换 seed、不跳过候选、不更新原 best。

`best_ckpt.json` 记录 Checkpoint 相对路径、global_step、EMA/NFE/C 和 selection 记录。普通 `best` 直接使用这些设置，加载后核对 checkpoint step，无需重跑 selection 排名。

selection 的 `candidates` 保存路径与 step，`candidate_results` 指向各候选的完整 rollout 结果。评测、选点和发布均不计算权重内容哈希；同路径、同 step 的权重替换不会被检测，选点后的 milestone 文件应保持不变。

`evaluate_policy` 返回 `(record, result_path)`，selection 直接使用内存中的统计排名，不回读候选 JSON 或重新计算统计。全部候选完成后，先原子保存 selection record，再更新 best；失败保留旧指针。`select_best_checkpoint` 返回 `(record, checkpoint_path)`，`eval_pipeline.py` 随后执行冻结测试并返回结果路径。

独立冻结测试只读取 `status=completed` 的选点记录和选中 Checkpoint，不读取实验目录的 `config.yaml` 或候选结果文件；配置来自记录内的 `test_request`。请求中的 `source.selection_result` 统一为相对实验目录的路径，实验搬迁后仍可定位选点记录及 Checkpoint。候选结果供查看实验详情，不提供独立离线复核或重新发布 best 的入口。

结果记录 Torch/CUDA、参数 dtype 与数值设置，但不要求它们与 selection 一致。复现实验须自行保留对应源码和运行环境。

## Seed 与 held-out

每任务 seed 池来自 `env_runner.eval_seeds`或 `dexmani_sim.DATA_DIR/eval_seeds/<task>.txt`；缺失报错。池内 seed 为不重复的 `[0,2**32)` 整数，排序后以 `random.Random(eval.seed)` 局部打乱：

```text
test      = shuffled_pool[:eval.episodes]
selection = shuffled_pool[eval.episodes:eval.episodes + eval.selection_episodes]
```

选点必须有 N+K 个 seeds；更改 selection 预算不会改变 test 前缀。普通评测只要求本次预算，显式 seeds 若有声明池则必须属于该池。每个 episode 按物理 seed 重置环境，并创建设备匹配的 Policy 采样 Generator；环境 RNG 仍归执行器管理。不同模型/数值内核仍可能产生不同轨迹。

`heldout_from_selection` 表示 selection/test seeds 隔离，不代表与训练场景独立。训练配置保留 `data_recipe[].source_evidence`，评测不再计算训练 seed 交集；相同或不同的整数 seed 都不足以判断训练场景是否重叠。

正式测试须运行 pipeline 或使用已完成的 selection record：

```bash
bash scripts/eval/evaluate.sh <policy_name> <task_name> <run> \
  --selection-record experiments/<policy_name>/<task_name>/<run>/eval_ckpt_selector/<id>/selection_result.json \
  training.device=cuda:0
```

该记录冻结 Checkpoint、EMA/NFE/C、任务、环境、seeds 与录像设置。普通 `--checkpoint` 始终为 `heldout_from_selection=false`；开发对照应使用 selection seeds 或独立普通评测，**不得根据正式 test 结果再次调整 Checkpoint、C 或 NFE**。

## 执行长度

Policy 先完成完整窗口解码与反归一化，输出 query 起的物理动作 `future_actions[B,P,D_control]`，Runner 仅执行 `future_actions[0,:C]`。要求 `1<=C<=P`；LatentFlow 的 `P=H`，其他策略 `P=H−N+1`。`eval.action_steps` 不改训练窗口、padding、normalizer 或 Real 的执行长度；普通配置 `pad_after=7`、DQ-RISE 为 15、LAMP/LatentFlow 为 0。

### LatentFlow 执行时长对照

先核对数据 `dt` 与环境控制周期。若 `dt≈0.0625s`，H=32 为约 2s 的控制周期预算，C=25/13 分别为 1.5625s/0.8125s；首末采样跨度实际为 `(帧数−1)*dt`，同步推理还会影响查询周期。必须完整生成、双向解码 H 后再截取 C；执行长度对照仅用开发 seeds，不覆盖冻结测试，也不意味着真机闭环已验证。

## 平面记录与统计

每个 episode 记录 `task_name、seed、success、steps、total_steps、video`；`steps` 为首次 raw success_condition 步数，`success` 为终止时的 hold/grace 判定，失败 episode 不纳入成功步数均值。`video` 为 MP4 路径字符串，未录像时为 `null`。

`evaluation/metrics.py` 统计 micro（总成功/总次数）、macro（各任务成功率等权平均）、成功 episode 的有效首次成功步数均值，并记录 per_task、总步数均值和 Wilson 95% 二项区间；该区间不是训练 seed 方差或 macro 的置信区间。

`result_details.json` 在模型加载前写入 request，正常完成后原子保存全部 episodes 和统计，标记 `completed`。可捕获异常时保存 traceback 和已完成前缀，`status=failed`、`statistics=null`。不逐 episode 重写文件，强制终止可能丢失尚未保存的进度。录像须先成功导出才登记该 episode，录像失败也令评测失败。

`selection_result.json` 同样只在开始、完成或异常时保存；异常时保留已完成候选的结果路径。

Episode 异常直接上抛并关闭环境，由评测入口统一记录失败，不再额外编码崩溃视频。保存失败记录本身出错时，报告写入错误并保留原异常。

```text
experiment/
├── eval_ckpt_selector/<id>/selection_result.json
├── eval_ckpt_selector/<id>/candidates/<id>/result_details.json
├── eval_dexsim/<id>/result_details.json
└── best_ckpt.json
```

视频在各评测目录的 `videos/`。结果记录 Python/Torch/CUDA、设备、dtype 和数值设置。同步先传输权重，再一起更新评测与选点记录，最后更新 best 指针。

评测回归测试使用 CPU 模型与环境替身，覆盖观测时序、动作分块、LAMP 历史、选点、冻结测试、异常保存和资源清理；短视频测试实际调用 FFmpeg：

```bash
conda run -n policy python -m pytest -q -p no:cacheprovider tests/test_evaluation.py tests/test_env_runner.py
```
