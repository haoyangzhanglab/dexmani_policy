# 仿真评测机制

仿真评测衡量策略在环境交互中完成任务的能力。评测模块恢复完整策略，由仿真运行器提供观测、执行动作并记录回合结果。

`env_runner._target_` 显式指定运行器，并随 checkpoint 保存。默认配方使用 `dexmani_policy.env_runner.sim_runner.SimRunner`；DexJoCo 配方使用 `dexjoco.policy_runner.DexJoCoRunner`。运行器提供环境与 seed 池，维护观测历史并执行动作；评测模块负责恢复策略及 selection/test 划分。

`SimRunner.load_seed_pool` 读取仿真任务的 seed 文件，外部运行器可覆盖此方法。运行器只向仿真请求策略所需的观测字段。视频录制可额外采集 RGB，帧率按环境控制周期计算。观测历史使用有界队列保存所需字段的独立快照，历史不足时重复首帧，避免环境复用数组改变先前观测。

## 闭环执行

每个回合从指定场景开始，重复以下过程，直到回合结束：

1. 读取最近的观测历史。
2. 生成未来动作窗口。
3. 执行配置的动作步数，并在每个控制步更新观测。
4. 根据新观测重新预测。

对 Diffusion/Flow，预测窗口决定规划范围，采样步数决定模型的迭代预算，执行前缀长度决定重新规划频率。环境控制周期须与 checkpoint 保存的数据控制周期一致。

leading DDIM 至少使用 2 NFE。在 100 个训练时间步下，默认 10 步从 `t=90` 开始，20 步从 `t=95` 开始。ManiFlow 的 Euler NFE 和 ODE 的数值子步由各自配方定义。

ODE 需要完整执行训练时的动作 chunk，并将上一条实际下发目标传给下一次预测；回合中途终止时立即停止。具体承接约定见[手部动作表示](手部动作表示.md#ode从上一条指令积分生成轨迹)。

## 任务结果与候选选择

成功由环境判定，成功率表示完成任务的回合比例；平均执行步数补充描述完成效率。训练损失衡量学习目标的拟合，不能代替闭环成功率，也不能跨不同动作表示直接排名。

| 阶段 | 作用 |
| --- | --- |
| 候选选择 | 在共同的 selection 回合上比较候选，确定胜者 |
| 独立测试 | 在不重叠的 test 回合上评估胜者，报告最终成绩 |

同一组对比预先固定评测池、`--seed`、`--selection-episodes` 和 `--test-episodes`，更换训练 seed 时沿用它们。候选依次按成功率、较少的平均执行步数、较大的训练步数排名。成功率区间只对应当前评测池及控制配方。

固定单个 checkpoint 时直接使用 `python -m dexmani_policy.evaluate`。相同 `--seed` 和测试回合数复用流水线的测试 seed，结果写入 `result_details.json`。多个候选用 `python -m dexmani_policy.eval_pipeline` 比较，`selection_result.json` 保存两组实际使用的 seed。若要调 raw/EMA、NFE 或执行长度，先用 `evaluate --seeds` 对所有组合传入同一份选择 seed，再用测试 seed 运行胜者。

每个候选默认使用自己的权重选择、推理步数与执行长度，也可显式统一这些设置。胜者的独立测试沿用选模时的实际设置，结果记录对应配置及回合表现。

## 比较条件

候选须使用相同运行器、任务、环境配置和控制周期。跨方法比较还应保持回合预算一致，并说明观测模态、先验来源及推理预算；策略结构可以不同。

评测流程位于 [evaluation/](../dexmani_policy/evaluation/)，闭环执行位于 [env_runner/](../dexmani_policy/env_runner/)。模块关系见[项目架构](项目架构.md)，远程操作见[SSH 服务器训练部署](SSH服务器训练部署.md)。
