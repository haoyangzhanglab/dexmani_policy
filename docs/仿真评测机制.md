# 仿真评测机制

训练配方从 `configs/eval/` 组合环境配置，评测从 checkpoint 恢复策略和环境设置。默认环境 `dexmani_sim` 执行关节或末端位姿动作，DexJoCo 执行原生 `action_rotvec`。 [dexmani_sim 配置](../dexmani_policy/configs/eval/dexmani_sim.yaml) · [DexJoCo 配置](../dexmani_policy/configs/eval/dexjoco.yaml)

## 运行评测

评测一个 checkpoint 用 `evaluate.sh`，比较多个 checkpoint 用 `eval_pipeline.sh`。流水线让所有候选使用同一批选模种子，并用独立的一批测试种子评测胜者。任务种子池须覆盖两批回合。

`dexmani_sim` 的评测种子池位于 `dexmani_sim.DATA_DIR/eval_seeds/<task>.txt`。示教 Zarr 的 `meta/episode_seeds` 记录采集回合使用的种子。

```bash
RUN=experiments/train/dp3/multi_grasp/run01

bash scripts/eval/evaluate.sh --checkpoint "$RUN/checkpoints/latest.pt" \
  --seed 1024 --episodes 100

bash scripts/eval/eval_pipeline.sh --checkpoints \
  "$RUN/checkpoints/step_00020000.pt" "$RUN/checkpoints/step_00040000.pt" \
  --seed 1024 --selection-episodes 25 --test-episodes 100
```

每次评测写入 `result_details.json`。流水线另将选模种子、测试种子和胜者写入 `selection_result.json`。复现测试回合时，单模型评测使用相同的任务种子池、`--seed` 和测试回合数，或用 `--seeds` 传入记录的测试种子。

加 `--video` 可录制单模型评测或流水线的独立测试。录像按控制频率编码，每个控制步一帧。`episodes[].video` 保存相对于结果 JSON 的路径 `videos/<task>/episode_<seed>.mp4`。仿真时长可用 `total_steps × control_dt_s` 计算。

## 闭环执行

策略用近期观测预测一段动作，执行 `--action-steps` 步后再预测。`--inference-steps` 控制推理步数，使用 DDIM 时至少为 2。ODE 每次执行与训练相同的窗口长度，并从上一条实际应用的关节目标开始预测。 [ODE 指令衔接](手部动作表示.md#ode从上一条指令积分生成轨迹)

环境控制周期须与 checkpoint 一致。DexJoCo 在首次 reset 前核对观测处理参数，点云模式同时核对相机的渲染尺寸和点数。

使用 `dexmani_sim` 且关闭录像时，可加 `--skip-intermediate-observations` 只采集下次预测所需的历史帧。环境仍按步执行动作并检查终止，传感器随机数消耗会变化，比较时应统一该选项。

## 比较条件

- 候选须使用相同的运行器、任务、环境配置和控制周期。比较时固定种子池、`--seed` 和各阶段回合数。
- 按成功率降序、成功回合的平均步数 `avg_steps` 升序、训练步数降序排名。DexJoCo 记录确认成功的步数，`dexmani_sim` 记录首次满足成功条件的步数。
- 权重、推理步数和执行步数默认取自各候选 checkpoint。可用 `--weights raw` 或 `--weights ema`、`--inference-steps`、`--action-steps` 统一设置。独立测试沿用胜者的选模设置。
- 比较多组推理设置时，用 `evaluate.sh --seeds` 为各组传入相同的选模种子，再用独立的测试种子评测胜者。跨方法报告观测模态、先验来源和推理预算。

成功率的 95% Wilson 区间反映评测回合的不确定性。训练结果的波动用多个训练种子衡量。
