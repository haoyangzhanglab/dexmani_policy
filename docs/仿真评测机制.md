# DexMani_Policy 仿真评测机制

评测使用实验保存配置与 checkpoint，不重新组合当前 Policy YAML。每个请求固定一个 checkpoint、一个标量 NFE 和明确的任务/seeds，rollout 只执行解析结果。历史结果与旧产物使用对应源码，不自动转换格式。

## 入口与流程

| 入口 | 用途与边界 |
| --- | --- |
| `eval_pipeline.sh` | 固定 selection/test 计划，选点后执行冻结测试；以 flock 防止同一流水线并发 |
| `select_checkpoint.sh` | 对完整 milestone 集合使用相同预算；显式输出目录须为空且位于实验的 eval_ckpt_selector 内 |
| `evaluate.sh --checkpoint ...` | 普通研究评测，支持 best/latest/百分比 tag/文件路径及研究覆盖；不是正式 held-out 证据 |
| `evaluate.sh --selection-record ...` | 正式测试，读取已完成选点记录；只允许改变 training.device 和输出目录 |

```bash
bash scripts/eval/eval_pipeline.sh <policy_name> <task_name> <run> eval.seed=1024 eval.episodes=70
bash scripts/eval/select_checkpoint.sh <policy_name> <task_name> <run> eval.selection_episodes=25
bash scripts/eval/evaluate.sh <policy_name> <task_name> <run> --checkpoint latest eval.episodes=5 eval.video.enabled=false
```

selection 默认不录像，创建协议时可开启，冻结测试沿用该设置；普通 evaluate 沿用保存配置。录像及 viewer 示例：

```bash
bash scripts/eval/evaluate.sh <policy_name> <task_name> <run> --checkpoint best \
  'eval.task_seeds={<task>:[5,12,33]}' eval.video.enabled=true env_runner.render_mode=human
```

替换实际任务名；viewer 需 X11/XWayland，录像需 ffmpeg。各入口的 `--help` 不要求实验目录或 DISPLAY。视频来自同一 rollout，不是独立测试证据。

## 请求解析

普通评测支持以下平面 dotlist；best 的推理默认值取直接指针，其他 checkpoint 取保存配置，显式覆盖优先。缺失必需字段直接失败。

| 字段 | 含义 |
| --- | --- |
| `eval.seed` | seed 池局部 shuffle 和模型初始化，与 training.seed 无关 |
| `eval.episodes` | 每任务 test/普通评测数量 |
| `eval.selection_episodes` | 每候选、每任务的固定选点预算 |
| `eval.task_seeds` | 普通评测的任务→有序 seeds，各任务预算相等 |
| `eval.inference_steps` | 单个正整数 NFE，sweep 由外层多次调用表达 |
| `eval.action_steps` | 执行长度 C，null 时取保存的 agent.n_action_steps |
| `eval.use_ema` | boolean，选择 EMA/raw |
| `eval.video.enabled`、`eval.video.fps` | 录像开关与帧率 |
| `training.device`、`env_runner.*` | 设备与符合 SimRunner 接口的环境参数 |

评测不能覆盖模型、观测长度/模态、RGB 预处理、语言条件、Dataset 或 normalization。多任务逐个执行单一 SimRunner，使用保存的 child 配方；task_texts 省略/null 时使用任务名，公共与子任务环境参数合并后核对 action_key/control_mode。

请求保存 checkpoint、配置与覆盖结果、任务/seeds、NFE、C、EMA/raw 和数值设置。仿真保持 checkpoint 参数精度，使用 no_grad，无 autocast/compile。

## Checkpoint selection

候选须为实际 milestone 文件，拒绝 latest 或符号链接。首个模型加载前保存完整候选和固定计划，默认每候选每任务 selection=25、每任务 test=70，不给平局者追加预算。候选的推理、任务、seeds、数值与 runtime 条件须一致，按以下顺序排序：

1. 较高 micro success rate。
2. 较低成功 episode 的有效首次成功步数均值。
3. 较高 global_step；仍相同则保留声明顺序。

正常完成但全失败仍是有效候选，avg_steps 为 null。模型/环境/OOM、缺失或重复 episode 等技术失败中止选点，不换 seed、不跳过候选、不更新旧 best。

`best_ckpt.json` 保存 ckpt_relpath、global_step、inference（use_ema/NFE/C）及 selection_result。普通 best 只校验指针与权重路径，加载时核对保存配置和 global_step，不要求候选证据；正式测试读取 completed selection record，核对冻结计划及 selection/test seeds 不相交，不逐个重读所有候选文件。

完整候选验真和重排名在生成选点记录时及以下离线入口执行，不启动模拟器：

```bash
python -m dexmani_policy.evaluation.selection --experiment-dir <run目录> --selection-record <selection_result.json路径>
# 完整验真后发布或重发当前 best 指针
python -m dexmani_policy.evaluation.selection --experiment-dir <run目录> --selection-record <selection_result.json路径> --publish-best
```

缺少证据会失败；先原子保存完成记录，再发布 best，发布失败保留原指针。复制实验后按相对引用寻找候选证据与 checkpoint，原请求路径保留为来源记录。

## Seed 与 held-out

每任务 seed 池来自显式 `env_runner.eval_seeds`（多任务取 task_configs）或 `dexmani_sim.DATA_DIR/eval_seeds/<task>.txt`，缺失时报错。池内整数须位于 `[0,2**32)` 且不重复，排序后由局部 `random.Random(eval.seed)` 打乱：

```text
test = shuffled_pool[:eval.episodes]
selection = shuffled_pool[eval.episodes:eval.episodes + eval.selection_episodes]
```

选点需要 N+K 容量，改变 selection 预算不改变 test 前缀；普通评测只需自身 N 或显式 seeds。有声明池时，显式 seeds 还须属于该池。环境按物理 seed reset，每个 episode 重置 Torch RNG；模型、NFE、数值路径和 GPU kernel 不同仍可能产生不同轨迹。

正式测试通过 pipeline 或以下命令创建，冻结 checkpoint、EMA/raw、NFE、C、任务、环境、seeds、录像和数值模式。普通评测始终为 `heldout_from_selection=false`，即使配置相同也不会自动成为正式测试。

```bash
bash scripts/eval/evaluate.sh <policy_name> <task_name> <run> \
  --selection-record experiments/<policy_name>/<task_name>/<run>/eval_ckpt_selector/<id>/selection_result.json \
  training.device=cuda:0
```

开发对照使用 selection_task_seeds 和独立普通评测；锁定条件后再创建选择协议。不要依据正式 test 结果重新选择 checkpoint、C 或 NFE。

## 执行长度

Policy 返回 query 起完整物理 `future_actions[B,P,D_control]`，内部完成解码、反归一化及历史/辅助维度剔除；Runner 只执行 `future_actions[0,:C]`。C 须为整数且 `1<=C<=P`，LatentFlow 的 P=H，其他策略为 H−N+1。

`eval.action_steps` 只改变消费长度，不改变训练 horizon、观测、normalizer、padding 或 Real 的 execution.action_steps。pad_after 显式固定：普通配置 7、DQ-RISE 15、LAMP/LatentFlow 0。

### LatentFlow 执行时长对照

先核对保存 dt 与环境控制周期。dt≈0.0625s 时，H=32 对应约 2s 控制周期预算，C=25 为 1.5625s，C=13 为 0.8125s；首末采样跨度为 `(帧数−1)*dt`，同步推理也影响实际查询周期。完整生成并双向解码 H 后才截取 C；C 的比较使用开发 seeds，不覆盖冻结测试，也不代表已验证闭环。

## 平面记录与统计

每个 episode 一条 `task_name、seed、success、steps、total_steps、video`。steps 为首次 raw success_condition 步数，success 为最终 hold/grace 判定；最终失败者不进入成功步数均值。

`env_runner/common/metrics.py` 统一计算：micro 为总成功数/总 episode 数，macro 为任务成功率等权均值，avg_steps 对所有成功且有有效 steps 的 episode 直接取浮点均值；另保存 per_task、总步数均值与二项 Wilson 95% 区间。该区间不表示训练 seed 方差或 macro 不确定性。

`result_details.json` 是单次评测事实记录。首个模型加载前写 request，每完成一个 episode 原子更新；完成收尾后标记 completed。失败时保留 traceback 和已完成前缀，status=failed、statistics=null；写记录/清理失败不替换主异常，磁盘上最后写入的前缀不能视为完成结果。

录像开启时，视频成功导出后才记录该 episode；缺帧、编码或写入失败使评测失败。rollout 已失败时，crash 视频导出错误作为次要异常报告。

```text
experiment/
├── eval_ckpt_selector/<id>/selection_result.json
├── eval_ckpt_selector/<id>/candidates/<id>/result_details.json
├── eval_dexsim/<id>/result_details.json
└── best_ckpt.json
```

视频在各结果目录的 videos/。记录包含源码 commit/dirty、Python/Torch/CUDA、设备与参数 dtype；dirty 标记不等于源码归档。远端同步顺序为候选事实、选择记录、best 指针。离线检查不证明闭环成功率、速度或真机安全。
