# 仿真评测机制

仿真评测衡量策略在环境交互中完成任务的能力。评测模块恢复完整策略，由仿真运行器提供观测、执行动作并记录回合结果。

## 闭环执行

每个回合从指定场景开始，重复以下过程，直到回合结束：

1. 读取最近的观测历史。
2. 生成未来动作窗口。
3. 执行配置的动作步数，并在每个控制步更新观测。
4. 根据新观测重新预测。

对 Diffusion/Flow，预测窗口决定规划范围，采样步数决定模型的迭代预算，执行前缀长度决定重新规划频率。环境控制周期须与 checkpoint 保存的数据控制周期一致。

ODE 需要完整执行训练时的动作 chunk，并将上一条实际下发目标传给下一次预测；回合中途终止时立即停止。具体承接约定见[手部动作表示](手部动作表示.md#ode从上一条指令积分生成轨迹)。

## 任务结果与候选选择

成功由环境判定，成功率表示完成任务的回合比例；平均执行步数补充描述完成效率。训练损失衡量学习目标的拟合，不能代替闭环成功率，也不能跨不同动作表示直接排名。

| 阶段 | 作用 |
| --- | --- |
| 候选选择 | 在共同的 selection 回合上比较候选，确定胜者 |
| 独立测试 | 在不重叠的 test 回合上评估胜者，报告最终成绩 |

两组回合在比较前固定，独立测试结果不反过来调整候选。候选依次按成功率、较少的平均执行步数、较大的训练步数排名。

每个候选默认使用自己的权重选择、推理步数与执行长度，也可显式统一这些设置。胜者的独立测试沿用选模时的实际设置，结果记录对应配置及回合表现。

## 比较条件

候选须使用相同任务、环境配置和控制周期。跨方法比较还应保持回合预算一致，并说明观测模态、先验来源及推理预算；策略结构可以不同。
