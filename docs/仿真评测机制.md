# 仿真评测机制

评测从 checkpoint 读取策略与环境配置。`dexmani_sim` 执行关节或末端目标，DexJoCo 执行 `action_rotvec`。两者的控制周期和观测处理都要与训练数据一致。 [dexmani_sim 配置](../dexmani_policy/configs/eval/dexmani_sim.yaml) · [DexJoCo 配置](../dexmani_policy/configs/eval/dexjoco.yaml)

使用 DexJoCo 或其 runner 子类时，训练从示教记录观测处理参数，评估以 checkpoint 中的参数核对环境。例如使用点云时，点数和用于投影的 RGB 尺寸都必须匹配。

## 运行评测

单个 checkpoint 使用 `evaluate.sh`，可加 `--video` 记录回合。比较多个 checkpoint 时用 `eval_pipeline.sh`。启动仿真前会逐个检查权重、推理步数和动作执行长度，同时核对候选的环境、任务和控制周期。所有候选在相同的选模种子上评测，胜者再用独立测试种子评测一次。 [单模型命令](../README.md#dexmani_sim)

```bash
RUN=experiments/train/dp3/multi_grasp/run01
bash scripts/eval/eval_pipeline.sh --checkpoints \
  "$RUN/checkpoints/step_00020000.pt" "$RUN/checkpoints/step_00040000.pt" \
  --seed 1024 --selection-episodes 25 --test-episodes 100
```

`dexmani_sim` 从 `dexmani_sim.DATA_DIR/eval_seeds/<task>.txt` 读取任务种子池，池大小须覆盖选模与测试回合之和。逐回合结果写入 `result_details.json`，选模结果和两组种子写入 `selection_result.json`。要复现测试回合，可把记录的测试种子传给 `evaluate.sh --seeds`。

## 闭环执行

策略用近期观测预测一段动作，执行其中 `--action-steps` 个目标后重新观测。执行步数默认取 checkpoint 的 `n_action_steps`，也可指定为不超过 `future_steps = horizon - n_obs_steps + 1` 的正整数。`--inference-steps` 控制生成这段轨迹的推理步数，DDIM 可取 2 到训练噪声步数。

## 指标与比较条件

- **成功率**是最终成功的回合占比。在 `dexmani_sim` 中，首次满足任务条件后还要通过环境的保持或宽限判定。95% Wilson 区间反映有限评测回合带来的不确定性，训练波动用多个训练种子衡量。
- **成功步数** `avg_steps` 只统计最终成功的回合。`dexmani_sim` 记录首次满足任务条件的步数，DexJoCo 记录环境确认成功的步数。候选先按成功率降序排名，平局时先取 `avg_steps` 更小者，再取训练步数更多者。
- **比较设置**固定任务、环境、种子池和各阶段回合数。权重及推理预算默认跟随 checkpoint，可用 `--weights raw` 或 `--weights ema`、`--inference-steps` 和 `--action-steps` 统一。比较多组设置时用同组选模种子，独立测试沿用胜者的设置。
- **观测采集**也会影响可比性。`dexmani_sim` 关闭录像时可用 `--skip-intermediate-observations` 跳过中间帧的完整采集，这会改变传感器随机数的消耗。横向比较应统一该选项，并报告观测模态和先验来源。
