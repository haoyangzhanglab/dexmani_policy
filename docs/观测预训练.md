# 观测预训练

观测预训练先学习场景变化或手物交互，再将编码器迁移到动作策略。AFRO 与 CordViP 的预训练不依赖示教动作标签；下游策略再利用真实动作进行模仿学习。

## 两种学习目标

| 方法 | 输入 | 核心目标 |
| --- | --- | --- |
| AFRO | 场景点云序列 | 用隐式动作解释并预测相邻场景的变化 |
| CordViP | 手部与物体点云、关节状态及接触标签 | 学习手物接触和手臂、手部的协调关系 |

## AFRO：学习场景动力学

AFRO 用点云编码器提取相邻帧特征。逆动力学模型从特征变化中提取隐式动作，前向动力学模型再利用当前特征和隐式动作预测另一时刻的特征，并同时学习正向与反向变化。

EMA 教师编码器提供缓慢变化的目标表征。学习目标同时要求预测准确、避免特征退化并减少冗余，使场景编码器能够表达时序变化。

隐式动作描述观测之间的变化，不直接等同于机器人的控制命令。

## CordViP：学习接触与协调

CordViP 分别编码手部点云、物体点云、手部状态与手臂状态，通过交叉注意力在观测窗口内交换信息。

预训练包含三类重建目标：手物接触、手臂状态和手部状态。接触标签来自手部与物体几何关系，不是实测触觉力；协调目标描述观测状态，不是未来动作。

## 迁移到动作策略

| 方法 | 迁移内容 | 下游学习方式 |
| --- | --- | --- |
| AFRO | 在线场景编码器及其输入变换 | 默认冻结场景编码器，学习状态编码与动作生成 |
| CordViP | 完整交互编码器及其输入变换 | 微调交互编码器并学习动作生成 |

动力学模型、教师分支以及接触与协调预测头仅服务于预训练，不参与下游动作生成。编码器与其输入变换共同迁移，保持表征含义一致。

## 训练命令

在已激活的 `policy` 环境、仓库根目录执行。下面的输出目录用于新实验，应尚未包含训练产物。

```bash
python -m dexmani_policy.training.pretrain.obs.afro \
  --output-dir experiments/pretrain/afro/run_01 \
  --zarr-path robot_data/pick_apple_messy.zarr --no-wandb
bash scripts/training/train.sh afro task_name=pick_apple_messy \
  initialization.encoder=experiments/pretrain/afro/run_01/encoder.pt
```

AFRO 默认冻结下游场景编码器，需要指定预训练产物；要研究从头训练，显式设置 `agent.freeze_visual=false` 并省略初始化。

CordViP 先从已有手物点云生成接触标签。输出另存为自包含 Zarr，不修改源数据：

```bash
python -m dexmani_policy.datasets.preprocess.contact_map \
  --zarr-path robot_data/pick_apple_messy.zarr \
  --output robot_data/pick_apple_messy.cordvip.zarr --num-workers 4
python -m dexmani_policy.training.pretrain.obs.cordvip \
  --output-dir experiments/pretrain/cordvip/run_01 \
  --zarr-path robot_data/pick_apple_messy.cordvip.zarr --no-wandb
bash scripts/training/train.sh cordvip task_name=pick_apple_messy \
  initialization.encoder=experiments/pretrain/cordvip/run_01/encoder.pt
```

接触生成需要 Open3D 和每帧 1024 个物体点。输出保留原有 `hoi_pcd`、手部点云配置、关节顺序、单位和 `dt`；部署仍校验真实任务与模板信息，生成器不会补造缺失元数据。原始 Zarr 含 `action` 时一并复制，供下游策略训练。

两个入口都接受配置覆盖，例如 `dataset.val_episodes=10 dataset.max_train_episodes=100`。同一数据与 `dataset.seed` 下，验证集固定；减少训练上限只减少训练回合，不移动验证回合。只有训练回合用于拟合新建的归一化参数。

## 续训与导出

```bash
python -m dexmani_policy.training.pretrain.obs.afro \
  --resume-from experiments/pretrain/afro/run_01 --no-wandb
```

CordViP 将入口换成 `dexmani_policy.training.pretrain.obs.cordvip`。恢复读取保存的配方、模型、优化器、调度器和随机状态；可调整 `--device`、`--num-workers` 等执行参数，不能通过配置覆盖改变保存的实验。`--max-updates` 限制本次运行量。日志随 checkpoint 步数回退。

正常结束或第一次中断后，目录保存用于续训的 `checkpoints/latest.pt` 和用于下游初始化的 `encoder.pt`。需要从指定 checkpoint 重新导出时：

```bash
python -m dexmani_policy.training.pretrain.obs.common \
  --checkpoint experiments/pretrain/afro/run_01/checkpoints/latest.pt \
  --output experiments/pretrain/afro/run_01/encoder.pt
```

AFRO 按 `training.num_epochs` 派生更新预算，教师在在线优化器更新前按 epoch 更新；CordViP 按 `training.loop.total_train_steps` 计更新预算。两者保留各自的验证和保存频率，导出均使用在线编码器及其输入归一化参数。

公共流程见[项目架构](项目架构.md)。预训练目标的改善是否转化为策略收益，需要通过下游[闭环评测](仿真评测机制.md)检验。
