# 观测预训练

观测预训练先学习场景变化或手物交互，再将编码器迁移到动作策略。AFRO 与 CordViP 的预训练不依赖示教动作标签；下游策略利用示教动作进行模仿学习。

## 两种学习目标

| 方法 | 输入 | 核心目标 |
| --- | --- | --- |
| AFRO | 场景点云序列 | 用隐式动作解释并预测相邻场景的变化 |
| CordViP | 手部与物体点云、关节状态及接触标签 | 学习手物接触和手臂、手部的协调关系 |

## AFRO：学习场景动力学

AFRO 用点云编码器提取相邻帧特征。逆动力学模型从特征变化中提取隐式动作，前向动力学模型结合当前特征与隐式动作预测另一时刻的特征，同时学习正向与反向变化。

EMA 教师编码器提供缓慢变化的目标表征，训练同时约束预测误差、特征退化与冗余。隐式动作描述观测之间的变化，不直接等同于机器人控制命令。

VICReg 依赖批统计，AFRO 观测预训练要求 `gradient_accumulation_steps=1`。

默认窗口为 33 帧，`frame_stride=2`，两端 padding 均为零。短于窗口的连续段没有训练窗口。复现官方尾部 padding 时可显式设置 `dataset.pad_after=7`，尾部重复帧会缩短实际帧间隔。teacher 独立初始化并冻结，EMA 在在线 optimizer 更新前执行。

## CordViP：学习接触与协调

CordViP 分别编码手部点云、物体点云、手部状态与手臂状态，通过交叉注意力在观测窗口内交换信息。

预训练包含手物接触、手臂状态和手部状态三类重建目标。`dataset.obs_horizon` 设置共用的观测窗口。协调重建读取同一时刻的完整关节状态，重建损失衡量该条件下的拟合。跨肢体预测能力需要独立实验。

`model.contact_loss_weight > 0` 时，`contact_map[T,1024]` 对应 1024 个固定物体点槽。Zarr 根属性 `data_processing.object_pointcloud.geometry_sha256` 记录共享的有序几何身份，续训须使用同一模板。混合几何导出时该值为 `null`，接触监督会拒绝这类数据。

`model.contact_loss_weight=0` 关闭接触头及标签读取，允许其他合法点数与几何变化，仍须启用至少一个协调损失。CordViP 支持按实际样本数加权的梯度累积。

仿真 HDF5 的 `object_geometry` 保存实际缩放后的有序局部点和分块边界。普通转换支持缺少该字段的历史回合。各回合模板一致时，转换器沿用 Real 的编码计算一次共享摘要。接触预处理检查点槽和几何身份后，原子发布配对的点云与标签并记录原始 Zarr 路径。CordViP 主策略从原始 Zarr 读取观测与动作。

```bash
python -m dexmani_policy.datasets.preprocess.contact_map --zarr-path datasets/task.zarr --output datasets/task.contact.zarr
python -m dexmani_policy.training.pretrain.obs.cordvip --policy-config "$POLICY_CONFIG" --zarr-path datasets/task.contact.zarr
python -m dexmani_policy.training.pretrain.obs.cordvip --zarr-path datasets/task.zarr model.contact_loss_weight=0
```

## 同源数据预算

先输出策略配方，再用同一配方生成先验并启动策略。`--policy-config` 复用任务、主 Zarr、`dataset.seed`、`dataset.val_episodes` 和 `dataset.max_train_episodes`。CordViP 启用接触时通过 `--zarr-path` 指定接触派生数据。以下以 AFRO 为例。

```bash
POLICY_CONFIG=afro-budget.yaml
SPLIT=(dataset.seed=42 dataset.val_episodes=20 dataset.max_train_episodes=100)
python -m dexmani_policy.train --config-name=afro --cfg job --resolve "${SPLIT[@]}" > "$POLICY_CONFIG"
python -m dexmani_policy.training.pretrain.obs.afro --policy-config "$POLICY_CONFIG"
python -m dexmani_policy.train --config-name=afro "${SPLIT[@]}" initialization.encoder="$ENCODER"
```

同一原始采集的连续段共用一个组。预训练更新和 affine 拟合只读取获准的训练组。验证组可用于选模，例如 VQ 的 `lookup_mse`。AFRO 和 CordViP 续训传 `--resume-from RUN`，从该目录的 `checkpoints/latest.pt` 恢复，沿用保存的 Zarr 与分组。策略加载同源先验时，分别检查其训练组和选模组是否在各自的预算内。

`encoder.pt` 保存编码器、normalizer、归一化配方和本次预训练的 `training_data`。严格预算以一个原始 Zarr 的实际路径为边界。本项目生成的接触派生使用明确记录的原始路径。独立数据或缺少 `training_data` 的初始化权重在 `prior_data` 中标记为预算未核验。

## 迁移到动作策略

**示教轨迹 → 观测预训练 → 编码器与输入变换 → 动作策略学习 → 闭环评测**

| 方法 | 迁移内容 | 下游学习方式 |
| --- | --- | --- |
| AFRO | 在线场景编码器及其输入变换 | 默认冻结场景编码器，学习状态编码与动作生成 |
| CordViP | 完整交互编码器及其输入变换 | 微调交互编码器并学习动作生成 |

动力学模型、教师分支及接触与协调预测头只服务于预训练。编码器与其输入变换共同迁移，以保持表征含义一致；预训练收益通过下游闭环任务表现检验。

当前 CordViP policy 的点云路径是逐点 MLP 后 max pooling，部署没有接触头。普通 policy 允许不同合法模板及采样实验，处理记录仅供对照；点序置换保持池化编码结果并不证明改变几何后的任务表现。

核心实现位于 [training/pretrain/obs/](../dexmani_policy/training/pretrain/obs/)，公共流程见[项目架构](项目架构.md)。
