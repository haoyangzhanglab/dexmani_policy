# AFRO 与 CordViP 观测预训练

预训练代码位于 `dexmani_policy/training/pretrain/obs/`，启动入口位于 `scripts/pretrain/`。预训练导出编码器权重，下游复用项目已有的 PolicyTrainer、checkpoint 和仿真评测入口。

| 默认配方 | AFRO | CordViP |
| --- | --- | --- |
| 预训练输入 | scene XYZ，无需 action 或 joint_state | hand/object XYZ、joint_state、contact labels，无需 action |
| 预训练窗口 | 33 帧，padding=0/7；stride=2 后为 17 帧 | 跨度12，padding=3/5，读取前4帧 |
| 编码器 | PointNet64 | 两个 PointNet1024、两个 Linear64、四个官方 Transformer |
| 下游 H/O/A | 16/2/8 | 12/4/6 |
| 下游更新 | 冻结 visual，训练 StateEncoder64 和 decoder | 整个 encoder finetune，初始化后复制 EMA |
| 预训练预算 / batch | 301 epochs / 128 | 100000 updates / 256 |
| 下游预算 | 100000 updates | 100000 updates |

数据使用世界坐标系、米制 XYZ，关节和动作顺序为 arm7+hand12。点云只读取前三列；AFRO 和 hand 点云的点数可变，CordViP 预训练的 object 点数固定为1024，与 contact head 的输出一致。下游读取实际 `action[t]`，不做官方机器人转换脚本中的 +2 平移。

## 训练入口

在仓库根目录执行。示例共用一个 split，使同源预训练和策略训练使用相同的训练/验证回合。

```bash
TASK_NAME=pick_apple_messy
DATA_PATH="robot_data/${TASK_NAME}.zarr"
SPLIT_PATH="robot_data/${TASK_NAME}_split.json"

conda run --no-capture-output -n policy python -m dexmani_policy.datasets.common.split \
  --zarr-path "$DATA_PATH" --output "$SPLIT_PATH" --seed 42 --val-ratio 0.1

bash scripts/pretrain/afro.sh \
  --output-dir "experiments/pretrain/obs/afro/${TASK_NAME}/run01" \
  task_name="$TASK_NAME" dataset.zarr_path="$DATA_PATH" dataset.split_manifest="$SPLIT_PATH"

conda run --no-capture-output -n policy python -m dexmani_policy.training.pretrain.obs.contact_map \
  --zarr-path "$DATA_PATH" --output "robot_data/${TASK_NAME}.contact.zarr"

bash scripts/pretrain/cordvip.sh \
  --output-dir "experiments/pretrain/obs/cordvip/${TASK_NAME}/run01" \
  task_name="$TASK_NAME" dataset.zarr_path="$DATA_PATH" dataset.split_manifest="$SPLIT_PATH" \
  dataset.contact_map_path="robot_data/${TASK_NAME}.contact.zarr"
```

两个 shell 入口只负责定位仓库、选择 `policy` 环境并原样转发参数；也可直接运行对应 Python module。短跑时加 `--max-updates 2 dataloader.batch_size=2 dataloader.num_workers=0`，完整实验去掉执行上限。输出目录使用新目录。

Contact 离线生成一次，训练时读取；只有生成阶段需要 Open3D。标签按原始 XYZ 和 KNN=30 法向量计算，gamma=1、theta=10，不对标签做归一化。当前仍使用独立 contact Zarr，绑定原数据的 episode 边界、可用身份信息及 `meta/observation_geometry_json`；生成后不要重排 object 点或修改原轨迹。

输出目录包含：

- `encoder.pt`：仅包含 `encoder_state`，保存 CPU 上的 raw encoder 权重。
- `resume.pt`：完整预训练模型（含 teacher/heads 和 normalizer）、optimizer、scheduler、RNG、epoch、global_step 及训练配置。
- `config.yaml`、`metrics.jsonl`：参数与训练日志。

下游直接以 `strict=True` 加载 `encoder_state`，旧版带额外元数据的导出也可直接读取。下游 normalizer 按自己的训练集重新拟合。两阶段使用同源数据时共用 split；使用独立语料时自行安排 held-out 划分，权重加载不比较来源、split 或几何元数据。

```bash
bash scripts/training/train.sh afro task_name="$TASK_NAME" \
  dataset.zarr_path="$DATA_PATH" dataset.split_manifest="$SPLIT_PATH" \
  agent.pretrained_path="experiments/pretrain/obs/afro/${TASK_NAME}/run01/encoder.pt" \
  hydra.run.dir="experiments/afro/${TASK_NAME}/run01"

bash scripts/training/train.sh cordvip task_name="$TASK_NAME" \
  dataset.zarr_path="$DATA_PATH" dataset.split_manifest="$SPLIT_PATH" \
  agent.pretrained_path="experiments/pretrain/obs/cordvip/${TASK_NAME}/run01/encoder.pt" \
  hydra.run.dir="experiments/cordvip/${TASK_NAME}/run01"
```

Matched scratch 保持模型、数据、split、batch 和预算一致：AFRO 设置 `agent.pretrained_path=null agent.freeze_visual=false`，CordViP 设置 `agent.pretrained_path=null`。下游短跑使用 `+max_updates=2`；不要为短跑改变总训练预算。

## 续训与评测

```bash
bash scripts/pretrain/afro.sh \
  --resume-from "experiments/pretrain/obs/afro/${TASK_NAME}/run01/resume.pt" \
  --output-dir "experiments/pretrain/obs/afro/${TASK_NAME}/run02"

bash scripts/pretrain/cordvip.sh \
  --resume-from "experiments/pretrain/obs/cordvip/${TASK_NAME}/run01/resume.pt" \
  --output-dir "experiments/pretrain/obs/cordvip/${TASK_NAME}/run02"

bash scripts/training/train.sh afro \
  +resume_from="experiments/afro/${TASK_NAME}/run01" \
  hydra.run.dir="experiments/afro/${TASK_NAME}/run02"
```

预训练续用保存的 split、normalizer、优化器和调度器状态。epoch 中途保存时，从该 epoch 开头重读；AFRO teacher momentum 继续使用保存的 epoch。`--max-updates` 只限制本次执行。完整策略 checkpoint 恢复推理不需要原预训练权重或 contact 文件。

正式评测沿用 `bash scripts/eval/eval_pipeline.sh METHOD TASK_NAME RUN_NAME`。跨策略比较应统一任务、场景随机化、seed 划分、回合数、成功标准和 checkpoint 选择规则；H/O/A、推理步数与 raw/EMA 选择按各方法配置报告。短跑可用 `bash scripts/eval/evaluate.sh afro "$TASK_NAME" run01 --checkpoint latest 'eval.seeds=[42]'`，短跑 checkpoint 不参与正式 milestone 选点。

## 保留的方法细节

- AFRO 默认 stride=2（官方代码），`model.frame_stride=4` 对应论文设置的消融；latent action 为实际网络使用的16维。teacher 独立初始化，在 backward 后、optimizer 前按 `m(e)=0.996+0.004×clamp(e,0,300)/300` 更新。
- AFRO 保留双向预测和 VICReg 的25/25/1权重。预训练 accumulation=1；小 batch 梯度累积不能替代 VICReg 的大 batch 统计。
- CordViP 保留官方64维 state embedding、自定义 LayerNorm 的 sample std，以及 contact/arm/hand 三个 mean MSE。协调目标为最后观测时刻的归一化 joint_state。
- 两个下游使用项目的 ConditionalUNet1D 和 Diffusion，宽度为 [512,1024,2048]，默认 sample/x0、100训练步/10推理步。CordViP 预训练只保存 raw encoder；下游 EMA 从已初始化的策略复制。
- normalizer 只统计真实训练帧，不统计验证回合或 padding。机器人维度、采样频率和实验预算采用本项目设置。

算法参考：[AFRO](https://github.com/KolaKivy/AFRO)、[CordViP](https://github.com/xuanxuanzzzii/cordvip)。具体移植位置保留在相关模块的文件头。
