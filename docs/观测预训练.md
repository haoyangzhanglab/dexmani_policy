# 观测预训练

观测预训练先学习场景变化或手物交互，再将编码器迁移到动作策略。AFRO 与 CordViP 的预训练不依赖示教动作标签；下游策略利用示教动作进行模仿学习。

## 两种学习目标

| 方法 | 输入 | 核心目标 |
| --- | --- | --- |
| AFRO | 场景点云序列 | 用隐式动作解释并预测相邻场景的变化 |
| CordViP | 手部与物体点云、关节状态及接触标签 | 学习手物接触和手臂、手部的协调关系 |

## AFRO：学习场景动力学

AFRO 用点云编码器提取相邻帧特征。逆动力学模型从特征变化中提取隐式动作，前向动力学模型结合当前特征与隐式动作预测另一时刻的特征，同时学习正向与反向变化。

EMA 教师编码器提供缓慢变化的目标表征，训练同时约束预测误差、特征退化与冗余。隐式动作描述观测之间的变化，不直接等同于机器人控制命令。

## CordViP：学习接触与协调

CordViP 分别编码手部点云、物体点云、手部状态与手臂状态，通过交叉注意力在观测窗口内交换信息。

预训练包含手物接触、手臂状态和手部状态三类重建目标。接触标签由手物几何关系离线生成，协调目标来自观测状态；两者分别描述接触关系与身体协调。

`model.contact_loss_weight > 0` 时读取 `contact_map[T,1024]`，物体点云必须有 1024 个槽，且数据集记录明确共享的 `data_processing.object_pointcloud.geometry_sha256`。该摘要表示有序 `points_local` 与 `offsets` 的数值身份，不包含显示名称；混合几何导出的摘要为 `null`，不能用于固定槽接触头。完整续训会核对 checkpoint 与当前数据的摘要。

设置 `model.contact_loss_weight=0` 后，不读取或校验 `contact_map`，也不构造接触头，允许合法的其他点数与几何变化；仍须至少启用一个协调损失。数据集直接引用同一 loss weight，没有单独开关。逐帧标签生成本身支持任意合法点数，并保留来源与摘要（包括 `null`）；可选 `action` 仅透传，其动作宽度由实际策略消费者检查：

```bash
python -m dexmani_policy.datasets.preprocess.contact_map --zarr-path datasets/task.zarr --output datasets/task.contact.zarr
python -m dexmani_policy.training.pretrain.obs.cordvip --zarr-path datasets/task.contact.zarr
python -m dexmani_policy.training.pretrain.obs.cordvip --zarr-path datasets/task.zarr model.contact_loss_weight=0
```

训练、验证和 `max_train_episodes` 按原始采集分组，单个采集的多个连续段不会泄漏到两个集合；采样窗口不跨段。

## 迁移到动作策略

**示教轨迹 → 观测预训练 → 编码器与输入变换 → 动作策略学习 → 闭环评测**

| 方法 | 迁移内容 | 下游学习方式 |
| --- | --- | --- |
| AFRO | 在线场景编码器及其输入变换 | 默认冻结场景编码器，学习状态编码与动作生成 |
| CordViP | 完整交互编码器及其输入变换 | 微调交互编码器并学习动作生成 |

动力学模型、教师分支及接触与协调预测头只服务于预训练。编码器与其输入变换共同迁移，以保持表征含义一致；预训练收益通过下游闭环任务表现检验。

当前 CordViP policy 的点云路径是逐点 MLP 后 max pooling，部署没有接触头。普通 policy 允许不同合法模板及采样实验，处理记录仅供对照；点序置换保持池化编码结果并不证明改变几何后的任务表现。

核心实现位于 [training/pretrain/obs/](../dexmani_policy/training/pretrain/obs/)，公共流程见[项目架构](项目架构.md)。
