# AFRO 与 CordViP 观测预训练

预训练代码位于 `dexmani_policy/training/pretrain/obs/`，启动入口位于 `scripts/pretrain/`。预训练同时导出编码器权重及其输入归一化参数，下游复用项目已有的 PolicyTrainer、checkpoint 和仿真评测入口。

`afro.py` 和 `cordvip.py` 各自组装 Dataset、DataLoader 与模型，并维护方法自身的训练循环；同目录 `common.py` 只共享运行配置加载、产物保存和验证指标汇总。两个 Dataset 共用 ObservationPretrainDataset 管理划分和验证视图，采样及样本组装仍由各自实现。Dataset 只持存储、索引和 `training` 标志，不保存 normalizer 或回指训练 Dataset。新训练在组装处用 `training/common/data.py::fit_normalizer()` 从实际 train 索引分块拟合，并将 affine 交给模型持有；续训随完整模型状态一次恢复，不重新拟合或向 Dataset 回填统计量。

| 默认配方 | AFRO | CordViP |
| --- | --- | --- |
| 预训练输入 | scene XYZ，无需 action 或 joint_state | hand/object XYZ、joint_state、contact labels，无需 action |
| 预训练窗口 | 33 帧，padding=0/7；stride=2 后为 17 帧 | 跨度12，padding=3/5，读取前4帧 |
| 编码器 | PointNet64 | 两个 PointNet1024、两个 Linear64、四个官方 Transformer |
| 下游 H/O/A | 16/2/8 | 12/4/6 |
| 下游更新 | 冻结 visual，训练 StateEncoder64 和 decoder | 整个 encoder finetune，初始化后复制 EMA |
| 预训练预算 / batch | 301 epochs / 128 | 100000 updates / 256 |
| 下游预算 | 100000 updates | 100000 updates |

数据使用世界坐标系、米制 XYZ，关节和动作顺序为 arm7+hand12。点云只读取前三列；AFRO 在完整窗口的 source rows 上应用 stride 后读取 XYZ，减少进入 batch 搬运和归一化的帧数；AFRO 和 hand 点云的点数可变，CordViP 预训练的 object 点数固定为1024，与 contact head 的输出一致。下游读取实际 `action[t]`，不做官方机器人转换脚本中的 +2 平移。

## 训练入口

在仓库根目录执行。CordViP 流程为：原始 Zarr → 派生 Zarr → 观测预训练 → 主策略训练 → 选点与测试。示例显式共用一个最多100训练回合的 split；预训练自身默认不限制回合数，可以独立设置语料与划分。

```bash
TASK_NAME=pick_apple_messy
DATA_PATH="robot_data/${TASK_NAME}.zarr"
CORDVIP_PATH="robot_data/${TASK_NAME}.cordvip.zarr"
SPLIT_PATH="robot_data/${TASK_NAME}_split.json"

conda run --no-capture-output -n policy python -m dexmani_policy.datasets.tools.contact_map \
  --zarr-path "$DATA_PATH" --output "$CORDVIP_PATH"

conda run --no-capture-output -n policy python -m dexmani_policy.datasets.split \
  --zarr-path "$DATA_PATH" --output "$SPLIT_PATH" --seed 42 --val-ratio 0.1 --max-train-episodes 100

bash scripts/pretrain/afro.sh \
  --output-dir "experiments/pretrain/obs/afro/${TASK_NAME}/run01" \
  task_name="$TASK_NAME" dataset.zarr_path="$DATA_PATH" dataset.split_manifest="$SPLIT_PATH"

bash scripts/pretrain/cordvip.sh \
  --output-dir "experiments/pretrain/obs/cordvip/${TASK_NAME}/run01" \
  task_name="$TASK_NAME" dataset.zarr_path="$CORDVIP_PATH" dataset.split_manifest="$SPLIT_PATH"
```

两个 shell 入口只负责定位仓库、选择 `policy` 环境并原样转发参数；也可直接运行对应 Python module。`--config` 使用固定 `dexmani_policy/configs/` 下的名称或相对子路径，如 `pretrain/obs/afro`（可带 `.yaml`）；这是入口约定，不提供配置安全隔离保证。短跑时加 `--max-updates 2 dataloader.batch_size=2 dataloader.num_workers=0`，完整实验去掉执行上限。输出目录使用新目录。

Contact 离线生成一次，只有生成阶段需要 Open3D，导入 Dataset 或查看工具帮助不会加载它。算法来源为 CordViP commit `ad6d441abe7b0480cf79b0311db266965c1313b6` 的 `train_policy/script/contact_map.py`，本地使用分块 NumPy 几何计算和原生 Zarr。派生 Zarr 按块复制 hand/object 点云、joint_state、episode_ends 和存在时的 action，保留帧序、点序与必要属性，不复制 RGB 图像等无关数据。原始 Zarr 保持不变；不要求来源 ID 或几何配方元数据。

标签按原始世界坐标米制 XYZ 和 KNN=30 法向量计算，gamma=1、theta=10；保留 float64 接触计算、float32 标签。预训练的观测和标签由同一个 SequenceSampler 使用相同 padding，标签不归一化，也不进入 obs。下游只读取 sensor_modalities 和 action。生成输出前检查 object 为 [T,1024,C>=3]、hand 为 [T,N>0,C>=3]、joint_state 为 [T,19]。窗口、padding 与 stride 是可调整的默认配方；stride 仍由 model.frame_stride 配置，由入口传给 Dataset，构建时确认正整数且采样后至少两帧，CordViP 的 dataset/model 观测长度须一致；CordViP 通过 SequenceSampler 的 fields 切片及 field_horizons 读取窗口前 N 帧，点云只取 XYZ，joint_state 和 contact labels 使用相同 rows；Dataset 负责组装 obs/contact_map。

`training/pretrain/obs/common.py` 的 `save_run()` 和 `restore_run()` 统一保存与恢复模型、normalizer、optimizer、scheduler、global_step 和 RNG；AFRO/CordViP 分别维护训练循环、epoch 计算及方法专属更新。

输出目录包含：

- `encoder.pt`：包含 `encoder_state` 和 `normalizer_state`，分别保存 detached CPU raw encoder 权重和 FP32 归一化 buffers。
- `resume.pt`：完整预训练模型（含 teacher/heads 和 normalizer）、optimizer、scheduler、RNG、global_step 及训练配置。epoch 由 global_step 和实际 batch 数推导。
- `config.yaml`、`metrics.jsonl`：参数与训练日志。

新训练中 Policy 的 `initialize_training()` 只读取一次预训练包，strict 加载编码器并返回 `normalizer_state`。Trainer 在组装处继承这些完整字段，仅从 train 索引拟合其余字段，检查导入 affine 的形状和目标 dtype 有限性后，将最终 normalizer 直接交给 Policy，再创建 EMA。验证 Dataset 独立持有验证采样索引并关闭训练增强，不回访训练 Dataset；训练、验证和推理使用模型持有的同一 affine。

| 场景 | 最终统计来源 |
| --- | --- |
| 从头训练 | 全部使用下游训练集统计 |
| AFRO 预训练初始化 | point_cloud 来自预训练；joint_state/action 来自下游 |
| CordViP 预训练初始化 | hand_pointcloud、object_pointcloud、joint_state 来自预训练；action 来自下游 |
| 完整策略续训、评测与部署 | 全部使用策略 checkpoint 中的最终统计，不访问 encoder.pt |

冻结与微调均继承预训练统计。预训练包不含 action；identity 字段没有 affine buffers。先加载包内 affine，只对其余字段拟合下游统计；继承字段不再经历无效的拟合和覆盖。训练/验证划分及必要 shape 检查保留；完整有限值扫描通过 `datasets.tools.check_data --zarr-path INPUT` 显式执行，构造时不额外读取全部数据。

使用约定：预训练和下游的观测字段定义、坐标单位及归一化类型一致，不进行跨模式转换或元数据比较。两阶段使用同源数据时共用 split；使用独立语料时自行安排 held-out 划分。

```bash
bash scripts/training/train.sh afro task_name="$TASK_NAME" \
  zarr_path="$DATA_PATH" dataset.split_manifest="$SPLIT_PATH" \
  initialization.encoder="experiments/pretrain/obs/afro/${TASK_NAME}/run01/encoder.pt" \
  hydra.run.dir="experiments/afro/${TASK_NAME}/run01"

bash scripts/training/train.sh cordvip task_name="$TASK_NAME" \
  zarr_path="$CORDVIP_PATH" dataset.split_manifest="$SPLIT_PATH" \
  initialization.encoder="experiments/pretrain/obs/cordvip/${TASK_NAME}/run01/encoder.pt" \
  hydra.run.dir="experiments/cordvip/${TASK_NAME}/run01"
```

Matched scratch 保持模型、数据、split、batch 和预算一致：AFRO 设置 `initialization.encoder=null agent.freeze_visual=false`，CordViP 设置 `initialization.encoder=null`。下游短跑使用 `+max_updates=2`；不要为短跑改变总训练预算。

## 续训与评测

```bash
bash scripts/pretrain/afro.sh \
  --resume-from "experiments/pretrain/obs/afro/${TASK_NAME}/run01/resume.pt" \
  --device cuda:0 --num-workers 4

bash scripts/pretrain/cordvip.sh \
  --resume-from "experiments/pretrain/obs/cordvip/${TASK_NAME}/run01/resume.pt" \
  --device cuda:0 --num-workers 4

python -m dexmani_policy.training.common.resume \
  --run "experiments/afro/${TASK_NAME}/run01" --device cuda:0 --num-workers 4

# 周期恢复点可显式导出，不需要打开训练数据。
python -m dexmani_policy.training.pretrain.obs.common --method afro \
  --checkpoint "experiments/pretrain/obs/afro/${TASK_NAME}/run01/resume.pt" \
  --output "experiments/pretrain/obs/afro/${TASK_NAME}/run01/encoder.pt"
```

AFRO 默认每20个 epoch 保存 `resume.pt`；CordViP 默认每10000次 optimizer updates 保存，可在 fresh 配方中用 `training.save_every_updates` 调整。周期保存只写完整恢复状态，不重复导出编码器。正常结束、短跑结束和 SIGINT/SIGTERM 可处理中断时保存恢复状态并导出一次 `encoder.pt`，也可使用显式导出命令。两种预训练不参与主策略五节点选点。

主策略和两个观测预训练入口共用 `training/common/signals.py` 管理 handler 的注册与恢复，各入口保留自身的停止处理。收到停止信号后完成当前 optimizer update，随后保存退出，不启动新的验证。验证开始前和 batch 间检查停止标志，中断返回未完成结果，不记录部分平均值。验证通过 try/finally 恢复训练 RNG 和原模型模式，覆盖 DataLoader 创建、模型前向、中断和异常。验证集在训练入口仅创建一次，之后复用采样索引；完整验证指标按各 batch 的窗口数加权，末尾小 batch 不会被放大；AFRO 的 VICReg 仍在各 batch 内计算统计量。

预训练续用 checkpoint 保存的配置、split、normalizer、优化器和调度器状态，在原目录继续追加日志；日志晚于恢复点时先保留完整备份，再去掉超出 step 的尾部。global_step 表示已完成 optimizer updates。以完整 epoch 的 batch 数 B 和 accumulation A 计算 U=ceil(B/A)，再由 divmod(global_step,U) 得到逻辑 epoch 和 epoch 内 update；从 update×A 的绝对 batch 下标继续。前缀在采样索引层跳过，不重新读取 Dataset；排列使用 seed+epoch，采样与 worker 初始化的 Generator 分离。AFRO teacher momentum 使用当前 update 所属逻辑 epoch。worker 随机增强不保证逐位重放。`--max-updates` 只限制本次执行，不改变总预算或学习率调度。resume 不接受配置覆盖或新输出目录，仅接受显式 `--device`、`--num-workers`、`--log-interval`、`--max-updates`、`--no-wandb`，数据搬家时用 `--zarr-path` 并校对已保存 split。完整策略 checkpoint 恢复推理不需要原 encoder.pt 或派生 Zarr。

主策略默认 training.seed=42、dataset.val_ratio=0.1、最多100个训练回合，不足时不补齐；显式 manifest 超过上限会报错。主策略在20/40/60/80/100% updates 保存，评测 CLI 默认 `--seed 1024`、25回合选点和100回合独立测试，模型实例和桌高随机化均开启。运行：

```bash
bash scripts/eval/eval_pipeline.sh \
  --checkpoints "experiments/cordvip/$TASK_NAME/run01/checkpoints/<a>.pt" \
                "experiments/cordvip/$TASK_NAME/run01/checkpoints/<b>.pt" \
  --selection-episodes 25 --test-episodes 100 \
  --output-dir "experiments/cordvip/$TASK_NAME/run01/eval_ckpt_selector/<new-comparison>"
```

上述预算要求实际任务 seed pool 至少有125个不同 seed。跨策略比较还应保持相同任务、环境条件、成功标准和回合时限；H/O/A、推理步数与 raw/EMA 按方法配置报告。短跑可用 `bash scripts/eval/evaluate.sh --checkpoint "experiments/afro/$TASK_NAME/run01/checkpoints/latest.pt" --seeds 42`；显式候选子集按实际预算报告。

## 保留的方法细节

CordViP 的表征组件位于 `agents/obs_encoder/interaction/correspondence/`：`contact_coordination_encoder.py` 中的 `ContactCoordinationEncoder` 对应论文 III-C 的接触与协调特征提取，`cross_attention_transformer.py` 中的 `CrossAttentionTransformer` 对应其中的交叉注意力 Transformer。命名参考[官方论文](https://arxiv.org/html/2502.08449v2#S3.SS3)；编码器返回手部点云、物体点云、手部状态和手臂状态四组特征，由预训练模块和下游 Policy 分别消费。

`CrossAttentionTransformer(query, context)` 以 context 编码结果作为 memory，输出保留 query 的时间轴。编码器的 `output_dims` 与 `out_dim` 声明各路及总特征宽度，预训练头和下游动作头据此计算连接维度。预训练的三个 MLP 头复用 `agents/modules.py::build_mlp`，与 PointNet、Uni3D、Sparse3D 和 HandStateMLP 共用构造逻辑；各调用方显式保留自己的激活及归一化配方，此处使用 ReLU、无 LayerNorm、输出层无激活。

- AFRO 默认 stride=2（官方代码），`model.frame_stride=4` 对应论文设置的消融；latent action 为实际网络使用的16维。teacher 独立初始化，在 backward 后、optimizer 前按 `m(e)=0.996+0.004×min(e,300)/300` 更新，`e` 为非负逻辑 epoch。
- AFRO 保留双向预测和 VICReg 的25/25/1权重。预训练 accumulation=1；小 batch 梯度累积不能替代 VICReg 的大 batch 统计。
- CordViP 保留官方64维 state embedding、自定义 LayerNorm 的 sample std，以及 contact/arm/hand 三个 mean MSE。协调目标为最后观测时刻的归一化 joint_state。
- 两个下游使用项目的 ConditionalUNet1D 和 Diffusion，宽度为 [512,1024,2048]，默认 sample/x0、100训练步/10推理步。CordViP 导出 raw encoder 及其输入统计；下游 EMA 从权重与最终统计均已初始化的策略复制。
- normalizer 统计全部真实训练帧，不随 stride 缩减，不统计验证回合或 padding；limits 只计算 min/max，Gaussian 只计算 mean/std，模型只保存 scale/offset。机器人维度、采样频率和实验预算采用本项目设置。

算法参考：[AFRO](https://github.com/KolaKivy/AFRO)、[CordViP](https://github.com/xuanxuanzzzii/cordvip)。具体移植位置保留在相关模块的文件头。

两个预训练循环沿用日志间隔记录 loss、LR 和 `train/step_time`。step_time 为包含取数等待、排除日志与保存开销的 update 墙钟时间；不记录分段等待或吞吐量，也不能据此推算精确 GPU kernel 时间。
