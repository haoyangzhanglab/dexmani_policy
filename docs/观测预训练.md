# AFRO 与 CordViP 观测预训练

预训练代码位于 `dexmani_policy/training/pretrain/obs/`，启动入口位于 `scripts/pretrain/`。预训练同时导出编码器权重及其输入归一化参数，下游复用项目已有的 PolicyTrainer、checkpoint 和仿真评测入口。

`afro.py` 和 `cordvip.py` 分别定义 `AFRO`、`CordViP` 及方法入口；`common.py::train(method, argv=None)` 顺序完成初始化、恢复及训练循环，管理周期保存、编码器导出及验证。`load_run(method, argv=None)` 仅解析 CLI、配置并读取 checkpoint，返回 cfg、checkpoint、max_updates；train 恢复所需状态后释放 checkpoint，并在 logger 初始化及配置记录之后恢复 RNG。AFRO 的 `ForwardDynamics` 与损失保留在方法文件中，DiTBlock 复用公共实现。两个 Dataset 共用 `datasets/pretrain/__init__.py` 中的 ObservationPretrainDataset 管理划分和验证视图，采样及样本组装仍由各自实现。Dataset 只持存储和索引，不保存 normalizer 或回指训练 Dataset；训练调用方只创建一次验证视图。新训练在组装处用 `training/common/data.py::fit_normalizer()` 从实际 train 索引分块拟合，并将 affine 交给模型持有；续训随完整模型状态一次恢复，不重新拟合或向 Dataset 回填统计量。

| 默认配方 | AFRO | CordViP |
| --- | --- | --- |
| 预训练输入 | scene XYZ，无需 action 或 joint_state | hand/object XYZ、joint_state、contact labels，无需 action |
| 预训练窗口 | 33 帧，padding=0/7；stride=2 后为 17 帧 | 跨度12，padding=3/5，读取前4帧 |
| 编码器 | PointNet64 | 两个 PointNet1024、两个 Linear64、四个官方 Transformer |
| 下游 H/O/A | 16/2/8 | 12/4/6 |
| 下游更新 | 冻结 visual，训练 StateEncoder64 和 decoder | 整个 encoder finetune，初始化后复制 EMA |
| 预训练预算 / batch | 301 epochs / 128 | 100000 updates / 256 |
| 下游预算 | 100000 updates | 100000 updates |

数据使用世界坐标系、米制 XYZ，关节和动作顺序为 arm7+hand12。点云只读取前三列；AFRO 在完整窗口的 source rows 上应用 stride 后读取 XYZ，减少进入 batch 搬运和归一化的帧数；AFRO 和 hand 点云的点数可变，CordViP 预训练的 object 点数固定为1024，与 contact head 的输出一致。下游读取实际 `action[t]`，不做官方机器人转换脚本中的 +2 平移。

## 训练入口

在仓库根目录执行。CordViP 流程为：原始 Zarr → 派生 Zarr → 观测预训练 → 主策略训练 → 选点与测试。两个预训练默认 `dataset.seed=42`、`dataset.max_train_episodes=null`、`dataset.val_episodes=0`，使用全部 episodes 训练，不构造验证 Dataset/DataLoader。预训练与下游独立设置语料、数据 seed 和数量参数。

```bash
TASK_NAME=pick_apple_messy
DATA_PATH="robot_data/${TASK_NAME}.zarr"
CORDVIP_PATH="robot_data/${TASK_NAME}.cordvip.zarr"

conda run --no-capture-output -n policy python -m dexmani_policy.datasets.preprocess.contact_map \
  --zarr-path "$DATA_PATH" --output "$CORDVIP_PATH"

bash scripts/pretrain/afro.sh \
  --output-dir "experiments/pretrain/obs/afro/${TASK_NAME}/run01" \
  task_name="$TASK_NAME" zarr_path="$DATA_PATH"

bash scripts/pretrain/cordvip.sh \
  --output-dir "experiments/pretrain/obs/cordvip/${TASK_NAME}/run01" \
  task_name="$TASK_NAME" zarr_path="$CORDVIP_PATH"
```

需要预训练验证时显式追加 `dataset.max_train_episodes=100 dataset.val_episodes=20`：预留 V 条后，训练数为 `min(M,N−V)`；同一排列依次选择 train、val、unused。150 条得到 100/20/30，110 条得到 90/20/0；V 必须小于总数，不缩小验证数量。仅设 `dataset.val_episodes=20` 时，其余 episodes 全部用于训练。验证只作诊断，结束时导出最终在线 encoder，不选 best 或默认导出 AFRO teacher。

两个 shell 入口只负责定位仓库、选择 `policy` 环境并原样转发参数；也可直接运行对应 Python module。`--config` 使用固定 `dexmani_policy/configs/` 下的名称或相对子路径，如 `pretrain/obs/afro`（可带 `.yaml`）；这是入口约定，不提供配置安全隔离保证。短跑时加 `--max-updates 2 dataloader.batch_size=2 dataloader.num_workers=0`，完整实验去掉执行上限。输出目录使用新目录。

Contact 离线生成一次，只有生成阶段需要 Open3D，导入 Dataset 或查看工具帮助不会加载它。算法来源为 CordViP commit `ad6d441abe7b0480cf79b0311db266965c1313b6` 的 `train_policy/script/contact_map.py`，本地使用分块 NumPy 几何计算和原生 Zarr。派生 Zarr 按块保存 hand/object XYZ FP32、joint_state[T,19] FP32、contact_map[T,1024] FP32、int64 episode_ends 和源数据存在时的 action[T,19] FP32。仅保留已有 dt、hand_pointcloud_config 根 attrs，不复制数组 attrs、颜色或其他列。帧序、点序和原 action 对齐不变；无 action 可预训练，主策略需要真实 action。新 XYZ 和旧 C≥3 点云均按前三列消费。原始 Zarr 保持不变；不要求来源 ID 或几何配方元数据。

离线标签预处理的 Open3D 依赖可用 `python -m pip install -e ".[preprocess]"` 安装。默认 `--num-workers 1` 在当前进程顺序计算；批量生成可追加 `--num-workers 4` 并设置环境变量 `OMP_NUM_THREADS=1`，通过 spawn 子进程并行计算各帧标签，避免继承已初始化的 OpenMP 线程状态。输出仍按原始帧序写入。

标签按原始世界坐标米制 XYZ 和 KNN=30 法向量计算，gamma=1、theta=10；法线与几何使用实际输出的 FP32 XYZ，距离累积保留 float64，最终标签为 float32。预训练的观测和标签由同一个 SequenceSampler 使用相同 padding，标签不归一化，也不进入 obs。下游只读取 sensor_modalities 和 action。生成输出前检查 object 为 [T,1024,C>=3]、hand 为 [T,N>0,C>=3]、joint_state 为 [T,19]。窗口、padding 与 stride 是可调整的默认配方；stride 由 dataset.frame_stride 配置，构建时确认正整数且采样后至少两帧，CordViP 从 Dataset 的实际 obs_horizon 构造模型观测长度；CordViP 通过 SequenceSampler 的 fields 切片及 field_horizons 读取窗口前 N 帧，点云只取 XYZ，joint_state 和 contact labels 使用相同 rows；Dataset 负责组装 obs/contact_map。

`training/pretrain/obs/common.py` 保存与恢复模型、normalizer、optimizer、scheduler、global_step 和 RNG；`restore_run()` 严格原地加载模型及优化器状态，训练入口在 logger/config 初始化后、进入循环前恢复 RNG；同一 train 作用域在恢复后显式释放原 checkpoint payload，再初始化 logger、恢复 RNG 并进入循环。两种方法共用训练循环和 epoch 计算，AFRO 在 optimizer 前执行 teacher 更新。optimizer 使用原有参数顺序，并保存 `param_names`；恢复要求 checkpoint 包含匹配的参数名顺序，避免状态按位置错配。训练参数使用 FP32；主策略可选 BF16 只作 autocast，不维护历史低精度 master parameters 的原精度续训轨迹。续训信任本项目自产 checkpoint，strict 加载完整模型状态后不再重复扫描 affine 数值；strict 只检查状态结构，不能证明数值有限。下游导入 `encoder.pt` 时仍检查 affine 的形状、有限性和可逆性。

模型统一使用 `encoder` 和 `normalizer` 成员。独立导出只接收 `--checkpoint`、`--output`，直接提取恢复文件中的两组状态及保存的输入归一化配方，无需构造模型或访问数据。`encoder.pt` 由下游编码器与 normalizer 严格加载。

输出目录包含：

- `encoder.pt`：包含 `encoder_state`、`normalizer_state` 和小型 `normalization` 字典，分别保存 detached CPU 在线 encoder 权重、FP32 affine buffers 及对应输入字段的归一化模式。
- `resume.pt`：完整预训练模型（含 teacher/heads 和 normalizer）、optimizer、scheduler、RNG、global_step 及训练配置。epoch 由 global_step 和实际 batch 数推导。
- `config.yaml`、`metrics.jsonl`：参数与训练日志。

新训练中 Trainer 的 fresh 初始化分支只读取一次预训练包，strict 加载 AFRO visual 或 CordViP encoder，并继承归属输入字段的 affine 或 identity，仅从 train 源帧拟合新字段。检查导入 affine 的形状、有限性和可逆性后，将最终 normalizer 直接交给 Policy，再创建 EMA。观测预训练的 holdout 视图共享只读 Store，独立持有验证采样索引，不能用于拟合；训练、验证和推理使用模型持有的同一 affine。主策略 Dataset 只构造训练 sampler，不提供验证视图。

| 场景 | 最终统计来源 |
| --- | --- |
| 从头训练 | 全部使用下游训练集统计 |
| AFRO 预训练初始化 | point_cloud 来自预训练；joint_state/action 来自下游 |
| CordViP 预训练初始化 | hand_pointcloud、object_pointcloud、joint_state 来自预训练；action 来自下游 |
| 完整策略续训、评测与部署 | 全部使用策略 checkpoint 中的最终统计，不访问 encoder.pt |

冻结与微调均继承预训练输入归一化，包括 identity。AFRO 固定覆盖 point_cloud；CordViP 固定覆盖 hand_pointcloud、object_pointcloud、joint_state。归属字段没有 scale/offset 双方 buffers 表示 identity，不能按下游默认值重新拟合；只有一方缺失时严格加载失败。包中的 `normalization` 记录原模式并覆盖下游对应有效配置，已有 affine 直接沿用；新字段才按下游配置拟合。构造时不额外读取全部数据。

使用约定：预训练和下游保持相同的字段定义、坐标及单位；用户无需手工使两份 YAML 的归一化模式相同。两阶段可使用独立语料、seed 和数量参数，不比较数据清单。如果验证集用于评价整个训练流程，实验的数据准备应让预训练也避开这些 held-out 数据。

```bash
bash scripts/training/train.sh afro task_name="$TASK_NAME" \
  zarr_path="$DATA_PATH" \
  initialization.encoder="experiments/pretrain/obs/afro/${TASK_NAME}/run01/encoder.pt" \
  hydra.run.dir="experiments/afro/${TASK_NAME}/run01"

bash scripts/training/train.sh cordvip task_name="$TASK_NAME" \
  zarr_path="$CORDVIP_PATH" \
  initialization.encoder="experiments/pretrain/obs/cordvip/${TASK_NAME}/run01/encoder.pt" \
  hydra.run.dir="experiments/cordvip/${TASK_NAME}/run01"
```

Matched scratch 保持模型、数据、split、batch 和预算一致：AFRO 设置 `initialization.encoder=null agent.freeze_visual=false`，CordViP 设置 `initialization.encoder=null`。下游短跑使用 `+max_updates=2`；不要为短跑改变总训练预算。

## 续训与评测

```bash
bash scripts/pretrain/afro.sh \
  --resume-from "experiments/pretrain/obs/afro/${TASK_NAME}/run01/resume.pt" \
  --device cuda:0 --num-workers 4

bash scripts/pretrain/cordvip.sh \
  --resume-from "experiments/pretrain/obs/cordvip/${TASK_NAME}/run01/resume.pt" \
  --device cuda:0 --num-workers 4

python -m dexmani_policy.training.common.resume \
  --run "experiments/afro/${TASK_NAME}/run01" --device cuda:0 --num-workers 4

# 从完整恢复点重新导出，不需要打开训练数据。
python -m dexmani_policy.training.pretrain.obs.common \
  --checkpoint "experiments/pretrain/obs/afro/${TASK_NAME}/run01/resume.pt" \
  --output "experiments/pretrain/obs/afro/${TASK_NAME}/run01/encoder.pt"
```

AFRO 默认每20个 epoch 保存 `resume.pt`；CordViP 默认每10000次 optimizer updates 保存，可在 fresh 配方中用 `training.save_every_updates` 调整。周期保存只写完整恢复状态，不重复导出编码器。正常结束、短跑结束和 SIGINT/SIGTERM 可处理中断时保存恢复状态并导出一次 `encoder.pt`，也可使用显式导出命令。两种预训练不参与主策略五节点选点。

AFRO 仅在 fresh 按 `num_epochs * batches_per_epoch` 推导并保存更新总预算，resume 使用保存的 `total_train_steps`。已完成预算的 resume 直接返回，不重写恢复文件、encoder 或日志；需要重新导出时使用上面的独立命令。fresh 在读取数据和构造模型前检查已有训练产物。每个 run 由一个进程写入，文件通过同目录临时文件加 `os.replace` 替换；不提供并发排他、断电持久性或 `resume.pt`/`encoder.pt` 两文件事务。

主策略和两个观测预训练入口共用 `training/common/` 的 `training_signal_handlers` 管理 handler 的注册与恢复，各入口保留自身的停止处理。首次停止信号后完成当前 optimizer update，随后保存退出，不启动新的验证；第二次信号允许立即退出并放弃保存。预训练入口统一调用 `get_validation_dataset()`，由 Dataset 判断验证 episodes 是否存在：没有时返回 `None`，不创建验证 sampler 或 loader；返回验证视图后才检查 `training.val_every_epochs` 并输出验证窗口数。选中的验证 episodes 无合法窗口时明确报错，不回退训练集。验证开始前和 batch 间检查停止标志，中断返回未完成结果，不记录部分平均值。验证使用 eval/no_grad，不更新 AFRO teacher，通过 try/finally 恢复训练 RNG 和原模型模式，覆盖 DataLoader 创建、模型前向、中断和异常。完整验证指标按各 batch 的窗口数加权，末尾小 batch 不会被放大；AFRO 的 VICReg 仍在各 batch 内计算统计量。

预训练续用 checkpoint 保存的配置、normalizer、优化器和调度器状态，在原目录继续追加日志；对未改变顺序与内容的 Zarr，用保存的 `dataset.seed`、`max_train_episodes` 和 `val_episodes` 重建 mask。历史日志原样保留并直接追加；只在末行缺换行时补换行，允许重复或较小 step，不解析、截断或备份历史。global_step 表示已完成 optimizer updates。以完整 epoch 的 batch 数 B 和 accumulation A 计算 U=ceil(B/A)，再由 divmod(global_step,U) 得到逻辑 epoch 和 epoch 内 update；从 update×A 的绝对 batch 下标继续。前缀在采样索引层跳过，不重新读取 Dataset；排列使用 training.seed+epoch，采样与 worker 初始化的 Generator 分离。AFRO teacher momentum 使用当前 update 所属逻辑 epoch。worker 随机增强不保证逐位重放。`--max-updates` 只限制本次执行，不改变总预算或学习率调度。resume 不接受配置覆盖或新输出目录，仅接受显式 `--device`、`--num-workers`、`--log-interval`、`--max-updates`、`--no-wandb`，数据搬家时用 `--zarr-path`；改变数据内容或顺序应作为新实验。完整策略 checkpoint 恢复推理不需要原 encoder.pt 或派生 Zarr。

主策略默认 training.seed=42、dataset.seed=42、dataset.val_episodes=0、dataset.max_train_episodes=null，使用全部 episodes。这是相较原 100 条上限的训练配方变化；对照实验显式设置上限，resume 沿用保存值。可显式保留 val episodes，但主策略标注为留出但未验证。主策略在20/40/60/80/100% updates 保存，评测 CLI 默认 `--seed 1024`、25回合选点和100回合独立测试，模型实例和桌高随机化均开启。运行：

```bash
bash scripts/eval/eval_pipeline.sh \
  --checkpoints "experiments/cordvip/$TASK_NAME/run01/checkpoints/<a>.pt" \
                "experiments/cordvip/$TASK_NAME/run01/checkpoints/<b>.pt" \
  --selection-episodes 25 --test-episodes 100 \
  --output-dir "experiments/cordvip/$TASK_NAME/run01/eval_ckpt_selector/<new-comparison>"
```

上述预算要求实际任务 seed pool 至少有125个不同 seed。跨策略比较还应保持相同任务、环境条件、成功标准和回合时限；H/O/A、推理步数与 raw/EMA 按方法配置报告。短跑可用 `bash scripts/eval/evaluate.sh --checkpoint "experiments/afro/$TASK_NAME/run01/checkpoints/latest.pt" --seeds 42`；显式候选子集按实际预算报告。

## 保留的方法细节

CordViP 的表征组件集中在 `agents/obs_encoder/interaction/correspondence.py`：`ContactCoordinationEncoder` 对应论文 III-C 的接触与协调特征提取，`CrossAttentionTransformer` 对应其中的交叉注意力 Transformer。命名参考[官方论文](https://arxiv.org/html/2502.08449v2#S3.SS3)；编码器返回手部点云、物体点云、手部状态和手臂状态四组特征，由预训练模块和下游 Policy 分别消费。

`CrossAttentionTransformer(query, context)` 以 context 编码结果作为 memory，输出保留 query 的时间轴。编码器的 `output_dims` 与 `out_dim` 声明各路及总特征宽度，预训练头和下游动作头据此计算连接维度。预训练的三个 MLP 头复用 `agents/modules.py::build_mlp`，与 PointNet、Uni3D、Sparse3D 和 HandStateMLP 共用构造逻辑；各调用方显式保留自己的激活及归一化配方，此处使用 ReLU、无 LayerNorm、输出层无激活。

CordViP 保留原版 sample std、根号外 epsilon 和克隆初始化。源实现的注意力参考 [taxpose](https://github.com/r-pad/taxpose) 与 [DCP](https://github.com/WangYueFt/dcp/blob/master/model.py)。

- AFRO 默认 stride=2（官方代码），`dataset.frame_stride=4` 对应论文设置的消融；latent action 为实际网络使用的16维。teacher 独立初始化，在 backward 后、optimizer 前按 `m(e)=0.996+0.004×min(e,300)/300` 更新，`e` 为非负逻辑 epoch。
- AFRO 正反方向合批执行 IDM/FDM，再分别计算 VICReg，保留25/25/1权重及原噪声采样顺序。预训练 accumulation=1，由入口固定；小 batch 梯度累积不能替代 VICReg 的大 batch 统计。
- CordViP 保留官方64维 state embedding、自定义 LayerNorm 的 sample std，以及 contact/arm/hand 三个 mean MSE。协调目标为最后观测时刻的归一化 joint_state。
- CordViP 的1024个接触输出槽沿用来源的稳定点序假设；全局 PointNet 本身对点排列不变。重建时 cross-attention 可读取目标模态，不能将其解释为严格遮挡预测。本次保留这些来源假设。
- 两个下游使用项目的 ConditionalUNet1D 和 Diffusion，宽度为 [512,1024,2048]，默认 sample/x0、100训练步/10推理步。CordViP 导出 raw encoder 及其输入统计；下游 EMA 从权重与最终统计均已初始化的策略复制。
- 新 normalizer 统计全部真实 train 源帧，不随 stride、窗口重叠或 padding 改变，不统计 val、unused、随机增强或随机点抽样；identity 和继承字段不读取统计。limits 只计算 min/max，Gaussian 只计算 mean/std，模型只保存 scale/offset。机器人维度、采样频率和实验预算采用本项目设置。

算法参考：[AFRO](https://github.com/KolaKivy/AFRO)、[CordViP](https://github.com/xuanxuanzzzii/cordvip)。代码文件头保留来源 commit。AFRO 对应 `afro_workspace/policy/afro.py`、`AFRO_Pretrain.py` 和 `afro_workspace/model/transformer/DiT1D.py`；CordViP 对应 `train_policy/policy/CordViP/CordViP/CordViP/policy/CordViP_pretrain.py`。

共享预训练循环在本次调用的首个实际 update、日志间隔及本次已知末步记录 loss、LR 和 `train/step_time`。仅记录日志的 update 计时：从首次 `next(iterator)` 前开始，覆盖取数等待、设备传输、全部 micro-batch 前向/反向、梯度处理及 optimizer/scheduler 更新，AFRO 还包含 teacher 更新。CUDA 在起止读时钟前同步当前设备，CPU 不调用 CUDA API。每组 detached loss 的有限性在设备端合并，只在 update 边界、teacher/optimizer/scheduler 前判定一次；较早 micro-batch 的非有限值也会终止本组更新，不保存半步状态。不额外逐参数扫描梯度，不保证检测 loss 有限但梯度非有限的情况。不计入 iterator 构造、后续日志归约/写入、验证与保存；不记录分段等待或吞吐量，也不能据此推算精确 GPU kernel 时间。
