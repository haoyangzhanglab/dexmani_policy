# AFRO 与 CordViP 观测预训练

实现范围是原生仿真的 `观测预训练 → encoder.pt → arm7+hand12 策略 → 完整 checkpoint 恢复 → SimRunner`。本文记录数据配方、使用命令、实现差异和验收结果。这是方法迁移，不是论文成功率复现；当前没有真机 CordViP 感知/部署入口。

## 数据与默认配方

- AFRO 预训练只需要 `point_cloud[T,1024,C>=3]`；不读 action 或 joint_state。dataset 固定原始窗口33帧、padding=0/7，默认 stride=2，得到 17 帧、16 个 transitions。
- CordViP 预训练只需要 `hand_pointcloud`、`object_pointcloud`（各 1024 点）、`joint_state[T,19]` 和独立 contact sidecar。dataset 固定窗口跨度12、padding=3/5，只读前4帧，contact 使用同一组 source rows。关节顺序始终为 arm7、hand12。
- XYZ 是世界坐标米制。RGB 不消费；contact 在原始 XYZ 上计算，不归一化标签。normalizer 使用全部真实训练帧，每帧一次；验证/排除 episodes、窗口 padding 不参与统计。同源两阶段共用 split；跨源缺少身份信息时程序明确报告无法自动证明无 held-out 重叠。
- CordViP 读取 `meta/observation_geometry_json` 的模板、role、part、scale 和点数布局。sidecar 绑定 source/episode/trial 身份（若有）、episode 边界、几何配方和算法版本。不要重排 object 点、做 FPS/dropout 或在生成标签后修改数据；全任务物体共享 1024 点。
- 下游标签是实际 `action[t]`，观测为 `obs[t]_before_action[t]`。不做 +2 状态平移。返回完整 `future_actions[B,H-O+1,19]`，由 runner 执行前 A 步。

| 配方 | AFRO | CordViP |
| --- | --- | --- |
| 下游 H/O/A、padding | 16/2/8，1/7 | 12/4/6，3/5；覆盖 `n_action_steps=8` 后 pad_after=7 |
| 观测 | scene XYZ + joint19 | hand/object XYZ + joint19 |
| encoder | PointNet64 + StateEncoder64 | 两个 PointNet1024、两个 Linear64、四个官方 Transformer |
| 全局条件宽度 | 256 | 8704，按 timestep 拼接四模态后展平 |
| U-Net | [512,1024,2048]，time embedding128 | [512,1024,2048]，time embedding64 |
| 下游更新 | 只冻结 visual；state/decoder 可训练 | 整个 encoder finetune；初始化后再复制 EMA |
| diffusion | 两者均为 DDIM，100 train timesteps / 10 inference steps，sample/x0、clip=true |
| AdamW | 两者均为 lr=1e-4、betas=(0.95,0.999)、eps=1e-8；所有可训练参数 wd=1e-6，无 grad clipping |
| batch 默认值 | 128 | 256 |
| 预算 | 预训练 301 epochs；下游 100000 updates | 预训练/下游均 100000 updates |
| warmup updates | 预训练5，下游0 | 预训练/下游500 |

默认 FP32/eager、无点云增强。真实数据 dt 会保留在导出记录中，不重采样。本次数据 dt≈0.0625s：AFRO stride=2 为约0.125s；AFRO/CordViP 执行块分别约0.5/0.375s。CordViP 原设置5Hz，不能把相同步数当成相同物理时长。

## 四步使用

需要本项目 `policy` 环境和原生 Zarr。只有生成 contact 时需要 Open3D（本次验证版本0.19.0）；普通预训练、下游训练和推理无需导入 Open3D、PyTorch3D 或官方参考仓库。以下命令使用 batch=2、每次最多2次 optimizer update，适合先验证自己的数据。输出目录必须未使用；完整实验由使用者明确去掉执行上限并选择 batch。

**1. 共享 split。**

```bash
conda activate policy
TASK_NAME=pick_apple_messy
DATA_PATH="robot_data/${TASK_NAME}.zarr"
SPLIT_PATH="/tmp/${TASK_NAME}_obs_split.json"
python -m dexmani_policy.datasets.common.split \
  --zarr-path "$DATA_PATH" --output "$SPLIT_PATH" --seed 42 --val-ratio 0.1
```

**2. 观测预训练与导出。** CordViP 的 contact 工具完整写完后才发布 sidecar，已有输出会报错。

```bash
python -m dexmani_policy.training.pretrain.obs.afro \
  --output-dir "experiments/pretrain/obs/afro/${TASK_NAME}/run01" --max-updates 2 \
  task_name="$TASK_NAME" dataset.zarr_path="$DATA_PATH" dataset.split_manifest="$SPLIT_PATH" \
  dataloader.batch_size=2 dataloader.num_workers=2

python -m dexmani_policy.training.pretrain.obs.contact_map \
  --zarr-path "$DATA_PATH" --output "robot_data/${TASK_NAME}.contact.zarr"
python -m dexmani_policy.training.pretrain.obs.cordvip \
  --output-dir "experiments/pretrain/obs/cordvip/${TASK_NAME}/run01" --max-updates 2 \
  task_name="$TASK_NAME" dataset.zarr_path="$DATA_PATH" dataset.split_manifest="$SPLIT_PATH" \
  dataset.contact_map_path="robot_data/${TASK_NAME}.contact.zarr" \
  dataloader.batch_size=2 dataloader.num_workers=2
```

每个输出目录包含 resolved `config.yaml`、`metrics.jsonl`、`encoder.pt` 和 `resume.pt`。`encoder.pt` 是可用 `weights_only=True` 读取的 CPU raw encoder、方法/结构/SHA、pretrain config/affine/split/source/dt 与几何信息；下游只加载 encoder weights，fresh normalizer 仍按下游训练集拟合。`resume.pt` 另含完整模型、teacher/heads、optimizer、scheduler、RNG、epoch/global_step。

**3. 下游训练。** 也可用 `bash scripts/training/train.sh afro|cordvip` 传同样 overrides。

```bash
python -m dexmani_policy.train --config-name=afro task_name="$TASK_NAME" \
  dataset.zarr_path="$DATA_PATH" dataset.split_manifest="$SPLIT_PATH" \
  agent.pretrained_path="experiments/pretrain/obs/afro/${TASK_NAME}/run01/encoder.pt" \
  dataloader.batch_size=2 dataloader.num_workers=2 workspace.wandb_cfg=null \
  hydra.run.dir="experiments/afro/${TASK_NAME}/run01" +max_updates=2
python -m dexmani_policy.train --config-name=cordvip task_name="$TASK_NAME" \
  dataset.zarr_path="$DATA_PATH" dataset.split_manifest="$SPLIT_PATH" \
  agent.pretrained_path="experiments/pretrain/obs/cordvip/${TASK_NAME}/run01/encoder.pt" \
  dataloader.batch_size=2 dataloader.num_workers=2 workspace.wandb_cfg=null \
  hydra.run.dir="experiments/cordvip/${TASK_NAME}/run01" +max_updates=2
```

Matched scratch 使用相同模型、输入、split、batch 和预算，AFRO 改为 `agent.pretrained_path=null agent.freeze_visual=false`，CordViP 改为 `agent.pretrained_path=null`，并换新输出目录。路径写错会显式失败；AFRO fresh frozen 且没有权重也会报错。不要用默认 RGB/窄 U-Net 的 DP3 代替 matched scratch。

**4. 短跑推理与仿真。** 此处 seed=42 是普通开发回合，不作为冻结 held-out 测试。

```bash
bash scripts/eval/evaluate.sh afro "$TASK_NAME" run01 --checkpoint latest 'eval.seeds=[42]'
bash scripts/eval/evaluate.sh cordvip "$TASK_NAME" run01 --checkpoint latest 'eval.seeds=[42]'
```

两个配置默认固定物体实例和桌高。仍需核对 simulator 实际 `env.get_observation_geometry()` 与保存的 `observation_geometry`：关闭模型随机化并不保证 scale 与数据相同，见下方实测差异。正式完整实验沿用现有 `bash scripts/eval/eval_pipeline.sh METHOD TASK_NAME RUN_NAME` 的 milestone 选点及冻结测试；两步 checkpoint 没有完整 milestone 集合，不能用它伪造正式评测。

## 恢复与内存

以下命令继续上述运行，每次再执行最多2个 updates。省略 `--output-dir` 时使用保存的 task_name 生成本次运行目录。预训练在 epoch 边界恢复：完成的 epoch 从下一 epoch 开始；epoch 中途保存会从该 epoch 开头重读，不承诺逐 batch 重放。AFRO teacher momentum 使用保存的 epoch；验证 forward 不更新 teacher。下游使用现有 PolicyTrainer 恢复语义。

```bash
python -m dexmani_policy.training.pretrain.obs.afro \
  --resume-from "experiments/pretrain/obs/afro/${TASK_NAME}/run01/resume.pt" \
  --output-dir "experiments/pretrain/obs/afro/${TASK_NAME}/run02" --max-updates 2
python -m dexmani_policy.training.pretrain.obs.cordvip \
  --resume-from "experiments/pretrain/obs/cordvip/${TASK_NAME}/run01/resume.pt" \
  --output-dir "experiments/pretrain/obs/cordvip/${TASK_NAME}/run02" --max-updates 2
python -m dexmani_policy.train --config-name=afro \
  +resume_from="experiments/afro/${TASK_NAME}/run01" agent.pretrained_path=null \
  workspace.wandb_cfg=null hydra.run.dir="experiments/afro/${TASK_NAME}/run02" +max_updates=2
python -m dexmani_policy.train --config-name=cordvip \
  +resume_from="experiments/cordvip/${TASK_NAME}/run01" agent.pretrained_path=null \
  workspace.wandb_cfg=null hydra.run.dir="experiments/cordvip/${TASK_NAME}/run02" +max_updates=2
```

恢复复用保存的 split/affine/optimizer/scheduler。当前 AFRO FDM 已删除不参与 forward 的 `pred_norm` 参数，完整预训练 resume 必须与当前模型一致；含该参数的早期 resume 不做转换或过滤，需重新预训练。encoder 导出与下游策略权重布局不受影响。`--max-updates`/`+max_updates` 只限制本次执行，不能把 `training.loop.total_train_steps` 改为2。下游完整 checkpoint 可以在移除数据、contact、预训练文件和参考仓库后恢复/推理；续训仍需要数据。freeze 从保存的构造配置恢复，不依赖 state_dict 保存 requires_grad。

优先显式降低 batch，不缩小 PointNet/Transformer/U-Net 或采样窗口。AFRO 预训练只允许 accumulation=1：VICReg 的小 batch 累积不等价于大 batch。CordViP 可设置 `training.loop.gradient_accumulation_steps` 累积三个 MSE，遵循现有 loader 的尾组检查；混合 microbatch 大小时需调整 batch 或显式 `dataloader.drop_last=true`。这属于记录在 config 中的配方变更，不是自动回退。

## 来源与实现差异

开始实施时 HEAD 为 `5ba4c2a0ab745d0b0cf09b222ea434dc7236e75e`，相对任务书基线 `874090b5c4ea9e3d5b50e7e317772d0185dd06d0` 仅新增两份任务文档，没有回退已有工作。

- [AFRO 固定版本](https://github.com/KolaKivy/AFRO/tree/283024a49e2c14bc030debf15383a4e7ee73836d)：移植 feature DiT、IDM/VICReg/teacher 活跃计算，保留 MIT 许可及 Qiwei Liang 归属。
- [CordViP 固定版本](https://github.com/xuanxuanzzzii/cordvip/tree/ad6d441abe7b0480cf79b0311db266965c1313b6)：移植 PointROEncoder 活跃 PointNet 路径、原 Transformer/自定义 LayerNorm、三 heads/loss、contact 数学。保留 MIT 许可及 Aureleo、taxpose/DCP、Holo-Dex 的上游归属。许可在 `dexmani_policy/licenses/`，移植文件头列出原路径和改动。
- 本地复用 PointNet、StateEncoder、ConditionalUNet1D、Diffusion、ReplayBuffer、SequenceSampler、split/normalizer、PolicyTrainer、checkpoint 和评测。PointNet 新增 `pooling="max"` 供两方法使用，旧方法仍默认 amax；新增预训练循环集中于 `training/pretrain/obs/`。

| 分歧 | 本实现选择 |
| --- | --- |
| AFRO 论文 stride4、运行代码 stride2 | 默认2；`model.frame_stride=4` 为显式消融，原始跨度仍33 |
| AFRO YAML latent32、实际网络16 | 固定16；未搬运失效字段 |
| AFRO teacher 的 deepcopy 被注释 | 独立初始化；backward 后、optimizer 前更新，m(e)=0.996+0.004×clamp(e,0,300)/300 |
| AFRO 论文300epochs/betas0.9，代码301/0.95 | 预训练301、betas=(0.95,0.999)；下游100000 updates 是原生实验预算 |
| CordViP 论文 state embedding16 | 保留实际64；LayerNorm 使用 sample std 和 `(std+eps)` |
| CordViP 论文描述 action sequence 协调 | 保留最后观测时刻的归一化 joint_state，contact/arm/hand 三个独立 mean MSE 再求和 |
| CordViP 论文 noise target、发布配置 sample | 默认 sample/x0；A=6 依据论文表/README，A=8 需显式覆盖 |
| CordViP 官方22维、转换脚本 +2 | 同权重先验22维，再适配 arm7+hand12；下游只读实际 action[t] |
| 官方预训练维护 EMA、导出 raw | 导出 raw，省去不影响 loss/导出的预训练 EMA；下游 EMA 复制已初始化模型 |
| 官方全 buffer normalizer | 改为 train-only 全真实帧统计；下游 fresh 重新拟合自己的训练集 |
| 机器人/频率/预算/输入 | 保留原生19维、真实 dt；CordViP 的完整模型几何是独立输入优势，不把它归因于预训练 |

## 已执行验证（2026-10-28）

环境：RTX4090 24GB，Python3.10.20，Torch2.4.1+cu124，diffusers0.27.2，timm1.0.19，Open3D0.19.0。GPU 与多 worker 实验在 sandbox 外执行，`OMP_NUM_THREADS=4 MKL_NUM_THREADS=4`；全部数值验收 FP32/eager。

| 验收 | 实际结果 |
| --- | --- |
| 官方同权重 PointNet64/1024，含 max ties | 输出、输入梯度、参数梯度最大绝对误差均0 |
| AFRO 默认 AdaLN-Zero 和打开 gate 两种状态 | loss、六项 VICReg、teacher 误差0；输入梯度≤1.17e-9、参数梯度≤1.20e-7；N=1/7 VICReg 误差0 |
| 复用 U-Net，两种完整默认宽度及条件宽度 | 输出误差0；输入/条件/参数梯度误差≤1e-7 |
| CordViP 官方22维与原生19维 | encoder 输出、三个 MSE 与总 loss 误差0；最终复核输入梯度≤8.15e-10、参数梯度≤9.32e-9；batch 隔离误差0、attention 沿时间轴 |
| contact 原逐点函数 vs 分块向量化 | float64 最大绝对误差2.23e-16以内；Open3D normals 完全一致；加权最小点不同于欧氏最近点的例子通过 |
| 实现期间回归测试（测试目录已清理） | 11 passed：恢复目录任务名/防覆盖、真实帧统计、短 episode、RGB NaN 不消费、padding/source rows、contact 点序/边界、worker、teacher 验证不更新、缺权重/scratch、失败标签不发布 |
| 实际数据有界预训练/下游 | 两方法各2次更新，再恢复2次到 step4；全部默认网络宽度，batch2；无非有限 loss/梯度 |
| 生命周期 | AFRO 仅 visual 冻结且训练后不变，state 更新；CordViP encoder 更新、初始化 raw/EMA 相同；两者 optimizer 无漏项/重复，统一 wd；恢复不调用 fit_field |
| 独立恢复 | 生命周期脚本禁止读取 checkpoint 之外的权重及任何 Zarr；strict restore 及固定 RNG 预测一致（首轮另做过物理移走文件验证）；动作形状分别[1,15,19]、[1,9,19]且为有限物理 rad |
| 非零 epoch / worker | AFRO 单窗口训练 epoch2→3，teacher 与 m(epoch2) 的 pre-optimizer 公式逐元素相同，301-update 总预算不变；两方法 workers=2 实际训练/导出通过 |
| 仿真 | 原 evaluate CLI 各完成一个240-step回合；CordViP 又在与训练完全相同的固定几何下完成240-step回合；均为seed42、success=false |
| 包与旧入口 | wheel 构建/安装成功；从 `/tmp` 加载四份配置与两份许可；阻断 Open3D/PyTorch3D/官方包导入后训练/策略 imports 通过；config-only smoke 覆盖 afro/cordvip/dp3 |

真实 fixture 来自 `robot_data/pick_apple_messy.zarr` 的 episodes 0/2/4（179/189/182帧，共550帧），前两段训练、第三段验证；AFRO view 没有 state/action，CordViP view 没有 action，policy view 保留实际动作。固定 hand 模板、apple1/plate0，scale=1.25/0.9、object 点数211/813。contact 实际生成全部550行。AFRO 318个训练窗口、159 batches/epoch，scheduler 总预算47859；CordViP 362窗口、181 batches/epoch，总预算100000；两种下游也始终保留100000预算。预训练最初两步 loss：AFRO 121.0491→119.1821，CordViP 1.4131→1.5121；这些短段数值不说明性能。

普通模拟器固定模式使用 apple scale1.3、点数225/799，属于不同点槽位配方。补验通过 `env.reinit_object` 显式采用 checkpoint 记录的 model_id/user_scale 后，再运行原 `SimRunner.run_episode`；结束时完整 geometry 字典与训练记录相等。这是对本机既有 simulator API 的验收，不增加环境适配层。
