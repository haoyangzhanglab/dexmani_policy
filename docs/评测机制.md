## 1. 评测体系总览

### 完整数据流

```
CLI 参数解析 (policy_name/task_name/exp_name)
  → 定位实验目录
  → 加载 config.yaml + OmegaConf overrides 合并
  → validate_eval_config (action_key 归一化 + horizon 边界校验)
  → set_seed (Python/CUDA 确定性)
  → build_eval_components
      ├── hydra.utils.instantiate(cfg.agent) → agent (未加载权重)
      ├── inject_faas_into_agent → FAASHandMapper 绑定
      ├── hydra.utils.instantiate(cfg.env_runner) → env_runner
      └── CheckpointStore(exp_dir/checkpoints)

evaluate_checkpoint_robotwin():
  ├── 解析 checkpoint 路径:
  │     ├── "20pct".."100pct" → discover_milestone_checkpoints() 匹配
  │     ├── "best" → best_ckpt.json → best.pt symlink (fallback)
  │     ├── "latest" → checkpoint_store.resolve_path("latest")
  │     └── 直接路径 → Path
  ├── load_ckpt_for_inference(agent, checkpoint_store, ckpt_path, use_ema)
  │     ├── checkpoint_store.load → TrainCheckpoint dataclass
  │     ├── train_params 逐字段校验 (n_obs_steps/action_dim/horizon/action_key)
  │     ├── FAAS 一致性校验 (ckpt use_faas vs agent use_faas)
  │     ├── EMA 选择 (use_ema 且 ema_model_state 存在则用 EMA，否则 model_state)
  │     ├── fix_state_dict (去 _orig_mod. 和 module. 前缀)
  │     └── agent.load_state_dict(strict=True) + normalizer.is_fitted(['action']) 终末校验
  ├── agent.to(device) + agent.eval()
  │
  ├── 确定性种子选择:
  │     ├── all_seeds = list(env_runner.get_seed_list())
  │     ├── rng = random.Random(eval_seed); rng.shuffle(all_seeds)
  │     └── eval_seeds = all_seeds[:n_total]
  │
  └── env_runner.run(agent, denoise_timesteps, eval_episodes)
        ├── make_env() → 动态导入 dexmani_sim 环境类
        └── while len(success_list) < eval_episodes:
              └── run_one_episode(agent, env, seed, denoise_timesteps)
                    ├── env.reset(seed=seed) → 初始 obs
                    ├── BaseRunner.reset() → 清空环形缓冲 + blender
                    ├── update_obs(obs_0) → 写入环形缓冲
                    └── 循环 (直到 done/truncated):
                          ├── get_obs_batch(device)
                          │     ├── get_stacked_obs → 环形缓冲时间有序切片
                          │     └── dict_apply(torch) + unsqueeze(0) batch 维
                          ├── get_action_chunk(obs_batch, agent, denoise_timesteps)
                          │     ├── [TaskTextSimRunner 覆写: 注入 task_text]
                          │     ├── agent.predict_action(obs_dict)
                          │     │     ├── _validate_obs_dict
                          │     │     ├── _convert_obs_to_faas (19D→39D, 幂等)
                          │     │     ├── _build_cond → preprocess → obs_encoder
                          │     │     └── predict_action_from_cond(cond)
                          │     │           ├── 零模板 (B, horizon, action_dim)
                          │     │           ├── action_decoder.predict_action (迭代去噪)
                          │     │           ├── unnormalize
                          │     │           ├── FAAS inverse_transform (39D→19D)
                          │     │           └── 切分: control_action[1:9] + tail[9:16]
                          │     └── [ChunkOverlapBlender 若有: 指数加权融合]
                          └── for i in range(n_action_steps):
                                ├── env.step(action_chunk[i])
                                ├── update_obs → 下一帧写入环形缓冲
                                ├── 检测 info['success_condition'] (用于 avg_steps)
                                └── 检测 info['success'] (用于 success_rate)
                    → 返回 (episode_success, task_done_step)
              ├── 收集 success_list / episode_details / videos (默认录制，--no-videos 禁用)
              └── clear_cache_freq=25: 定期 close+重建 env 防 GPU 泄漏

  汇总: success_rate / avg_steps (仅成功) / avg_steps_all (全部)
  输出: _result.txt (RoboTwin 格式) + result_details.json
```

### 训练 vs 评测的关键差异表

| 维度 | 训练 (train.py) | 评测 (eval_best_ckpt.py) |
|------|-----------------|-------------------|
| **入口框架** | `@hydra.main` Hydra 全栈 | Hydra-free CLI，手动 `OmegaConf.load` |
| **autograd** | 启用，`loss.backward()` | `@torch.no_grad()` 全局禁用 |
| **model mode** | `model.train()` | `model.eval()` (BN 切换 / dropout 关闭) |
| **数据来源** | Dataset (Zarr → ReplayBuffer → SequenceSampler) | Env (实时仿真交互) |
| **数据增强** | 5+1 种增强器 (Color/Coord/Noise/Dropout) | 无 (仅观测归一化) |
| **modality_dropout** | 由 `self.training` 门控 | 自动跳过 |
| **action 来源** | GT action (zarr 预录数据) | 模型预测 + 迭代去噪 |
| **action 生成路径** | `compute_loss`: GT actions 加噪 → model 预测 target → MSE | `predict_action`: 纯噪声 → 迭代去噪 → unnormalize |
| **扩散步数** | 训练 100 步 (DDPM forward noising) | 推理默认 10 步 (DDIM 确定性 / Euler ODE) |
| **FAAS 转换** | Dataset 产出已转 FAAS 数据 | `predict_action` I/O 边界实时转换 |
| **ACT 时序融合** | 不存在 | `ChunkOverlapBlender` 指数加权融合 chunk 重叠区 |
| **Normalizer** | 训练前全量 replay buffer 拟合 | 从 checkpoint state_dict 恢复 |
| **EMA** | 维护 EMA twin model | 可选使用 EMA 权重加载 |
| **优化器** | AdamW + scheduler + grad_accum | 无 |
| **梯度裁剪** | `clip_grad_norm_` | 无 |
| **NaN 检测** | 两层防护 (loss NaN + grad NaN) | 无 |
| **checkpoint 保存** | 里程碑 20/40/60/80/100% | 不保存模型相关文件 |
| **输出** | loss curve + 里程碑 checkpoint + wall time | success_rate + avg_steps + 视频 (默认录制，--no-videos 禁用) + metrics.json |
| **多卡** | DDP (mp.spawn, 最多 4 卡) | 严格单卡 |
| **compile** | 多数启用 (mode='reduce-overhead' 或 'default') | 随 agent 继承 (SAT=default) |
| **seed** | config 指定，DDP 下 rank 差异化增强 | 默认 training.seed + 1024，可 CLI 覆盖 |

## 2. 入口层 (eval_best_ckpt.py)

### 两阶段评测工作流

评测采用两阶段工作流，由三个脚本协作完成：

```bash
# 一键管道（推荐）：串联 select → eval → demo
bash scripts/eval/eval_pipeline.sh dp3 pour <exp_dir>

# 或分步执行：
# 阶段 1: 选出最优 checkpoint（自适应淘汰赛）
bash scripts/eval/select_best_ckpt.sh dp3 pour <exp_dir>

# 阶段 2: 在全部 eval seed 上评测最终成功率
bash scripts/eval/eval_best_ckpt.sh dp3 pour <exp_dir>
```

- `eval_pipeline.sh` (→ 三个 Python 入口串联): 一键完成 select → eval → demo，全部使用 config 默认参数
- `select_best_ckpt.sh` (→ `select_best_ckpt.py`): 在少量 seed(25) 上对所有里程碑 checkpoint 做自适应淘汰赛
- `eval_best_ckpt.sh` (→ `eval_best_ckpt.py`): 在全部 eval seed(~100) 上评测指定 checkpoint，输出 RoboTwin 兼容格式

### CLI 参数和配置加载流程

`eval_best_ckpt.py` 是离线评测入口，设计为 **Hydra-free 独立脚本**。

**命令行接口**：

```bash
python dexmani_policy/eval_best_ckpt.py \
    --policy-name=dp3 --task-name=pour --exp-name=<timestamp> \
    [--ckpt-tag best] [--episodes 100] [--denoise-steps 10] [--no-ema] \
    [overrides...]
```

关键参数:

| 参数 | 默认 | 说明 |
|------|------|------|
| `--policy-name` | (必需) | 策略名 |
| `--task-name` | (必需) | 任务名 |
| `--exp-name` | (必需) | 实验目录时间戳 |
| `--ckpt-tag` | `best` | `best` (读 `best_ckpt.json`), `latest`, `20pct`..`100pct` |
| `--ckpt-path` | - | 直接 `.pt` 路径 (覆盖 `--ckpt-tag`) |
| `--episodes` | config 值 | 评测 seed 数 |
| `--denoise-steps` | config 值 | 去噪步数 |
| `--no-ema` | - | 使用原始权重代替 EMA |

**配置加载与合并流程** (`main` → `evaluate_checkpoint_robotwin`):

1. 拼接实验目录路径: `experiments/{policy_name}/{task_name}/{exp_name}`
2. `OmegaConf.load(config.yaml)` 加载原始训练配置
3. 合并命令行 overrides + 注入 `cfg._exp_dir`
4. 参数解析: `CLI > _get_eval_param(cfg, param, "offline") > 硬编码 default`（三级 fallback）
5. 调用 `validate_eval_config(cfg)` + `build_eval_components(cfg, device)`

### 实验目录发现机制

```
experiments/
  └── {policy_name}/
        └── {task_name}/
              └── {exp_name}/
                    ├── config.yaml
                    ├── best_ckpt.json        ← select_best_ckpt.py 输出
                    └── checkpoints/
                          ├── latest.pt        (symlink)
                          ├── best.pt          (symlink, 可选)
                          └── epoch=*-step=*-milestone=*.pt
```

### Checkpoint 解析策略

`eval_best_ckpt.py` 支持 4 种 checkpoint 指定方式：

| 方式 | 示例 | 解析逻辑 |
|------|------|---------|
| 里程碑百分比 | `--ckpt-tag 40pct` | `discover_milestone_checkpoints()` 匹配 `pct` 字段 |
| best (推荐) | `--ckpt-tag best` | 读 `best_ckpt.json` → fallback `best.pt` symlink |
| latest | `--ckpt-tag latest` | `checkpoint_store.resolve_path("latest")` |
| 直接路径 | `--ckpt-path /path/to/ckpt.pt` | 相对路径补全 `exp_dir/checkpoints/` 前缀 |

### 确定性种子选择

与旧版评测不同，`eval_best_ckpt.py` 实现**可复现的确定性种子选择**：

```python
all_seeds = list(env_runner.get_seed_list())
rng = random.Random(eval_seed)      # 用 eval seed 固定随机状态
rng.shuffle(all_seeds)              # 确定性 shuffle
eval_seeds = all_seeds[:n_total]    # 取前 N 个
env_runner.eval_seeds = eval_seeds  # 注入 env_runner（跳过内部 get_seed_list）
```

重跑同一 checkpoint 永远产生相同结果——RoboTwin 复现性标准。

`select_best_ckpt.py` 和 `record_demo.py` 使用相同的 `random.Random(eval_seed)` shuffle 约定，确保三个入口在同一实验上选取完全一致的 seed 子集。

### 评测输出

```
{exp_dir}/eval_dexsim/
  ├── _result.txt           ← 单行浮点数 (RoboTwin 兼容)
  ├── result_details.json   ← 完整明细 (success_rate, avg_steps, per_seed_details)
  └── <YYYYmmdd_HHMMSS>/    ← 视频目录 (默认录制，--no-videos 跳过)
        └── episode_<seed>.mp4
```

## 3. 模型加载与评测编排

### 共享加载流程 (`eval_utils.load_ckpt_for_inference`)

两个评测入口 (`eval_best_ckpt.py` 和 `select_best_ckpt.py`) 共享同一个模型加载函数。这是一个多层校验的防护性加载流程:

```
checkpoint_store.load(ckpt_path)
  → TrainCheckpoint dataclass 反序列化 (weights_only=False, map_location='cpu')
  → payload 格式: {'state': {...}, 'weights': {...}, '_format': 'simple.v1'}

逐字段校验 train_params:
  checkpoint.n_obs_steps    == agent.n_obs_steps
  checkpoint.n_action_steps == agent.n_action_steps
  checkpoint.action_dim     == agent.action_dim
  checkpoint.horizon        == agent.horizon
  checkpoint.action_key     == agent.action_key
  → 任一不匹配 → ValueError (含明确差异描述)

FAAS 一致性校验:
  checkpoint.train_params.get('use_faas', False) == agent.use_faas
  → 拒绝 FAAS checkpoint 与非 FAAS agent 混用 (反之亦然)

EMA 选择:
  if use_ema and ema_model_state exists:
      使用 EMA 权重 (推荐: 训练时的指数移动平均通常泛化更好)
  else:
      使用 model_state (未保存 EMA 时 warning)

fix_state_dict 前缀修复:
  1. 去除 _orig_mod. 前缀     ← torch.compile 包装
  2. 检测/移除 module. 前缀   ← DDP 包装 (评测固定 is_current_ddp=False)
  → 兼容 DDP 训练 checkpoint 在单卡评测时直接加载

agent.load_state_dict(ckpt_state, strict=True)
  → strict=True 确保所有权重完全匹配，partial load 会直接报错
  → 加载发生在 CPU 上，agent 尚未 moved to device

normalizer.is_fitted(required_keys=['action'])
  → 终末校验: normalizer 必须已拟合 'action' key
  → 否则 RuntimeError (推理时无法 unnormalize 动作)
```

**关键设计细节**:

- `weights_only=False`: 因为 `TrainCheckpoint` 中的 `Normalizer.nn.ParameterDict` 不在 PyTorch 安全加载白名单内，但仅加载到 CPU (`map_location='cpu'`)
- `fix_state_dict` 的双向前缀修复: 同时处理 `_orig_mod.` (compile) 和 `module.` (DDP) 的嵌套组合 (`_orig_mod.module.param`)
- 配置容错: `eval_best_ckpt.py` 通过 `_get_eval_param()` 三级 fallback (子节 → eval 共享层 → 硬编码 default)，避免因配置缺失 crash

### evaluate_checkpoint_robotwin 核心编排

`eval_best_ckpt.py:evaluate_checkpoint_robotwin()` 是整个评测的核心编排函数，全程在 `@torch.no_grad()` 下运行:

```
1. validate_eval_config(cfg) → 校验 action_key + horizon 边界
2. set_seed(eval_seed) → 确定性种子
3. build_eval_components(cfg, device) → agent + env_runner + checkpoint_store
4. 解析 checkpoint 路径 (见 Section 2)
5. load_ckpt_for_inference(agent, checkpoint_store, ckpt_path, use_ema)
6. agent.to(device) + agent.eval()

7. 确定性种子选择:
   ├── all_seeds = list(env_runner.get_seed_list())
   ├── rng = random.Random(eval_seed); rng.shuffle(all_seeds)
   ├── eval_seeds = all_seeds[:n_total]
   └── env_runner.eval_seeds = eval_seeds  # 注入

8. result = env_runner.run(agent, denoise_timesteps, eval_episodes)
   └── BaseRunner.run():
       ├── make_env() → 构造仿真环境
       ├── while len(success_list) < eval_episodes:
       │     ├── run_one_episode(agent, env, seed, timesteps)
       │     ├── 收集 success / task_done_step / [video (可选)]
       │     └── clear_cache_freq=25: 定期 env.close() + 重建
       ├── 计算 success_rate / avg_steps / avg_steps_all
       └── finally: env.close()

9. collect_episode_details(result) → per_seed 明细
10. 输出: _result.txt (RoboTwin 单行浮点数) + result_details.json
```

**异常处理**:

- **三层异常隔离** — `BaseRunner.run()` 内 episode 级 try/except 结构:
  1. **Episode 执行** (`run_one_episode`): 抛异常 → 记为 `False`，尝试保存 crash 视频帧，继续下一个 seed
  2. **帧提取** (`env.get_video()`): 独立 try/except → 失败则 `video=None`，不影响 episode 成功/失败记录
  3. **视频编码** (`_encode_video`): 独立 try/except → 失败打印 warning，不影响 episode 指标
  - 三层之间用 `episode_completed` 标志位精确分离，确保视频相关异常不会污染 `success_list`
- `KeyboardInterrupt` 直接 raise (不捕获): 用户中断必须立即生效
- `MultiTaskSimRunner.run()` 三层异常: KeyboardInterrupt 直接 raise, (RuntimeError/ValueError/AttributeError) 记录为 known failure 继续, 其他 Exception 记录为 unexpected 并打印 traceback

### 去噪步数配置

去噪步数通过 `--denoise-steps` CLI 参数或 config 的 `eval.denoise_steps`（通过 `_get_eval_param` 三级 fallback）指定，单一值（非列表遍历）:

- **Diffusion 推理**: `denoise_steps=10` → DDIM scheduler 设置为 10 步等间隔去噪
- **FlowMatch 推理**: `denoise_steps=10` → Euler ODE 积分步数 `dt = 1/10 = 0.1`
- 不同去噪步数的对比通过多次调用 `eval_best_ckpt.sh --denoise-steps N` 实现

## 4. 环境执行层 (Env Runner)

### BaseRunner → SimRunner → MultiTaskSimRunner 类层级

```
BaseRunner (抽象基类)
  ├── __init__: 环形观测缓冲 + ACT blender + clear_cache_freq
  ├── update_obs: 单帧观测写入环形缓冲
  ├── get_stacked_obs: 时间有序观测栈 (冷启动 padding)
  ├── get_obs_batch: 转 tensor + 加 batch 维
  ├── get_action_chunk: agent 推理 + ACT 融合
  ├── run_one_episode: 单 episode 执行循环
  ├── run: 多 episode 评测循环 (make_env 为抽象方法)
  └── reset: 清空缓冲和 blender

  ├── SimRunner(BaseRunner)
  │     ├── make_env: 动态导入 dexmani_sim.envs.{task} 环境类
```

### 环形观测缓冲机制

环形观测缓冲是 `BaseRunner` 的核心基础设施，用于在仿真推理循环中高效管理历史观测帧。

**数据结构**:

```
_obs_buffer:    dict[str, np.ndarray]     # 预分配 (n_obs_steps, *obs_shape)
_obs_str_buffer: dict[str, list]           # 字符串观测 dequeue
_obs_cursor:    int                        # 写入位置 (模 n_obs_steps)
_obs_count:     int                        # 已存储帧数 (上限 n_obs_steps)
```

**关键设计**:

1. **延迟分配**: 首次 `update_obs()` 时根据实际帧 shape 分配 `np.zeros`，避免需要预知观测维度。`ndarray` 分配 `(n_obs_steps, *shape)`，`Tensor` 跟随输入 device 分配。

2. **模索引写入**: `pos = _obs_cursor % n_obs_steps; _obs_buffer[key][pos] = value`，无限环形覆盖，零额外内存分配。

3. **冷启动 padding**: 当 `get_stacked_obs()` 被调用但缓冲帧数不足 `n_obs_steps` 时，用第一帧填充头部缺口:
   ```python
   # _obs_count < n_obs_steps (冷启动)
   pad_len = n_obs_steps - _obs_count
   result[:pad_len] = buf[0]        # 复制第一帧填开头
   result[pad_len:] = buf[:_obs_count]  # 实际帧填后面
   ```
   这与训练时的 `SequenceSampler(pad_before=1)` 语义一致。

4. **正常读取**: 通过模算术切片构造时间有序的 `(n_obs_steps, ...)` 栈:
   ```python
   start = (_obs_cursor - n_obs_steps) % n_obs_steps
   indices = (start + np.arange(n_obs_steps)) % n_obs_steps
   result = buf[indices]  # numpy fancy indexing (零拷贝 copy)
   ```

5. **模态过滤**: `update_obs` 仅存储 `sensor_modalities` 中声明的 key (如 `point_cloud`, `joint_state`)，非传感器模态 (如 `task_text`, `rgb`) 被忽略——它们由子类在推理边界注入。

6. **字符串模态**: 单独管理 `_obs_str_buffer`，用 `list + pop(0)` 维护固定长度 dequeue (非环形索引，因为 str 不可 in-place 赋值)。

### run_one_episode 的完整时序

单个 episode 的执行时序精确到步：

```
时刻 t=0:
  obs_0 = env.reset(seed=seed)           # 环境初始化
  self.reset()                           # 清空环形缓冲 + blender
  self.update_obs(obs_0)                 # 写入第一帧

时刻 t=0 到 t=T (循环直到 done/truncated):
  ┌─ obs_batch = get_obs_batch(device)   # 环形缓冲 → (1, n_obs_steps, ...) tensor on GPU
  │
  ├─ action_chunk = get_action_chunk()   # agent 推理 + ACT 融合
  │   │
  │   ├─ agent.predict_action(obs_dict)
  │   │   ├─ _convert_obs_to_faas: joint_state 19D→39D (幂等)
  │   │   ├─ _build_cond: preprocess(normalize+truncate+flatten) → obs_encoder
  │   │   └─ predict_action_from_cond(cond):
  │   │         ├─ 零模板 (1, 16, 39)  # FAAS 空间
  │   │         ├─ decoder.predict_action: randn → 10 步去噪
  │   │         ├─ normalizer['action'].unnormalize → 物理范围
  │   │         ├─ faas_mapper.inverse_transform_action → FAAS 39D→native 19D
  │   │         └─ 切分:
  │   │               control_action = pred[:, 1:9]   # 8 步待执行
  │   │               tail = pred[:, 9:16]            # 7 步待融合
  │   │
  │   └─ [ChunkOverlapBlender.update(pred_action, n_action_steps=8) 若启用]
  │         提取 new_head = pred[:, 1:9]
  │         若有 prev_tail:
  │           前 overlap=7 步: blended = (prev*1.0 + new*exp(-0.01)) / (1.0+exp(-0.01))
  │           第 8 步: 直接 new_head[-1]
  │         保存 tail = pred[:, 9:16] 为下次 prev_tail
  │
  └─ for i in range(len(action_chunk)):   # 通常 8 步
        │
        ├─ obs_next, reward, done, truncated, info = env.step(action_chunk[i])
        │
        ├─ self.update_obs(obs_next)      # 下一帧立即写入环形缓冲
        │
        ├─ if info.get('success_condition') and task_done_step is None:
        │     task_done_step = env.action_cnt  # 记录首次达成步数 (无保持延迟)
        │
        └─ if info.get('success'):        # 含保持判定的最终成功
        │     episode_success = True
        │
        if done or truncated:
            break

返回 (episode_success, task_done_step)
```

**关键时序约定**:

- `success_condition` vs `success`: 前者是任务目的达成的原始瞬间信号 (如物体进入目标容器)，不含保持延迟判断；后者在达成后需保持若干步才算最终成功。`avg_steps` 使用 `success_condition` 记录的 `task_done_step`，`success_rate` 使用 `success`
- `task_done_step` 从 `env.action_cnt` 获取——这是环境内部的绝对步数计数器，比手动计数更准确
- `action_chunk` 长度可能小于 `n_action_steps` (最后一帧提前 `done`/`truncated`)，循环按实际长度执行不越界

### ACT 时序融合的实现

ACT (Action Chunking with Temporal Ensemble) 的核心思想是: 由于 `horizon=16` 但每步只执行 `n_action_steps=8`，两个连续 action chunk 之间有 `horizon - n_action_steps = 8` 步重叠。对重叠区域做指数加权融合，可以平滑时序预测并提高鲁棒性。

**ChunkOverlapBlender 详解** (`temporal_ensembler.py`):

```
给定: action_chunk (1, 16, action_dim) from agent.predict_action
       n_action_steps = 8

new_head = action_chunk[:, 1:1+8]    # 位置 [1,8] → 8 步待执行动作
                                       # 注意: 从位置 1 开始 (非 0)
                                       # 位置 0 是当前 obs 对应的已执行动作

prev_tail 来自上一次 update:
  prev_tail = action_chunk[:, 1+8:16]  # 位置 [9,15] → 7 步未执行尾部

overlap = min(prev_tail.size(1), new_head.size(1)-1)
        = min(7, 8-1) = 7              # 前 7 步有旧预测重叠

融合公式:
  w0 = 1.0                    (旧预测权重, exp(-coeff*0))
  w1 = exp(-0.01) ≈ 0.99005  (新预测权重)
  wsum = w0 + w1 ≈ 1.99005

  blended[0:7] = (prev_tail[0:7] * 1.0 + new_head[0:7] * 0.99) / 1.99
  blended[7]   = new_head[7]              # 第 8 步无旧预测对应, 直接用新值

保存: prev_tail = action_chunk[:, 9:16]   # 供下一个 chunk 融合
```

**关键设计选择**:

- **chunk 索引从 1 开始**: 维度 0 是当前观测对应的动作 (由上一轮已执行)，有效预测在 `[1, horizon-1]` 范围
- **w0=1.0 恒定**: `exp(-coeff*0) = 1.0`，即最新预测的旧值为最高权重基准
- **coeff=0.01**: 新旧预测近乎等权 (~50% vs ~49.75%)，平滑效果温和
- **blender 用 pred_action (全 horizon) 而非 control_action**: 因为需要完整的 `tail[9:16]` 保存为下次融合的 `prev_tail`
- **每 episode reset**: `_prev_tail = None` 确保跨 episode 不泄漏状态

### 成功率判定逻辑

```
单 episode 成功判定 (run_one_episode):
  episode_success = info.get('success', False)    ← 含保持判定的最终成功
  task_done_step = 首次 info['success_condition']!=None 时的 env.action_cnt
                   ← 无保持延迟的原始信号

多 episode 汇总 (BaseRunner.run):
  success_rate = len(success_list) / len(success_list)
                # 注意: success_list 仅含成功 episode
                # BaseRunner.run 的 while 循环确保收集到足够数

  avg_steps = mean(task_done_steps for success episodes only)
             # 仅统计成功 episode, 失败 episode 不入计

  avg_steps_all = sum(total_steps_per_episode) / len(success_list)
                 # 所有 episode 的总步数平均 (失败 episode 为最大步数)

多任务汇总 (MultiTaskSimRunner.run):
  avg_success_rate = mean(各 task 的 success_rate)
  avg_steps = mean(各 task 的 avg_steps (仅成功 task))
```

**设计考量**: `success_condition` vs `success` 的分离确保了 `avg_steps` 指标在不同任务间可比——均以任务首次物理达成的时刻为基准，不受环境特定的保持延迟参数影响。

## 5. Agent 推理层

### predict_action() vs compute_loss() 的差异

| 维度 | `compute_loss` (训练) | `predict_action` (推理) |
|------|----------------------|------------------------|
| **入口** | `BaseAgent.compute_loss(batch)` | `BaseAgent.predict_action(obs_dict)` |
| **装饰器** | 无 (需要 autograd) | `@torch.no_grad()` |
| **输入** | `batch` (dict, 含 `action` GT) | `obs_dict` (仅观测, 无 GT action) |
| **观测校验** | `_validate_batch` (batch 级 + obs vs action batch 交叉) | `_validate_obs_dict` (仅观测级, expected_batch=None) |
| **action 处理** | GT action 归一化 + 加噪 → model 预测 target | 纯噪声起点 → 迭代去噪 → unnormalize |
| **FAAS 转换** | 不需要 (Dataset 已输出 FAAS 数据) | 入口: `_convert_obs_to_faas` (19D→39D), 出口: `inverse_transform_action` (39D→19D) |
| **Normalizer** | 输入观测 normalize (dict 中不在 params_dict 的 key 静默透传) | 同训练, 共享 preprocess |
| **modality_dropout** | `self.training=True` 时可能触发 | `self.training=False` 自动跳过 |
| **NaN 检测** | 两层检测 (loss NaN + grad NaN) | 无 (但 SATFlowMatch 有 `assert isfinite`) |
| **损失** | `F.mse_loss` + 可选 aux_loss (R3D 分组 loss / MoE load balancing) | 无损失, 返回 dict `{pred_action, control_action, tail}` |
| **输出维度** | `loss: scalar` | `control_action: (B, n_action_steps, action_dim)` + `tail: (B, horizon-n_action_steps, action_dim)` |

### FAAS 转换在推理中的位置

FAAS (Function-Actuator-Aligned Space) 转换仅在推理时显式执行 (训练时 Dataset 已产出 FAAS 数据而非 native)，在 I/O 边界完成两级转换:

```
推理输入边界 (predict_action 入口):
  joint_state (19D native) → faas_mapper.native_to_faas → joint_state (39D FAAS)
  ↑ 幂等保护: 仅当 joint_state 最后一维 == 7+12=19 时转换
  已是 39D 则直接返回 (训练路径可能传入 FAAS 数据)

  模型内部: 所有计算均在 FAAS 空间 (39D)
  - obs_encoder 接收 39D joint_state
  - action_decoder 去噪输出 39D pred_action

推理输出边界 (predict_action_from_cond 出口):
  pred_action (39D FAAS) → normalizer.unnormalize → 物理范围
                         → faas_mapper.inverse_transform_action → control_action (19D native)
  ↑ 逆变换在 unnormalize 之后、control_action 提取之前
  确保 control_action/tail 全是 native 维度，env.step 直接接收
```

**关键不变式**:

- `faas_mapper` 作为 `nn.Module` 子类，所有映射表 (indices/scales/offsets) 通过 `register_buffer(persistent=True)` 保存，因此自动包含在 checkpoint 中，无需外部文件
- `_convert_obs_to_faas` 幂等设计防止双重转换——若训练路径误传入 FAAS 数据也不会破坏
- FAAS 对 obs_encoder/backbone/action_decoder 完全透明——agent 代码除 `predict_action` 和 `predict_action_from_cond` 两个方法外无需任何 FAAS 感知逻辑

### 各 action decoder 的推理路径

所有 decoder 共享统一接口 `predict_action(cond, action_template, denoise_timesteps) → Tensor`，但去噪算法各异:

#### 1. Diffusion (DDIM) — DP/DP3/MoE/R3D/DQRISE

```
输入: cond (B, cond_dim), action_template (B, H, Da)
起点: x = torch.randn_like(action_template)  ← 标准高斯噪声
      template 仅提供 shape/device/dtype, 内容为零

DDIM scheduler 设置:
  beta_start=0.0001, beta_end=0.02
  schedule='squaredcos_cap_v2'
  clip_sample=True, set_alpha_to_one=True
  num_inference_steps=10 (默认) / 100 (MoE, 不做加速)

迭代 (i = 0 → N-1):
  t = scheduler.timesteps[i]
  output = model(x, t, context=cond)      ← UNet1D / DiTDiffusion / OneWayTransformer
  x = scheduler.step(output, t, x).prev_sample
  ↑ prediction_type 决定 output 语义:
    'epsilon' (DQRISE) → scheduler 用 noise-based 去噪
    'sample' (DP/DP3/MoE/R3D) → scheduler 用 x0-based 去噪
    'v_prediction' (MultiTask) → scheduler 用 velocity-based 去噪

返回: x (B, H, Da)  # 去噪后的动作序列

DDIM 确定性采样: eta=0, 相同噪声 + 相同输入 → 相同输出 (复现性保证)
```

#### 2. FlowMatch (Euler ODE) — MultiTask

```
输入: cond (B, N_obs, obs_dim), action_template (B, H, Da)

起点: x = torch.randn_like(action_template)
N = denoise_timesteps (默认 10)
dt = 1.0 / N

迭代 (i = 0 → N-1):
  t_i = i * dt  (0 → 1-dt)
  v = model(x, t_i, context=cond)  ← DiT self-attn + AdaLN
  x = x + v * dt                   ← Euler 积分

返回: x (B, H, Da)

目标语义: v = x1 - x0 (瞬时速度场, 学习直线路径)
          Euler 积分沿速度场从 noise (t=0) 到 data (t=1)
```

#### 3. FlowMatchWithConsistency — ManiFlow

```
输入: cond (B, N_obs, obs_dim), action_template (B, H, Da)

与 FlowMatch 相同 Euler 积分, 区别在 model 调用:
  v = model(x, t_i, target_t=dt, context=cond)
      ↑ target_t=dt 利用 consistency training 习得的自校正能力
      ↑ 训练时: flow 子批次 target_t=0, consistency 子批次 target_t>0

关键约定: 训练 target_t=0, 推理 target_t=dt>0
         无 EMA 教师时条件分布偏移, 通过 consistency 路径缓解

1-t clamp min: max(1/N, 1e-3) 防止除零 (前几步 1-t 接近 0)
DiTX backbone: self-attn(action) → cross-attn(action→obs) → MLP
```

#### 4. SATFlowMatch — SAT

```
输入: cond (B, N_obs, obs_dim), action_template (B, Da, T)
      ↑ 注意形状: (B, Da, T) 而非 (B, T, Da) — SAT 结构中心表示

起点: x = torch.randn_like(action_template)  ← Gaussian init (论文 A⁰~N(0,I))
N = denoise_timesteps (默认 10)
dt = 1.0 / N

迭代 (i = 0 → N-1):
  t_i = i * dt
  v = model(x, t_i, context=cond, shuffle=False)
      ↑ shuffle=False: 推理时关节保持 canonical order, EJC 提供 identity
      ↑ SATBackbone: x_embedder (2层MLP) → +EJC (3-field sum) → AdaLNZero pre-norm → SATBlock × 8 (MultiModalAttention)
  x = x + v * dt
  assert torch.isfinite(x).all()  ← SAT 唯一定点 NaN/Inf 保护

返回: x (B, Da, T)
```

### Normalizer 在推理中的角色

Normalizer 在推理中扮演三个关键角色:

**1. 观测归一化 (preprocess 中)**:

```
obs_dict → normalizer.normalize(obs_dict)
  ↓
model 看到 [-1, +1] (limits 模式) 或 ~N(0,I) (gaussian 模式) 的 joint_state
  ↓
point_cloud / rgb 不被 normalizer 处理 (它们不在 params_dict 中, 静默透传)
  → 点云归一化由 PointNeXT encoder 内部完成 (Center+Scale)
  → RGB 归一化由 DINO/CLIP/SigLIP 的预处理器完成 (ImageNet mean/std)
```

**2. 动作逆归一化 (predict_action_from_cond 中)**:

```
pred (FAAS 空间, decoder 输出) → normalizer['action'].unnormalize(pred)
  → 模型输出从 [-1, +1] 缩放回物理范围 (关节角弧度 / 末端位置米)
  → 之后才做 FAAS 逆变换 (因为 FAAS mapper 假设物理范围输入)
```

**3. 终末校验**:

```
normalizer.is_fitted(required_keys=['action'])
  → 确保 'action' key 存在且已拟合
  → 若 checkpoint 缺少 normalizer state_dict 会在此处失败 (而非在推理时静默输出异常值)
```

**训练 vs 推理的 Normalizer 一致性**:

- 训练: normalizer 在用全量 replay buffer (含验证集) 拟合，保存在 checkpoint 内
- 推理: normalizer 从 checkpoint 恢复 (`load_state_dict(strict=True)`)
- 因此训练和推理使用完全相同的 scale/offset，不存在分布偏移
- `limits` 模式下，全量拟合不影响 min/max (验证集无法扩展训练集的 min/max)，实际等效于 train-split 拟合

## 7. 画龙点睛

> **离线仿真评测系统是一个闭环的"感知 → 推理 → 执行"管道——从磁盘上的训练配置和权重出发，通过确定性种子选择保证复现性，在完全解耦的推理环境下将模型暴露给干净的仿真交互，通过环形观测缓冲平滑实时感知、扩散/流匹配迭代去噪生成动作、ACT 指数加权融合平滑时序预测，最终以 RoboTwin 兼容的原始成功率信号给出无偏的策略质量度量；整个过程在 `torch.no_grad()` 的语义安全边界内运行，每个 episode 独立的异常隔离确保单点故障不污染全局统计，训练时从未见过的仿真交互正是衡量泛化能力的终极标尺。**
