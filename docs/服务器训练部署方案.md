# DexMani_Policy 服务器训练部署方案（v2 反思优化版）

## 原方案问题诊断

| 问题 | 严重度 | 优化 |
|------|--------|------|
| 每个脚本硬编码 `sshpass -p` 密码 | 🔴 安全+可读性 | 统一配置 `~/.ssh/config`，所有脚本引用 `dexserver` |
| `--delete` 无保护，可能误删服务器文件 | 🟡 中等 | 仅对源码目录用 `--delete`，加 `--dry-run` 预览开关 |
| 缺少 `--partial`，大文件传输出错需重传 | 🟡 中等 | 8.8GB robot_data 必须用 `--partial` 断点续传 |
| `conda run` 在 tmux 中 GPU 可见性不可靠 | 🟡 中等 | 用绝对路径 `~/.conda/envs/dex_policy/bin/python` |
| `train_remote.sh` 前台运行，SSH 断开训练死 | 🔴 体验 | 默认 tmux 后台，加 `--fg` 选项前台 |
| `sync_down.sh` 无过滤，一次拉全部 73GB 实验 | 🟡 中等 | 支持 `policy/task/timestamp` 路径过滤 |
| 缺少 GPU 分配文档 | 🟢 低 | 补充 8 GPU 分区策略 |
| 缺少停止/清理/日志查看等运维脚本 | 🟡 中等 | 补充 `stop.sh`, `tail_log.sh`, `cleanup.sh` |
| 同步前不做服务器连通检查 | 🟡 中等 | 加 pre-flight check |
| `setup.py` 无依赖声明，`pip install -e .` 空操作 | 🟢 低 | 明确列出需手动验证的包清单 |

## 优化后方案

### Phase 0: SSH 配置（一次性，最高优先级）

**目标**: 消除所有脚本中的密码和端口号，将 `sshpass -p 'robot2024' ssh -p 51822 zjurobot@192.168.88.230` 简化为 `ssh dexserver`。

```bash
# 在本地 ~/.ssh/config 添加:
Host dexserver
    HostName 192.168.88.230
    Port 51822
    User zjurobot
    ServerAliveInterval 60
    ServerAliveCountMax 5
    # 如果仍用密码（不想设 key）：
    # 配合 sshpass 使用: sshpass -p 'robot2024' ssh dexserver
```

> **密码处理**: 如果服务器支持 SSH key，执行 `ssh-copy-id dexserver` 一劳永逸。否则所有脚本中统一用 `sshpass -p 'robot2024' ssh dexserver`，密码只出现在脚本顶部的**一个变量**中。

### 优化后的目录布局

```
服务器:
~/dexmani_policy/                          # 项目根 (本地 SSD, ~60MB)
├── dexmani_policy/                        # ← rsync 源码
├── scripts/                               # ← rsync 脚本
├── configs/                               # ← rsync 配置  
├── data/                                  # ← rsync (53MB, 含 Uni3D 权重)
├── docs/                                  # ← rsync
├── pyproject.toml / setup.py              # ← rsync
├── robot_data → /data_ssd/dexmani/robot_data/        # symlink
├── experiments → /data_ssd/dexmani/experiments/      # symlink
└── pretrained_models → /data_ssd/dexmani/pretrained_models/  # symlink

/data_ssd/dexmani/                         # NFS SSD (21TB 可用, 放大数据)
├── robot_data/                            # 8 个 .zarr (共 8.8GB)
├── experiments/                           # 训练输出
│   └── <policy>/<task>/<timestamp>/
└── pretrained_models/                     # 自动编码器权重 (2MB)
```

> **设计理由**: 代码在本地 SSD（快速 Python import/compile），大数据在 NFS SSD（空间充裕，zarr 顺序读不受 NFS 延迟影响）。symlink 让配置中的 `robot_data/pour.zarr` 相对路径对代码透明。

### 脚本体系（3+2 个脚本）

```
scripts/
├── sync_up.sh          # 上传: 代码 + 数据
├── sync_down.sh        # 下载: 实验结果（支持路径过滤）
├── train_remote.sh     # 一键: 检查 → 同步 → 启动训练
├── tail_log.sh         # 便捷: 实时查看训练日志
└── stop.sh             # 便捷: 停止远程训练
```

#### 1. `sync_up.sh` — 上传

```bash
#!/bin/bash
# 上传源码和数据到服务器
# 用法:
#   bash scripts/sync_up.sh                  # 仅源码（秒级）
#   bash scripts/sync_up.sh --with-data       # 源码 + 数据
#   bash scripts/sync_up.sh --dry-run          # 预览不执行

set -euo pipefail
SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
PROJECT_ROOT="$(dirname "$SCRIPT_DIR")"

# ---- 配置（修改这里） ----
SERVER="dexserver"                            # SSH config Host
SERVER_CODE="$SERVER:~/dexmani_policy/"       # 代码目标
SERVER_DATA="$SERVER:/data_ssd/dexmani/"      # 数据目标
# ---- 配置结束 ----

DRY_RUN=""
WITH_DATA=false
for arg in "$@"; do
    case "$arg" in
        --dry-run) DRY_RUN="--dry-run" ;;
        --with-data) WITH_DATA=true ;;
    esac
done

RSYNC="rsync -avz --partial --progress $DRY_RUN"

echo "[sync_up] Syncing source code → ~/dexmani_policy/"
$RSYNC \
    --exclude='.git/' --exclude='__pycache__/' --exclude='*.pyc' \
    --exclude='*.egg-info/' --exclude='.claude/' --exclude='.codex/' \
    --exclude='.vscode/' --exclude='.ruff_cache/' \
    --exclude='experiments/' --exclude='robot_data/' --exclude='pretrained_models/' \
    --exclude='wandb/' --exclude='_wandb/' --exclude='outputs/' --exclude='logs/' \
    --delete \
    "$PROJECT_ROOT/" "$SERVER_CODE"

if $WITH_DATA; then
    echo "[sync_up] Syncing robot_data (8.8GB) → /data_ssd/dexmani/robot_data/"
    $RSYNC "$PROJECT_ROOT/robot_data/" "$SERVER_DATA/robot_data/"

    echo "[sync_up] Syncing pretrained_models → /data_ssd/dexmani/pretrained_models/"
    $RSYNC "$PROJECT_ROOT/pretrained_models/" "$SERVER_DATA/pretrained_models/"
fi

# 上传后验证
if [[ "$DRY_RUN" == "" ]]; then
    echo "[sync_up] Verifying imports..."
    ssh "$SERVER" "cd ~/dexmani_policy && ~/.conda/envs/dex_policy/bin/python -c 'import dexmani_policy; print(\"OK\")'" \
        || echo "[sync_up] WARNING: import check failed — run pip install -e . on server?"
fi

echo "[sync_up] Done."
```

#### 2. `sync_down.sh` — 下载结果

```bash
#!/bin/bash
# 从服务器下载训练结果
# 用法:
#   bash scripts/sync_down.sh                              # 全部实验（可能很大）
#   bash scripts/sync_down.sh dp3/pour                     # 特定 policy/task
#   bash scripts/sync_down.sh dp3/pour/2026-08-03_12-34_42 # 特定 run
#   bash scripts/sync_down.sh --dry-run                    # 预览

set -euo pipefail
SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
PROJECT_ROOT="$(dirname "$SCRIPT_DIR")"

SERVER="dexserver"
SERVER_EXP="$SERVER:/data_ssd/dexmani/experiments/"

DRY_RUN=""
SUBPATH=""
for arg in "$@"; do
    case "$arg" in
        --dry-run) DRY_RUN="--dry-run" ;;
        --no-wandb) NO_WANDB="--exclude='wandb/'" ;;
        *) SUBPATH="$arg" ;;
    esac
done

RSYNC="rsync -avz --partial --progress $DRY_RUN ${NO_WANDB:-}"
REMOTE="$SERVER_EXP${SUBPATH:+$SUBPATH/}"
LOCAL="$PROJECT_ROOT/experiments/${SUBPATH:+$SUBPATH/}"

echo "[sync_down] Pulling: $REMOTE → $LOCAL"
mkdir -p "$LOCAL"
$RSYNC "$REMOTE" "$LOCAL"

echo "[sync_down] Done."
```

#### 3. `train_remote.sh` — 一键训练

```bash
#!/bin/bash
# 在服务器上启动训练（默认 tmux 后台）
# 用法:
#   bash scripts/train_remote.sh <config> <task_name> [hydra_overrides...]
#   bash scripts/train_remote.sh --fg <config> <task_name> [...]   # 前台运行
#   bash scripts/train_remote.sh --dry-run <config> <task_name> [...] # 预览
#
# 示例:
#   bash scripts/train_remote.sh dp3 pick_apple_messy
#   bash scripts/train_remote.sh ddp/maniflow pour
#   bash scripts/train_remote.sh --fg dp3 pour 'training.seed=123'

set -euo pipefail
SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"

SERVER="dexserver"
SERVER_PROJ="~/dexmani_policy"
SERVER_DATA="/data_ssd/dexmani"
CONDA_PYTHON="~/.conda/envs/dex_policy/bin/python"

FOREGROUND=false
DRY_RUN=false

# 解析选项
while [[ $# -gt 0 ]]; do
    case "$1" in
        --fg) FOREGROUND=true; shift ;;
        --dry-run) DRY_RUN=true; shift ;;
        *) break ;;
    esac
done

CONFIG="${1:?Error: specify config name}"
TASK="${2:?Error: specify task name}"
shift 2

# ---- Pre-flight checks ----
echo "=== Pre-flight ==="

# 1. Server reachable
if ! ssh -o ConnectTimeout=5 "$SERVER" "echo ok" &>/dev/null; then
    echo "ERROR: Cannot reach server '$SERVER'" >&2
    exit 1
fi

# 2. Code synced
echo "Syncing code..."
bash "$SCRIPT_DIR/sync_up.sh"

# 3. Disk space
echo "Checking disk..."
ssh "$SERVER" "df -h /data_ssd | tail -1"

# 4. robot_data exists for this task
echo "Checking dataset..."
ssh "$SERVER" "test -d $SERVER_DATA/robot_data/${TASK}.zarr" || {
    echo "ERROR: ${TASK}.zarr not found on server. Run: sync_up.sh --with-data" >&2
    exit 1
}

# 5. GPU memory check
echo "Checking GPUs..."
ssh "$SERVER" "nvidia-smi --query-gpu=index,memory.free --format=csv,noheader"

echo "=== Pre-flight OK ==="

# ---- Build command ----
if [[ "$CONFIG" == ddp/* ]]; then
    TRAIN_CMD="bash scripts/train_ddp.sh $CONFIG task_name=$TASK $@"
else
    TRAIN_CMD="bash scripts/train.sh $CONFIG task_name=$TASK $@"
fi

FULL_CMD="cd $SERVER_PROJ && $CONDA_PYTHON -u \$(echo $TRAIN_CMD | sed 's/bash scripts\/train\(_ddp\)\?\.sh //' | sed \"s/task_name=$TASK/$TASK/\" | sed 's/ bash.*//')"

# Simpler approach: construct the hydra command directly
HYDRA_OVERRIDES="task_name=$TASK"
for override in "$@"; do
    HYDRA_OVERRIDES="$HYDRA_OVERRIDES $override"
done

if [[ "$CONFIG" == ddp/* ]]; then
    REMOTE_CMD="cd $SERVER_PROJ && $CONDA_PYTHON dexmani_policy/train_ddp.py --config-name=$CONFIG $HYDRA_OVERRIDES"
else
    REMOTE_CMD="cd $SERVER_PROJ && $CONDA_PYTHON dexmani_policy/train.py --config-name=$CONFIG $HYDRA_OVERRIDES"
fi

# ---- Launch ----
SESSION="${CONFIG//\//_}_${TASK}"

if $DRY_RUN; then
    echo "[DRY RUN] Session: $SESSION"
    echo "[DRY RUN] Command: $REMOTE_CMD"
    exit 0
fi

if $FOREGROUND; then
    echo "=== Launching (foreground) ==="
    ssh -t "$SERVER" "$REMOTE_CMD"
else
    echo "=== Launching in tmux session: $SESSION ==="
    # Kill existing session with same name
    ssh "$SERVER" "tmux kill-session -t '$SESSION' 2>/dev/null; true"
    # Create new detached session
    ssh "$SERVER" "tmux new-session -d -s '$SESSION' '$REMOTE_CMD; echo \"Training finished. Press Enter to close.\"; read'"
    echo ""
    echo "Training started in background tmux session."
    echo ""
    echo "Monitor:  ssh $SERVER -t tmux attach -t '$SESSION'"
    echo "Tail log: bash scripts/tail_log.sh $CONFIG $TASK"
    echo "Stop:     bash scripts/stop.sh $SESSION"
fi
```

> **改进**: 1) 默认 tmux 后台，加 `--fg` 选项；2) 启动前 5 项 pre-flight 检查；3) 命令构建直接用 Python + Hydra 参数，避免 shell 嵌套引号问题

#### 4. `tail_log.sh` — 查看训练日志

```bash
#!/bin/bash
# 实时查看服务器上的训练日志
# 用法:
#   bash scripts/tail_log.sh dp3 pour                # 自动找最新 run
#   bash scripts/tail_log.sh dp3 pour 2026-08-03_12-34_42  # 指定 run

set -euo pipefail
SERVER="dexserver"
SERVER_EXP="/data_ssd/dexmani/experiments"

POLICY="${1:?Usage: tail_log.sh <policy> <task> [timestamp]}"
TASK="${2:?}"
TS="${3:-}"

if [[ -n "$TS" ]]; then
    LOG_DIR="$SERVER_EXP/$POLICY/$TASK/$TS"
else
    # 找最新 timestamp
    LOG_DIR=$(ssh "$SERVER" "ls -dt $SERVER_EXP/$POLICY/$TASK/*/ 2>/dev/null | head -1" || echo "")
    if [[ -z "$LOG_DIR" ]]; then
        echo "ERROR: No experiment found for $POLICY/$TASK" >&2
        exit 1
    fi
fi

echo "Tailing: $LOG_DIR/metrics.jsonl"
ssh "$SERVER" "tail -f ${LOG_DIR%/}/metrics.jsonl"
```

#### 5. `stop.sh` — 停止训练

```bash
#!/bin/bash
# 停止服务器上的训练任务
# 用法:
#   bash scripts/stop.sh dp3_pick_apple_messy    # 按 tmux session 名
#   bash scripts/stop.sh --all                    # 停止所有训练

set -euo pipefail
SERVER="dexserver"

if [[ "${1:-}" == "--all" ]]; then
    echo "Stopping all training sessions..."
    ssh "$SERVER" "tmux list-sessions 2>/dev/null | cut -d: -f1 | xargs -I{} tmux kill-session -t {} 2>/dev/null; true"
else
    SESSION="${1:?Usage: stop.sh <session_name> or --all}"
    echo "Stopping session: $SESSION"
    ssh "$SERVER" "tmux kill-session -t '$SESSION' 2>/dev/null && echo 'Stopped.' || echo 'Session not found.'"
fi
```

```bash
# 1. 创建目录结构
```

### GPU 多任务并行策略

8 张 H200 可以通过 `CUDA_VISIBLE_DEVICES` 分区：

```bash
# 两个 DDP 训练各占 4 GPU
CUDA_VISIBLE_DEVICES=0,1,2,3 bash scripts/train_ddp.sh ddp/maniflow task_name=pour
CUDA_VISIBLE_DEVICES=4,5,6,7 bash scripts/train_ddp.sh ddp/dp3_faas task_name=pick_apple_messy

# 或 8 个单卡训练并行
for i in 0 1 2 3 4 5 6 7; do
    CUDA_VISIBLE_DEVICES=$i bash scripts/train.sh dp3 task_name=stack_cups training.seed=$i &
done
```

在 `train_remote.sh` 中使用：
```bash
bash scripts/train_remote.sh ddp/maniflow pour \
  'training.gpu_ids=[0,1,2,3]'
```

### Wandb 远程监控

服务器能访问 PyPI → 大概率能访问 wandb.ai。推荐在训练时启用 online 模式：

```bash
bash scripts/train_remote.sh dp3 pick_apple_messy \
  'workspace.wandb_cfg.mode=online'
```

这样可以在本地浏览器打开 wandb 看实时损失曲线、GPU 利用率等，无需 SSH 到服务器。

> 若 wandb 也不通（防火墙），保持默认 `offline` 模式，训练结束后用 `wandb sync` 上传。

### 关键改进总结

| 改进点 | 原方案 | 优化后 |
|--------|--------|--------|
| SSH 密码 | 每个脚本重复 `sshpass -p 'robot2024' ssh -p 51822 zjurobot@...` | 一个 `~/.ssh/config` Host，所有脚本用 `dexserver` |
| 大文件传输 | 无 `--partial`，中断需重传 8.8GB | 加 `--partial`，断点续传 |
| 训练模式 | 默认前台，SSH 断开即死 | 默认 tmux 后台，`--fg` 调试 |
| 启动前检查 | 无 | 5 项 pre-flight：连通性、同步、磁盘、数据、GPU |
| 结果下载 | 全量拉取，无过滤 | 支持 `policy/task/timestamp` 三级过滤 |
| 脚本数量 | 4 个（含 server_setup） | 3+2 个（核心+运维辅助） |
| 运维工具 | 缺失 | tail_log.sh, stop.sh |
| 代码 vs 数据位置 | 全部放 NFS | 代码本地 SSD，数据 NFS SSD（性能最优） |
| 密码安全 | 明文在多个文件 | 集中于 `~/.ssh/config`，推荐 SSH key |
| GPU 并行 | 未提及 | 文档化 8 GPU 分区策略 |
| 同步后验证 | 无 | sync_up 自动验证 import |
