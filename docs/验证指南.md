# DexMani_Policy 验证指南

命令从仓库根目录执行，使用已安装依赖的 Conda `policy` 环境。按 [协作规则](../AGENTS.md#验证) 选择覆盖当前风险的检查。

## Config-only smoke

```bash
conda activate policy
python dexmani_policy/smoke_test.py --config-only dp dp3 dqrise sat r3d \
  maniflow multitask_dit lamp latent_flow
python dexmani_policy/smoke_test.py --config-only \
  ddp/dp ddp/dqrise ddp/maniflow ddp/multitask_dit ddp/r3d ddp/sat
```

检查配置、策略/训练/Dataset/增强类导入及其他 Hydra target 模块，不加载数据、实例化模型或执行 GPU 算子。它不验证权重、仿真或 DDP 可运行。

Smoke 接受多个配置名或显式 `.yaml` 路径，共用 Hydra loader（含 `defaults`）；不接受 Hydra 字段覆盖。

## Data-only smoke

```bash
python dexmani_policy/smoke_test.py --data-only dp3 --max-batches 2
python dexmani_policy/smoke_test.py --data-only dp multitask_dit lamp latent_flow
```

`--data-only` 与 `--config-only` 互斥。使用 CPU 上的生产 Dataset、normalizer 和训练 DataLoader，不构建模型、optimizer、EMA、Workspace 或仿真环境，不下载权重或创建 W&B run。`--max-batches` 默认 2，分别限制训练和已有验证集的 batch 检查数量，只在 data-only 模式使用；不支持 resume 数据检查。

检查完整动作维度、horizon、数值观测时间长度和有限性，以及实际 RGB/点云布局、dtype、多任务文本和手部 action_context；输出配置名、窗口摘要、实际 batch 形状与检查数量。点云依据 Dataset 原始/随机减点配方检查，不使用模型 FPS 后点数；RGB 可以是 HWC uint8 或预处理后的 CHW uint8/float。

Dataset 仍会执行生产有效性扫描，normalizer 仅对有效训练窗口消费的源行流式统计；LatentFlow relative action 按窗口/reference 统计，`--max-batches` 不截断统计总体，不保证恒定耗时。验证集通过 `get_validation_dataset()` 获取，使用自身的无增强配方，不重新拟合统计；没有验证集明确报告“无 holdout”。提前停止或异常退出时清理 DataLoader worker。

DDP 配置按单进程检查数据，不表示 DDP 验证通过。临时 Zarr 配合真实 Dataset 的检查属于合成数据验证，不能代替实际训练数据检查；也不验证模型权重、梯度或仿真。

## 手部策略定向 CPU 检查

```bash
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python -m unittest discover -s tests -v
```

使用真实小规模 VQ、码本、LAMP prior/head 和 Sparse3D 组件，需可在 CPU 上运行的 PyTorch3D 算子。覆盖 DQ 导出/重载后的 lookup 误差、固定模型评估和选点；LAMP 历史噪声、损失公式、梯度、日志开关及当前格式 checkpoint 的 Builder/训练状态恢复和 raw 推理；同时检查默认 diffusion、原始坐标、prior-feature 优化、train-only 统计、时序、分组裁剪及 LR/KL 边界。产物写入临时目录并清理，不下载权重或启动 W&B。

LatentFlow 检查覆盖未来窗口、增强前 q0、relative 统计、真实 Sparse3D/DiTX/HandVAE 梯度、零权重跳过 decoder、固定 EMA、独立 codec 选点以及外部 codec 删除后的 raw/EMA 推理和部署。续训检查集中在同源迁移回归：使用首次构建时固定 manifest 的临时 Zarr，删除外部 codec，经 Dataset → Builder → restore_training_state → Trainer 比较连续训练和恢复的下一次更新，核对模型、optimizer、scheduler、EMA、RNG 与训练游标；稳定 source_id 允许迁移，缺少稳定 source_id 的索引 manifest 拒绝迁移。逐字段负例确认身份、划分、dt 和其他路径没有被排除。选点测试对已实际评估的标量施加可控排序，确认早期权重最终落盘且完整预算执行；它不证明训练质量。

配置边界测试拒绝错配的 LatentFlow Policy/Dataset 及动作时间轴不同的多任务组合。多任务采样回归检查两个模拟 rank 的游标恢复、跨 epoch 顺序、固定验证覆盖、零权重任务和 loader 几何改变时的恢复拒绝；它不运行多进程 DDP。

这些检查使用合成数据和临时 checkpoint，不替代实际数据上的 CUDA/compile 完整 smoke、DDP 或闭环评测。

## 完整 smoke 与短训练

```bash
python dexmani_policy/smoke_test.py dp3 --max-updates 4
bash scripts/training/train.sh dp3 'task_name=<task>' '+max_updates=4'
```

完整 smoke 需要 CUDA、实际数据及配置所需权重/手部产物，默认做 4 次 optimizer update，检查有限参数更新、保存状态、预测及 raw/EMA 推理恢复；正常或异常退出均释放 DataLoader worker、关闭 Workspace 并清理临时目录，不创建 W&B run。它不执行完整续训或 DDP，续训需另用训练入口验证。

第二条用于覆盖配置或保留短跑产物，会创建正常实验和日志；`workspace.wandb_cfg=null` 可关闭 W&B。`max_updates` 只限制本次执行，不改变总计划、warmup 或编译配方。首步学习率可能为零，验证参数变化需给原 schedule 足够的更新预算。

## SAT / DQ-RISE smoke

```bash
python dexmani_policy/smoke_test.py --config-only sat dqrise ddp/sat ddp/dqrise
python dexmani_policy/smoke_test.py sat --max-updates 4
python dexmani_policy/smoke_test.py dqrise --max-updates 4
```

Config-only 检查配置与 Hydra target 模块导入；完整 smoke 检查模型更新、预测及 checkpoint 恢复，需要 CUDA、实际数据和匹配产物。DQ 完整 smoke 必须使用真实 Codebook；可将明确设置了 Codebook 和相同数据/split 的独立实验 YAML 路径传入。正式配置保留 `codebook_path=null`，缺少产物时应失败。LAMP 同样需要当前 raw prior；两者完整 smoke 都需显式共享 manifest，准备方式见 [手部动作表示](手部动作表示.md#数据与准备)。CUDA、DDP、compile 和真实评测须分别验证。

## LatentFlow / HandVAE

```bash
python -m unittest discover -s tests -p test_latent_flow.py -v
python -m unittest discover -s tests -p test_training_contracts.py -v
PYTHONPATH=tests python -m unittest test_lamp_bc.LAMPBCTests.test_builder_resume_and_inference -v
python dexmani_policy/smoke_test.py --config-only latent_flow
python dexmani_policy/smoke_test.py --data-only latent_flow --max-batches 2
python dexmani_policy/smoke_test.py latent_flow --max-updates 4
```

HandVAE 使用独立配置和 Dataset，不能交给 policy config-only 验证。上述定向测试在合成数据上执行真实 Torch 优化、验证指标计算与产物加载，真实 codec 的 held-out MAE/KL 必须另用实际产物和验证数据验收；完整预训练命令见 [手部动作表示](手部动作表示.md#独立-handvae-预训练)。完整 policy smoke 需与当前未来窗口契约匹配的 codec.pt；缺少权重时不使用旧 codec 冒充通过。

若 sandbox 阻断 CUDA 或多 worker IPC，获授权后优先在 sandbox 外使用原配置验证。只能在受限环境检查数据时，可将加载后的配置保存为临时独立 YAML，仅设置 `dataloader.num_workers=0、persistent_workers=false、prefetch_factor=null`，再传给 data-only smoke。单进程通过不代表原多 worker 路径通过；不修改正式配置或向 smoke 传 Hydra overrides。CPU、真实数据、CUDA/BF16、compile、DDP 和闭环分别报告，缺少匹配 codec 时不能用合成 codec 代替真实完整 smoke。

## 基础设施与跨仓库离线检查

```bash
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python -m unittest discover -s tests -p test_infrastructure.py -v
# 从 dexmani_real 根目录，用安装了两个仓库的环境执行；无设备连接
python scripts/check_deployment.py
```

基础设施测试使用合成环境，覆盖完整 future_actions 与双端 dtype、固定预算/平局/全失败排序、平面统计、普通评测独立性、直接 best/旧指针迁移与显式证据验真、发布失败、冻结参数、seed 精确覆盖、加载/rollout/收尾失败前缀、记录与清理双重失败、视频进程回收、RTC 局部 autograd、数据 seed/padding 解耦和 trial 划分。它不运行真实模拟器闭环。

Real 的脚本使用 unittest、mock 与可控时钟，覆盖模式准入、异步迟到/过期/撤权、reset 后旧预测隔离、单在途查询及关闭、轻量结果必存/Raw 可选、模型启动失败时结果收尾和产物 I/O 失败。它不连接设备，不运行 pytest/Ruff，不证明硬件停止或安全。本轮结果见下表，上一轮执行记录见 [实施状态](infra_simplification_status.md)。
