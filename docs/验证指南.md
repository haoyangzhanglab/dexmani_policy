# DexMani_Policy 验证指南

命令从仓库根目录执行，使用已安装依赖的 Conda `policy` 环境。按 [协作规则](../AGENTS.md#验证) 选择覆盖当前风险的检查。

## Config-only smoke

```bash
conda activate policy
python dexmani_policy/smoke_test.py --config-only dp dp3 dqrise sat r3d \
  maniflow multitask_dit lamp temporal_codec_flow
python dexmani_policy/smoke_test.py --config-only \
  ddp/dp ddp/dqrise ddp/maniflow ddp/multitask_dit ddp/r3d ddp/sat
```

检查配置、策略/训练/Dataset/增强类导入及其他 Hydra target 模块，不加载数据、实例化模型或执行 GPU 算子。它不验证权重、仿真或 DDP 可运行。

Smoke 接受多个配置名或显式 `.yaml` 路径，共用 Hydra loader（含 `defaults`）；不接受 Hydra 字段覆盖。

## Data-only smoke

```bash
python dexmani_policy/smoke_test.py --data-only dp3 --max-batches 2
python dexmani_policy/smoke_test.py --data-only dp multitask_dit lamp temporal_codec_flow
```

`--data-only` 与 `--config-only` 互斥。使用 CPU 上的生产 Dataset、normalizer 和训练 DataLoader，不构建模型、optimizer、EMA、Workspace 或仿真环境，不下载权重或创建 W&B run。`--max-batches` 默认 2，分别限制训练和已有验证集的 batch 检查数量，只在 data-only 模式使用；不支持 resume 数据检查。

检查完整动作维度、horizon、数值观测时间长度和有限性，以及实际 RGB/点云布局、dtype、多任务文本和手部 action_context；输出配置名、窗口摘要、实际 batch 形状与检查数量。点云依据 Dataset 原始/随机减点配方检查，不使用模型 FPS 后点数；RGB 可以是 HWC uint8 或预处理后的 CHW uint8/float。

Dataset 仍会执行生产有效性扫描，normalizer 仍对完整 replay buffer（含 holdout）统计，`--max-batches` 不截断统计总体，不保证恒定耗时。验证集通过 `get_validation_dataset()` 获取，使用自身的无增强配方，不重新拟合统计；没有验证集明确报告“无 holdout”。提前停止或异常退出时清理 DataLoader worker。

DDP 配置按单进程检查数据，不表示 DDP 验证通过。临时 Zarr 配合真实 Dataset 的检查属于合成数据验证，不能代替实际训练数据检查；也不验证模型权重、梯度或仿真。

## Python 语法检查

```bash
python -m compileall -q dexmani_policy
```

检查 Python 文件能否编译，不执行模块导入或运行逻辑。

## 数据、训练与推理接口定向检查

```bash
python -m unittest discover -s tests -v
```

使用临时合成 Zarr 和 CPU 小模型，覆盖窗口 padding、有效性筛选、完整 buffer 统计、增强存储隔离、Zarr 序列化重开、多任务布局、手部上下文、预训练批次遍历、尾部梯度累积及跨 epoch 保存恢复。恢复检查比较 raw/EMA 参数、采样顺序、scheduler 和 RNG，拒绝错误游标及数据长度。

推理接口检查显式观测模态、normalizer 维度、多任务点云通道、训练到部署的数值配方及物理动作输出，并拒绝缺少当前字段的 checkpoint。定向检查还覆盖 RGB 数值与几何变换、统计与观测窗口的存储隔离、warmup 合成值、评测参数优先级、分批选点统计及视频编码异常回收。部署观测转换检查在 CUDA 可用时同时覆盖 GPU。

入口检查覆盖评测 CLI 参数传递、必需的 seed/录像来源、合成数据的 data-only smoke、归一化总体与 raw/EMA 保存校验、输出目录保护及异常退出清理；DDP 入口使用 mock 检查设备分配与恢复分支，不启动通信进程组。

这些检查使用合成输入或 mock，不下载权重或创建 W&B run，不能代替实际数据、CUDA、DDP 和闭环 smoke。

## 完整 smoke 与短训练

```bash
python dexmani_policy/smoke_test.py dp3 --max-updates 4
bash scripts/training/train.sh dp3 'task_name=<task>' '+max_updates=4'
```

完整 smoke 需要 CUDA、实际数据及配置所需权重/手部产物，默认做 4 次 optimizer update，检查有限参数更新、保存状态、预测及 raw/EMA 推理恢复；正常或异常退出均释放 DataLoader worker、关闭 Workspace 并清理临时目录，不创建 W&B run。它不执行完整续训或 DDP，续训需另用训练入口验证。

第二条用于覆盖配置或保留短跑产物，会创建正常实验和日志；`workspace.wandb_cfg=null` 可关闭 W&B。`max_updates` 只限制本次执行，不改变总计划、warmup 或编译配方。首步学习率可能为零，验证参数变化需给原 schedule 足够的更新预算。

## SAT / DQ-RISE smoke

```bash
python dexmani_policy/smoke_test.py --config-only sat dqrise ddp/sat ddp/dqrise
python dexmani_policy/smoke_test.py sat --max-updates 4
python dexmani_policy/smoke_test.py dqrise --max-updates 4
```

Config-only 检查配置与 Hydra target 模块导入；完整 smoke 检查模型更新、预测及 checkpoint 恢复，需要 CUDA、实际数据和匹配产物。DQ 完整 smoke 必须使用真实 Codebook；可将明确设置了 Codebook 和相同数据/split 的独立实验 YAML 路径传入。正式配置保留 `codebook_path=null`，缺少产物时应失败。CUDA、DDP、compile 和真实评测须分别验证。

配置检查、data-only、完整 smoke、多卡和闭环分别验收。检查只覆盖当前产物结构，不证明真实成功率或加速比例；sandbox 无法访问 CUDA 也不说明主机没有 GPU。通过与缺口按 [AGENTS.md](../AGENTS.md#验证) 报告。
