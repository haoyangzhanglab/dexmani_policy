# 仿真数据集格式

仿真示范数据存放于 `robot_data/<task_name>.zarr`，每个任务对应一个本地 Zarr v2 目录，多个 episode 沿时间轴拼接。本文以当前数据规格为准：`T` 表示总帧数，`E` 表示 episode 数。

## 存储结构与回合切分

```text
<task_name>.zarr/
├── .zattrs       # 任务、动作空间、控制时序和机器人配置
├── data/         # 逐帧数组，第一维为 T
└── meta/         # 逐回合数组，第一维为 E
```

`meta/episode_ends` 保存每个 episode 的累计结束位置，采用左闭右开切片。例如 `[100, 250]` 对应两个 episode：`[0:100]` 和 `[100:250]`。边界必须为正且严格递增，最后一个值等于所有 `data/*` 数组的第一维长度。

**切分 episode 使用 `episode_ends`。** `done` 可能在成功后的多帧中连续为真，不能作为回合分隔符。

## 逐帧字段

| `data/` 字段 | Shape | dtype | 含义 |
| --- | --- | --- | --- |
| `joint_state` | `(T, 19)` | float32 | 实测关节位置，单位 rad |
| `action` | `(T, 19)` | float32 | 实际执行的绝对关节目标，单位 rad |
| `action_ee` | `(T, 21)` | float32 | 末端位置 3 + rotation-6D 6 + 手部关节目标 12 |
| `eef_pose` | `(T, 9)` | float32 | 实测末端位置 3 + rotation-6D 6 |
| `fingertip_xyz` | `(T, 5, 3)` | float32 | 五个指尖的位置，单位 m |
| `finger_tactile_force` | `(T, 5, 3)` | float32 | 五指接触力，单位 N，按物理子步平均 |
| `rgb` | `(T, 240, 320, 3)` | uint8 | HWC 图像，取值范围 `[0, 255]` |
| `depth` | `(T, 240, 320)` | uint16 | 深度，单位 mm；0 表示无效 |
| `segmentation` | `(T, 240, 320)` | uint8 | 映射后的语义标签 |
| `camera_intrinsic` | `(T, 9)` | float32 | 展平的 OpenCV `3×3` 内参，首像素中心为 `(0,0)`；`Camera.get_camera_config()` 导出前将 SAPIEN 原生 K 的 `cx/cy` 各减 `0.5`，读取端直接使用保存值 |
| `camera_extrinsic` | `(T, 12)` | float32 | 展平的 `3×4` world→camera CV 外参，直接将世界系点云变换到相机系 |
| `point_cloud` | `(T, 1024, 6)` | float32 | 相机可见场景点云，XYZRGB |
| `hand_pointcloud` | `(T, 1024, 6)` | float32 | 手部模型表面点云，XYZRGB |
| `object_pointcloud` | `(T, 1024, 6)` | float32 | 任务物体完整表面点云，XYZRGB |
| `done` | `(T,)` | bool | 本步执行后的终止标记 |

历史 SAPIEN 文件若仍保存原生内参，导入前将 `cx/cy` 各减 `0.5`；已校正文件及 OpenCV 标定无需重复处理，HDF5→Zarr 转换只复制保存值。

关节顺序为 `arm:7 → thumb:3 → index:3 → middle:2 → ring:2 → pinky:2`。五指位置和接触力均按 `thumb/index/middle/ring/pinky` 排列。

末端位置、指尖位置、点云 XYZ 和接触力均使用世界坐标系；位置单位为 m。令 `R=rotation_world_from_eef`，rotation-6D 按前两列依次拼接：`cat([R[..., :, 0], R[..., :, 1]])`。列向量满足 `p_world=R@p_eef+eef_xyz`；行向量的局部指尖位置为 `(fingertip_xyz-eef_xyz[:, None]) @ R`，右乘 R。当前关节控制数据中的 `action_ee` 由执行关节目标通过 FK 得到，区别于实测 `eef_pose`。

`joint_state`、`eef_pose` 和 `fingertip_xyz` 须按同一观测时刻对齐，每个历史帧使用该帧的实测旋转。`HandStateEncoder` 的 wrist 槽直接采用此末端原点和坐标轴，不额外假定为掌心或触觉传感器框架，不通过动作目标或在线 FK 替代实测位姿。

点云 RGB 取值为 `[0, 1]`。`point_cloud` 来自相机观测，经裁剪、体素下采样和采样得到；`hand_pointcloud`、`object_pointcloud` 来自几何模板，使用固定表面颜色并包含遮挡部分。物体点云的 1024 点由各任务物体共享，普通 clutter 不包含在内。

## 数据使用约定

训练使用的数据版本不就地改写。数据生产方应保证浮点数据转换为 FP32 后仍有限；Dataset 构造检查必要结构，增强与 affine 在组装处验证，外部 Runtime 每次检查形状和有限性。Dataset 不自动全量扫描，Sparse3D 内部不重复每 batch 扫描。

存储与 Runtime 外部 RGB 接口使用 HWC uint8。公共预处理固定输出连续 CHW uint8，ImageProcessor 在插值和 mean/std 标准化前转为 FP32 并除以 255；模型内部已有 FP32 输入直接沿用。保留 resize/crop/颜色增强顺序及最终 uint8 量化时机。checkpoint 只使用当前配方，废弃参数明确拒绝，不自动迁移。触觉输入要求实际五指 Tensor，合法零力有效；缺测协议不在当前支持范围，未来监督仍使用真实后继 mask。

## 动作时序

根属性声明 `obs_alignment = "obs[t]_before_action[t]"`，即：

```text
obs[t] → 执行 action[t] → obs[t+1]，同时产生 done[t]
```

每个 episode 的观测数与动作数相同，最后一次动作执行后的观测不单独保存。当前数据的 `action_space="joint"`，控制周期 `dt≈0.0625 s`（16 Hz），物理周期 `physics_dt≈1/240 s`，每步执行 `frame_skip=15` 个物理子步。

`.zattrs` 还记录 `task_name`、`action_dim` 和 `robot_setup_json`；后者保存机器人基座位姿及初始关节配置。JSON 字符串字段需要解析后使用。

## 回合元信息

`meta/` 下的数组长度均为 `E`，第 i 项对应第 i 个 episode。

| 字段 | 内容 |
| --- | --- |
| `episode_ends` | int64，累计结束边界 |
| `episode_seeds` | int64，回合生成 seed |
| `success_frame_idx` | int64，首次成功的回合内帧索引，从 0 开始；未成功为 -1 |
| `physics_static_friction`、`physics_dynamic_friction`、`physics_mass_scale` | float64，回合物理参数记录；未记录时为 NaN |
| `outcome_json` | 成功、失败、截断、轨迹质量和生成诊断 |
| `scene_info_json` | 场景实例、缩放、物理参数和初始化信息 |
| `simulation_config_json` | 仿真配置快照 |
| `observation_geometry_json` | 几何坐标系、物体角色、部件及点数分配 |

`*_json` 均为字符串。成功与轨迹质量是不同标记；Dataset 不会自动根据 `outcome_json` 筛选回合。

## 训练读取

[DemonstrationDataset](../dexmani_policy/datasets/demonstration.py) 根据 `sensor_modalities` 选择观测字段，根据 `action_key` 选择动作表示，输出 `{"obs": {...}, "action": Tensor}`。

普通 Dataset 以 `horizon=16`、`obs_horizon=2`、关节动作和点云观测为例，单个样本为：

```text
obs.joint_state: (2, 19)
obs.point_cloud: (2, 1024, 6)
action:         (16, 19)
```

窗口不跨 episode，配置 padding 时重复回合边缘帧；组成 batch 后增加首维 `B`。存盘数据保留物理量和原始图像格式，归一化及图像预处理由训练配置决定。划分、归一化和方法专属窗口约定见[项目架构](项目架构.md#数据接口)。

InterAct-Dex 已接入 `HandStateEncoder → HandSceneFusion`，并将交互历史与 `SceneTokenizer` 场景 token 拼接。sim 原始世界系力先按每帧自己的 EEF 姿态旋转，再归一化；默认 limits 在训练源帧的同一 EEF 系拟合三轴共享 Min-Max，显式 RMS/MaxAbs 保留世界系原始标量统计。调用方随后合并 batch/time；身体锚点和 patch 中心仍是世界系米制坐标，局部几何方向使用末端轴。完整约定见[观测归一化](项目架构.md#handstateencoder-与-handscenefusion)。

InterAct 辅助权重为0时使用普通 `DemonstrationDataset`，不产生未来力监督字段；正权重时使用 `InterActDexDataset`，保留普通观测/动作窗口，额外提供 batch 顶层的 `future_force[B,1,5,3]`（FP32）和 `future_force_valid[B,1]`（bool）。`interaction_horizon` 必须为正整数，默认 `4`：query 行为 q 时读取 `q+4`，与实际执行长度 C 独立。有效性依据未裁剪的目标行计算，同一 episode 内存在后继行才有效；合法零值有效，无效标签用 episode 末行占位，全无效窗口保留。

标签只进入 loss，五指预测特征来自与动作共享的 `CoupledDiTX` 主干。仿真残差先在世界系计算 `F[q+4]-F[q]`，再用 query 时刻的末端旋转转到 EEF 系，并乘已有触觉 normalizer 的 scale；不读取未来位姿或另拟合统计。默认16步动作、4帧观测和前后各3帧 padding 对长度 L 的 episode 产生 `max(0,L-9)` 个窗口，已有窗口的 +4 标签均有效，但不覆盖全部 episode 尾部 query。动态状态、mask 和推理生命周期见[项目架构](项目架构.md#interact-dex-动作耦合交互状态预测)。
