# 仿真数据集格式

仿真示范数据按任务存放在 `robot_data/<task_name>.zarr`，采用 Zarr v2。一个任务包含多个 episode，逐帧数据沿时间轴拼接，回合边界单独记录。本文中 `T` 表示总帧数，`E` 表示 episode 数。

## 数据组织与回合边界

| 位置 | 内容 |
| --- | --- |
| 根属性 `.zattrs` | 任务、动作空间、控制时序与机器人配置 |
| `data/` | 逐帧观测、动作与终止标记，第一维为 `T` |
| `meta/` | 回合边界与逐回合元信息，第一维为 `E` |

`meta/episode_ends` 保存各 episode 的累计结束位置，采用左闭右开切片。例如 `[100, 250]` 表示两个回合，分别为 `[0:100]` 和 `[100:250]`。边界为正且严格递增，最后一个边界等于总帧数。

**回合切分以 `episode_ends` 为准。** 成功后的多帧可能连续出现 `done=true`，因此 `done` 不能用来寻找回合边界。

## 逐帧字段

| `data/` 字段 | Shape | dtype | 含义与单位 |
| --- | --- | --- | --- |
| `joint_state` | `(T, 19)` | float32 | 实测关节位置，rad |
| `action` | `(T, 19)` | float32 | 实际执行的绝对关节目标，rad |
| `action_ee` | `(T, 21)` | float32 | 末端目标位置 3 + rotation-6D 6 + 手部关节目标 12 |
| `eef_pose` | `(T, 9)` | float32 | 实测末端位置 3 + rotation-6D 6 |
| `fingertip_xyz` | `(T, 5, 3)` | float32 | 五指指尖位置，m |
| `finger_tactile_force` | `(T, 5, 3)` | float32 | 五指接触力，N；按物理子步平均 |
| `rgb` | `(T, 240, 320, 3)` | uint8 | HWC 图像，取值 `[0, 255]` |
| `depth` | `(T, 240, 320)` | uint16 | 深度，mm；0 表示无效 |
| `segmentation` | `(T, 240, 320)` | uint8 | 映射后的语义标签 |
| `camera_intrinsic` | `(T, 9)` | float32 | 展平的 OpenCV `3×3` 相机内参 |
| `camera_extrinsic` | `(T, 12)` | float32 | 展平的 `3×4` world→camera CV 外参 |
| `point_cloud` | `(T, 1024, 6)` | float32 | 相机可见场景点云，XYZRGB |
| `hand_pointcloud` | `(T, 1024, 6)` | float32 | 手部模型完整表面点云，XYZRGB |
| `object_pointcloud` | `(T, 1024, 6)` | float32 | 任务物体完整表面点云，XYZRGB |
| `done` | `(T,)` | bool | 本步动作执行后的终止标记 |

## 物理量与坐标约定

关节顺序为 `arm:7 → thumb:3 → index:3 → middle:2 → ring:2 → pinky:2`。指尖位置和接触力均按 `thumb/index/middle/ring/pinky` 排列。

末端位置、指尖位置、点云 XYZ 和接触力使用世界坐标系，位置单位为 m。rotation-6D 依次拼接旋转矩阵 `R=rotation_world_from_eef` 的前两列，满足 `p_world = R @ p_eef + eef_xyz`。因此，世界系指尖位置转换为末端局部坐标时，对行向量使用 `(p_world - eef_xyz) @ R`。

`joint_state`、`eef_pose` 与 `fingertip_xyz` 对齐到同一观测时刻；历史帧使用各自的实测末端旋转。手部身体表征以这个末端原点和坐标轴定义 wrist，不额外假定为掌心或传感器坐标系。当前关节控制数据的 `action_ee` 由执行目标经正向运动学得到，不能替代实测 `eef_pose`。

相机内参采用首像素中心为 `(0,0)` 的 OpenCV 约定，读取时直接使用保存值。外参将世界系点变换到相机系，用于点云与图像的几何对应。

点云颜色范围为 `[0,1]`。`point_cloud` 来自相机观测；`hand_pointcloud` 和 `object_pointcloud` 来自几何模板，使用固定表面颜色并包含遮挡部分。物体点云的 1024 点由任务物体共享，不包含普通 clutter。

## 观测与动作时序

根属性 `obs_alignment="obs[t]_before_action[t]"` 表示：`obs[t] → 执行 action[t] → obs[t+1]`，同时产生 `done[t]`。每个 episode 的观测数与动作数相同，最后一次动作执行后的观测不单独保存。

当前数据采用 `action_space="joint"`。控制周期约为 `0.0625 s`（16 Hz），物理周期约为 `1/240 s`，每个动作执行 15 个物理子步。根属性还记录 `task_name`、`action_dim` 及 `robot_setup_json`；机器人配置包含基座位姿与初始关节状态。

## 回合元信息

`meta/` 中每项的第 i 个值对应第 i 个 episode。

| 字段 | 含义 |
| --- | --- |
| `episode_ends` | int64，累计结束边界 |
| `episode_seeds` | int64，回合生成 seed |
| `success_frame_idx` | int64，首次成功的回合内帧索引，从 0 开始；未成功为 -1 |
| `physics_static_friction`、`physics_dynamic_friction`、`physics_mass_scale` | float64，回合物理参数；未记录时为 NaN |
| `outcome_json` | 成功、失败、截断与轨迹质量等生成记录 |
| `scene_info_json` | 场景实例、缩放、物理参数与初始化信息 |
| `simulation_config_json` | 仿真配置快照 |
| `observation_geometry_json` | 几何坐标系、物体角色、部件与点数分配 |

`*_json` 字段以 JSON 字符串保存。成功与轨迹质量是不同标记，训练读取不会自动依据 `outcome_json` 筛选回合。

## 训练中的使用方式

策略按所需模态选择观测字段，并在自身支持范围内选择关节目标或末端目标。训练样本由一段观测历史与动作窗口组成，窗口不跨 episode；启用边缘 padding 时重复回合首尾帧。训练与留出数据按 episode 划分，新拟合的统计只使用对应训练回合；预训练编码器或固定先验沿用各自输入尺度。存盘数据保留物理量与原始图像格式。

InterAct-Dex 使用五指 aggregate 接触力，并可在同一回合内读取未来力作为辅助监督。合法零力是有效观测，越过回合末尾的未来目标不参与监督；未来标签的有效性与动作前缀条件分别定义。关闭未来力辅助监督时，无需读取这些未来标签。

观测编码、窗口与归一化机制见[项目架构](项目架构.md)，手部动作的不同建模方式见[手部动作表示](手部动作表示.md)。
