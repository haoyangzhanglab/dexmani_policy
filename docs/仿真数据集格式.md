# 仿真数据集格式

仿真示教按任务保存为 Zarr 数据集，每个任务包含多个 episode（回合）。数据模块将连续轨迹转换为策略学习所需的时序样本。

## 回合与时序

每帧记录动作执行前的观测，以及随后执行的动作目标：

**当前观测 → 执行动作目标 → 下一帧观测**

实测关节状态描述机器人当时的位置，动作描述希望到达的目标，两者不能互相替代。实测末端位姿与末端动作目标也具有同样区别。

回合边界由独立的回合记录确定。训练窗口不会跨回合，动作后的终止标记用于描述交互状态。

## 主要模态

| 模态 | 内容与用途 |
| --- | --- |
| 机器人状态 | 关节位置、实测末端位姿和指尖位置，描述身体状态与手部几何 |
| 图像与标定 | RGB、深度及相机参数，用于视觉编码和图像与点云的空间对应 |
| 场景点云 | 相机可见的场景几何，为策略提供空间条件 |
| 手部与物体点云 | 来自几何模板的形状信息，可包含遮挡表面，用于手物交互建模 |
| 触觉 | 仿真中的五指汇总接触力，用于当前接触感知和未来力监督 |
| 动作 | 绝对关节目标或末端位姿与手部目标，作为策略学习的监督 |

各方法使用不同模态组合。几何计算依赖一致的坐标与物理单位；仿真汇总力与真实密集触觉具有不同来源，不能仅凭字段相似互换。

策略训练使用 `object_pointcloud` 时，Zarr 根属性必须提供 `hoi_pcd`：`task_name` 是非空字符串且等于训练任务，`object_names` 是非空、无重复的非空字符串列表，`template_sha256` 是 64 位十六进制字符串；点云存储为 `float32[T,1024,3]`。Hash 绑定固定点索引、对象顺序和实际 Mesh，不能用任意占位值代替。训练只将这三个字段传入 Checkpoint，并将 Hash 统一为小写，不修改源数据；续训和真机部署检查同一任务与模板。不使用 `object_pointcloud` 的策略不读取或传递该属性。

## 从轨迹到训练样本

数据模块按方法需要提取观测历史和动作窗口，再交给策略编码与学习。训练与留出数据按回合划分，新拟合的归一化统计仅使用训练回合。

观测预训练可从轨迹中学习场景变化或手物接触关系；触觉方法还可使用同一回合的后继观测构造未来力目标。它们提供的监督不同于动作目标。

模块关系见[项目架构](项目架构.md)，触觉的作用见[触觉与交互建模](触觉与交互建模.md)。
