# 仿真数据集格式

仿真示教按任务保存为 Zarr，每个数据集包含多个 episode（回合），路径由 `zarr_path` 指定。数据模块将连续轨迹转换为策略学习所需的时序样本。

## 回合与时序

Zarr 的 `data/` 沿时间轴保存各模态，`meta/episode_ends` 标记回合边界。根属性 `task_name`、`dt`、`action_space` 分别描述任务、控制周期和采集动作空间。

| 来源 | action_space | 监督字段 | 本体状态 |
| --- | --- | --- | --- |
| dexmani_sim | `joint` | `action`（19 维）或 FK 派生的 `action_ee`（21 维） | `joint_state`（19 维） |
| DexJoCo | `eef_rotvec` | `action_rotvec`（单臂 22 / 双臂 44 维） | `proprio`（单臂 23 / 双臂 46 维） |

DP/DP3 通过 `agent.state_key` 选择本体状态字段。DexJoCo 配方从数据推导状态和动作维度，并与模型配置一起保存到 checkpoint。

每帧记录动作执行前的观测，以及随后执行的动作目标：

**当前观测 → 执行动作目标 → 下一帧观测**

实测关节状态描述机器人当时的位置，动作描述希望到达的目标，两者不能互相替代。控制周期随策略 checkpoint 保存，用于保持训练与执行的时间尺度一致。

## 主要模态

| 模态 | 内容与用途 |
| --- | --- |
| 机器人状态 | 关节位置、实测末端位姿和指尖位置，描述身体状态与手部几何 |
| 图像与标定 | RGB、深度及相机参数，用于视觉编码和图像与点云的空间对应 |
| 场景点云 | 相机可见的场景几何，为策略提供空间条件 |
| 手部与物体点云 | 来自几何模板的形状信息，可包含遮挡表面，用于手物交互建模 |
| 触觉 | 仿真中的五指汇总接触力，用于接触感知和未来力监督 |
| 动作 | 绝对关节目标，或末端位姿与手部目标；旋转表示由监督字段决定 |

各方法使用不同模态组合，几何计算依赖一致的坐标与单位。字段定义与读取入口分别位于 [common/config.py](../dexmani_policy/common/config.py) 和 [datasets/episode_store.py](../dexmani_policy/datasets/episode_store.py)。

## 几何坐标

当前 `dexmani_sim` 的 `BaseEnv.load_robot()` 未指定 `root_pose`，`XArm7XHand` 将默认单位位姿 `sapien.Pose()` 传给 `set_root_pose()`，因此 World 与 Base 重合。场景点云经 Camera Model Matrix 转入 World，`eef_pose` 和 `fingertip_xyz` 来自 Entity Pose，其数值已满足 Base-aligned 输入约定；`camera_extrinsic` 的 World→Camera 也就是 Base→Camera。此结论仅针对当前仿真设置。

`dexmani_real` 的 `PointCloudProcessor` 通过 `T_xarm_base_from_color` 将 RGB-D 点云转换到 xArm Base，`ArmFK` 从 `link_base` 计算 EEF，`hand_geometry()` 输出 Base 系指尖与手部点云，导出的相机外参为 Base→Camera。

上述 dexmani_sim 与 dexmani_real 数据可直接输入[多模态交互编码器](触觉与交互建模.md#多模态交互编码器)，无需额外存储坐标变换。

DexJoCo 的 DP/DP3 使用其 MuJoCo 世界坐标系：点云 XYZ 单位为米，RGB 范围为 [0,1]，TCP 状态和目标沿用原生环境。双臂排列为右臂位姿、右手、左臂位姿、左手；状态四元数为 wxyz，策略动作使用旋转向量。它不使用 xArm 的 Base 坐标或 rotation-6D 动作约定。

## 从轨迹到训练样本

1. 仿真按独立回合划分训练与留出数据，新拟合的归一化统计仅使用训练回合。Real 数据按原始采集分组；`val_episodes`、`max_train_episodes` 计采集组，不计连续段。
2. 在所选回合内提取观测历史与动作窗口；窗口不跨回合，padding 重复本回合首尾帧。
3. 按方法补充上一条动作、接触标签或未来力等输入与监督，再交给策略学习。

当前 Real 导出在根属性保存逐段 `source_episodes` 和 `source_row_ranges=[start, stop)`，两者与 `meta/episode_ends` 等长。不同路径下同名采集仍是不同组；同源多个段必须在同一划分中。该来源要求适用于策略、观测预训练和 VQ 手部先验，不提供旧 Real 来源补录或兼容读取。

核心实现位于 [datasets/](../dexmani_policy/datasets/)，模块关系见[项目架构](项目架构.md)。
