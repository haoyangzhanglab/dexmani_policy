# dexmani_policy 全仓审查：问题优先级、根因与修复建议

> 状态：Active  
> 审查基线：`550fa8f5af20745eb3abd61e1bfd481f5a7531a8`（2026-09-02）  
> 范围：训练/续训、数据与预处理、Agent/Decoder/Encoder、仿真评测、部署、远程脚本、依赖、测试与文档  
> 目的：将已完成 fact-check 且在当前 `main` 仍成立的问题，整理为适合个人研究项目执行的最小修复路线

## 1. 结论先行

当前最应优先处理的不是代码风格，而是会直接改变模型输入、训练恢复轨迹或评测结论的问题：

1. **R3M 输入尺度错误**会让当前实现与官方 R3M 预处理不等价；修复时还必须处理旧 checkpoint 兼容性。
2. **MultiTask 评测入口和统计口径错误**会崩溃或产生超过 100% 的成功率，不能用于模型选择。
3. **评测异常分类缺失**会把配置错误、CUDA OOM、模型异常等记为任务失败；新增 ActionFlow NFE 校验仍可能被吞掉并产出虚假的 0%。
4. **checkpoint/续训状态不完整**会改变 LR、EMA、样本序列和 epoch 轨迹；当前“重跑同一命令自动续训”的文档承诺不成立。
5. **部署 parity 检查发生在 selector 发布之后**，parity 失败不等于没有发布。

建议先完成 P0 和 P1，再继续比较新模型、校准 NFE 或发布部署 artifact。P2/P3 以“小步修复、补契约测试”为主，不建议借机重构整个框架。

## 2. 排序口径

优先级综合以下三个维度，不采用看似精确但缺乏数据支撑的数值打分：

- **影响**：是否会改变训练数据/模型输入、丢失训练进度、污染评测结果或错误发布；
- **可达性**：默认配置是否触发，还是只在可选功能、非法 override 或非默认 shape 下触发；
- **修复收益**：能否用较小改动封住一类问题，并建立稳定回归测试。

| 优先级 | 含义 | 处理要求 |
|---|---|---|
| P0 | 会直接产生错误实验结论或错误模型输入 | 暂停依赖该路径的新比较，立即修复 |
| P1 | 影响训练恢复、评测有效性、发布正确性或运维安全 | P0 后优先处理；进入长期训练/发布前完成 |
| P2 | 条件触发的正确性、可靠性、复现性或显著效率问题 | 按实际启用路径分批处理 |
| P3 | 文档、注释、API 清晰度和低风险维护债 | 随相关模块修改一并清理 |

## 4. P0：先阻止错误实验结论

### 4.1 R3M 预处理与 checkpoint 兼容

**现象**

`dexmani_policy/agents/obs_encoder/rgb/r3m.py` 对 dataset 已归一化到 `[0,1]` 的 RGB 再乘 255，随后直接执行 ImageNet Normalize；官方 R3M 路径对 `[0,255]` 输入会先除以 255。两者不等价。

**根因**

- dataset、image processor 和 backbone 都隐式拥有输入范围转换责任；
- 代码没有显式的 `preprocess_version` 或输入范围断言；
- 只检查 tensor shape，没有把“数值域”作为模型契约的一部分。

**最小修复**

1. 在 R3M encoder 增加显式模式，例如 `preprocess_version: official_v1 | legacy_255`；新训练默认 `official_v1`。
2. `official_v1` 接收 `[0,1]` 并直接 Normalize；不要先乘 255。
3. checkpoint/config/部署 sidecar 记录该版本；旧 checkpoint 没有字段时明确映射到 `legacy_255`，禁止静默切换。
4. 为历史模型给出二选一策略：保留 legacy 推理，或在官方预处理下重新训练/校准；不要直接混用。

**验收标准**

- 固定图像上，本仓库 `official_v1` 与官方 R3M forward 的预处理张量及 feature 在约定容差内一致；
- legacy checkpoint 加载后仍选择旧预处理，并打印一次明确告警；
- 新 checkpoint 和 deployment artifact 均能追溯预处理版本。

### 4.2 MultiTask 评测 API 与统计

**现象**

- `MultiTaskSimRunner` 没有公共入口调用的 `get_seed_list`；
- 手动绕过后，跨任务展平的成功 episode 数仍可能用单个 seed 列表长度作分母，成功率可超过 1；
- child task 异常时可能从 macro 聚合中被排除，使结果偏乐观；
- `per_task` normalizer 的标准 builder 调用顺序会先触发错误，预期的 unsupported 分支不可达。

**根因**

单任务接口假设“一个 seed 对应一个 episode 集”，而多任务实际样本单位是 `(task, seed)`。当前实现只组合了 runner，没有同时重新定义 seed、失败状态和统计契约。

**最小修复**

1. 明确定义评测单位为 `(task_name, seed)`，`get_seed_list` 返回逐任务映射或由 MultiTask runner 自己展开。
2. 输出至少四个字段：逐任务成功率、macro average、micro average、有效/无效 episode 数。
3. micro 分母必须等于实际有效 episode 数；macro 对所有配置任务求平均，失败任务不得被静默省略。
4. 配置/导入/环境构造失败标记为 `invalid` 并使命令非零退出；只有完整运行后的任务失败才进入成功率分母。
5. 在 builder 入口直接拒绝当前不支持的 `per_task` normalizer，或实现完整分任务 normalizer；不要保留不可达的二段式错误。

**验收标准**

- 2 个任务 × 3 个 seed 固定产生 6 个 episode 单元，micro 分母为 6；
- 任意成功组合的所有成功率均在 `[0,1]`；
- 一个任务基础设施失败时整体结果为 invalid，不能获得“best”；
- 单任务 runner 的既有统计不受影响。

## 5. P1：训练恢复、评测有效性与发布正确性

### 5.1 建立评测异常分类，补齐 ActionFlow fail-fast

**现象**

`BaseRunner.run` 捕获 episode 主路径的所有 `Exception` 并记录 `success=False`。因此非法 midpoint NFE、shape 错误、CUDA OOM、模型异常和真正的任务失败会混在同一指标里。新增 `_resolve_nfe` 虽能拒绝 midpoint 奇数 NFE，但异常发生在 `predict_action` 内，仍可能被 runner 吞掉并产生 0%。

**根因**

runner 只有布尔成功语义，没有区分：

- 配置/契约错误；
- 基础设施或模型执行错误；
- 环境正常运行但任务未成功。

**最小修复**

1. 在构建 env 和 episode 前校验完整 `denoise_timesteps_list`、episodes、seed pool、action slice 和 MultiTask child config。
2. 只把环境正常结束后的任务状态映射为 `success=False`。
3. `ContractError`、OOM、模型 forward、环境构造/损坏异常必须上抛并非零退出；视频编码错误可继续与 episode 指标分离。
4. selector 要求每个候选达到相同且非零的有效样本数；任何候选 invalid 都不能参与 best 选择。

**验收标准**

- midpoint `NFE=3` 在 episode 启动前失败，退出码非零且不生成 0% 结果；
- 注入 OOM/模型异常时 selector 不写 `best_ckpt.json`；
- 真正任务失败仍记录为合法 `success=False`。

### 5.2 修复 checkpoint 与续训语义

**现象**

- Hydra output dir 含时间戳，重新运行命令不会自动找到上一次目录；
- EMA 权重恢复了，但 `EMAUpdater.optimization_step` 没有保存，下一次更新可能以 decay 0 覆盖恢复值；
- RNG、sampler/DataLoader、micro-step 和 epoch 内 batch 位置没有保存；
- 里程碑或中断 checkpoint 可在 epoch 中间保存，但恢复按下一 epoch 启动，可能跳过样本；
- 固定 W&B id 可能续写远端 run，而本地训练实际从头开始。

**根因**

checkpoint 被当作“模型权重快照”，但文档把它描述成“训练过程恢复点”。后者需要保存完整状态机，而不只是 model/optimizer/global step。

**适合个人研究的最小方案**

优先选择**只承诺 optimizer-step/epoch 边界恢复**，不要立即实现任意 micro-batch 的 bitwise resume：

1. 提供显式 `resume_from=<experiment_dir|checkpoint>`，不要跨时间戳目录猜测。
2. 保存 EMA counter、Python/NumPy/Torch/CUDA RNG、scheduler、epoch、batch/optimizer-step 边界标记。
3. milestone 和 interrupt 默认只在已完成 optimizer step 后发布；如果无法保存 sampler 位置，则明确从当前 epoch 开头重放并记录语义。
4. W&B id 由 experiment identity 派生；本地未成功恢复时禁止继续旧 run。

**验收标准**

- 中断前后第一个 optimizer step 的 LR、EMA decay、global step 一致；
- 连续训练与中断恢复在固定小数据集上的最终权重达到约定一致性；
- 文档不再声称“重跑同一命令自动续训”。

### 5.3 DDP、累积尾批和梯度异常

**修复建议**

1. DDP 恢复顺序统一为：构造 optimizer → 构造 scheduler → load optimizer state → load scheduler state。
2. 明确 accumulation 尾部策略：推荐在 epoch 尾执行一次缩放后的 flush；若选择丢弃，则要求 `drop_last`/整除校验并在单卡和 DDP 中一致。
3. `clip_grad_norm_` 的非预期 `RuntimeError` 必须上抛；只处理经过明确识别的 non-finite 分支。
4. DDP debug checkpoint 由真正检测到异常的 rank 提供证据，或汇总每个 rank 的 loss/grad 状态。

### 5.4 parity 通过后再发布

**现象与根因**

`qualify_policy_parity` 先调用 exporter，exporter 已原子切换 selector，之后才比较 direct/export 输出。exporter 自身的 selector-last 和回滚是正确的；问题在 qualification 调用顺序。

**最小修复**

1. exporter 增加 `publish=False` 或输出到候选临时目录；
2. 完成 artifact reload、direct/export parity 和 sidecar 校验；
3. 全部通过后只执行一次原子 selector 更新；
4. parity 失败时清理候选 artifact，selector 保持原值；顺便清理 pre-selector orphan，使同名重试幂等。

### 5.5 远程脚本输入边界

**修复建议**

- `--gpus` 只接受 `^[0-9]+(,[0-9]+)*$`，同时拒绝重复和越界 id；
- policy/task/timestamp/session 只接受明确白名单，不把用户输入拼成远端 shell 代码；
- `SUBPATH` 必须是 clean relative path，拒绝绝对路径、`..`、空组件和符号链接逃逸；
- tmux session 使用仓库专属前缀和 metadata，`--all` 只操作该集合；
- 未知或多余参数立即退出，`--dry-run` 拼错不能退化为真实执行。

### 5.6 预训练权重必须 fail-closed

Uni3D/R3D 权重缺失、下载失败或大范围 key 不匹配时，不应只 warning 后继续随机初始化。要求显式 `allow_random_init=true` 才允许从零训练；否则验证 artifact hash/revision、关键 key 和 loaded ratio 后再继续。

### 5.7 最小 CI，而不是完整 GPU 平台

个人研究仓库不需要先建设昂贵的 GPU CI。建议只增加一个 CPU 快速 workflow：

1. Python AST/compile、YAML/JSON、`bash -n`、Markdown link；
2. ActionFlow contract、normalizer/sampler、MultiTask 纯统计、checkpoint schema、deployment 静态测试；
3. 把 GPU/仿真/Real 测试标记为手动或 nightly，并明确依赖条件。

当前最新树有 83 个静态 test method，其中 68 个仍属于 deployment；新增 ActionFlow 测试改善了局部覆盖，但没有保护训练、数据和 MultiTask 主路径。

## 6. P2：可靠性、复现性和效率

### 6.1 真正配对的 NFE/checkpoint 比较

相同环境 seed 不等于相同策略随机数。ActionFlow 每次推理重新生成 initial noise，而 sweep 只在整次开始时 set seed；不同候选的 episode 长度还会继续移动 RNG。

最小实现是在每个 `(eval_seed, candidate)` 前恢复相同 policy RNG，或让 ActionFlow 接收预生成 `initial_noise`。结果应同时保存环境 seed、policy noise seed、逐 episode outcome 和候选执行顺序。现有 NFE4 对 NFE2 的聚合结果不足以支持“显著更优”，保留默认 NFE2 是合理的保守选择。

### 6.2 统一 config/input contract

建议增加小型纯函数校验层，不要引入新的配置框架：

- 所有整数参数要求 `Integral` 且拒绝 bool；
- 所有浮点超参数要求 `Real`、拒绝 bool、`math.isfinite`，再校验范围；
- `noise_shift_alpha/ratio`、GeoFormer wavelength、NFE、episode 数、GPU id、dropout、尺寸、权重等在构造入口一次性校验；
- 关键不变量用显式异常替代 `assert`，确保 `python -O` 下仍生效；
- horizon/token/embedding/head_dim/position encoding 的耦合 shape 在模型构造时给出具体错误。

### 6.3 数据与内存效率

1. DDP 只在 rank 0 读取/拟合 normalizer，再广播小型状态；不要每个 rank 先做完整工作。
2. shared MultiTask normalizer 使用流式统计或分块更新，避免 `np.concatenate` 全量复制。
3. 非 deterministic sampler 不在每个 worker 物化完整 O(total samples) Python list，可用紧凑数组或按需 permutation。
4. 避免为每个 dataset/validation copy 创建独立 `multiprocessing.Manager`；共享 epoch 可用 worker seed/共享 value 等更轻量方案。
5. EMA 只跟踪可训练部分，或至少跳过冻结 backbone；当前 decoder 无 BN，可暂缓实现复杂 buffer EMA。

### 6.4 RGB/RGB-D 空间变换只保留一个责任方

- 对同一训练配置，只在 dataset 或 agent 做随机 crop，不要同时 240→224 crop、0.95 crop 再 resize；
- transform metadata 记录原图、resize 后、crop 后三个尺寸；
- depth 与 RGB 原始 H/W 不一致时 fail-fast 或分别计算可证明正确的映射；
- 同时设置 `image_size` 和 `center_crop_size` 时明确拒绝或定义优先级，不能静默忽略一个参数；
- 浮点 RGB/depth 先检查 finite，再检查范围和 scale。

### 6.5 normalizer 和 sampler 所有权

- `LinearNormalizer.fit` 前清空旧 key，更新参数时使 field view cache 失效；
- 空数据、单样本 std 和非法 episode boundaries 在入口报错；
- `SequenceSampler` 复制调用方 mask，并用与 `create_indices` 完全一致的 clamp 后 padding 规则预过滤。

仓库约定当前 normalizer 使用完整 replay buffer 拟合，这是**有意设计**，不应作为实现 bug 偷偷改掉。若实验协议要求严格 train-only statistics，应以显式配置和新的实验版本引入，并重新评估与旧 checkpoint 的可比性。

### 6.6 ActionFlow 测试与实验凭据

- 新 KV-cache 测试应模拟 `setup_kv_cache` 写入部分 layer 后抛错；只在 forward 抛错无法证明本次 setup 清理修复有效；
- `use_step_conditioning` 目前只接收常数 0，canonical config 已禁用。短期可删除公开开关或明确标记 unsupported，不必实现一套无实验需求的新条件机制；
- 每次正式实验提交一个小型 manifest：producer commit、resolved config、checkpoint SHA-256、dataset/version、seed 列表、policy noise seed、原始 `result_details.json` 和命令；无需引入 MLflow 等重型系统。

### 6.7 MoE 语义

当前 MoE 为每个样本计算所有 active experts 后再 gather top-k，因此是输出路由稀疏，不是计算稀疏。修复顺序应是：

1. 先修 README/配置表述和 `return_aux=False` 分支；
2. 对 activation、expert 数、top-k、有限 action 做显式校验；
3. 只有在 profile 证明 MoE 是瓶颈后，再考虑真正的 token dispatch/sparse expert execution。

## 8. 推荐执行路线

### Phase A：结果可信度 gate

1. R3M official/legacy 预处理版本化和数值等价测试；
2. MultiTask `(task, seed)` 统计重写；
3. eval 入口预校验 NFE/episodes/seeds，异常不再混入 success rate；
4. selector 拒绝无效或样本数不一致的候选。

完成标准：R3M 与 MultiTask 结果可以被解释，非法配置不能生成看似正常的指标。

### Phase B：长训练与发布 gate

1. 显式 `resume_from`、EMA counter、RNG 和边界恢复语义；
2. DDP scheduler/optimizer 恢复顺序和 accumulation 尾批；
3. parity 后发布 selector；
4. 远程脚本白名单和路径 containment。

完成标准：中断恢复不会静默改变关键状态，parity 失败不会切换线上 selector。

### Phase C：小型回归集

1. CPU CI；
2. setup-cache 中途失败、非法 CLI NFE、MultiTask 失败任务、resume LR/EMA 测试；
3. 预训练权重 fail-closed；
4. paired NFE 固定 initial noise。

### Phase D：按需维护

只有在对应研究路径实际启用时，再处理 Uni3D 非默认 feature mode、MoE 真稀疏、完整 train-only normalizer、视频流水线和 dormant components。

## 9. 修复后必须保留的回归测试

| 测试 | 必须证明的性质 |
|---|---|
| R3M preprocessing parity | 与官方预处理数值等价；legacy checkpoint 不静默换模式 |
| MultiTask statistics | micro/macro 分母正确；结果永不超过 1；invalid task 不被省略 |
| Invalid NFE CLI | 在 episode 前非零退出，不写 0%/best 结果 |
| Runner exception taxonomy | OOM/模型错误上抛；真实任务失败仍可计数 |
| Resume equivalence | 恢复后的 LR、EMA decay、global step 和样本边界一致 |
| DDP resume | optimizer/scheduler 恢复后首个 LR 正确 |
| Accumulation tail | 不整除 epoch 的尾部梯度被明确 flush 或明确拒绝 |
| KV-cache partial setup failure | 部分 cache 已建立后异常，所有 layer 最终均清空 |
| Qualification rollback | parity 失败时 selector hash 完全不变 |

## 10. 结论状态与覆盖边界

本轮更新已修复 ActionFlow `n_obs_steps!=2` 的 M01，并加强 ActionFlow NFE 类型/偶数约束；GeoFormer 注释和 smoke 参数预算也已更新。这些项目不再列入待修主线。

其余训练（T01–T21）、数据（D01–D29）、评测（E01–E19）、部署（P01–P05）、脚本（S01–S10）结论在当前基线仍成立，但其中包含条件触发、方法学选择和低风险维护债，不能全部等同于默认路径 bug。模型部分为 M02–M18，M01 已关闭；新增复查问题为 N01–N07。

以下旧说法已撤回或修订，后续不要重新作为确定性 bug 传播：

- Flow/SAT batch=1 的 `squeeze` 不是已证明必崩；
- Hydra 1.2 与 OmegaConf 2.3 不是已证明的 resolver 硬冲突；
- exporter 自身具备 selector-last 和发布后回滚，真正问题是 qualification 顺序；
- 所有视觉策略双重 crop、所有 flow decoder 都缺少 NFE 校验等笼统说法均不准确；
- normalizer 使用完整 replay buffer 是当前项目明确设计，是否改为 train-only 属于实验协议选择。

在 P0/P1 完成前，不应：

- 用当前 MultiTask 总成功率做模型排名或发布决策；
- 把采用错误 R3M 预处理训练的 checkpoint 与官方预处理模型直接比较；
- 把重新运行同一训练命令视为可靠续训；
- 把非法 override 或基础设施异常产生的 0% 当作真实策略失败；
- 把 parity 命令失败理解为 selector 一定没有改变。
