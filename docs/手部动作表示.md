# 手部动作表示

本项目比较三种动作建模方式：SAT 直接表示关节轨迹，DQ-RISE 用离散手姿原型表示手部，DexLatent 使用冻结的连续手部先验。它们都以观测表征为条件，生成一段动作，最终还原为 xArm7 + XHand 的 19 维绝对关节目标。

三者共享本地的空间观测编码与 Rectified Flow 主干。公共数据流见[项目架构](项目架构.md)，动作的时间对齐、单位和关节顺序见[仿真数据集格式](仿真数据集格式.md)。本篇说明动作表示如何改变学习目标与解码过程。

## 三种表示的区别

| 方法 | 生成模型学习的动作空间 | 主干中的 token | 手部先验 |
| --- | --- | --- | --- |
| SAT | 19 维归一化关节轨迹 | 每个关节对应一个覆盖整段时间的轨迹 token | 无独立手姿先验 |
| DQ-RISE | 每时刻 7 维手臂目标 + 1 维连续手姿索引 | 按时间组织 | 从本地示范手姿学习的离散原型表 |
| DexLatent | 每时刻 7 维手臂目标 + 32 维连续手部表示 | 按时间组织 | 官方冻结 XHand 编码器与解码器 |

这三种方式分别改变轨迹组织、手姿量化和手部表示空间。即使使用相同主干，它们的 token 数、输入输出头、表示维数和预训练来源也不同，不能视为只交换 token 轴的消融。

## SAT：按关节组织轨迹

SAT 将每个关节在整段动作中的变化编码为一个 token，而非让一个 token 表示某一时刻的全部关节。每个 token 同时包含轨迹特征、手臂或手部的身份信息，以及对应的关节身份信息。

主干在观测条件下处理这些关节 token，输出归一化关节轨迹在 Flow 生成过程中的速度场。这里的速度描述生成路径，不是机器人执行的物理关节速度。Flow 的训练与积分始终在归一化关节坐标中进行；token 化发生在每次网络预测内部，不改变最终绝对关节目标的含义。

本地身份信息只对应固定的 xArm7/XHand 控制顺序。它区分手臂与手部及各自关节，不代表官方多机器人语义编号，也不意味着本地模型能够直接迁移官方多机器人权重。

## DQ-RISE：从手姿原型到连续索引

DQ-RISE 将手部的 12 个关节目标替换为一个手姿索引，手臂仍使用连续关节目标。其核心过程分为三步。

1. **学习原型。** 用训练示范中的单帧手部动作训练残差 VQ-VAE。编码器把手姿映射到量化空间，多级码本量化残差，解码器重建手姿；重建与 commitment 目标共同训练该表示。默认两级、每级四个 code，组合后得到 16 个手姿原型。
2. **建立索引。** 枚举码本组合，按学习到的层权重合成并解码为手姿，再沿解码手姿的第一主成分排序。对每个训练动作，在归一化手姿空间寻找最近原型，将原型编号映射为连续标量。
3. **生成与查表。** Flow 联合生成手臂动作与连续索引序列。积分结束后才将索引取整并查表，得到手部关节目标，再还原物理尺度。积分过程中不反复量化。

原型数 $K>1$ 时，对于编号为 $i$ 的原型，连续索引为：

$$
s_i = \frac{2i}{K-1}-1,\qquad i=0,\ldots,K-1.
$$

仅有一个原型时，所有手姿都使用该原型。PCA 排序只为原型赋予一维顺序；部署时使用的是固定原型表，不再运行 VQ-VAE 编码器或解码器。

码本学习、最近邻标签和原型误差都使用训练示范拟合的逐关节尺度。该尺度随原型表一起用于下游策略，保证同一索引始终表示同一手姿。单帧原型不依赖动作窗口长度或执行步数。

离散原型限制了可还原的手姿集合。评价时除闭环任务成功率，还应关注原型查表后的手姿误差；更换原型表或重新编号会改变索引语义，需要重新训练下游策略。

## DexLatent：冻结的连续手部先验

DexLatent 使用官方预训练模型的 `xarm7_xhand_right` 分支。冻结编码器将归一化的 12 维手部目标映射为确定性的 32 维 mean，冻结解码器再将其还原为手部目标。

这里的 32 维表示对本地 12 维手姿属于维度扩展。策略不采样潜变量，也不增加 KL、几何重建或其他先验训练目标；先验在下游训练期间保持固定。

训练与推理的关系如下：

| 阶段 | 手部路径 |
| --- | --- |
| 构建监督目标 | 物理手姿 → 官方关节尺度归一化 → 冻结编码器 → 32 维 mean → 本地训练集 latent 归一化 |
| 动作生成 | Flow 生成 latent → 还原 latent 尺度 → 冻结解码器 → 还原物理手姿 |

手部进入先验前使用官方 XHand 关节上下限，并限制在其输入范围内；latent 的数值尺度则由本次训练示范中的真实动作拟合。二者分别对应先验的输入定义与本地策略的生成空间。

Flow 联合预测手臂和手部 latent，积分过程中不投影或裁剪 latent，结束后只解码一次。作为观测输入的关节状态仍保留原有 19 维含义，不替换为 latent。

## 本地适配与比较边界

| 方法 | 本地适配的关键点 |
| --- | --- |
| SAT | 保留按关节组织轨迹的思路，接入本项目的观测编码、Flow 与固定机器人身份 |
| DQ-RISE | 将官方硬件空间改为本地 XHand 示范的归一化关节空间；原型组合使用学习到的层权重，按解码手姿排序 |
| DexLatent | 复用官方冻结手部先验，以确定性 mean 和本地 latent 尺度接入共同 Flow；不构成完整 XL-VLA 下游复现 |

DQ-RISE 的原型来源于本地示范，DexLatent 的先验来源于官方预训练。共同策略配方并不意味着预训练数据、参数量或计算量相同。比较应明确示范预算、先验来源、推理预算及[仿真评测条件](仿真评测机制.md)。

三者的 Flow 误差分别处于关节、连续索引或 latent 空间，数值不能直接用于横向排名。当前单 XHand 设置也不能据此验证跨手泛化。
