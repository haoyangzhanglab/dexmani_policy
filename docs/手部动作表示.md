# 手部动作表示

SAT、DQ-RISE、DexLatent 和 ODE 均输出 19 维绝对关节目标（7 维手臂、12 维手部）。

| 配方 | 生成方式 | 如何得到关节目标 |
| --- | --- | --- |
| SAT（`sat`） | 将每个关节在整个动作窗口内的轨迹作为一个 token | 还原轨迹排列和关节尺度 |
| DQ-RISE（`dqrise`） | 7 维手臂目标和 1 个连续手姿索引 | 将索引离散化后查询固定码本 |
| DexLatent（`dexlatent`） | 7 维手臂目标和 32 维连续手姿潜表示 | 用冻结的解码器还原手部关节目标 |
| ODE（`ode`） | 关节空间向量场，支持可选速度偏移 | 从上一条有效关节目标积分得到动作窗口 |

SAT、DQ-RISE 和 DexLatent 共享 RGB 与点云观测编码，在各自的完整生成空间计算 Rectified Flow 的速度 MSE。`time_shift_alpha` 控制训练时间采样，推理使用等间隔 Euler 积分。

## 手部先验

- **DQ-RISE** 从本地示教的手部目标训练残差 VQ-VAE。解码所有码本组合后，在归一化手部空间按 PCA 排序。有验证集时按查表误差选模，否则使用最终模型。用 `bash scripts/pretrain/vqvae.sh --policy-config "$POLICY_CONFIG"` 从已解析的 `dqrise` 配方复用数据划分。策略通过 `initialization.codebook=<run>/codebook.npz` 加载码本及手部尺度，并重新拟合手臂尺度。 [同源数据预算](观测预训练.md#同源数据预算)
- **DexLatent** 使用外部预训练的 XHand 编码器和解码器，以编码分布的均值表示手姿。策略训练时冻结两者，沿用先验的动作尺度，用当前训练数据拟合潜表示尺度。 [预训练资源](../data/README.md)

## ODE：从上一条指令积分生成轨迹

ODE 以点云历史和最新实测关节状态为条件，积分 `n_action_steps` 个控制周期。仿真以下发后实际应用的关节目标为起点。

真机示教的 `action_ode` 保存最近确认的完整关节目标。命令失败或未发送时沿用上一目标，保持原时序。新段从实测关节状态起步，在线跳过控制步后也从实测状态重新规划。原始记录须包含逐行命令提交状态，在 `dexmani_real` 用 `scripts/export_zarr.py --fields joint_state point_cloud action_ode` 导出。
