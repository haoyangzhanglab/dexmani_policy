# DexMani_Policy 手部动作表示

DQ-RISE、LAMP 和 Temporal 是本地研究适配，模型、窗口与目标均有差异，不能直接视为纯动作空间消融。通用接口见 [项目架构](项目架构.md)，命令从仓库根目录执行。

## 数据与准备

仅支持当前 SIM/Real 导出时序：`obs[t]` 在 `action[t]` 提交前采集，不使用 `obs_alignment` 或自动移位。要求有限正 `dt`；手部为 XHand thumb×3、index×3、middle×2、ring×2、pinky×2，单位 radians。

正式 baseline 在表示预训练、Policy 和各 seed 间复用 episode 级 held-out manifest，格式见 [划分与数据身份](项目架构.md#划分与数据身份)。缺少真实 episode/trial 身份时重新导出，不补造。smoke 可无 holdout，但不据此报告泛化；比较需记录实际窗口数与 padding 比例。

以下示例统一 joint action 和数据划分，各方法保存独立产物，已有文件默认不覆盖：

```bash
conda activate policy
DATA_ZARR=/path/to/dataset.zarr
SPLIT=/path/to/episode_split.json
HAND_RUN="experiments/hand_spaces/$(date +%Y%m%d_%H%M%S)_${RANDOM}"
DATA=("zarr_path=$DATA_ZARR" "dataset.split_manifest=$SPLIT"
      dataset.max_train_episodes=null dataset.val_ratio=0)
```

## DQ-RISE 码本

```bash
VQ_DATA=()
for item in "${DATA[@]}"; do VQ_DATA+=(--policy-override "$item"); done
python -m dexmani_policy.training.pretrain.hand_prior.vqvae \
  --policy-config dexmani_policy/configs/dqrise.yaml \
  "${VQ_DATA[@]}" \
  --output_dir "$HAND_RUN/dqrise"
python -m dexmani_policy.training.pretrain.hand_prior.export_codebook \
  --checkpoint "$HAND_RUN/dqrise/vqvae_hand_best.pt" \
  --output "$HAND_RUN/dqrise/codebook.npz"
bash scripts/training/train.sh dqrise "${DATA[@]}" \
  codebook_path="$HAND_RUN/dqrise/codebook.npz"
```

正式配置固定 Joint Action `7+12`（`action_key=action`、`action_dim=19`、`tcp_dim=7`），默认 `codebook_path=null`；必须显式指定匹配当前配方与动作坐标的 Codebook。便捷入口为 `bash scripts/pretrain/vqvae.sh <task> [VQ options...]`。

采用 [DQ-RISE v1 §III](https://arxiv.org/html/2509.17450v1) 的单帧 residual VQ、组合原型、PCA 排序和单标量 lookup，默认 2 组×4 code，共 16 原型。训练标签为部署表的最近 normalized prototype，`s=2*i/(M-1)-1`；解码取 `floor((clamp(s,-1,1)+1)*(M-1)/2+0.5)` 查表。运行时直接存储 normalized prototypes，在同一空间计算平方欧氏距离并查表，再逆 action affine 得到物理动作。

本仓使用 weighted L1 reconstruction 与 EMA commitment；[固定官方训练代码](https://github.com/rise-policy/DQ-RISE/blob/2889d27fce823288e8dd12ec6e91506b52ed086a/train_dqrise.py)同样按原型 NN 标注。本仓训练/导出均使用学习到的 softmax layer weights，区别于[官方导出](https://github.com/rise-policy/DQ-RISE/blob/2889d27fce823288e8dd12ec6e91506b52ed086a/eval_vqvae.py)的两 code 平均。VQ 的训练样本取有效训练窗口引用的唯一 action 源行；其 affine 由公共 Builder 在完整 Replay Buffer 上拟合，与 Policy 相同，包含 held-out episode，验证复用该 affine。这里不是 train-only normalization；若后续改为 train-only，应在公共数据层统一应用于 VQ 和 Policy。

[官方 VQ 训练](https://github.com/rise-policy/DQ-RISE/blob/2889d27fce823288e8dd12ec6e91506b52ed086a/train_vqvae.py)定期保存 checkpoint，并保存 `policy_last`；本仓额外按实际部署表的查表误差选 best。每个 epoch 结束后，以固定模型在 eval/no_grad 下生成与导出相同的组合原型（含 learned layer weights、decoder、act_scale 和 clamp），计算 `lookup_mse = sum_i min_j ||hand_norm_i - prototype_j||² / (N * hand_dim)`。有 holdout 使用 `val_lookup_mse`；无 holdout 独立遍历完整训练源行、包含尾批，使用 `train_lookup_mse` 并标记 `train_no_holdout`。原 `train_mse`、`val_mse` 仍是 VQ reconstruction 辅助指标，训练目标不变；PCA 仅在最终导出和结束诊断阶段执行，排序不改变最近邻误差。

### SAT / DQ-RISE 比较协议

两者共享 Sparse3D Global 观测架构，动作模型完全独立：SAT 以关节轨迹 tokens 和 RectifiedFlow 生成连续 19D；DQ-RISE 以 UNet/DDIM 生成 `[B,16,8]`，最后一维量化查表为 12D hand，再与 7D arm 拼接并统一反归一化。两者都输出 `[B,16,19]`，默认执行 `[1:9]` 的 8 步。观测与静态关节映射见 [观测与动作建模](项目架构.md#观测与动作建模)。

正式实验需同时固定数据路径、episode-level `split_manifest`、seed、有效 batch、optimizer update 数及 selection/test 预算；VQ 也使用相同动作键和划分。配置的 `split_manifest=null`、最多 80 个训练 episodes 是无 holdout 的启动配方，不用于报告泛化。提供 manifest 时设置 `max_train_episodes=null`、`val_ratio=0`。单卡 batch=128，DDP 为 32×4×1=128，默认 100000 updates；保留各自学习率/warmup，SAT 默认 10 NFE，DQ 默认 20 NFE。

比较报告至少包含：

- 相同 held-out seeds 的 success rate，沿用现有选点和 rollout 入口。
- 相同 held-out 数据窗口上 `[1:9]` 的物理动作 MAE/RMSE，arm `:7`、hand `7:19` 分开，单位 radians；生成随机 seed 和窗口样本集合同时记录。
- DQ GT hand 经 normalized NN→lookup 的 quantization error；复用 VQ 训练结束时生成的 `codebook_diagnostics.json`，区分 full-source-row 统计与 Policy 执行窗口统计，不能以 VQ 重建误差替代。
- 推理延迟（包含观测编码、生成与解码，排除加载/预热/数据搬运；CUDA 计时前后同步），记录设备、精度、batch、NFE、均值和 P50/P95。
- 总参数量及可训练参数量，注明是否计入 VQ 预训练网络；Policy 参数量不把查表 buffers 当可训练参数。

这属于两类动作空间方法的 Baseline 对比；生成网络与训练目标不同，不是严格控制网络因素的纯 Action Representation 消融。指标需实际训练和评测后报告，CPU 合成测试不构成实验结论。

## LAMP 历史先验

```bash
python -m dexmani_policy.training.pretrain.hand_prior.lamp --config lamp "${DATA[@]}" \
  lamp.prior_path="$HAND_RUN/lamp/prior.pt"
bash scripts/training/train.sh lamp "${DATA[@]}" \
  lamp.prior_path="$HAND_RUN/lamp/prior.pt"
```

产物默认写入 `agent.prior_path`（由 `lamp.prior_path` 插值）；使用 `--output` 时需同步 Policy 路径。

对应 [LAMP v1 Eq.1–6](https://arxiv.org/html/2607.06323v1)：H=Nobs=C=1，K=8 为严格过去的执行命令历史，不足时用初始实测 q0 补齐。prior 预训练以重参数采样重建下一命令并加 Gaussian KL；Policy 冻结 E/D，以观测和 `[mu,std]` 回归 arm 与 delta_z，不采样 prior：

```text
hand_hat_norm = D(mu + delta_z)
hand_ref_norm = stop_gradient(D(mu))
L = arm_mse + hand_loss_weight * hand_mse
    + drift_reg_weight * mean((hand_hat_norm - hand_ref_norm)²)
    + offset_reg_weight * mean_batch(sum_latent(delta_z²))
```

arm 用 Policy affine，hand 预测、参考和监督目标均用匹配的 prior affine；hand MSE 和 drift MSE 对 batch、关节维度取均值，损失在动作裁剪之前计算。冻结 decoder 仍保留对 delta_z 的梯度，仅参考分支停止梯度。两条分支使用同一次历史编码得到的 mu，参考解码复用于 prior-error 日志，推理没有参考分支。日志中的 `hand_drift_mse` 是原始误差，`loss_drift` 是乘权重后的正则项。

`lamp.yaml` 使用 `hand_loss_weight=1.0`、`drift_reg_weight=1.0`、`offset_reg_weight=0.0`，参考[固定官方 BC](https://github.com/dex-lamp/LAMP/blob/0467ba3504e0d199727a0586ba525c5fe14f8138/imitation_learning/behavior_clone/scripts/train_jax.py)的 decoded drift。论文 Eq.6 的 latent L2 由 `offset_reg_weight` 控制；两种正则不能同时启用，允许都为零。drift 权重 1 是官方默认参照，尚未证明是当前任务的最优值。12→2、19 维 proprio 和 Sparse3D 属于本地适配，不含 RL。

BC 训练设置 `history_noise_std=0.01`，单位为归一化手部坐标中的高斯噪声标准差。因 `encode_history()` 内部执行 affine，调用前向物理历史添加 `randn_like(history) * history_noise_std / prior.hand_scale`。仅在 Policy 为 training 且标准差大于零时采样；prior 始终为 eval。增强不修改输入、监督动作或执行历史队列，验证和推理关闭，零噪声不额外消耗 RNG。prior 预训练、历史对齐、bootstrap 与 `[mu,std]` 条件语义不变。

配置和直接构建 Policy 均须显式提供 `history_noise_std`、`hand_loss_weight`、`offset_reg_weight`、`drift_reg_weight`，不为缺失字段推断训练配方。resume 使用保存的完整 `effective_config`，切换噪声或正则配方需开始新训练。

## Temporal hand VAE

```bash
python -m dexmani_policy.training.pretrain.hand_prior.temporal_vae --config temporal_codec_flow "${DATA[@]}" \
  codec.path="$HAND_RUN/temporal/codec.pt"
bash scripts/training/train.sh temporal_codec_flow "${DATA[@]}" \
  codec.path="$HAND_RUN/temporal/codec.pt"
```

产物默认写入 `agent.codec_path`（由 `codec.path` 插值）。采用 [Temporal v1 §3、Appendix A/B](https://arxiv.org/html/2609.19666v1) 的 q0 条件双向时序 VAE、差分重建、posterior mean 和 latent FM，保留 H=16、Nobs=2、C=8、12→9。本仓单手和视觉配方为适配；[Wuji 固定发布代码](https://github.com/wuji-technology/wuji-openpi/tree/be6b32540546fb4fdd274f5cc86a7f9a67148a4c)未提供该 codec，不能称完整系统的逐行复现。

`r=(hand_chunk-q0-mean)/std`，q0 是 query 源帧未增强实测值，由 `action_context.hand_reference` 提供；统计按训练窗口计入重叠与 padding。预训练的位置/一阶/二阶差分 weighted Huber 权重为 1/0.2/0.05，关节权重由 `codec.joint_weights` 控制。差分匹配目标运动，不作趋零平滑。

Policy 在线用冻结 encoder mean 作 FM 标签：`s~0.999*Beta(1,1.5)`、`x_s=(1-s)*noise+s*target`、`v=target-noise`，clean estimate 为 `x_s+(1-s)*v_hat`。损失为 `L_arm_FM+0.25*L_latent_FM+0.75*L_decoded`，各组全 H 取 mean；decoded MSE 仅在 standardized relative 空间，physical MAE/RMSE 只诊断，冻结 D 保留梯度。

窗口为 `a[t-1:t+15]`，q0=q_t；完整解码后执行 `[1:9]`，整段 q0 固定，不截断双向 decoder、不逐帧重锚定。物理解码仅一次 `decoded*std+mean+q0`；同源帧可有不同 q0，不建逐帧 latent cache。

## 预训练数据与选点

| 方法 | 有 holdout | 无 holdout | 当前产物 |
| --- | --- | --- | --- |
| DQ-RISE VQ | 按 `val_lookup_mse` | 按 `train_lookup_mse`，标记 `train_no_holdout`，可导出 | VQ checkpoint、codebook NPZ (`pose_space=normalized`) |
| LAMP | deterministic prior-mean MSE | 最终合格步骤 | prior checkpoint |
| Temporal | physical MAE | 最终合格步骤 | temporal codec checkpoint |

LAMP 默认 20k steps、2k warmup、beta=1e-3；Temporal 默认 30k、4k 零 KL + 4k ramp、beta=3e-4。仅在 KL 达正目标后选点，schedule 不足时训练前报错；无 holdout 标记 `final_no_holdout`。选点信息保存在 selection，指标和调度参数留在 metrics/train_args。

`hand_data` 保存 episode 身份/边界、train/val 集合、动作键、dt、窗口/历史长度及样本计数。它不计算内容哈希，数据重新生成使用新路径。VQ 的 `codebook_diagnostics.json` 记录实际 NN→lookup 的 normalized/physical 误差、利用率与跳变；各 split 的 `lookup_mse` 是 normalized MSE，与选点指标对应。VQ checkpoint 显式保存 `selection_split`、`selection_metric` 和对应 metrics，导出直接读取，不从 episode 列表推断选点 split。

## 加载

三个阶段共用配置/窗口校验和数据覆盖。Fresh training 核对 `hand_data` 与坐标：DQ/LAMP 核对手部 affine，Temporal 用内嵌相对统计；观测归一化可在 encoder 约束内另选，Sparse3D 点云仍须 `identity`。

strict resume 用 checkpoint 内嵌表示并重新核对保存的 `hand_data`；raw/EMA 均内嵌表示和 normalizer，独立推理无需原产物或训练数据。

DQ codebook 使用 `pose_space=normalized`，核对原型布局、`pca_permutation`、有限值和 normalizer 一致性。配置、预训练 checkpoint 和 NPZ 只按当前字段及张量结构读取，不迁移或补齐旧产物；历史实验使用对应源码。视觉修改不要求重训仍匹配坐标的手部表示。

新的 VQ 选点不会修改已训练 Policy 内嵌的码本。选择不同码本后，下游 Policy 需要重新训练，不能直接替换旧 Policy 的码本。

LAMP/Temporal 仅支持 sync，拒绝 prefix/delay。LAMP 的 `action_context.hand_history` 由执行端维护，`predict` 不更新历史；格式与执行职责见 [部署边界](项目架构.md#部署边界)，真机闭环 **NOT VERIFIED**。

预训练与导出入口位于 `training/pretrain/hand_prior/`，表示模型位于 `agents/hand_prior/`，历史/q0 Dataset 位于 `datasets/hand_prior/`，均相对于 `dexmani_policy/`。
