# 手部动作表示

下列方法都从示教学习绝对关节目标，默认每步 19 维（7 维手臂、12 维手部）。它们的区别在于模型生成什么，以及如何将生成结果还原为关节目标。

| 策略 | 模型生成的表示 | 如何得到关节目标 |
| --- | --- | --- |
| InteractionFlow (`interaction_flow`) | 每个控制时刻的 19 维动作用一个 token 表示 | 生成整段轨迹并反归一化。 [模型架构](InteractionFlow模型架构.md) |
| FlowMatch (`flowmatch`) | 默认每个控制时刻一个19维动作 token；可选 arm/hand 两个 tokens | 在19维关节空间积分后反归一化 |
| SAT | 每个关节在整个窗口内的轨迹用一个 token 表示 | 还原轨迹排列和关节尺度 |
| DQ-RISE | 7 维手臂目标和 1 个连续手姿索引 | 离散化索引，查询固定手姿码本 |
| DexLatent | 7 维手臂目标和 32 维手姿潜变量 | 用冻结的解码器还原手部关节目标 |

FlowMatch、SAT、DQ-RISE 和 DexLatent 共享 RGB、点云和关节状态编码。四者均在表中各自的生成空间训练 Rectified Flow。

## Flow Matching 的公共设置

FlowMatch（含 Factorized 模式）、SAT、DQ-RISE、DexLatent、InteractionFlow 默认使用10步 Euler；ManiFlow 保持官方默认10步，其评测配置也跟随 `agent.num_inference_steps`。运行时 `inference_steps` 仍可覆盖，训练时间采样、积分方向和动作窗口均不变。

这些 Action Expert 默认开启 `qk_norm`：投影后的 Q/K 在 head dimension 上使用 LayerNorm，V 和 SDPA 缩放不变。固定 Context 的 Key 在准备 K/V 时只归一化一次；Self-Attention 不新增归一化机制。SAT 的可选 DiT 沿用已有 QK Norm 位置，使用相同的 LayerNorm；其他 RMSNorm 不变。Observation Encoder 与辅助预测头不受影响。

所有连续 Flow 时间条件共用 `FlowTimestepEmbedding`，采用 [OpenPI π₀ 的周期定义](https://github.com/Physical-Intelligence/openpi/blob/main/src/openpi/models/pi0.py)：

```python
fraction = linspace(0, 1, embedding_dim // 2)
period = 0.004 * (4.0 / 0.004) ** fraction
angles = timestep[:, None] * (2 * pi / period)[None, :]
embedding = concat((sin(angles), cos(angles)), dim=-1)
```

频率使用不写入 checkpoint 的 FP32 buffer，设备或 dtype 转换时重建；每次 Forward 只计算 FP32 相位及三角函数，再衔接原有 Time MLP 的 dtype。DiTX、InteractionDiTX 和 SAT DiT 的 Flow 时间，以及 ConsistencyDiTX 的当前时间与目标时间，均使用此实现；Time MLP、AdaLN 和初始化不变。这里只改变网络时间特征，不改变原始 Flow Time、噪声插值、Velocity Target 或 Consistency Target。DDPM/DDIM 的离散时间编码和独立 Force Predictor 保持原设计。

训练默认使用 FP32（`training.use_bfloat16=false`），显式设置为 `true` 才启用 BF16 autocast。公共评测与部署入口恢复 FP32 权重并关闭 autocast，训练时开启 BF16 不会改变该推理行为。

在 PyTorch 2.4.1、RTX 4090 的小模型验证中，SAT 可选 DiT 的 BF16 Inductor 训练与 eager 仍有少量输出及梯度超过测试容差，严格数值等价性尚未通过。其 FP32 编译及 BF16 缓存采样通过；该限制针对显式开启的 BF16 编译训练，不涉及默认 FP32 路径。

## 手部先验

- **DQ-RISE** 从示教的手部目标训练残差 VQ-VAE，导出时将各组码向量等权平均，解码后按 PCA 排序。默认训练 1,500 轮，完成后从末轮的 `checkpoints/last.pt` 导出码本。启用验证时，`val_lookup_mse` 记录留出手姿的量化误差。`bash scripts/pretrain/vqvae.sh` 接受与下游相同的数据划分参数。下游通过 `initialization.codebook=<run>/codebook.npz` 载入码本。 [同源数据预算](观测预训练.md#同源数据预算)
- **DexLatent** 用冻结的 XHand 编码器将手姿表示为潜分布的均值，再用冻结的解码器还原手指关节。 [预训练权重](../data/README.md)

## FlowMatch

FlowMatch 是 SAT、DQ-RISE、DexLatent 的共同原始关节空间基线。默认 `agent.factorized=false`，直接使用 DiTX 的动作输入投影和速度输出头；`agent.factorized=true` 启用 [DeCAL §4.2](https://arxiv.org/html/2609.09119v1#S4.SS2) 的 arm/hand 分解与联合建模机制。[作者实现](https://github.com/AureleoPKU/DeCAL/blob/main/src/lerobot/policies/DeCAL/modeling_decal.py)

| 默认配置下 | 普通模式 | Factorized 模式 |
| --- | --- | --- |
| 每个控制时刻的动作 tokens | 1个，输入完整19维动作 | 2个，分别输入7维 arm 和12维 hand |
| Action Hidden States | `[B,16,768]` | `[B,32,768]` |
| 速度输出头 | 一个 DiTXOutput | arm/hand 各一个独立 DiTXOutput |
| 输出速度 | `[B,16,19]` | `[B,16,19]` |
| Action Expert 参数量，不含观测编码器 | 89,806,867 | 90,398,995 |

两种模式共用 RGB–点云与 Joint State 编码器。默认两帧各输出128个场景 tokens 和1个 State Token，合为 `[B,258,192]`，经 DiTX 投影为 `[B,258,768]`。Action Expert 为6层、768维、8 heads，每层执行 Self-Attention → Observation Cross-Attention → FFN，9组 AdaLN 参数仅由 flow timestep 调制。

Factorized 模式使用独立的 arm/hand 输入投影，共享控制时刻位置编码，按 `[arm_0…arm_15, hand_0…hand_15]` 排列。全部动作 tokens 在同一 Self-Attention 中联合建模，分别解码后沿动作维拼接。它复用本仓库的观测主干、DiTX readout、位置编码和时间采样设置，是动作分解机制的适配，不是完整 DeCAL 的复现。

两种模式均在归一化后的19维关节空间训练：`x_t=(1-t)*noise+t*action`，速度目标为 `action-noise`，对全部19维计算平均 MSE。完整张量的一次独立高斯采样即可提供独立的 arm/hand 噪声分量，同一样本共用一个 timestep，不额外调整两组 loss 权重。沿用 `time_shift_alpha=3.0`；输入投影及动作位置编码按标准差0.02初始化，AdaLN 和速度输出末层保持零初始化。

默认10步 Euler 在关节空间积分，多步 eval 采样复用每层 Observation K/V，动作 Query 每步重新计算。Action Horizon 为16，去除1步历史后返回15步 `future_actions`，执行窗口为8步。归一化、EMA、保存恢复和 RTC 使用公共流程，不需要手部先验或未来观测标签。

```bash
bash scripts/utils/download_pretrained.sh dinov2
RUN=experiments/train/flowmatch/multi_grasp/run01
bash scripts/training/train.sh flowmatch task_name=multi_grasp hydra.run.dir="$RUN"
bash scripts/eval/evaluate.sh --checkpoint "$RUN/checkpoints/latest.pt" --episodes 100
```

启用 Factorized 模式时，在训练命令中追加 `agent.factorized=true` 并使用新的运行目录。该开关改变模型参数结构；续训沿用 checkpoint 保存的配置：

```bash
conda run -n policy python -m dexmani_policy.training.resume --run "$RUN"
```

比较实验保持相同的数据划分、观测、训练预算和评测种子；采样延迟需分别测量两种模式。
