# DexMani Policy · 手部动作表示

SAT、DQ-RISE 和 DexLatent 均为本地策略适配，统一观测编码器、窗口、flow、策略训练配方和公共 6 层、768D DiTX 主干配置；SAT 由 SATActionIO 编解码关节轨迹，DQ/DexLatent 使用普通时间 token 输入输出。表示维度、token 数、输入输出头和量化机制仍不同，不能将比较称为“只交换 token 轴”的消融，也不能直接横比 Flow MSE。共享接口见 [项目架构](项目架构.md)，以下命令从仓库根目录、Conda `policy` 环境执行。

训练与续训沿用 `training.use_bfloat16` 配方及训练参数存储策略。正式部署、仿真评测及 warmup 在完整策略严格加载后统一使用 FP32，并在预测入口关闭 autocast；SAT 的初始噪声和 Euler 状态使用公共 RectifiedFlow 的 FP32 默认值，DQ-RISE 和 DexLatent 保留显式 FP32 参数。

| 方法 | 手部坐标与表示 | 默认配置 |
| --- | --- | --- |
| SAT | normalized joint19 的逐关节轨迹 token | [sat.yaml](../dexmani_policy/configs/sat.yaml) |
| DQ-RISE | normalized 单步手姿 → K 个 prototype 的连续索引（默认预训练 K=16） | [dqrise.yaml](../dexmani_policy/configs/dqrise.yaml) |
| DexLatent | 官方冻结 XHand encoder 的逐帧确定性 32D mean | [dexlatent.yaml](../dexmani_policy/configs/dexlatent.yaml) |

SAT 的动作输入保持 `[B,16,19]`，`SATActionIO` 内部转为 19 个长度 16 的关节轨迹 token，按[官方 SAT 固定源码](https://github.com/XiaohanLei/SAT/blob/cd7c0a8877d6090a9a85ebee0ceca961830b3654/sim/sat/model/diffusion/sat.py)拼接轨迹、robot identity 和 joint identity embedding。公共单时间 DiTX 处理 `[B,19,768]`，插件以 `DiTXOutput` 预测速度并转回 `[B,16,19]`；`return_features` 的特征轴对应 19 个关节。Flow 始终在归一化动作坐标中训练和积分，插件只编码每次网络调用的含噪动作。本地身份只定义固定 xArm7/XHand 控制顺序：arm 的 robot ID 为 0、joint ID 为 0–6，hand 的 robot ID 为 1、joint ID 为 0–11，不额外添加动作 token 位置表。它们不是官方多机器人语义编号，也不声明可迁移官方预训练权重或完整复现论文网络。

VQ 预训练入口使用 `--config` 加 Hydra `key=value`；配置使用固定 `dexmani_policy/configs/` 下的名称或相对子路径，如 `pretrain/hand_prior/vqvae`（可带 `.yaml`）；这是入口约定，不提供配置安全隔离保证。手部直接按 limits 拟合，配置不生成或保存 normalization 标记；训练参数位于独立配置的 `vq_vae`。训练数据须至少组成一个完整训练 batch，小规模短训需显式减小 `vq_vae.batch_size`；验证批次由距离矩阵预算独立决定，保留尾批。

实现位于 `training/pretrain/hand_prior/`。其中 `codebook.py` 负责原型构建、PCA 排序、导出和独立 CLI。VQ 训练与 CLI 共用 `export_codebook()` 读取完整 VQ checkpoint 并原子保存 NPZ，返回 `codebook`。运行时 `HandStateCodebook(hand_dim, num_codes)` 保存有序 prototype 表并编解码，`load_codebook(path)` 返回 `(codebook, hand_affine)`。NPZ 只保存 `sorted_hand_poses [K,12]`、`hand_normalizer_scale [12]`、`hand_normalizer_offset [12]`，均为 FP32；姿态固定使用 normalized 坐标。PCA 排列只用于生成有序原型，learned layer weights 仍参与解码并随 VQ 模型状态保存。

## 数据与准备

数据契约为 `obs[t]_before_action[t]`，动作是 7 arm + 12 hand 的绝对 joint targets，单位 radians；手部顺序为 XHand thumb×3、index×3、middle×2、ring×2、pinky×2。单帧 DQ 码本不依赖 dt 或动作窗口。不自动移位或猜测旧采集语义。

主策略默认 `dataset.seed=42`、`dataset.max_train_episodes=null`、`dataset.val_episodes=0`，不建立离线验证流程；使用全部 episodes 是相较原 100 条上限的配方变化，论文预算显式设置，resume 沿用保存参数。VQ-VAE 使用 `pretrain/hand_prior/vqvae` 独立配方，默认训练上限为 null、验证数量为 0。各阶段的数据路径、seed 和数量参数独立；训练划分不读取来源或 trial 身份。数量语义见 [Episode 划分](项目架构.md#episode-数量划分)。

```bash
conda activate policy
DATA_ZARR=/path/to/dataset.zarr
HAND_RUN="experiments/hand_spaces/$(date +%Y%m%d_%H%M%S)_${RANDOM}"
DATA=("zarr_path=$DATA_ZARR")
```

如需 VQ holdout，追加 `dataset.max_train_episodes=100 dataset.val_episodes=20`：150 条时得到 100/20/30，110 条得到 90/20/0。预留 V 条后按 `min(M,N−V)` 取 train；同一排列依次选择 train、val、unused。无上限时其余全部用于 train，V 必须小于总数。用于评估整个训练流程的 held-out 数据也应由实验者从预训练数据中排除；模型不执行跨阶段数据比较。

通用 affine 的训练源行总体见 [归一化](项目架构.md#归一化)；DQ 手部 affine 使用下文的 limits 统计。下游 limits/gaussian 仅拟合 arm 再拼入预训练 hand affine，identity 不扫描；rms/max_abs 保留全 action 统计以维持 arm 共享尺度。DexLatent 的 train latent 统计独立保留。

## DQ-RISE 码本

```bash
python -m dexmani_policy.training.pretrain.hand_prior.vqvae --config pretrain/hand_prior/vqvae \
  "${DATA[@]}" "vq_vae.output_dir=$HAND_RUN/dqrise"
bash scripts/training/train.sh dqrise "${DATA[@]}" \
  initialization.codebook="$HAND_RUN/dqrise/codebook.npz"
```

依据 [DQ-RISE v2 §III](https://arxiv.org/html/2509.17450v2) 和固定代码 [2889d27](https://github.com/rise-policy/DQ-RISE/tree/2889d27fce823288e8dd12ec6e91506b52ed086a)。默认 VQ 训练结束后从 `vqvae_hand_last.pt` 自动导出 `codebook.npz`，不额外遍历训练集选模。显式启用 val 时，从 `val_lookup_mse` 最低的 best 导出。任意含完整模型与 hand affine 的周期、last 或用户指定 checkpoint 都可独立导出，不要求选模 metadata：

```bash
python -m dexmani_policy.training.pretrain.hand_prior.codebook \
  --checkpoint "<checkpoint.pt>" --output "<codebook.npz>" --device cpu
```

`--device` 默认在 CUDA 可用时使用 `cuda`，否则使用 `cpu`；覆盖已有产物须显式传入 `--overwrite`。默认 `initialization.codebook=null`，新训练须提供匹配产物；来源路径只在 fresh 组装时使用。VQ 参数通过 `vq_vae.*` 覆盖，例如 `vq_vae.kmeans_init=true`；`vq_vae.output_dir` 须为新目录。归一化手部数组直接在主进程加载，无需额外 worker。

预训练通过 `vq_vae.num_groups` 和 `vq_vae.codebook_size` 配置量化结构，默认 2 组、每组 4 个 code。Policy fresh 读取一次实际码表，按表的行数设置必需构造参数并保存 `agent.num_codes=K`；运行时不依赖量化分组。导入时检查表的 shape、有限值和 hand affine，主策略配置不包含预训练配方。

预训练直接读取 train episodes 的全部真实 12D hand commands；仅启用验证时读取 val，不构造或扫描视觉 Dataset。仅以训练数组分块拟合 `hand` limits，再共用于训练和验证。VQ 固定读取 joint19 的 `action[:,7:19]`，不提供 action_key 选项；实际 hand affine 随码本保存，导出直接消费该 affine。新 Policy 从本阶段 train 拟合 action，再将码本的 hand affine 覆盖到唯一 action normalizer 的手部子段；运行码本只保存姿态 buffer。val、unused、随机增强和 padding 不参与统计，horizon 不改变统计总体。

官方 ROHand 预训练使用固定设备量程映射 `2*clip(hand_raw,0,65536)/65536-1`，不从数据拟合 min/max。本地 XHand 输入为 radians，沿用 train-only 逐关节 limits；验证直接使用训练 affine，允许超出 `[-1,1]`，不额外 clamp。逐关节缩放改变了距离度量，在 normalized hand-pose 坐标中进行 decoded-pose PCA、最近原型标签和 lookup 误差计算是本任务接受的适配，不宣称与官方硬件空间数值等价。

`scripts/pretrain/vqvae.sh [key=value ...]` 直接透传配置覆盖，例如 `task_name=pick_apple_messy`、`zarr_path=/path/to/data.zarr` 和 `vq_vae.output_dir=/path/to/new_run`。未指定数据路径时，路径随最终 `task_name` 解析；未指定输出目录时，预训练入口在 `experiments/vq_hand/<数据集名>/` 下自动创建独立目录。

VQ 量化单步 normalized hand target：encoder/decoder 各 6 个 512D 隐藏层，latent 256；两层 residual quantizer 各 4 code，共 16 个组合。残差减去 detached quantized，训练用 straight-through，commitment 对 code 停梯度，各层按 learned softmax weights 合成。

非 kmeans 初始化使用一致的单位伪计数：`cluster_size=ones(K)`、`embed_avg=embed*cluster_size[:,None]`，避免首批未命中 code 除以接近零的计数而放大。kmeans 使用实际 counts/centers。更换 codebook 后须重训下游 Policy，不替换已训练策略的内嵌码本。

VQ、kmeans、预训练选点和 Policy 手部训练标签的最近邻搜索共用 `codebook_distances`，在关闭 autocast 的 FP32 下使用 `cdist(..., compute_mode="donot_use_mm_for_euclid_dist")`，避免内积展开的消减误差及默认 cdist 的矩阵乘法分派改变近重合原型的索引。推理仅将连续索引取整后直接查表，不执行最近邻搜索。VQ EMA 用定长 scatter 计数、index_add 累加和替代 one-hot；kmeans 也避免 CUDA bincount 的 host 读取。保留 Laplace smoothing、空簇旧中心和死码替换；浮点累加顺序变化不保证逐位续训。码本算法核对了官方固定版本的 [residual_vq.py](https://github.com/rise-policy/DQ-RISE/blob/2889d27fce823288e8dd12ec6e91506b52ed086a/policy/vqvae_rise/vector_quantize_pytorch/residual_vq.py) 与 [vector_quantize_pytorch.py](https://github.com/rise-policy/DQ-RISE/blob/2889d27fce823288e8dd12ec6e91506b52ed086a/policy/vqvae_rise/vector_quantize_pytorch/vector_quantize_pytorch.py)。

direct 距离优先保证索引数值正确，大潜变量码本可能明显变慢。已有串行测量使用 RTX 4090、Torch 2.4.1、TF32=False，N256/K4/D256 的距离与 argmin 前向为内积展开 0.033 ms、direct 0.007 ms；N4096/K512/D256 为 0.085 ms、2.670 ms，后者是已接受的精度/效率取舍，不代表整段预训练耗时。选点在 `training/pretrain/hand_prior/vqvae.py` 构造验证 loader 时调用 `codebook_chunk_size(K, 4096)`，按 16 MiB 的 FP32 `[N,K]` 距离矩阵预算确定 batch_size；`evaluate_vq()` 不再二次分块，按实际样本总数累计 MSE，尾批不与整批等权。预算至少容纳一行，不构造 `[N,K,12]` 中间量，大表仍可能增加耗时。计时方式见项目架构的 agents 优化依据与验证。

VQ 保持 FP32 参数，独立 AdamW 仅在 CUDA 启用 fused；恢复时先在 CPU 严格加载参数和 buffers，再迁移设备，导出调用方设置 eval。损失为 `3*mean(abs(reconstruction-target)*joint_weight) + 5*sum(commitment)`，前 8 个关节权重 1、后 4 个 0.5；reconstruction MSE 仅作诊断，在 no_grad 下计算。评估/导出统一使用 learned weights → decoder → act_scale → clamp `[-1,1]`，在解码手姿空间做 PCA 排序。

监督标签为最终部署表中最近的 normalized prototype：`s=2*i/(K-1)-1`；解码为 `floor((clamp(float32(s),-1,1)+1)*(K-1)/2+0.5)`，lookup 后逆 action affine。K=1 时所有状态映射到唯一原型。显式启用的验证仅计算选模使用的 lookup_mse，不执行额外重建前向；训练仍记录 reconstruction、commitment 和总 loss。选点使用固定模型 eval/no_grad 的 `lookup_mse=sum_i min_j ||hand_norm_i-prototype_j||²/(N*12)`，不更新 codebook EMA；PCA 排序不改变该误差。

decode 在离散化之前拒绝 NaN/Inf，将 continuous 转为 FP32 后再 clamp、缩放和 half-up 取整，并在整型转换后截断索引。这样避免 BF16/FP16 运算引入额外的边界舍入，但不能恢复输入此前已丢失的精度；后续物理动作有限性检查无法替代离散化前检查。上述检查及截断均保留。

### 窗口与 flow

新训练与 SAT 统一为 `Nobs=2,H=16,C=8`、`pad_before=1,pad_after=7,action_start_index=1`。普通 6 层、768D DiTX 以共享 dense 观测 `[B,194,256]` 为条件，标准 uniform RectifiedFlow 预测 `[B,16,8]`（7D arm + 1D hand index），默认 10 步均匀 Euler 后再 lookup 为 `[B,16,19]`。第 0 步与历史对齐，`future_actions` 返回解码、逆 affine 后的 `[1:]`，运行时执行其前 8 步。积分过程中不裁剪或取整索引；仅在最终 decode 保留既有离散化。单帧码本与 H/C、padding 或 dt 无关，VQ-VAE 预训练配方不变。恢复严格使用 checkpoint 保存的完整架构、参数和 normalizer，无需原码本文件或初始 DINO 权重。

DQ 推理通过现有 `dtype=torch.float32` 参数固定初始噪声和 Euler 累计状态的精度；正式推理网络前向也使用 FP32。lookup 后保留 FP32 prototype，与 FP32 arm 拼接后由 FP32 action normalizer 逆 affine，最终物理动作为 FP32，Runtime 继续适配为 NumPy float64。该精度约定不改变 checkpoint 格式，也不要求重训 VQ。

## DexLatent 连续手部表示

采用 [DexLatent 固定源码](https://github.com/EmptyBlueBox/DexLatent/blob/502750df34b9fa6a1b56a66481586887ec722f9c/HandLatent/model.py)及官方四手预训练权重中的 `xarm7_xhand_right` 分支。E/D 为 `(64,128,64)` 的 Linear/LayerNorm/ReLU MLP，decoder 输出接 Tanh，编码只使用 32D mean。32D 对 XHand 的 12D 手部关节是维度扩展。E/D 构造时冻结，前向关闭 autocast 并使用 FP32；不采样、不计算 KL、不引入几何或辅助损失。

DexLatent 与 SAT/DQ 复用观测、6 层 768D DiTX 配方、两帧观测及 `H=16,C=8` 窗口。普通时间 token 的 Flow 目标为 `[B,16,39]`：训练集 limits 归一化的 arm7，加上训练集 limits 归一化的 hand latent32。保持全元素平均 Flow MSE，不做 arm/hand 分组加权。标签来自 action commands，joint_state 观测仍使用原 19D 训练集 affine。

唯一 action normalizer 的 hand12 使用官方 URDF 尺度：lower 为 `[0,-0.698,0,-0.174,0,0,0,0,0,0,0,0]`，upper 为 `[1.832,1.745,1.745,0.174,1.919,1.919,1.919,1.919,1.919,1.919,1.919,1.919]`，`scale=2/(upper-lower)`、`offset=-1-lower*scale`。归一化 hand 在 E 入口 clamp 到 `[-1,1]`。

`dexmani_sim` 的[组合机器人 URDF](https://github.com/haoyangzhanglab/dexmani_sim/blob/6ccaed388aecfc0d78579fdaf5db2c012312c8e9/dexmani_sim/assets/robots/xhand/xarm7_xhand_right.urdf)和[独立手 URDF](https://github.com/haoyangzhanglab/dexmani_sim/blob/6ccaed388aecfc0d78579fdaf5db2c012312c8e9/dexmani_sim/assets/robots/xhand/xhand_right.urdf)已将 `right_hand_thumb_rota_joint1` 和 `right_hand_thumb_rota_joint2` 上限统一为 1.745 rad。当前 `dexmani_sim`、`dexmani_real` 与 DexLatent 官方 XHand URDF 的 12 个主动关节位置上下限一致；此处不代表完整 URDF、坐标系、effort 或实际运行限制全部一致，`dexmani_real` 的运行配置仍可能进一步收紧下限。

编码和解码继续使用现有官方固定 hand affine；物理关节目标沿用公共执行端处理，无需增加 DexLatent 专用限位转换、比例缩放或裁剪逻辑。

Fresh 先加载 DINO/E/D，拟合公共 affine 并覆盖 action 手部尺度，再通过 `dataset.iter_normalization_data("action")` 分块拟合内部 `hand_latent` limits，最后创建 EMA。该统计只消费 train split 的真实行，不读图像或 padded 窗口、不缓存 latent 数据集。`hand_latent` 不加入 Dataset/YAML normalization；其 affine buffers 随完整策略保存，恢复形状从实际权重推导。官方先验无需匹配本地 split，latent affine 则必须来自本次训练划分。

推理显式传递 generator，以 FP32 状态完成 10 步 Euler，随后仅解码一次并逆 action affine 为 `[B,16,19]`；公共接口返回 `[B,15,19]`，执行前 8 步。积分中不裁剪或投影 latent；保留请求内条件 K/V 复用和 sync/async，不支持 RTC。构造、续训和推理均不读取初始权重或重新拟合统计。

在上文 `DATA` 路径设置后执行；`TASK` 须对应数据的实际任务，用于保存部署和评测配置：

```bash
bash scripts/utils/download_pretrained.sh dexlatent
TASK=pick_apple_messy
RUN="experiments/dexlatent/$TASK/$(date +%Y%m%d_%H%M%S)"
bash scripts/training/train.sh dexlatent "${DATA[@]}" "task_name=$TASK" "hydra.run.dir=$RUN"
python -m dexmani_policy.training.common.resume --run "$RUN" --device cuda:0

# 只使用保存的策略与真实观测做离线推理，不连接机器人或启动闭环评测。
RUN="$RUN" DATA_ZARR="$DATA_ZARR" python - <<'PY'

PY
```

## 官方实现与本地适配

| 方法 | 重要的本地差异 |
| --- | --- |
| DQ | 策略与 SAT 共用 dense 编码器和 uniform flow，动作头为普通 DiTX；本地 VQ `num_layers=6` 计全部隐藏层，导出使用 learned weights（非官方固定 0.5/0.5）。默认导出 last，显式 val 时按 lookup 误差选 best |

## DQ-RISE 训练默认值

训练预算、LR、betas、decay、裁剪与调度以 [策略配置](../dexmani_policy/configs/) 和预训练入口为准。DQ 策略采用与 SAT 相同的 `1e-4` LR、`(0.95,0.999)` betas、`1e-6` decay、cosine/warmup 500、grad norm 1.0 和训练/评测 EMA，100000 updates 是共同本地预算，不宣称最优；DINO 默认冻结，其余 encoder 可训练。`obs_lr` 作用于整个可训练观测编码器，包括可选 LoRA。VQ 预训练及 codebook EMA 独立保留，策略 EMA 不改变码本训练。优化器按有效 update 推进，关闭裁剪仍检查非有限值。SAT/DQ 总 flow MSE 不可直接横向比较，DQ 另关注部署 lookup 重建误差。

## 预训练数据与选点

| 方法 | 有 holdout | 无 holdout | 产物 |
| --- | --- | --- | --- |
| DQ VQ | `val_lookup_mse` 最低的 best | 固定预算结束后的 last，不执行训练集 selection pass | VQ checkpoint、codebook NPZ |

VQ 将数据路径、seed、数量参数和完整配方记录在 `config.yaml`，逐 epoch 保存 `metrics.jsonl`，保留 last 和非最后一轮的周期 checkpoint，最后一轮不另存同内容的 epoch 快照；有验证时另存 best。checkpoint 保存模型结构、权重、hand affine 及当时指标。数量不足或验证指标非有限时明确失败，不回退训练集选模。模型导出和下游加载均不要求数据清单或选模身份。
