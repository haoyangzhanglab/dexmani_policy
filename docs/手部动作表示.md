# 手部动作表示

SAT、DQ-RISE、DexLatent 与 ODE 最终都输出手臂与手部的绝对关节目标。前三者共享空间观测编码与 Rectified Flow 框架，区别在于动作表示；ODE 从上一条实际下发目标出发，通过向量场积分生成轨迹。

## 表示与生成方式

| 方法 | 模型生成什么 | 如何还原动作 |
| --- | --- | --- |
| SAT | 按关节组织的整段轨迹 | 还原轨迹排列与关节尺度 |
| DQ-RISE | 手臂目标与连续手姿索引 | 将索引离散化，在固定码本中选择手姿 |
| DexLatent | 手臂目标与连续手部潜表示 | 使用冻结解码器还原手部关节目标 |
| ODE | 关节空间向量场与可选速度偏移 | 从上一条实际下发目标积分为关节轨迹 |

SAT、DQ-RISE 和 DexLatent 通过相机标定融合点云局部几何与图像语义，再结合关节状态作为动作生成条件。

## SAT：按关节组织轨迹

SAT 将同一关节在整个动作窗口内的轨迹组织为一个 token，再联合建模不同关节之间的关系。模型直接学习关节表示，不需要独立的手姿先验。

Flow 学习的是生成过程中的变化方向，输出动作仍是关节目标，而非物理关节速度。

## DQ-RISE：从固定码本选择手姿

DQ-RISE 先用示教手姿训练残差 VQ-VAE，再将解码得到的手姿原型排序，形成固定码本。每个原型代表整只手的一种目标姿态。

策略联合生成手臂目标与连续手姿索引，生成结束后将索引离散化并查表。在线推理只使用码本，不再运行 VQ-VAE；可生成的手姿受码本限制。

## DexLatent：在连续先验空间生成手姿

DexLatent 使用预训练的 XHand 编码器和解码器，并在策略训练中保持冻结。训练时，编码器将示教手姿转换为连续潜表示；推理时，Flow 生成潜表示，再由解码器还原关节目标。

潜表示是先验学习到的手姿坐标，各维不直接对应关节，也不意味着对手姿进行低维压缩。DQ-RISE 的码本来自本地示教，DexLatent 使用外部手部先验，比较时需考虑先验来源。

## ODE：从上一条指令积分生成轨迹

ODE 以点云历史和最新实测关节状态为条件，从上一条实际下发目标积分 `H=n_action_steps` 个控制周期，并以完整关节轨迹作为监督。训练起点取同回合上一条原始指令，回合首帧取实测状态。

执行端通过 `prev_action` 传入上一条实际下发目标，每回合从 `None` 初始化。每次发送成功后，以裁剪后的实际目标更新该值；完整执行 H 步后再重新预测，中途终止则立即停止。模型自身不保存执行状态。

核心实现位于 [agents/hand_prior/](../dexmani_policy/agents/hand_prior/) 和 [ODE decoder](../dexmani_policy/agents/action_decoders/ode.py)，整体关系见[项目架构](项目架构.md)。
