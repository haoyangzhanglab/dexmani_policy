# 手部动作表示

机器人最终执行的是 19 维绝对关节目标：7 维手臂目标与 12 维手部目标。SAT、DQ-RISE 和 DexLatent 的区别在于，模型用什么方式表示并生成这些目标。

三者共享本项目的空间观测编码与 Rectified Flow 动作生成框架：先根据观测，在选定的表示空间中逐步将噪声变为动作序列，再还原为关节目标。公共数据流见[项目架构](项目架构.md)，动作单位与时间对齐见[仿真数据集格式](仿真数据集格式.md)。

## 三种表示的区别

Transformer 将特征组织为 token，即供主干处理的特征单元。SAT 按关节组织 token；DQ-RISE 和 DexLatent 按时间组织，但先改变了手部动作的表示空间。

| 方法 | 生成坐标 | token 如何组织 | 预先学到的手部表示 |
| --- | --- | --- | --- |
| SAT | 归一化的 19 维关节轨迹 | 每个 token 包含一个关节在整段时间内的轨迹 | 无独立手姿先验 |
| DQ-RISE | 每时刻归一化的 7 维手臂目标 + 1 维连续手姿索引 | 每个 token 对应一个时刻 | 本地示教中的离散手姿原型 |
| DexLatent | 每时刻归一化的 7 维手臂目标 + 32 维归一化手部潜表示 | 每个 token 对应一个时刻 | 官方冻结的 XHand 编码器与解码器 |

因此，这组比较同时改变了轨迹组织、表示维数和先验来源，衡量的是不同动作建模方式的整体差异。

## SAT：把每个关节的轨迹作为整体

SAT 的一个 token 描述同一关节在整个动作段内如何变化。例如，一个拇指关节的未来目标序列先被编码为一个特征，再与其他关节的特征共同建模。token 中还加入手臂或手部的身份，以及对应的关节身份，帮助模型区分各关节。

主干处理这些 token 后，将输出还原为各关节轨迹在 Flow 生成路径上的变化率。这里的变化率用于把噪声逐步变为目标轨迹，不是机器人执行时的物理关节速度。训练与生成始终在归一化关节坐标中进行，最终输出仍是绝对关节目标。

本地身份只描述固定的 xArm7/XHand 及其控制顺序，不代表官方多机器人语义编号，也不意味着能够直接迁移官方多机器人权重。

## DQ-RISE：用一个索引选择整只手的姿态

DQ-RISE 的部署码本是一张固定手姿表，每行都是一组 12 维手部关节目标，称为一个手姿原型。模型生成一个索引，就能从表中取出整只手的目标姿态；手臂仍直接生成连续关节目标。

### 从示教学习手姿表

首先，用训练示教中的单帧手部动作学习残差 VQ-VAE。编码器把手姿变为连续特征，多级量化依次表示前一级未能表示的部分，解码器再重建手姿。重建损失要求还原原始手姿，量化约束（commitment）则让连续编码靠近其量化结果。

随后，枚举各级码本的组合，按学得的权重合成并解码为手姿原型。原型沿主要手姿变化方向，也就是 PCA 的第一主成分排序，从而得到一维编号。策略运行时只使用这张表，不再调用 VQ-VAE 的编码器或解码器。

### 把编号变成 Flow 的学习目标

对每个示教动作，在归一化手姿空间中寻找最近原型，并将其编号映射为连续标量。设原型数为 $K>1$，编号为 $i$，对应的连续索引为 $s_i$：

$$
s_i = \frac{2i}{K-1}-1,\qquad i=0,\ldots,K-1.
$$

例如，三个原型的索引为 −1、0、1。最终生成的索引若为 0.8，就会选中索引为 1 的第三个原型，而非在两个手姿之间插值。

Flow 联合生成手臂目标与连续手姿索引。积分结束后才将索引离散化、查表并还原关节尺度；中间生成状态不反复量化。

码本学习、最近邻标签与查表误差都使用训练示教拟合的逐关节尺度，下游策略沿用同一尺度。原型描述的是单帧手姿，不依赖动作窗口长度。固定原型表限制了可还原的手姿集合，因此还应关注查表后的手姿误差；更换原型或重新编号会改变索引含义，需要重新训练下游策略。

## DexLatent：在冻结先验的连续空间中生成手姿

DexLatent 使用官方预训练的 XHand 编码器与解码器。它们在策略训练中保持固定：编码器把 12 维手部目标变为 32 维连续向量，解码器再将向量还原为手部目标。这个向量称为潜表示（latent），可理解为网络学到的手姿坐标，其各维不直接对应某一个关节。

本地使用编码器输出的均值向量（mean），不从潜变量分布中随机采样。32 维对于原来的 12 维手姿是维度扩展，不能称为低维压缩；下游策略学习动作生成，不再训练手部先验。

| 阶段 | 手部目标如何变换 |
| --- | --- |
| 构建训练目标 | 关节目标 → 按官方关节范围归一化 → 冻结编码器 → 32 维均值向量 → 按本地训练集的潜表示范围归一化 |
| 生成动作 | Flow 生成潜表示 → 还原潜表示尺度 → 冻结解码器 → 还原关节目标 |

这里有两种不同尺度。官方关节范围定义先验接受什么输入，进入编码器前的手姿限制在该范围内；本地潜表示范围则用于调整生成坐标的数值尺度。二者不能互相替代。

Flow 联合生成手臂目标和手部潜表示，积分中不裁剪或投影潜表示，结束后只解码一次。作为观测输入的关节状态仍保留原来的 19 维含义。

## 如何解释比较结果

DQ-RISE 的原型来自本地示教，且在本地 XHand 的逐关节归一化空间中学习；DexLatent 使用官方冻结先验。它们具有不同的先验来源，公共策略配置并不意味着预训练数据、参数量或计算量相同。

三种方法的 Flow 误差分别处于关节、连续索引和潜表示空间，数值不能直接横向排名。比较时应列明先验来源、示教预算和推理预算，并依据[仿真评测机制](仿真评测机制.md)比较闭环表现。

这些都是接入本项目共同架构的本地适配，不能据此声称完整复现各论文系统；当前单 XHand 设置也不构成跨手泛化验证。
