四、观测与归一化契约

外部输入：
joint_state          [B,T,19]
point_cloud          [B,T,N,6]，默认 N=1024
eef_pose             [B,T,9]
fingertip_xyz        [B,T,5,3]
finger_tactile_force [B,T,5,3]
默认 T=4。数据按 obs[t] 在 action[t] 之前的既有语义使用。

BasePolicy.preprocess 已执行归一化并合并 B/T；新 observation encoder 收到的是 [B*T,...]。
不要再次归一化、再次 flatten B/T，或在每个模块内部猜测时间维。
由 n_obs_steps 恢复时间轴，必要边界检查总帧数可整除 T。

归一化：
joint_state: limits
action: auto
point_cloud: identity
eef_pose: identity
fingertip_xyz: identity
finger_tactile_force: rms

point_cloud XYZ、eef_pose 平移、fingertip_xyz、anchor_xyz 必须保留同一世界坐标系的米制几何。
eef_pose 的旋转是已有列式 rot6d。复用 HandStateEncoder 的解释，不改成行式，不重复做局部坐标变换。
腕槽表示 EEF 原点，不能当作掌心或触觉传感器坐标系。
归一化后的关节用于状态编码；几何运算继续使用原始位姿/位置。
真实 aggregate SDK force 与仿真世界系牛顿值不能直接共享尺度或假设同一坐标轴；按当前数据 source 单独拟合并保存 normalizer。
不要用指尖位置推造触觉传感器旋转，不把 force 当作 XYZ 旋转。
有效零触觉不是缺失。不要从数值是否为零推导 tactile_valid。
当前标准数据契约没有要求 tactile_valid，本版不扩展 dataset/runtime 字段或新做缺测增强；正常输入不传 mask，复用融合模块既有行为。
默认不启用 modality dropout，尤其不能把几何字段分别清零后继续当作有效坐标。

五、A1 observation encoder 的确定数据流

令 M=B*T，D=192，S=6，K=12。

1. 按已有 preprocess_point_cloud 处理点数和 XYZRGB；将同一份处理后的米制点云同时传给 Sparse3D 与 HandSceneEncoder。
   Sparse3D 配置沿用现有实现：
   channels=384，num_patches=96，group_size=32，depth=4，
   num_heads=8，mlp_ratio=2.0，geometry_scale=0.10，rope_scale=0.05，rope_base=100.0。
   patches = pc_encoder(pc)
   patches["tokens"]: [M,96,384]
   patches["xyz"]:    [M,96,3]
   patches["mask"]:   [M,96]

2. 调用 HandStateEncoder(joint_state, eef_pose, fingertip_xyz)，宽度192。
   hand["hand_tokens"]: [M,6,192]
   hand["anchor_xyz"]: [M,6,3]
   hand["rotation_world_from_eef"]: [M,3,3]
   槽位固定为 wrist/thumb/index/middle/ring/pinky。
   HandStateEncoder 已有 keypoint embedding，不再复制一套身体身份 embedding。

3. HandSceneEncoder 显式指定 scene_channels=384，身体 token 宽度192；局部几何其余参数沿用当前默认。
   relation = hand_scene(
       pc, patches, hand["anchor_xyz"], hand["hand_tokens"],
       rotation_world_from_eef=hand["rotation_world_from_eef"],
   )
   该分支必须读取未压缩的96个patches。不能先执行全局12区域压缩再供手指查询。

4. GatedTactileFusion(token_channels=192, tactile_encoder=已有实例)。
   由 fusion 持有 tactile_encoder；不要把同一个模块重复注册到另一路属性。
   interaction = tactile_fusion(
       relation, tactile=obs["finger_tactile_force"]
   )["interaction_tokens"]
   这里传的是已按 rms 归一化的原始五指力，不是提前编码的 tactile tokens。
   fusion 内部会执行触觉编码，禁止重复编码。
   返回值已经是完整 H + Δscene + gΔtactile，外层不要再次加 H、relation_update 或额外残差。

5. 独立的全局场景分支：
   scene_aggregator = SceneAggregator(token_channels=384, ...)
   使用当前默认12区域及 refinement 结构。
   scene = scene_aggregator(
       patches["tokens"], patches["xyz"], patch_mask=patches["mask"]
   )["scene_token"]
   注意实际返回键是单数 scene_token。
   用一个 Linear(384,192) 投影，得到 [M,12,192]。
   不增加 query_context 分支，不构建物体级跟踪，不把 FPS 区域编号当作跨帧身份。

6. interaction 恢复 [B,T,6,192]，执行下一节 HandHistoryEncoder。
   scene 恢复 [B,T,12,192]。
   condition = torch.cat((interaction, scene), dim=2).flatten(1,2)
   得到 [B,T*18,192]，默认 [B,72,192]。
   obs_token_dim=192。
   展平顺序必须是 frame-major：t0的6身体+12场景，然后t1，再t2、t3。
   不能先放四帧所有身体，再放四帧所有场景；DiTX 会按每18个token注入同一帧的时间位置。
   返回浮点条件时确保 FP32，使现有 RectifiedFlow 的噪声与 Euler 累加保持 FP32；网络内部仍可按现有 autocast 使用 BF16。
   不给已自带时间位置的 DiTX 再增加一套额外的最终 context 时间编码。

Sparse3D 与 SceneAggregator 的现有非空点云/有效patch前提继续成立。不实现全视觉缺失 fallback。
可见表面距离不是接触真值，融合 gate 不是接触概率；不要为这些中间量加新的监督或语义标签。

六、HandHistoryEncoder 的精确结构

默认 history_mixer=true，开关位于 agent 配置；false 仅供 A0 消融。
输入输出严格保持 [B,T,6,192]，保留全部T帧。
模块挂在 observation encoder 下，保证现有 optimizer_groups 自动覆盖参数。

按以下次序实现两个 Pre-LN 残差块，各只有一次注意力和一次FFN：

空间块：
- reshape 为 [B*T,6,192]。
- LayerNorm -> MultiheadAttention(192,4,batch_first=True,dropout=0.0)，残差相加。
- LayerNorm -> Linear(192,384) -> GELU -> Linear(384,192)，残差相加。
- 六个槽位在同一帧内相互读取，不跨时间。

时间块：
- 恢复后 permute 为 [B,6,T,192]，再 reshape 为 [B*6,T,192]。
- 加入一个 learned time embedding [1,T,192]，按 std=0.02 初始化。
- 使用同样的 Pre-LN attention+FFN 残差结构，宽度192，4heads，FFN384，dropout=0。
- 每条序列只对应同一个身体槽，不能混入其他手指或batch。
- 因果mask只屏蔽严格未来位置，允许自身和过去位置。
- nn.MultiheadAttention 的 bool mask 中 True=禁止读取；不要照搬 SDPA 的相反含义。
- mask 可注册为 persistent=False 的 buffer，随模块迁移设备，不新增跨调用缓存。
- 恢复 [B,T,6,192] 返回。

小残差使用FP32累加，遵循现有交互模块习惯；不要给每个算子包一层通用dtype适配。
不额外增加外层 U + history(U)，模块自身已经执行完整残差。
不添加第二套身体身份 embedding、recurrent state、记忆队列、跨episode状态、动态深度或额外门控。
history_mixer=false 时跳过整个模块及其时间embedding，不留未使用的历史编码器参数。
12个场景token不进入这段时间注意力；DiTX已有完整四帧场景条件。
空间/时间两个块是观测编码器的一部分，不改变动作DiTX的8层约束。

七、策略与标准 Flow Matching 接线

InterActDexPolicy 继承 BasePolicy，supported_action_keys=("action",)。
构造 observation encoder、普通 DiTX、RectifiedFlow 后调用 BasePolicy.__init__。
参照 ManiFlowPolicy 的直接构造风格，但不要复制一致性模型或相关参数。
普通 DiTX：
n_layers=8，hidden_dim=768，n_head=8，mlp_ratio=4.0，
timestep_embed_dim=128，p_drop_attn=0.1，
qkv_bias=false，qk_norm=false，
horizon=16，action_dim=19，n_obs_steps=4，obs_token_dim=192。
不得出现 target_t_embed_dim、target_t、flow_batch_ratio 等一致性训练参数。
普通 DiTX 不接收 pre_norm_modality；不要把 ConsistencyDiTX 的该参数传给它。

RectifiedFlow 必须显式指定：
t_sample_mode="uniform"
time_shift_alpha=1.0
num_inference_steps=10
不把 num_flow_train_timesteps 解释为 uniform 连续训练时的离散网格，不把它与推理NFE绑定。

训练：
z ~ N(0,I)，t ~ Uniform(0,1)，与专家归一化动作 A 独立采样；
x_t=(1-t)*z+t*A；
target_v=A-z；
loss=mean((v_theta(x_t,t,C)-target_v)^2)。
这是唯一训练损失；复用 RectifiedFlow.compute_loss，不另写同名损失实现。
requires_ema_for_loss 应自然为 false。

推理：
x_0 ~ N(0,I)
对 j=0..N-1：
x_{j+1}=x_j+v_theta(x_j,j/N,C)/N
不改积分方向、终点、噪声先验，不添加裁剪/温度/引导/后处理机制。
沿用已有 generator、inference_steps override 和一次ODE求解内的context K/V复用，不做跨观测缓存。

尽量完整继承 BasePolicy 的 compute_loss、predict_action、format_action_output、optimizer_groups 和 metadata 行为。
标准配置 action_start_index=T-1=3；完整输出 [B,16,19]，反归一化后由 BasePolicy 返回 future_actions [B,13,19]。
由现有执行器取前4步，不在策略内再次截为4步，也不把16解释为16个未来执行步。
继承现有sync/async支持，不新增RTC执行能力。
不要在policy中复刻训练循环、动作归一化或checkpoint逻辑。
